# Спека для ядра панели: генерация и проверка холодных писем КЦ

Назначение: вшить конвейер генерации/проверки в ядро панели отправки
(движок C:\sender, точки _ai_letter/_review_letter + review_lenses).
Эталонная реализация: email-templates/pipeline/{regen_kc.py, stream_regen.py,
send_stream.py} - Python stdlib + провайдерский клиент. Правки владельца
23-24.07 все учтены.

## 0. Провайдер

Все LLM-вызовы - провайдерский API (Anthropic-совместимый, PROVIDER_BASE_URL,
модель claude-fable-5), СТРИМИНГ обязателен, ретраи с экспоненциальной паузой
(до 6 попыток), плюс ретрай парсинга JSON-ответа (до 3 раз, regex \{.*\} по
телу ответа). Заголовки клиента - как в seo-texts/gen_provider.py.

## 1. Вход конвейера (на одно письмо)

- recipient: {email, company_name, okved, segment, contact_name|null, extra{}}
- template_mode:
  a) NEWS - есть новость: обязательны extra.news_object и extra.city
     (опц. news_month). Заход из пула NEWS-ZAHODY.md, ротация механик.
  b) GENERIC - новости нет. Заход от отрасли/профиля. Имитация события
     запрещена (гейт-проверка ниже).
- именной/общий: contact_name есть -> {greeting}/{first_name} доступны;
  нет -> общий шаблон, именные поля НЕ упоминать (незаполненный плейсхолдер
  роняет отправку).
- факты (kc-facts.json): региональные счётчики опубликованных кейсов,
  клиенты по регионам, канон «больше 5580 внедрений». Числа в письме - ТОЛЬКО
  отсюда или техконстанты.

## 2. Генерация (промпт-скелет)

Роль: «пишешь холодные B2B-письма ООО «Руспром» (Компрессор Центр)».
Состав промпта, по порядку:
1. RULES - 13 правил ДОСЛОВНО из pipeline/regen_kc.py (юр-рамка; отказ ровно
   один раз; голос «подбираю», поставляет компания; без тире; канон чисел;
   оборудование-не-сервис; техточность; структура; 50-110 слов; темы;
   человечность; не-реклама; маршрутизация новость/генерик).
2. Эталоны тона (фрагменты шаблонов владельца) + запреты дословного
   клонирования оборотов, «закладываю», псевдо-новости.
3. Блок ФАКТЫ (см. п.1).
4. Данные получателя + режим (NEWS с заходом из пула / GENERIC).
5. Формат ответа - строгий JSON {"letters":[{"idx","subject","body"}]}.
Батчинг: 3-5 писем на вызов, параллельность 3-4 потока.

## 3. Механический гейт (код, порядок проверок)

Тема (subject):
- \d в теме -> брак «цифра в теме»; [?!] -> брак; ^re: -> брак; > 6-7 слов -> брак.
Тело (body), regex (?i) где уместно:
- «—» длинное тире; \bпредлага; \bскидк; \bакци(я|и|ю|ей|ям)\b; \bкупит[ье];
  \bгаранти; \bлизинг; \bцен(а|ы|у|е|ой|ам|ах)\b; рубл; «в наличии»;
  поставля(ю|ем)\b («я поставляю» запрещено); \bмы\b; реализовал;
  \bданн(ый|ая|ое|ые); таким образом; в ассортименте; представлен[ыа]\b;
  осуществля; требует (пересмотра|внимания); надеюсь.*письмо|позвольте
  представиться (плезантрии); закладыва; (подбор|посчита|подготовл|отвеч)...
  (за день|за час|в течение час|в течение дня) - обещание скорости;
  ведущих производ|собственной разработк|любого масштаба - эпитеты-витрины;
  (вижу|заметил|обратил внимание)...(модернизир|расшир|запуска|строит) -
  псевдо-новость (только в GENERIC-режиме);
  \bРуспром\b|prokompressor|\bИНН\b - подпись в теле; <ul; \{[a-z_]+\} -
  незакрытый плейсхолдер.
- Опция отказа: substring-список + regex-детектор (в т.ч. внутри вопроса:
  «(писать|беспокоить|отвлекать) не (стоит|буду)» и др., см. OPTOUT_RE).
  Нет отказа -> брак. «извините за» больше 1 раза -> брак (заискивание).
- Объём: 45-140 слов (цель 50-110).
- Финал тела - строка «С уважением,» (подпись добавляет отправщик).
- Числа: множество цифр тела минус допуск (факты + техконстанты 3-5, 7-35,
  20-40 бар, +3/-40/-70 C, кВт из шаблона) -> непустой остаток = брак.
  Проценты только для чистоты азота (95/97/99).
- Витрина: (вхождения «5580») + (вхождения «опубликованн... кейс/проект») > 1
  -> брак «два числа-достижения».

## 4. Верификатор (провайдер, JSON-вердикты)

Промпт: те же RULES + инструкция «строгий контролёр, пропуск нарушения дороже
ложной тревоги» + ОТДЕЛЬНАЯ линза человечности («прочитай глазами получателя;
глянец/пресс-релиз/параллельные тройки = брак») + реклама-тест («письмо больше
о нас, чем о них -> переписать»). Формат: {"verdicts":[{"idx","ok","problems"}]}.
Линзы: юрист / тон / спам / инженер / факты / структура / человечность.

## 5. Цикл доработки

до 3 раундов: гейт -> (если прошёл) верификатор -> все замечания -> fix-вызов
провайдера («устрани ПЕРЕЧИСЛЕННЫЕ нарушения, ничего не ломая» + RULES +
факты + текст + список нарушений) -> заново гейт. После 3 раундов не прошло ->
принудительный раунд с жёсткой инструкцией (пример: «предпоследняя строка -
дословная строка отказа») -> не прошло -> письмо в брак-лог, НЕ отправлять.

## 6. Анти-штамп (уровень кампании)

Счётчик оборотов по партии: {частый случай|история|ситуация: 4, судя по
профилю: 4, смотрел ваш: 5, рано или поздно: 3, бьёт по: 3, встаёт вопрос: 4,
под контролем: 5, точная фраза отказа: 8} на 49 писем (~10%, масштабировать
пропорционально). Превышение -> перефраз-вызов «обороты израсходованы, замени
своими» -> заново гейт. Счётчик живёт в state кампании.

## 7. Отправка

- Подпись дописывает отправщик: тело + "\n" + «Менеджер по продажам,\n{имя из
  карточки ящика}\n«Компрессор Центр»\nООО «Руспром», ИНН 2221239841».
  Имя также в From. Без домена, без «отписаться», без List-Unsubscribe.
- Заголовки: X-Variation-Id (id письма), X-Campaign (id кампании), Message-ID
  с доменом отправителя, Date.
- Пейсинг: тестовая пара 20-40 сек; боевой канон - раз в 10-15 минут в рабочее
  время буднями (FIRST-TOUCH-NOTES), микро-сегменты до ~50 адресов.
- Резюм: прогресс {sent[], log[], stats} персистентно; дедуп по id письма;
  повторный запуск досылает неотправленное.

## 8. Логи и брак

Хранить на каждое письмо: финальный текст, раунды с причинами (гейт-фейлы,
вердикты линз), время, статус отправки. Брак-лог с причинами - вход для
следующей итерации правил.

## 9. Данные-контракты

- {greeting}/{first_name} - только при contact_name.
- NEWS: news_object + city обязательны, иначе GENERIC.
- Региональное число - только по батчу региона получателя; клиент - только в
  письме его региона.
- equipment_pitch (AI по ОКВЭД): 1-2 предложения, боль отрасли, без цен и
  «предлагаем» - контракт в KC-SHABLONY-V3.md.

## 10. Матрица генерации (для режима «с нуля», извлечена из пилота и нормализована)

РОЛИ (4 канонические, определяют лексику и фокус):
1. Главный инженер / технический директор - техпараметры, надёжность, точка росы.
2. Директор (ген./по производству/по развитию) - простой, экономика, риски сроков.
3. Начальник производства - пиковые смены, брак, «линия встала».
4. Снабжение / закупки - сроки поставки, доступность, «кто поставщик».

УГЛЫ (7, ротировать по батчу):
1. Короткий вопрос-диагностика («на баллонах или уже генератор?»).
2. Боль простоя оборудования (конкретная картинка).
3. Региональный кейс-пруф («N опубликованных кейсов по региону», только батчу региона).
4. Экономика и энергозатраты (без процентов и обещаний экономии).
5. Надёжность / замена стареющего парка / бренды, ушедшие из РФ.
6. Новостной повод (ТОЛЬКО NEWS-режим, заход из пула NEWS-ZAHODY).
7. Сроки и доступность (бывший угол «цена/лизинг» пилота: цены и лизинг
   запрещены юр-рамкой, угол мутирует в «типовые уходят быстро, нестандартные
   после расчёта» - без сумм).

ТОН (две оси):
- Размер бизнеса: малый / средний / крупный (лексика, масштаб болей).
- Стиль: деловой прямой | партнёрский практичный | технический конкретный |
  экспертный сдержанный | уважительный без навязывания | лаконичный без воды.
Соответствия по умолчанию: снабжению - углы 1/7, инженеру - 2/4 + техстиль,
директору - 4/5, производству - 2/1.

## 11. Контракт «ОКВЭД -> боль» (equipment_pitch)

Промпт-инструкция генератору боли: «По ОКВЭД получателя сформулируй ОДНУ
конкретную боль применительно к сжатому воздуху/техническим газам. Боль -
картинкой (что физически случилось и что встало), 1-2 предложения, без цен,
процентов, обещаний и слова "предлагаем"». Примеры соответствий:
металлообработка -> влага в пневмолинии, брак покрытия, ржавый инструмент;
пищевое производство -> азот в упаковку, срыв графика поставок баллонов;
розлив/ПЭТ -> бустер 20-40 бар, конденсат в заготовках;
деревообработка -> пиковые смены, старая станция не тянет;
стройматериалы -> энергозатраты при постоянной нагрузке;
аквакультура -> кислород, задержка баллонов в критический момент;
стройплощадки -> дизельные МКС, холодный запуск, удалённость.
Выход гейтится теми же проверками, что и письмо.

## 12. Ротация по батчу (разнообразие сверх бюджета оборотов)

- Угол: не более ~25% писем батча на один угол; соседние письма батча - разные
  углы (счётчик углов в state кампании, аналогично PHRASES).
- Механика новостного захода: ротация по пулу NEWS-ZAHODY, один и тот же
  вариант не чаще 1 из 10.
- Форма CTA: чередовать бинарный вопрос / «как сейчас решаете» / маршрутизацию
  («кто отвечает за...») / микро-CTA подборки.
- Форма отказа: чередовать «внутри вопроса» и «отдельной строкой» (лимит
  дословной фразы уже в бюджете оборотов).
