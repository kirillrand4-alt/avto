# Промпт для сессии на ветке движка (persona-prompt-seo-sender-vi4tcq)

Скопировать сессии, работающей над ядром панели, целиком:

---

Ты работаешь на ветке движка рассыльщика claude/persona-prompt-seo-sender-vi4tcq
(Python-движок ~20 модулей + веб-панель, 718 тестов зелёные, деплой C:\sender).
Задача: вшить в ядро панели генератор холодных писем КЦ с проверками - по
готовой спеке, выработанной и обкатанной на партии 49 писем 23.07.2026.

ИСТОЧНИКИ ИСТИНЫ (ветка claude/rusprom-b2b-email-templates-8rrstf, читать до кода):
- email-templates/PANEL-INTEGRATION-SPEC.md - главная спека, параграфы 0-12
- email-templates/pipeline/regen_kc.py - 13 правил (RULES) дословно, все
  гейт-регексы, промпт-скелеты генерации/верификации/фикса
- email-templates/pipeline/stream_regen.py - бюджет оборотов, циклы доработки
- email-templates/pipeline/send_stream.py - подпись-блок, механика отправки
- email-templates/KC-SHABLONY-V3.md (шаблоны + канон чисел и подписи),
  NEWS-ZAHODY.md (пул новостных заходов), FIRST-TOUCH-NOTES.md (практики),
  kc-regen-49.json (эталонная партия - образец целевого качества)

ЧТО ВКЛЮЧИТЬ В ГЕНЕРАТОР (чеклист, всё обязательно):
1. Модуль правил: RULES (13 правил) как единый конфиг/константа. Любые будущие
   правки владельца - только через него, промпты собираются из него.
2. Механический гейт отдельной чистой функцией (регексы из спеки параграфа 3:
   юр-стоп-слова, тире, «я поставляю», «мы», канцелярит, детектор отказа с
   вариантами внутри вопроса, двойное заискивание, объём 45-140 слов, темы 2-7
   слов без цифр/знаков/Re:, финал «С уважением,», числа только из допуска
   фактов, витрина максимум одно число-достижение, псевдо-новость в генериках,
   плейсхолдеры). Вызывается до верификатора и после каждого фикса.
3. Верификатор через провайдера: расширить review_lenses.py линзами
   юрист/тон/спам/инженер/факты/структура/человечность (с реклама-тестом
   «письмо о них или о нас») - промпт из спеки параграфа 4. Строгий JSON-вердикт.
4. Цикл доработки (параграф 5): гейт -> верификатор -> fix-вызов с перечнем
   нарушений, максимум 3 раунда + один принудительный (жёсткая инструкция,
   например дословная строка отказа). Не прошло - в брак-лог, НЕ отправлять.
5. Кампанейный state в store: бюджет фирменных оборотов (параграф 6, ~10%
   партии на оборот) и счётчик углов (параграф 12, максимум ~25% батча на
   угол, соседние письма - разные углы). Превышение - перефраз-вызов.
6. Маршрутизация NEWS/GENERIC (параграф 1): extra.news_object + extra.city
   заполнены -> новостной шаблон, заход из пула NEWS-ZAHODY с ротацией механик
   (вопрос в заходе = вопрос-шаг письма); иначе генерик, которому гейт
   запрещает имитацию события («вижу, вы модернизируете» без данных).
7. Генерация с нуля по матрице (параграф 10): роль получателя -> уместные
   углы, тон = размер бизнеса + стиль. Контракт «ОКВЭД -> боль» (параграф 11) -
   вшить в equipment_pitch в personalize.py: одна боль картинкой, 1-2
   предложения, без цен/процентов/обещаний.
8. Merge-поля: добавить campaign-уровневые manager_name/manager_role (в core
   их нет); валидация - именной шаблон не уходит получателю без contact_name,
   news-шаблон - без news-полей (незаполненный плейсхолдер роняет отправку,
   это поведение сохранить).
9. Подпись (параграф 7): тело кончается «С уважением,», отправщик дописывает
   блок «Менеджер по продажам, / {имя из карточки ящика} / «Компрессор Центр» /
   ООО «Руспром», ИНН 2221239841». Без домена, без «отписаться», без
   List-Unsubscribe. Согласовать с personalize._ensure_attribution, чтобы ИНН
   не задублировался (дубль подписи - главный баг старого пилота).
10. Таргетинг сегмента КЦ vs Meyer: фильтр segment в iter_recipients +
    Campaign.segment (блокер P1.5 из REMAINING-WORK) - без него кампании
    направлений не развести.
11. Пейсинг кампании конфигом: тестовая пара 20-40 сек; боевой канон - раз в
    10-15 минут, будни, рабочее время, микро-сегменты до 50 адресов.
12. Логи на каждое письмо: раунды с причинами (гейт-фейлы, вердикты линз),
    финальный текст, статус отправки. Брак-лог - вход для новых правил.
13. Тесты: юнит на каждый гейт-регекс (позитив+негатив), детектор отказа,
    бюджет оборотов, счётчик углов, маршрутизацию, сборку подписи. Приёмка:
    эталонная партия kc-regen-49.json проходит гейт 49/49.

ОГРАНИЧЕНИЯ:
- ХОЛД на боевые отправки в силе: никаких SMTP наружу, только тестовая пара
  по отдельной команде владельца.
- Все LLM-вызовы через провайдерский API (клиент как seo-texts/gen_provider.py:
  стриминг обязателен, ретраи, curl-UA для WAF шлюза), модель claude-fable-5.
- Работать только на своей ветке, коммитить осмысленно, модель-идентификатор
  в коммиты не вписывать.
- Правила текста письма НЕ менять по своему вкусу - они выстраданы правками
  владельца; любые изменения формулировок правил - только по его команде.
