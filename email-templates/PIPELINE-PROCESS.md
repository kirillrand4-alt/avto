# Как генерилась партия 49 КЦ-писем (23.07.2026): процесс конвейера

Копия писем в отправленном виде: kc-regen-49.json (тела без подписи - её
добавляет отправщик, канон подписи в KC-SHABLONY-V3.md).

## Входные данные

1. Сырьё: 61 вариация ночного пилота 20-21.07 (variations-100.json на дропе),
   матрица роль x угол x тон; 12 Meyer-писем отложены, 49 КЦ в работу.
2. Проверенные факты (kc-facts.json): региональные счётчики опубликованных
   кейсов из projects-index сайта (1017 из 1079), подтверждённые клиенты по
   регионам, канон «больше 5580 внедрений» (CRM). Выдуманные числа пилота
   заменены на честные.
3. Замечания глубокого ревью каждого исходника (pilot-deep-review.json).
4. 13 правил письма (pipeline/regen_kc.py, RULES) - собраны из требований
   владельца + эталонов его шаблонов v2 + практик продажников
   (FIRST-TOUCH-NOTES.md).

## Стадии конвейера

Все генерации и смысловые проверки - через провайдерский API (claude-fable-5,
стриминг). Оркестрация и механика - код.

1. REWRITE: чанки по 3 письма, 4 параллельных воркера. Промпт = правила +
   факты + исходное письмо + замечания ревью.
2. МЕХАНИЧЕСКИЙ ГЕЙТ (код): ~30 проверок - юр-стоп-слова, длинные тире,
   «мы»/«поставляю» от первого лица, канцелярит, плейсхолдеры, regex-детектор
   опции отказа (ровно одна), объём 45-140 слов, тема 2-7 слов без цифр и
   знаков, финал «С уважением,», числа только из допуска фактов и
   техконстант, проценты только для чистоты азота, псевдо-новость без данных,
   двойное заискивание.
3. ВЕРИФИКАТОР (провайдер): строгий контролёр по правилам, линзы
   юрист / тон / спам / инженер / факты / структура / человечность
   (с реклама-тестом «письмо о них или о нас»).
4. FIX-РАУНДЫ: до 2-3 кругов точечной доработки с конкретным фидбеком
   гейта и верификатора; хвост добит принудительной вставкой строки отказа.
5. АНТИ-ШТАМП: бюджет фирменных оборотов на партию (stream_regen.PHRASES,
   лимит ~10% писем на оборот) - при переборе принудительный перефраз.
6. ПОТОКОВАЯ ОТПРАВКА: готовое письмо -> kc-queue-NNN.json на дропе ->
   демон на сервере (send_stream.py как send_campaign.py) снимает по одному,
   собирает MIME (подпись-блок с именем ящика, X-Variation-Id, X-Campaign),
   шлёт SMTP s1->s2 с паузой 20-40 сек, прогресс в kc-stream-progress.json;
   STOP-маркер завершает демона после опустошения очереди.
7. ФИКСАЦИЯ: каждое ушедшее письмо -> stream-letters.jsonl -> git
   (kc-regen-49.json).

49/49 отправлено, 0 отказов. Механический гейт пройден всеми; вердикты
верификатора и причины браков промежуточных версий - в логах конвейера.

## Эволюция правил за день (правки владельца 23-24.07)

линза человечности -> правило «не-реклама» -> голос «подбираю» (поставляет
компания) -> канон чисел «опубликованные кейсы» -> подпись-блок (меняется
только имя) -> анти-штамп оборотов -> отказ ровно один раз -> темы как
внутренняя переписка + адресация функции -> маршрутизация новость/генерик
с запретом псевдо-новости -> пул новостных заходов (NEWS-ZAHODY.md).
