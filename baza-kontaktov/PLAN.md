# План: база контактов по 6 агро/пищевым сегментам (РФ + РБ)

Основа: сайты компаний. Реестры нужны только для списка «кого искать» и для
обогащения по ИНН, найденному на сайте (ОКВЭД, выручка). Контакты ЛПР берём
только с сайтов.

Свод трёх отчётов (инвентаризация сервера и веток, источники, методология), 05.10.2026.

## 0. Решение: собираем заново, «от сайта к компании»

База «Мейер» (`meyer-*`, `MEYER-BAZA-*` на drop) **не используется как основа**:
владелец оценил её качество как низкое. Её беда — путь «реестр по ОКВЭД → ищем
сайт → директор из ЕГРЮЛ». Отсюда:
- у 41% компаний сайта нет;
- ФИО ЛПР почти всегда директорские, взятые из ЕГРЮЛ;
- нет признака экспорта;
- в сегментах мусор.

Новый путь — обратный:
1. **Сначала находим сайты** реальных производителей, элеваторов, семеноводов,
   экспортёров и т.д.
2. **Затем по сайту определяем компанию** (ИНН/УНП на странице) и её сегмент
   (по тексту).
3. **Затем с этого же сайта берём ЛПР.**

В базу попадает только компания с подтверждённым собственным сайтом.

Готовый код (`seo-texts/server/` на ветке `claude/detailed-study-7j12hg`:
`contact_extract.py`, `regex_lica.py`, `poisk_saytov.py`, `site_facts.py`,
Zenno-кубик `obhod_stranic.cs`) берём **только как заготовки**. Каждый модуль
сначала проходит пилот на размеченной выборке, и если не дотягивает до целей
п. 4, переписывается.

Меток у компании может быть несколько. ОКВЭД даёт бонус к баллу, если ИНН найден.
Флаг экспортёра ставится при ≥3 баллах:
- реестр Агроэкспорта, Аргус-Фито или GACC — 3;
- версия сайта /en или /cn — 2;
- «экспорт» вместе со страной или условием FOB/CIF — 2;
- ОКВЭД 46.21.1x — 1.

## 2. Воронка (сайт → компания → контакты)

1. **Поиск доменов — основной источник списка.**
   - Отраслевые запросы × регионы РФ (+ РБ по .by) через Yandex Search API в отложенном
     режиме (~25 ₽ за 1000) или XMLRiver. Словарь запросов строится по сегментам из
     п. 1, например:
     - «элеватор приёмка зерна {регион}», «ХПП», «зерносушилка услуги»;
     - «семена гибриды {культура} производитель», «калибровка семян», «семенной завод»;
     - «экспорт нута/льна/пшеницы», англоязычные «grain exporter Russia»;
     - «переработка грецкого ореха», «фундук ядро производитель»;
     - «голубика плантация», «заморозка ягод IQF», «ягодный питомник»;
     - по разделу 10 — продукт × «завод/производитель» × регион.
   - Каталоги, где компании добавляют себя сами, используем как источник **доменов**
     (не данных):
     - agroserver, zol.ru, productcenter;
     - экспоненты ПродЭкспо, Золотой осени, Агропродмаша;
     - члены Зерновой ассоциации, Масложирового союза, НССиР, ягодного союза;
     - для РБ: export.by, b2b.by, cci.by.
   - Добор пропусков: открытые данные ФНС (реестр МСП + «доходы-расходы») по кодам п. 1.
     Это список названий, по которым идут запросы «"название" город». Компанию из
     реестра без найденного сайта в базу не включаем.
   - Домены агрегаторов, маркетплейсов, СМИ и дилеров отсекаем по стоп-листу.
     Яндекс.Карты и 2ГИС как источник данных не используем: их условия запрещают
     хранить данные.
2. **Фильтр «живой собственный сайт».** HTTP 200, сайт не припаркован, не агрегатор,
   по тексту похож на профильного игрока (баллы по словарям сегмента выше порога).
3. **Обход сайта** (Zenno или Python/Playwright).
   - Страницы: главная, контакты, о компании, руководство/команда, реквизиты (в том
     числе PDF карточки), политика ПДн, /en, /export, sitemap.
   - До 12–15 страниц на сайт.
4. **Паспорт сайта.**
   - Найденные страницы.
   - ИНН/ОГРН/УНП со ссылкой на страницу (с проверкой контрольной суммы).
   - Языковые версии, признаки экспорта, словарные попадания по сегментам.
   - Продукция, CMS, год копирайта.
5. **Компания.**
   - ИНН с сайта → ITSOFT (`egrul.itsoft.ru/{ИНН}.json`): ОКВЭД основной и
     дополнительные, статус, адрес, директор.
   - ГИР БО / revexp: выручка.
   - Если ИНН на сайте нет — поиск по названию и городу в ЕГРЮЛ с ручной проверкой
     спорных случаев.
   - Сегменты: по тексту сайта + бонус ОКВЭД, мульти-метка, флаг экспортёра.
6. **ЛПР — только с сайта.**
   - Пара ФИО + должность засчитывается, только если оба стоят в одном блоке DOM.
   - Телефон из шапки сайта не приписываем конкретному ЛПР.
   - Должности нормализуем к коду `role_code`:

     CEO, COMM, CHIEF_ENG, **MECH_ENERGY** (главный механик/энергетик, ключевые для
     оборудования), PROD, TECH, QA, PROCURE, ELEV_HEAD, AGRO, FIN, GENERIC.

     Приоритеты 1–3 по сегментам взяты из ТЗ. Бухгалтерию берём только когда нет P1–P2.
   - Метка качества контакта `contact_quality`:
     - `direct` — ФИО + мобильный, добавочный или личный e-mail;
     - `named_general` — ФИО + только общий канал;
     - `department` — отдел без ФИО;
     - `general` — info@, приёмная, 8-800.
   - Директор из ЕГРЮЛ — отдельная строка с `source_type=egrul`. Это не замена
     контактам с сайта и в метрики «ЛПР с сайта» не входит.
7. **Нормализация и склейка.**
   - Телефоны в E.164 (libphonenumber).
   - E-mail: проверка синтаксиса и MX-записи, без SMTP-проб.
   - Дедупликация по ИНН/УНП, затем по домену; филиалы и холдинги связываем через
     `holding_group_id`.
8. **Выгрузка.**
   - Таблицы `companies`, `site_passport`, `contacts`.
   - Плоский CSV (UTF-8 с BOM) и XLSX для заказчика в порядке колонок ТЗ, плюс
     колонки «сегменты», «экспортёр», «качество контакта», «URL источника»,
     «дата сбора». Выручка идёт отдельным столбцом, по ней компании не отсекаем.

## 3. Порядок работ

1. **Решения владельца:**
   - коды ОКВЭД утверждены 05.10;
   - база «Мейер» отклонена 05.10;
   - 05.10 также подтверждено: Беларусь входит в объём (ягоды + переработка, по
     .by-доменам и ОКРБ 01250/10390/10320/01300); Зенка на сервере работает;
     бюджет на поисковый API есть (Yandex Search API, отложенный режим, или XMLRiver).
2. **Эталон для замеров.** Вручную разметить по 30 сайтов на сегмент: сегмент, ИНН,
   все ЛПР с должностями и каналами. На этом эталоне меряем каждый модуль.
3. **Пилот поиска доменов:** по 1–2 региона на сегмент. Замерить долю профильных
   собственных сайтов в выдаче и точность фильтра п. 2.2.
4. **Пилот обхода и извлечения:** 200 сайтов на сегмент. Замерить долю сайтов с ИНН,
   с ЛПР P1–P2 и с `direct`-контактами, а также точность сегментации. Решить, какие
   готовые модули годятся, а какие переписать.
5. **Масштабирование по регионам** → паспорт → ЛПР → обогащение → QA → выгрузка
   порциями по сегментам. Первыми идут малые и точные сегменты: элеваторы, семеноводы,
   орехи, ягоды, экспортёры. Раздел 10 — последним.

## 4. Приёмка (цели предложены, согласовать)

| Показатель | Цель |
|---|---|
| ИНН/УНП найден | ≥70% |
| ≥1 ЛПР приоритета P1–P2 с ФИО | ≥50% (элеваторы и семеноводы ≥40%) |
| ≥1 контакт `direct` | ≥25% |
| Валидные телефоны | ≥99% |
| E-mail с MX | ≥95% |
| Дубли | ≤0,5% |
| `source_url` и дата заполнены | 100% |

Ручная выборка: 50 компаний на сегмент, точность сегмента ≥90%. Полнота: ≥90% из
списка 50 заведомо известных игроков.

Реалистичная оценка: узкие ЛПР (главный инженер, технолог, агроном) с прямым
мобильным есть примерно на 10–25% сайтов. Остальное покрываем ролевыми ящиками
отделов и контактами директора.

## 5. Риски

- **152-ФЗ.** ФИО, мобильный и личный e-mail — это ПДн. Нужно:
  - уведомить РКН (штраф за неуведомление 100–300 тыс. ₽);
  - опубликовать политику обработки ПДн;
  - хранить данные в РФ;
  - записывать источник и дату по каждому контакту;
  - вести поле `do_not_contact`.
- **38-ФЗ ст. 18.** Рекламные звонки и письма — только с согласия адресата.
  Первое касание — индивидуальное деловое письмо.
- **РБ.** Аналогично: Закон 99-З и закон о рекламе.
- **Безопасность.** На drop лежат `runner-secrets.env`, `rs.env`,
  `sender-secrets.env`. С ними любой, у кого есть `DROP_TOKEN`, может запускать задачи
  на сервере. Рекомендуется убрать их с drop.
- **Антибот.** rusprofile и checko отдают 403, list-org показывает капчу примерно
  после 12 запросов. Массово агрегаторы не парсим.
