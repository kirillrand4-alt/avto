## 1. Почему база «Мейер» вышла плохой: причины в коде

Сборку делает `meyer_baza.py`. Это не отдельный конвейер, а выборка из уже собранного под
компрессорную рассылку: `enrich.db` и `obzvon-index.db`, комментарий в строках 1–20. Отсюда и
все три жалобы.

### 1.1. «ФИО только директоров»

1. **Директор из ЕГРЮЛ подмешивается каждой компании как ЛПР приоритета 1.**
   - `meyer_baza.py:381-383`: если в строке компании есть `_дир`, добавляется контакт
     «руководитель (ЕГРЮЛ)».
   - `роль()` (строка 91; правило в строке 64) даёт ему метку `директор/руководитель`.
   - Метки `ДИР` (строка 75) входят в `ТОП` каждого сегмента (строки 76–88), поэтому `приоритет()` (строка 99) ставит 1.
   - В колонку «ЛПР» компании (`лучший`, строка 447) он попадает первым, если на сайте
     нет никого с приоритетом ≤2.
2. **ФИО с сайта собирались только «к адресу».**
   - LLM-разбор `enrich_contacts.extract_roles` (строки 4784–4915) возвращает `emails[]` и
     `phones[]` с полем `person` (строки 4824–4832). Человек без своего e-mail или телефона в
     выход не попадает вообще.
   - `fio_iz_kesha.py` (строки 1–30) работает так же: ФИО ищут для уже снятых адресов.
   - Страница «Руководство» с ФИО и должностями, но без личных каналов (типичный агросайт)
     даёт ноль людей.
3. **DOM-экстрактор людей написан, но не подключён.** `people_from_html`
   (`enrich_contacts.py:3492`) не вызывается ни в одном модуле ветки, проверено
   `git grep people_from_html`.
4. **Должности сводились к «директору».** В `_POST_VAL_RE` (`enrich_contacts.py:2123-2150`)
   ветка `директор\w*` срабатывает с середины фразы. Тест:
   - «Коммерческий / Финансовый / Исполнительный / Генеральный директор» → `директор`;
   - «Главный агроном», «Технолог», «Председатель», «Заведующий элеватором», «Управляющий»,
     «Зоотехник», «Семеновод» → не распознаются вовсе.

   Шкала ролей `_ROLE_RANK` (строки 627–668) компрессорная: гл.инженер, гл.энергетик, нач.КС.
   Агронома, заведующего элеватором, семеновода в ней нет.
5. **Фильтр `meyer_lpr.py` (строки 1–12) оставлял только мобильный или рабочий с добавочным.**
   Именные контакты с почтой выпадали. Из «настоящих» людей оставались те, у кого в базе
   обзвона был мобильный, а это чаще руководитель из реестровой выгрузки.

### 1.2. «Сайтов нет у 41%»

1. **Список компаний взят из реестра и базы обзвона, а не из поиска по отрасли.** `meyer_baza.py`
   берёт `companies ∪ obzvon` по ОКВЭД (строки 213–240). Мелкие КФХ, СПК и ИП с кодами 01.11 и
   01.13 сайтов не имеют физически.
2. **Сайт ищут по названию.** `find_site_via_xmlriver` строит запрос
   `"{название} {регион} официальный сайт"` (`enrich_contacts.py:1709`).
   - С начала названия снимаются только `ООО|АО|ЗАО|ПАО|ОАО|ИП|ПО`. СПК, КФХ, «Глава КФХ»,
     СХПК, АО «Агрофирма …» в длинной форме остаются в запросе.
   - Вместо города подставляется **регион**: `цели()` в `poisk_saytov.py:337` передаёт
     `'city': reg`.
3. **Приговор «искали — не нашли» вечный.** `poisk_saytov.py:335`: компания с записью в журнале
   без поломки канала больше не ищется. Это касается и отказа «площадка», и «не открылся».
4. **Домен, занятый другим ИНН, отвергается.** `poisk_saytov.py:529`: если ИНН на странице нет,
   домен не отдаётся второй компании. Агрохолдинги (один сайт на несколько юрлиц — элеватор,
   ХПП, семенной завод) теряют сайт у дочерних компаний.
5. **С глубины выдачи кандидат не берётся.** `poisk_saytov.py:413,445`: без улики годен только
   первый адрес. Это осознанное решение против мусора, но оно увеличивает долю «без сайта».
6. **Подтверждение «имя на сайте» нестрогое.** `poisk_saytov.py:418`: проверяется половина слов
   длиннее 3 букв как подстроки в `html.upper()`. Для названий вроде «РОДИНА», «НИВА»,
   «РАССВЕТ» это проходит на чужих сайтах. Ложный сайт потом дополнительно режется вердиктом
   LLM `owner_match`.

### 1.3. «Мусор в сегментах»

1. **Сегмент присваивается по любому коду, включая дополнительные.** `meyer_baza.py:251-253`:
   `попадает(все, пр)` проверяет и основной, и все дополнительные коды. У многих компаний десятки
   «запасных» доп. кодов, отсюда:
   - торговец с доп. 10.xx попадает в «пищевые»;
   - любой зерновой фермер с 01.11 — в «семеноводы»;
   - мельница с 10.61 — в «элеваторы».

   Текст сайта не проверяется вообще. Признак «сила попадания» пишется в колонку, но не
   фильтрует.
2. **Флаг экспортёра стоит на ложных совпадениях.** `meyer_baza.py:43-45,254`:
   `ЭКСПОРТ & ТОВАР` по описанию, а в `ТОВАР` подстроки без границ слова. Тест:
   - «Производство **сталь**н**ых** конструкций, экспорт» → экспортёр (подстрока `льн`);
   - «**Круп**ный поставщик упаковки, экспортные поставки» → экспортёр;
   - «Мебе**льн**ая фабрика, экспорт» → экспортёр.
3. **В список вошёл сегмент 7 «доп. ОКВЭД (предложено)».** Строки 41–42: `46.21, 01.12, 01.61,
   46.31, 46.37`, где 46.37 — оптовая торговля кофе и чаем.
4. **Описание компании берётся из компрессорного паспорта.** Поля `site_facts` (строки 288–308, ключи в строке 300):
   `цитата/продукция/сырьё` из промпта под компрессоры, рентген и фотосепараторы. Описание
   пищевика может быть пустым или про «энергохозяйство».

**Вывод для нового пути:**
- сегмент ставить по тексту сайта со стоп-словами (п. 1 плана), ОКВЭД — только бонус;
- ЛПР — DOM-разбором страниц руководства **независимо от наличия личного канала**;
- директор ЕГРЮЛ — отдельной строкой `source_type=egrul`, вне метрик.

Всё это уже записано в PLAN.md. Код Мейера этому противоречит в каждом пункте.

## 2. По модулям

### 2.1. `enrich_contacts.py` (detailed-study, `seo-texts/server/`)

**Что делает.** Полный конвейер «ИНН/название → сайт → обход → LLM-роли → MX → запись в
enrich.db». Плюс 30 побочных источников: list-org, ЕИС, hh, VK, справочники, ОПО Ростехнадзора,
SMTP. Функция `main()` — 4 700 строк (6046–10780).

**Вход и выход.**
- stdin: `{"companies":[{inn,name,city,site}]}`;
- stdout: `{"results":[{inn,site,emails[{email,role,person}],phones,…}]}`.

**Зависимости.**
- При импорте:
  - `import verify_company as VC` (строка 302);
  - `enrich_db` (строка 661, в try).
- При работе:
  - `browser_probe` — Playwright, Dolphin, CapMonster/2captcha;
  - `VC._provider_call_stdlib` — провайдерский LLM;
  - XMLRiver (`XMLRIVER_USER/KEY`);
  - секреты из `runner-secrets.env` и `C:\seostat\drop\drop-storage\runner-secrets.env`
    (строки 62–112);
  - Dolphin-профили (`dolphin-profiles.txt` на drop);
  - кэш `C:\seostat\drop\pagecache`;
  - `C:\sender\obzvon-index.db`.

**Отделимость.** Нужные функции чистые по сигнатуре, но пользуются глобальными переменными
модуля (`EMAIL_RE`, `_IMG_EXT`, `_is_junk_email`, `VC.UA`). Поэтому их надо **копировать в новый
пакет**, а не импортировать: импорт тянет 700 КБ кода, `verify_company` и побочные чтения
секретов.

#### `crawl_contacts(site, …, inn='')` (строки 4397–4781)

**Что хорошо (взять как правила):**
- кандидаты собираются все, обрезка до 10 идёт **после** сортировки по приоритету
  (строки 4442–4479);
- `_iz_sitemap` берётся раньше угадывания путей;
- угаданные пути открываются лёгким заходом `_lyogkiy_zahod`;
- второй уровень обхода с остановкой «три подряд без новых контактов» (строки 4515–4569);
- пагинация Bitrix (`PAGEN_n`);
- атрибуция «e-mail или телефон → первая страница» (`url_first`, `phone_url_first`);
- кэш `{key, site, pages:[{url,html}]}`; при пустом ИНН ключом уже служит домен (строки 4418–4423).

**Баги и слабые места.**
- **Ссылки только в двойных кавычках:** `re.findall(r'href="([^"]+)"', home)` (строки 4442, 4519,
  4585). `href='…'` и ссылки без кавычек теряются.
- **Протокол-относительные ссылки собираются неверно.** Строки 4459, 4527, 4590: `//cdn.site.ru/x`
  начинается с `/`, получается `http://dom//cdn.site.ru/x`.
- **Кириллические слаги не опознаются.** Хинты (строки 352–358) ищутся в сыром href, а
  `/контакты/` приходит как `%D0%BA%D0%BE…`. Сайты на `.рф` с кириллическими путями
  пропускают контакты.
- Хинт `'poставщик'` (строка 357) набран **смесью латиницы и кириллицы** (`p`, `o` латинские) и
  не срабатывает никогда.
- **Нет приоритета для реквизитов, политики ПДн, `/en` и PDF.** `rekvizity` есть в хинтах, но
  `_crawl_prio` (строки 4466–4477) даёт ему ступень 3. `/en`, `/export`, `politika`, `.pdf` не
  ищутся вовсе. Для нашего п. 2.3–2.4 (ИНН, языковые версии, экспорт) это главные страницы.
- **HTTP-ошибка считается страницей.** `_fetch_site` в ветке `except urllib.error.HTTPError`
  (строки 5116–5122) возвращает тело 404 или 500 как `'direct'`. Страницы ошибок попадают в обход.
- **Редирект на другой домен не учитывается.** `dom = _domain(site)` берётся из входа, а
  `_fetch_site` не возвращает финальный URL. Абсолютные ссылки нового домена отбрасываются
  проверкой `_domain(full) == dom`.
- **Выход — склейка текста под LLM**: `meta_blok + karty_v_tekst + _contact_cap(txt)` с капом
  24 тыс. знаков. Нам нужен список `(url, финальный_url, статус, html)`, а не промпт.
- Fallback-цепочка `_fetch_site` (прокси → мобильный → Playwright → Dolphin, строки 5097–5189)
  тянет серверную инфраструктуру.

**Вердикт:** переписать. Новый обходчик — тонкий, на `httpx` или Playwright либо через Зенку
(раздел 3). Правила остановки и приоритета перенести.

#### `people_from_html(html, url)` (строки 3492–3554) и `_фио` (3385–3429)

Тесты из приложения A, кратко:
- **Вложенные div-карточки** (`div.team-item > div.name + div.post + div.tel`) → **0 человек**.
  `_CARD_RE` (строки 3341–3345) нежадно ловит до **первого** `</div>`, то есть до закрытия
  `div.photo`, и ФИО в захват не попадает. Так свёрстано большинство современных страниц
  «Команда»/«Руководство».
- **Таблица руководства на 6 строк** → 4 человека:
  - «Коммерческий директор Козлов» и «Генеральный директор Иванов» оба получили должность
    `директор`;
  - «Главный агроном Морозова» и «Заведующий элеватором Строев» — пустая должность;
  - «Председатель СПК Газизов» выпал целиком.
- **Почему выпал Газизов.** `_НЕ_ИМЯ` (строки 3378–3382) режет по подстроке: `газ`, `торг`,
  `нефт`, `цех`, `проект`, `групп`. Отброшены «Газизов Ринат Ильдарович», «Торгашев Иван
  Петрович», «Нефтяев Олег Иванович», «Цехов Илья Ильич», «Проектов…», «Групповой…».
  Это частые фамилии, в Поволжье и на Урале (Газизов, Газиев) — массово.
- **Почему выпал «Технолог Лебедев Максим Олегович».** `_ФИО_ПОЛН` захватывает три слова с
  заглавной «Технолог Лебедев Максим» (должность с заглавной буквы в начале ячейки).
  Отчества в захвате нет, функция берёт два последних слова, не принимает их и **не ищет
  дальше со сдвигом**. Человек теряется.

### 3.3. Итоговая схема

```text
домены (поиск п. 2.1)  ->  фильтр «живой собственный» (п. 2.2)
      -> zenno/ochered/<пачка>.txt     строки «<домен>;<url>;baza»
      -> ZennoPoster: obhod_stranic.cs (правки 4-10)
      -> zenno/gotovo/<ключ>_N.html + <ключ>.urls.txt (запрошенный\tитоговый\t…)
      -> priyom (новый, правки 1-2,12) -> pagecache/<ключ>.json.gz
      -> паспорт сайта: ИНН/УНП по подписи, языки, экспорт, сегменты (Python, офлайн)
      -> owner_resolver: ИНН -> ЕГРЮЛ (ITSOFT) -> компания; ключ «домен» заменяется на ИНН
      -> ЛПР: DOM-разбор people (новый) + contact_extract (доработанный)
```

**Ключ домена переходит в ИНН только на шаге «компания».** До этого все файлы, кэш и журналы
живут по домену. Таблица `site_passport(domain PK, inn NULL, …)` связывает их. Ничего из
обхода не переименовывается: у одной компании может быть несколько доменов, у одного домена
(холдинг) — несколько ИНН.

**Управление прогоном:** `zenno_pult.py pusk <задача> N` как есть (с правкой `komanda.txt`
из п. 2.11).

## 4. Общие доработки для экстракторов (чек-лист к пилоту п. 3.4)

1. **Словарь `role_code`** вместо компрессорных `LOCAL_ROLE`, `_POST_VAL_RE`, `_ROLE_RANK`,
   `РОЛИ` из meyer_baza:

   | `role_code` | Маркеры |
   |---|---|
   | `CEO` | генеральный директор, директор без уточнения, председатель (СПК, колхоз), глава КФХ, управляющий, владелец, собственник, учредитель, президент |
   | `COMM` | коммерческий директор, директор по продажам или развитию, начальник отдела продаж, ВЭД |
   | `CHIEF_ENG` | главный инженер, технический директор |
   | `MECH_ENERGY` | главный механик, главный энергетик |
   | `PROD` | директор по производству, начальник производства, начальник цеха |
   | `TECH` | главный технолог, технолог |
   | `QA` | качество, лаборатория, ОТК |
   | `PROCURE` | закупки, снабжение, МТО |
   | `ELEV_HEAD` | заведующий или начальник элеватора, ХПП, зернотока, склада |
   | `AGRO` | главный агроном, агроном, семеновод, зоотехник |
   | `FIN` | финансовый директор, главный бухгалтер, бухгалтерия |
   | `GENERIC` | прочие |

   Должность искать **целиком, от начала фразы**: «Коммерческий директор» не должен
   превращаться в «директор». Тест: `_POST_VAL_RE` теряет прилагательное.
2. **ФИО:**
   - формы ФИО, ИОФ, «Фамилия И.О.», «И.О. Фамилия», «Имя Фамилия» (последняя — только при
     совпадении имени со словарём имён);
   - стоп-слова **целыми словами**, а не подстроками (`газ` режет Газизова);
   - при неудаче — сдвиг на слово вперёд (кейс «Технолог Лебедев Максим Олегович»).
3. **DOM-карточка:** ближайший общий предок, где одно ФИО. Каналы (`tel:`, `mailto:`, текст),
   найденные внутри, принадлежат ему. Телефон из шапки или подвала (повтор на ≥2 страницах) —
   никому, только компании (п. 2.6 плана).
4. **Телефоны:** `phonenumbers`, регионы RU и BY, E.164, добавочный отдельным полем. Тип:
   мобильный, городской, 8-800. Рубеж против реквизитов перенести из
   `enrich_contacts.py:382-490`.
5. **ИНН, УНП, ОГРН:** по подписи, с исключением банка и веб-студии, голосованием по страницам,
   сверкой ИНН↔ОГРН и ЕГРЮЛ. Окно — по каждой странице отдельно, не по склейке.
6. **Обход:** финальный URL после редиректа, `href` в любых кавычках, `urljoin`, раскодирование
   кириллических путей, HTTP-статус.
7. **Отказ от провайдера и enrich.db.** Ни одна функция нового конвейера не импортирует
   `enrich_contacts`, `verify_company`, `gen_provider`, `browser_probe`. Нужное копируется в
   пакет `baza-kontaktov/lib/` с тестами на сохранённых страницах эталона (п. 3.2 плана).
