# ТЗ для новой сессии: пилот поиска сайтов через XMLRiver (Яндекс + Google)

## Контекст

Задача владельца — собрать базу B2B-контактов по 6 сегментам: экспортёры, семеноводы,
пищевые (раздел 10), элеваторы, орехи, ягоды (вместе с Беларусью). Путь сбора — «от
сайта к компании». Полный план лежит в `baza-kontaktov/PLAN.md`
(ветка `claude/admiring-cray-f8gwyq`). Прочитай его первым.

Старые базы на сервере, в том числе «Мейер», владелец признал некачественными. Но они
пригодятся как **эталон «уже известного»**: по ним пилот проверит, находит ли поиск
новые компании.

**Вопрос пилота:** даёт ли выдача Яндекса и Google через XMLRiver заметную долю **новых**
профильных компаний, которых нет в существующих базах, или мы находим в основном старые?

## 2. Выборка пилота

- Только запросы P1 из `zaprosy.csv`. Для каждого сегмента — **2 региона с приоритетом
  пилота 1** из `regiony.csv`, подходящих этому сегменту. Например:
  - элеваторы: Алтайский край и Ростовская область;
  - ягоды РФ: Брянская или Московская область;
  - ягоды РБ: Брестская область.

  Выбор регионов запиши в отчёт.
- Запросы без гео (экспортёры, английские) — как есть.
- Подставь плейсхолдеры. Ограничение: **не больше ~150 запросов на сегмент, ~900–1000
  всего на один поисковик**. Каждый запрос гони и в **Яндекс**, и в **Google**.
- Глубина: топ-50 (Яндекс: 5 страниц по 10 или group по 50 — как поддерживает аккаунт;
  Google: топ-50). Регион для Яндекса — `lr` региона (Беларусь — 149 и областные коды),
  для Google — `country=ru` / `by` и `loc`, если поддерживается. Точные параметры возьми из
  рабочего кода на сервере (`serp_fetch.py`, `poisk_saytov.py`, `news_scan.py`
  `col_xmlriver`), не угадывай.
- Перед массовым прогоном сделай **пробу из 5 запросов** на каждый поисковик. Проверь
  формат ответа, расход лимита и стоимость. Если по расчёту весь пилот выйдет дороже
  ~2000 ₽, остановись и сообщи владельцу.

## 3. Сбор и обработка (скрипт на сервере)

1. Для каждого запроса сохрани сырую выдачу в jsonl:
   `engine, query, segment, subsegment, region, pos, url, title, snippet, ts`.
2. **Нормализация домена:** eTLD+1, без `www`, в нижнем регистре, punycode ↔ кириллица
   для `.рф`.
3. **Отсев:**
   - домены из `stop_domeny.txt`;
   - пост-фильтр из `minus_slova.txt` по title и url;
   - соцсети, PDF-хостинги;
   - домены, которые встретились в выдаче по ≥5 разным сегментам (это порталы).
4. **Уникальные домены-кандидаты:** для каждого храни список запросов, сегментов,
   поисковиков и лучшую позицию.
5. **Быстрая проверка профиля (без LLM):**
   - скачай главную страницу каждого кандидата (первые ~100 КБ, таймаут 15 с);
   - зафиксируй HTTP-статус и финальный URL после редиректов;
   - посчитай балл по словарям сегмента (основы слов; title и H1 ×2; стоп-слова снимают
     балл):

| Сегмент | Маркеры | Стоп-слова |
|---|---|---|
| Экспортёры | экспорт*, ВЭД, FOB, CIF, трейдинг, зерновой терминал, перевалка, СДИЗ, фитосанитар*, export, grain/oilseeds/pulses supplier; товар: пшениц*, ячмен*, кукуруз*, подсолнечн*, рапс*, льносемен*, соя, горох, нут, чечевиц*, жмых, шрот | таможенный брокер, логистическая компания (без товарных слов) |
| Семеноводы | семен*, семеновод*, гибрид*, оригинатор, элит*, репродукци*, семенной завод, протравлива*, калибров*, посевной материал, селекци* | семена для дачи, интернет-магазин семян, «сорт кофе» |
| Пищевые | производств* + продукт*/пищев*, завод, цех, ХАССП/HACCP, ISO 22000, фасовк*; товар: мука, крупа, масло, молок*, кондитер*, хлеб*, консерв*, сок*, крахмал | кафе, ресторан, доставка еды, магазин продуктов |
| Элеваторы | элеватор*, ХПП, КХП, зернохранилищ*, силос*, приёмка зерна, сушка зерна, зерносушилк*, подработка зерна, очистка зерна, хранение зерна | элеваторный узел, отопление, ИТП, теплоснабжение, гидроэлеватор, лифт |
| Орехи | орех*, фундук, грецк*, миндал*, кешью, фисташк*, кедровый орех, ядро ореха, колка/калибровка/обжарка орехов | пиломатериал, мебель «орех» |
| Ягоды | ягод*, клубник*, земляник*, малин*, смородин*, голубик*, клюкв*, брусник*, облепих*, жимолост*, шоковая заморозка, IQF, ягодный питомник, джем, конфитюр, пюре, морс | — |
   - отметь парковки и заглушки («домен продаётся», пустая страница, CMS по умолчанию);
   - ИНН/УНП на главной: 10 или 12 цифр **рядом со словом «ИНН»** и с проверкой
     контрольной суммы; УНП — 9 цифр рядом с «УНП». Если на главной нет — проверь одну
     ссылку «Контакты» или «Реквизиты», если она есть в меню.

## 4. Сверка «новые или старые» (главный результат)

Эталон «уже известного» — всё, что уже есть на сервере:

- `enrich.db` → `companies` (169 790 строк, поле сайта и `division` kc/meyer);
- `enrich.db` → `phone_contacts.source_url` (взять домены);
- `obzvon-index.db` → `obzvon` (161 799 карточек: сайты, e-mail, ИНН);
- сайты и ИНН из `meyer-kompanii-0510.csv` и `MEYER-BAZA-KOMPANII.csv` (на drop).

Собери из этого множество известных **доменов**. В него же добавь домены из e-mail
компаний, кроме бесплатных почтовиков: mail.ru, yandex.ru, gmail.com, bk.ru, list.ru,
inbox.ru, rambler.ru и т.п. Отдельно собери множество известных **ИНН**.

Для каждого профильного кандидата (балл ≥ порога, сайт живой, не парковка) определи
статус:

| Статус | Условие |
|---|---|
| `old_domain` | домен уже есть в эталоне |
| `old_inn` | домена в эталоне нет, но ИНН с сайта там есть: компания старая, сайт новый для неё. Это тоже ценно: значит, старый поиск сайтов промахнулся |
| `new` | ни домена, ни ИНН в эталоне |
| `new_no_inn` | домена в эталоне нет, ИНН на сайте не найден: это ещё не точно новая компания |

## 5. Отчёт

Положи на drop `BAZA-PILOT-DOMENY.csv`: одна строка на домен-кандидат, колонки:

`domain, final_url, http_status, is_parked, engines(yandex|google), segments, subsegments,
regions, queries_count, best_pos, profile_score, inn, unp, status(old_domain/old_inn/new/new_no_inn), title`

Сырые выдачи — в `BAZA-PILOT-SERP.jsonl.gz`.

В репозиторий закоммить `baza-kontaktov/PILOT-XMLRIVER-OTCHET.md` с такими разделами:

1. **Параметры.** Регионы, сколько запросов ушло по каждому поисковику, стоимость и
   расход лимита, время прогона.
2. **Воронка по сегментам и поисковикам:**

   уникальные URL → домены → после стоп-листа → живые → профильные → с ИНН/УНП

3. **Главная таблица по сегментам:** доли `old_domain` / `old_inn` / `new` /
   `new_no_inn` среди профильных доменов, отдельно для Яндекса, Google и их
   объединения.
4. **Пересечение Яндекс ∩ Google** и сколько уникального даёт каждый.
5. **Какие запросы и подсегменты дали больше всего новых** профильных доменов (топ-20) и
   какие дали один мусор (кандидаты на удаление из `zaprosy.csv`).
6. **Ручная проверка:** по 10 случайных `new` на сегмент — действительно ли профильная
   компания с собственным сайтом. Точность фильтра в процентах.
7. **Экстраполяция:** сколько новых профильных компаний ожидать при прогоне по всем
   регионам и запросам P1–P2, и во что это обойдётся.
8. **Вывод:** стоит ли масштабировать поиск через XMLRiver, какой поисковик главный,
   что поправить в запросах.

Коммить с понятным сообщением на русском и пушь в `claude/admiring-cray-f8gwyq`. Если
пуш отклонён — `git pull --rebase` и повтори.

## 6. Чего не делать

- Не обходить сайты глубже главной страницы и одной страницы «Контакты/Реквизиты». Полный
  обход — следующий этап.
- Не вызывать LLM-провайдера в пилоте: всё делается правилами.
- Не писать в `enrich.db` и другие рабочие базы на сервере: только читать. Свои данные
  храни в отдельных файлах, например `C:\sender\_ops\baza_pilot\`.
- Не печатать значения секретов и переменных окружения.
- Не запускать больше одного XMLRiver-задания одновременно.
