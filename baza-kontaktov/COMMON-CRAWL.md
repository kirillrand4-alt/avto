# Common Crawl как источник сайтов, контактов и паспортов

Замеры сделаны 05–06.10.2026 из песочницы. Где написано «оценка», это допущение, его
нужно проверить на пилоте.

## 1. Что такое Common Crawl

Common Crawl (CC) — некоммерческий проект. Каждый месяц его робот CCBot обходит
интернет и бесплатно выкладывает результат на `data.commoncrawl.org` (это зеркало
Amazon S3, регион us-east-1). Каждый краул состоит из трёх частей:

| Часть | Что внутри | Зачем нам |
|---|---|---|
| **Колоночный индекс** (`cc-index/table/...`, 300 parquet-файлов на краул) | одна строка на страницу: URL, домен, статус ответа, MIME-тип, язык, имя WARC-файла, смещение и длина записи | отбор нужных страниц без скачивания самих страниц |
| **WARC** | полный HTTP-ответ: заголовки и HTML | точечное скачивание одной страницы по смещению (Range-запрос) |
| **WET** | чистый текст страниц | в WET-файлах нет индекса по страницам, качать пришлось бы целиком, поэтому мы ими не пользуемся |

**Объём .ru в последнем краулe CC-MAIN-2026-39 (сентябрь)**, считая вместе с .рф:
**1 083 749 доменов**, 1,15 млн хостов, 107 млн страниц. Для сравнения: в .ru
зарегистрировано около 6,1 млн доменов.

## 2. Какие наши сайты там есть (замер)

**Выборка:** 194 сайта компаний сегментов, взятые из базы «Мейер», из них 150 живых и
не заглушек. Для каждого сайта проверено наличие страниц в колоночном индексе четырёх
последних краулов: сентябрь, август, июль, июнь 2026.

| Краулов | Есть хоть одна страница сайта | Есть главная (200 OK) | Есть «контакты / о компании / реквизиты» |
|---|---|---|---|
| 1 | 60% | 33% | 25% |
| 2 | 63% | 45% | 36% |
| 3 | 67% | 53% | 42% |
| 4 | **69%** | **57%** | **45%** |

**По сегментам** (один краул, хоть одна страница):

| Сегмент | Доля сайтов в CC |
|---|---|
| Семеноводы | 72% (28 из 39) |
| Пищевые | 63% (26 из 41) |
| Экспортёры | 53% (10 из 19) |
| Элеваторы | **46%** (19 из 41) |

Ягоды не оцениваем: в выборке всего 7 сайтов.

**Какие сайты в CC попадают чаще:**
- те, на которые много ссылаются с других сайтов. CCBot идёт по ссылкам и в
  первую очередь берёт «заметные» сайты;
- давно живущие, с нормальным HTTPS и обычным HTML;
- сайты средних и крупных компаний, сайты из каталогов и СМИ, на которые ставят
  ссылки.

**Какие сайты в CC не попадают или попадают частично:**
- сайты-одностраничники и «визитки», на которые никто не ссылается. Таких много у
  элеваторов и хозяйств;
- сайты только на http со старым TLS. Пример: ulcaxap.ru (АО «Ульяновский сахарный
  завод», доход 6,65 млрд) отсутствует во всех четырёх краулах;
- новые сайты (CC отстаёт на 1–6 месяцев);
- сайты, где содержимое рисует JavaScript: CC хранит HTML без выполнения скриптов;
- сайты, закрытые от CCBot в robots.txt;
- PDF-карточки предприятий: CC сохраняет PDF редко и обрезает длинные файлы.

**С большого сайта CC берёт обычно лишь часть страниц.** Поэтому «сайт есть в CC» ещё
не значит, что там есть «Контакты». По замеру такие страницы есть у 45% сайтов.

## 3. Как это будет работать (конвейер)

### Шаг 1. Список доменов .ru / .рф / .su / .by из индекса

- **Без скачивания страниц.** Запрос к колоночному индексу (DuckDB поверх parquet по
  HTTP) по 4–6 последним краулам:
  - зона: `url_host_tld` из списка `ru`, `xn--p1ai`, `su`, `by`;
  - ответ: `fetch_status = 200`;
  - тип: HTML.
- **Что получаем:** все домены зоны, у каждого — число страниц, список URL и
  ссылки на записи в WARC.
- **Эффективность:** индекс отсортирован по SURT-ключу (`ru,домен)/путь`), поэтому зона
  .ru лежит компактно: в сентябрьском краулe это 15 файлов из 300. Читаются только
  нужные группы строк.
- **Объём:** по оценке, 1,3–1,8 млн доменов в объединении краулов; несколько ГБ
  чтения индекса.

### Шаг 2. Дешёвый предотбор по адресам страниц

- В адресах русских сайтов много транслита: `/produkciya/semena-podsolnechnika`,
  `/uslugi/hranenie-zerna`, `/elevator`, `/export`, `/oreh`, `/yagody`, `/zamorozka`.
- Регулярками по полю `url_path` и по имени домена (`agro`, `zerno`, `semena`,
  `elevator`, `hpp`, `kxp`, `sad`, `yagod`, `orehi`, `export`, `moloko`, `myaso`,
  `hleb`...) отмечаем домены-кандидаты по каждому сегменту.
- Это тоже работа только с индексом, без скачивания страниц, займёт минуты.
- Шаг даёт приоритеты: такие домены идут первыми. Остальные не выбрасываем, их
  проверяет шаг 3.

### Шаг 3. Главные страницы → словари сегментов

- Для каждого домена берём **одну** запись главной страницы, самую свежую из краулов.
- Скачиваем её Range-запросом по `warc_filename`, `offset`, `length`. Запись — это
  gzip-кусок примерно 10–40 КБ.
- **Объём:** около 1–1,5 млн записей ≈ 20–50 ГБ (оценка). На сервере при умеренной
  параллельности (CC просит не перегружать `data.commoncrawl.org`, на ответ 503 —
  пауза) это 1–3 суток. В регионе AWS us-east-1 — часы и копейки.
- По тексту главной считаем баллы словарей сегментов. Словари и стоп-слова — в
  `TZ-PILOT-XMLRIVER.md`, раздел 3.5. Вес в title и H1 — ×2.
- Отсекаем парковки, продажу доменов, интернет-магазины, СМИ, агрегаторы (по
  `stop_domeny.txt`).
- **Результат:** профильные домены-кандидаты. По оценке это десятки тысяч, точнее
  покажет пилот.

### Шаг 4. Контактные страницы кандидатов → паспорт и ЛПР

- По каждому кандидату из индекса берём все URL с путями «контакты, kontakty,
  contacts, rekvizity, requisites, about, o-kompanii, rukovodstvo, management, team,
  komanda, struktura, export, en/». Если у страницы есть версии из нескольких
  краулов, берём самую свежую.
- Скачиваем их тем же способом. Это 3–10 страниц на сайт.
- **Извлекаем** (правила из `PLAN.md` п. 2.6 и `AUDIT-KODA.md`):
  - ИНН, ОГРН, УНП — только рядом с подписью и с проверкой контрольной суммы;
  - телефоны в формате E.164 с типом;
  - e-mail с типом (личный / отдел / общий);
  - пары «ФИО — должность», только если они в одном блоке DOM;
  - продукция, признаки экспорта, языковые версии.
- **Каждому полю сохраняем источник:** URL страницы, имя краула и дату снимка. Это
  нужно для поля «источник» и для оценки свежести.

### Шаг 5. Привязка к компании и сверка

- По ИНН с сайта подтягиваем данные ФНС:
  - доходы за 2025 год (набор «Сведения о доходах и расходах»);
  - ОКВЭД основной и дополнительные, регион (реестр МСП);
  - данные крупных компаний (через ITSOFT или ЕГРЮЛ на сервере).
- Присваиваем статус `new` / `old_domain` / `old_inn`, сверяя со старыми базами, как в
  `TZ-PILOT-XMLRIVER.md`, раздел 4.

### Шаг 6. Чего CC не дал — досбор своими силами

- **Кандидат есть, а контактных страниц в CC нет** (по замеру это около 55% сайтов
  из CC) → живой обход Zenno или Python, только этих страниц.
- **Компании нет в CC вообще** (около 31% живых профильных сайтов) → поиск через
  XMLRiver, каталоги, домены из e-mail и поиск по названию и ИНН из списка ФНС.
- **Свежесть.** Телефон и ФИО со снимка старше 3 месяцев перепроверяем живым запросом
  к той же странице. Это одна страница на компанию, дёшево.

## 4. Обратный ход: поиск сайта по ИНН

Отдельный выигрыш CC: на шаге 4 можно собрать **все** пары «ИНН → домен» со страниц
реквизитов и контактов всей зоны .ru, а не только кандидатов.

Тогда для любого ИНН из списка ФНС (например, 37 931 юрлицо сегментов с доходом больше
30 млн) сайт находится мгновенно, без поисковика, если компания публикует ИНН на сайте.

Это лечит главную болезнь прежних баз: у 41% компаний не был найден сайт.

Стоимость: те же Range-запросы, но по всем доменам зоны, только для страниц с
«реквизитными» адресами. Это ещё порядка 1–3 млн записей (оценка).

## 5. Где запускать

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Сервер владельца** (через `run_script_on_server.py`, долгие прогоны отдельным процессом) | бесплатно, всё рядом с остальными данными | 1–3 суток на шаг 3, общий пул воркеров с другими сессиями |
| **Отдельный Linux-VPS** | не мешает рабочему серверу, быстрее сеть | 500–1000 ₽ в месяц |
| **AWS us-east-1** (EC2 или Athena по индексу) | данные «рядом», шаги 1–4 за часы | нужен аккаунт AWS, по оценке $20–100 за прогон |
| Песочница Claude | проверено: индекс читается, DuckDB работает | для десятков ГБ не подходит, только для пилотов |

## 6. Ограничения и риски

- **Полнота:** около 69% профильных сайтов, хуже всего у элеваторов (около 46% в одном
  краулe). CC не заменяет поиск, а сокращает его.
- **Свежесть:** снимки отстают на 1–6 месяцев. Контакты нужно сверять или помечать
  датой снимка.
- **Беларусь (.by)** не замерена. Нужен отдельный замер на выборке ягодных и
  перерабатывающих компаний РБ.
- **Нагрузка:** `data.commoncrawl.org` ограничивает частоту запросов. Нужна
  параллельность в несколько десятков потоков с паузой на 503, без агрессивного
  перебора.
- **Правовой аспект:** данные CC открыты, условия использования разрешают обработку.
  Но к ФИО и личным телефонам применяется 152-ФЗ, как и при живом обходе
  (`PLAN.md` п. 5).

## 7. Предлагаемый пилот CC (1–2 дня)

1. **Индекс.** Шаги 1–2 по всей зоне .ru за 4 краула: число доменов и число
   кандидатов по адресам страниц по сегментам.
2. **Главные страницы.** Шаг 3 на случайной выборке 20 тыс. доменов: доля профильных
   по словарям, ручная проверка 100 штук.
3. **Контакты.** Шаг 4 на 500 профильных кандидатах: доля сайтов с ИНН, с ФИО и
   должностью, с прямым контактом.
4. **Сравнение с XMLRiver.** Сопоставить с результатом `TZ-PILOT-XMLRIVER.md`: сколько
   новых компаний даёт каждый путь и насколько они пересекаются.
