# RUNBOOK — как работать и как продолжить после обрыва

Этот файл — точка входа, если сессия/токены оборвались. Прочитай его целиком,
и ты (или новый ассистент) сможешь продолжить с любого места.

## Что это за проект
Автоматизация ручной отправки URL на индексацию в Google Search Console
(кнопка «Запросить индексирование») сразу по многим аккаунтам, с веб-панелью
управления. Развёрнут на Windows-сервере `parsercompressor.online`.

- **Ветка разработки:** `claude/nifty-shannon-7nw58j` (в неё всё коммитим/пушим).
- **Папка на сервере:** `C:\seostat\avto`
- **Сайт-панель:** `https://parsercompressor.online/avto/` (за Caddy → 127.0.0.1:8090)
- **Твой сайт-ресурс в GSC:** `dizel-compressor.ru` (владелец — ты).

## Архитектура (карта файлов)
- `web/server.mjs` — веб-панель (Express, монтируется на `/avto`), запущена как
  служба Windows **avto-panel** (NSSM). Управление аккаунтами/URL/движком/прокси,
  кнопки запуска, HTTP Basic вход, встроенный планировщик автопрогона.
- `src/run.mjs` — прогон: по каждому аккаунту отправляет до N URL/день на индексацию.
- `src/login.mjs` — первичный вход в Google-аккаунт (один раз на аккаунт).
- `src/session.mjs` — единая «сессия браузера»: движки `builtin` / `dolphin` / `adspower`.
- `src/lib.mjs` — конфиг, прокси, отпечаток, стелс, предохранители, checkProxy.
- `src/gsc.mjs` — сам клик «Запросить индексирование» + разбор результата.
- `src/humanize.mjs` — человекоподобная мышь/клавиатура (кривые, лог-нормальные паузы).
- `src/proxybridge.mjs` — локальный прокси-мост (для builtin + ASocks SOCKS5-с-авторизацией).
- `src/dolphin.mjs` / `src/adspower.mjs` — коннекторы к антидетект-браузерам (Local API + CDP).
- `deploy/Caddyfile.example`, `deploy/nginx.example.conf` — примеры прокси.
- Не в git (в `.gitignore`): `config.json`, `.env`, `state.json`, `profiles/`, `screenshots/`.

## Движки (как выбирается браузер)
Настраивается в панели → «Движок браузера»:
- **builtin** — наш Chromium: профиль в `profiles/<id>`, прокси через **мост**,
  отпечаток + стелс + анти-WebRTC. Прокси задаётся в панели («Прокси»).
- **adspower** / **dolphin** — профиль антидетекта через его Local API; прокси и
  отпечаток живут внутри профиля. У аккаунта указывается «ID профиля антидетекта».
  Требуют, чтобы десктоп-приложение было запущено в интерактивной RDP-сессии.

Текущий рабочий вариант на этом сервере — **builtin + мост** (десктоп-антидетекты
на этом сервере не поднялись: Dolphin API платный, AdsPower не рисуется, Самара без API).

## Прокси (ASocks, мобильный/резидентский)
- Строка: `socks5://ul01ktnhed20hmsr76jkrftt8zfb:B4wjeOlxZa3Bek9Z@89.39.105.78:11560`
- Chromium НЕ умеет SOCKS5 с логином/паролем → используем **мост** `proxybridge.mjs`,
  который слушает `127.0.0.1:11561` без авторизации и форвардит в ASocks.
- В панели «Прокси» → Сервер `http://127.0.0.1:11561`, логин/пароль пусто.

## ЕЖЕДНЕВНАЯ РАБОТА (операторская)
1. **Мост** (отдельное окно PowerShell, держать открытым):
   ```powershell
   cd C:\seostat\avto
   node src/proxybridge.mjs "http://ul01ktnhed20hmsr76jkrftt8zfb:B4wjeOlxZa3Bek9Z@89.39.105.78:11560" 11561
   ```
2. **Панель** уже работает как служба. Открыть: `https://parsercompressor.online/avto/`.
   Перезапуск службы: `nssm restart avto-panel`. Лог: `C:\seostat\avto\panel.log`.
3. **Прогон** (панель-кнопка «Прогнать все» или из консоли):
   ```powershell
   cd C:\seostat\avto
   node src/run.mjs          # все аккаунты
   node src/run.mjs acc1     # один
   ```

## ЗАВЕСТИ НОВЫЙ АККАУНТ (по шагам)
1. Купить обычный **@gmail.com** (НЕ Workspace!), с recovery-почтой/телефоном, отлежавшийся, гео RU.
2. В Search Console ресурса `dizel-compressor.ru`: **Настройки → Пользователи и
   разрешения → Добавить пользователя** → email → **Полный доступ**.
3. В панели «Добавить аккаунт»: ID (`acc4`…), свойство `sc-domain:dizel-compressor.ru`,
   разные URL (не дублировать между аккаунтами!). Профиль антидетекта — пусто для builtin.
4. Мост запущен → логин (через прокси):
   ```powershell
   node src/login.mjs acc4
   ```
   Войти в Gmail, пройти проверку через recovery, открыть Search Console, закрыть окно.
5. Прогон: `node src/run.mjs acc4`.

## ПРАВИЛА БЕЗОПАСНОСТИ (почему теряли аккаунты)
- **НИКОГДА не логинить аккаунт без прокси** (голый IP сервера = бан). Код это
  блокирует (`allowNoProxy:false`), не отключай.
- Логин только через мост/антидетект. Прокси проверяется перед стартом (checkProxy).
- **Прогрев:** первые 2-3 дня по 2-3 URL/аккаунт, потом до 10.
- Разные URL по аккаунтам (N аккаунтов = N×10 РАЗНЫХ URL/день).
- Только личные @gmail (Workspace-аккаунты не имеют доступа к GSC).

## ИЗВЕСТНЫЕ ГРАБЛИ (уже решены — не наступай снова)
- **npm/node нет** → ставили Node LTS через MSI.
- **winget/gost блокирует Defender** → мост написан на Node (`proxybridge.mjs`).
- **ERR_INVALID_AUTH_CREDENTIALS** → креды прокси нельзя в URL для Chromium; мост решает.
- **ERR_TUNNEL_CONNECTION_FAILED** → Chromium не тянет SOCKS5-auth; мост решает.
- **AdsPower крутится** → нет WebView2 Runtime + нужен ребут; на этом сервере так и не поднялся.
- **Google Workspace-аккаунт** → «service turned off», брать только личные @gmail.
- **Медленный прокси** → таймауты навигации подняты до 90с; можно сменить ноду ASocks.
