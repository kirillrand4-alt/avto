# Рабочий протокол сессий (как держать качество)

Этот файл — про то, КАК работать с ассистентом в этом репозитории, чтобы ответы
оставались точными. Родился из наблюдения: в длинной многотемной сессии качество
падает — появляются ошибки интерпретации, путаница терминов, пересказ выводов по
памяти вместо пере-вывода из данных.

## Почему качество просаживается (механика, не мотивация)

1. **Компактификация.** Когда диалог упирается в лимит памяти, старая часть
   сворачивается в короткое резюме. Резюме лоссовое — теряются сырые цифры и
   промежуточные проверки. После этого ассистент пересказывает выводы по памяти.
2. **Разбавление контекста.** Одна сессия на много тем → внимание размазывается,
   середина контекста проваливается («lost in the middle»).
3. **Смена типа задач.** Аналитика (проверка на данных — родная среда) vs советы/
   интерпретация (легко расслабиться и editorializ­ировать вместо опоры на данные).

## Правила

1. **Одна сессия = одна ОБЛАСТЬ работы.** Меняешь область (SEO ↔ рассылка ↔
   сендер) → новая сессия. Не мешать области в одной сессии.
2. **Факты живут в файлах, не в чате.** Ground-truth пишем в файлы (см.
   `SESSION-INDEX.md`). Файлы переживают сжатие, чат — нет. Если факт важен — он в
   файле.
3. **Стоячая команда «покажи проверку на данных».** На любую цифру/факт —
   механический чек (скрипт/выборка), а не память. Ответ по памяти помечать явно.
4. **После сжатия — сначала перечитать данные области, а не верить резюме.**
   Ассистент может сигналить «работаю из сжатого контекста, перепроверяю».
5. **Держать сессии короткими.** Пошло сжатие → чекпоинт выводов в файл → свежая
   сессия со скоупом «работаем над X, читай такие-то файлы».

## Старт новой сессии (шаблон)

> Работаем над областью «<название>». Читай `SESSION-INDEX.md` (раздел <область>)
> и её ground-truth-файлы, продолжай с <шаг>. Проверяй утверждения на данных.

## Эфемерное vs durable (ВАЖНО)

- **scratchpad сессии** (`/tmp/.../<uuid>/scratchpad`) — ЭФЕМЕРНЫЙ, виден только
  внутри своей сессии. Новая сессия его НЕ видит.
- **git-репозиторий (закоммиченное)** — переживает между сессиями. Клонируется
  заново при старте контейнера.
- **drop-сервер** (`seo-texts/server/drop_client.sh`) — для тяжёлых файлов.
- Вывод: **чекпоинт-файлы для следующей сессии обязаны быть в git** (или на drop),
  иначе следующая сессия их не найдёт.

## Правило владельца (перекрывает дефолты)

Вся тяжёлая LLM-работа — через провайдерский API (`seo-texts/gen_provider.py`,
`claude-fable-5`, router.cheap), в трекаемом фоне, с кэшем и резюмируемостью.
Токены сессии — только оркестрация (git, скрипты, короткие ответы). Подробно — в
`CLAUDE.md`.
