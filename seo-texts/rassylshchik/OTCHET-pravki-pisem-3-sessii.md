# Что правится в письмах между очередью и отправкой

Третья сессия, 02.08.2026. Разбор по выгрузке живой `C:\sender\sender.db`
(`sender-dump-3s.json.gz` на дропе): 470 писем, 458 карточек подтверждения,
452 записи генератора, 36 строк журнала отправки.

Всё ниже — по файлу, а не по памяти. Где я сначала прочла неверно, поправка
названа прямо.

---

## 1. Правок 22, и все 22 письма ушли

| | |
|---|---:|
| карточек в очереди подтверждения | 458 |
| из них с правкой руками | **22** |
| у скольких из правленых итог `sent` | **22 из 22** |
| тема менялась | 5 |
| тело менялось | 22 |

Правка — почти всегда пропуск в отправку. Ни одно правленое письмо не было
отклонено. То есть очередь работает как «переписать и послать», а не как
«отбраковать».

Кто решает по очереди: `okved-gate` 86 (автоматический отсев по ОКВЭД),
`card-audit` 48, **`kirill` 41** (руками), `auto-twin` 9 (автоотсев тёзок),
не решено 271.

Правка **доходит** до отправленного письма: тело в `messages.body_rendered`
совпадает с отредактированным на 93–96%, расхождение — ровно подпись и строка
отписки (+85…90 знаков). Проверено на 16 письмах, где тело сохранено; у
остальных 14 из 35 ушедших `body_rendered` пуст, по ним сравнить нечем.

## 2. Общие закономерности правок

Считано по строкам диффа: убрано 83 строки (11 271 знак), добавлено 87
(13 699). **Письмо после правки длиннее на 21%** — вопреки ожиданию, что руками
сокращают.

| признак | убрано | добавлено |
|---|---:|---:|
| конкретная цифра из новости (млн, тонн, «к 2030 году», %) | 7 | 2 |
| марка/модель оборудования из новости | 1 | 0 |
| боль и страх (простой, не вытянет, тормозит, запчасти) | 3 | 2 |
| вопрос-вилка «уже решено или ещё подбираете» | 4 | 1 |
| пневмоаудит | 13 | 9 |
| аналоги ушедших с рынка брендов | 0 | **2** |
| просьба перенаправить ответственному | 6 | 4 |
| «Компрессор Центр» **в кавычках** | 0 | **2** |
| Компрессор Центре без кавычек | 17 | 5 |
| поздравление с событием | 0 | **1** |

Пять закономерностей, каждая видна в нескольких письмах:

1. **Из новости убирают числа и модели.** «выход на 5 млн упаковок к 2030 году»,
   «добычу планируют поднять до 45 млн тонн, в апреле отгрузили рекордный
   объём», «Байкал BOCHU FSWELD 3800» → «Байкал». Остаётся сам факт события.
   Похоже, точная цифра из новости читается как слежка и легко бывает неверной.
2. **Убирают запугивание.** «старый компрессор может не держать давление в
   смену», «поставка может растянуться на недели, и это тормозит весь пуск»,
   «уходят в простой на неделю из-за отсутствия запчастей» — вычеркнуто везде,
   где было.
3. **Закрытый вопрос заменяют открытым.** «Компрессорная уже решена?» и «уже на
   стадии пусконаладки или ещё подбираете?» → «актуален ли для вас вопрос
   обновления компрессорного парка? Если да, под какие задачи?».
4. **Дописывают конкретную услугу**: пневмоаудит, подбор под задачу и —
   новое, чего в генерации нет вовсе — **аналоги моделей ушедших с рынка
   брендов, по которым сложно с запчастями**.
5. **Тема переписывается с телеграфной на деловую**, все 5 случаев:

   | было | стало |
   |---|---|
   | роботизированный комплекс в Новокузнецке | Вопрос по обновлению компрессорного парка |
   | для техотдела: компрессорная под расширение | Вопрос по актуальности расширения компрессорного парка |
   | для снабжения: компрессорное оборудование | Для снабжения: обновление компрессорного оборудования |
   | цех механообработки | Вопрос по расширению компрессорного парка под новое производство в «ИнтерПолярис» |
   | компрессорная под электронику | Компрессоры для нового производства гофроупаковки |

   Тема в генерации — строчная и про новость. Тема руками — с заглавной, про
   компрессоры, часто с именем компании.

## 3. Контакт при отправке НЕ меняли. Поправка к первому прочтению

Сначала я сравнила адрес в карточке подтверждения с адресом в строке
получателя и получила 12 расхождений — то есть «адресата меняли перед
отправкой». **Это неверно.** По журналу отправки `send_log` адрес совпал с
очередью во всех 22 случаях: письмо ушло ровно туда, куда стояло.

Расхождение оказалось другого рода и важнее.

**14 из 35 ушедших писем ушли на замороженный адрес: в базе на момент отправки
уже лежал другой, и строка получателя обновлялась ДО отправки, а не после.**

Это прямо по цели владельца: письмо уходит в приёмную, хотя адрес отдела или
человека уже добыт и лежит рядом. Адрес замораживается при постановке в
очередь и больше не пересматривается. Починка — перечитывать лучший адрес
получателя в момент клейма письма, а не при постановке.

## 4. Генератор трижды переписывает почти каждое письмо

`ai_letter_log`: 452 письма, из них `ok` 427, `brak` 25. Кругов
самопроверки на письмо: **369 писем прошли все 3 круга**, 11 — два, 72 — один.
То есть три четверти писем упираются в предел кругов.

Чаще всего модель сама себе пишет:

| замечание | раз |
|---|---:|
| нет опции отказа | 656 |
| правило 11 (человечность, труизмы, клонирование оборотов) | 402 |
| правило 2 | 192 |
| правило 8 | 190 |
| правило 13 (маршрутизация: есть новость, но заход не новостной) | 126 |
| правило 12 (реклама) | 105 |

«Нет опции отказа» — самое частое замечание и при этом чисто шаблонное: строка
«если неактуально — извините за письмо» есть в готовых письмах всегда. Её
можно дописывать шаблоном, а не гонять из-за неё круг генерации. Это самая
дешёвая экономия из видимых: 656 срабатываний.
