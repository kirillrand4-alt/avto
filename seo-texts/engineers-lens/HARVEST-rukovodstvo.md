## Чем этот путь лучше протоколов

| | Протокол закупки | Страница «Руководство» |
|---|---|---|
| ФИО | инициалы (обычно) | **полное, с отчеством** |
| Должность | на дату документа | **текущая** |
| Телефон | нет (или чужой, участника) | **есть, иногда прямой** |
| Почта | нет | **есть** |
| Стоимость | поиск + разбор PDF | **один GET** |
| Что даёт сверх | какая компания что покупает и когда | вся верхушка сразу |

Протокол остаётся нужен, но для другого: он говорит, **какая компания и что покупает**,
то есть отбирает цель и даёт повод для обращения. Личность и контакт берутся со страницы
руководства.

Важно: у большинства филиалов на странице руководства стоит **общий ящик приёмной**
(`priem@moren.ru`, `secr@orene.ru`, `adm@ch-energo.ru`), а не личный. Общий ящик —
реальный опубликованный адрес, по нему можно писать. Личный — только реконструкция.

Реконструированные адреса перед рассылкой валидировать **без отправки письма**: проверка MX
домена и детект catch-all. Массовые баунсы по угаданным адресам бьют по репутации домена
отправителя — это ровно тот риск, который описывала адверсариальная линза.

### Проверка MX: все крупные заказчики держат свою почту

Проверено 29.07.2026 прямым DNS-запросом MX по всем собранным доменам.

| Домен | MX | Кто держит |
|---|---|---|
| `moren.ru` (Мордовэнерго) | `post.moren.ru` | своя |
| `penzacom.ru` (Пензаэнерго) | `mail1.penzacom.ru` | своя |
| `ues.mrsk-volgi.ru` (Ульяновские РС) | `mx1.ues.mrsk-volgi.ru` | своя |
| `samara.mrsk-volgi.ru` (Самарские РС) | `mail1.samara.mrsk-volgi.ru` | своя |
| `orene.ru` (Оренбургэнерго) | `mail2.orene.ru` | своя |
| `ch-energo.ru` (Чувашэнерго) | `zenit.ch-energo.ru` | своя |
| `kl.mrsk-cp.ru` (Калугаэнерго) | `mx1.kl.mrsk-cp.ru` | своя |
| `rossetivolga.ru` (головной офис) | `mx1.rossetivolga.ru` | своя |
| `chak-avto.ru` (АО «ЧАК») | `mailer.chak-avto.ru` | своя |
| `celltechnologies.ru` (ИМКТ) | `mx.yandex.net` | Яндекс 360 |

Ни одного Mail.ru и ни одного Google. Гипотеза «`и.фамилия@` — это стандартный шаблон
почты на Mail.ru» **не подтвердилась**: раз MX свой, провайдер никакого шаблона не
навязывает, и схема `и.фамилия@` у Чувашэнерго — внутреннее соглашение их администратора.
Это усиливает вывод, что шаблон надо выводить по каждому домену отдельно.

Три следствия для конвейера:

1. **MX как бесплатный фильтр сегмента.** Своя почта на своём домене — маркер крупной
   организации со своей ИТ-службой, то есть нашего ICP. Яндекс/Mail.ru — маркер мелкой
   (единственный такой в выборке — небольшое медучреждение). Отсекать целевой список можно
   одним DNS-запросом, до всякого обогащения.
2. **Единой логики валидации адресов не будет.** У своих серверов поведение разное:
   greylisting, catch-all, закрытый VRFY. Снимать поведение придётся по каждому домену.
3. **Доставляемость мерить отдельно.** Корпоративные почтовые серверы фильтруют строже
   публичных, поэтому статистика по ним не совпадёт с общей статистикой рассылки.

## Замеченные детали, важные для конвейера

**Один человек в двух организациях.** Полуэктов Константин Юрьевич значится и как
заместитель директора по экономике и финансам «Оренбургэнерго», и как и.о. директора филиала
«Чувашэнерго». Это не ошибка сбора, а реальная ситуация: либо переход, либо совмещение.
Дедупликация по ФИО без учёта организации и даты слепит две разные записи в одну.

**Разметка страницы легко даёт сдвиг привязки.** На странице блока главного инженера ячейка
слева содержит должность И телефон, а ФИО лежит в соседней ячейке справа. Наивный парсер,
идущий по порядку текста, припишет телефон предыдущему человеку. Привязка проверена глазами
по скриншоту, а не по тексту.

**Телефон бывает и прямой, и общий.** Ульяновские РС и Самарские РС дают разный номер
каждому руководителю (69-75-59 / 69-75-51 / 69-75-61) — это прямые линии. Мордовэнерго,
Оренбургэнерго и Чувашэнерго дают один номер приёмной на всех. Определять по данным, а не
предполагать.

## Масштабируемость

URL страниц руководства строятся по шаблону
`/<филиал>/menedzhment_filiala/`, и внутри одной группы слаги различаются лишь названием
филиала. Это значит, что для сетевых холдингов (Россети и её МРСК, генерирующие компании,
водоканалы регионов) обход всей группы — это цикл по списку филиалов, а не ручная работа.

У «Россети Волга» семь филиалов. По стране только в контуре Россетей таких филиалов
несколько десятков, и у каждого есть главный инженер. **НЕ ПРОВЕРЕНО:** одинаков ли шаблон
URL у других МРСК; у «Россети ЦП» домен `mrsk-cp.ru` с сервера не открылся.
