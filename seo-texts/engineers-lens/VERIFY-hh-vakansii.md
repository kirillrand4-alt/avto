# Вакансии hh как горячий сигнал: проверка доступа и состояние `hh_vacancy_scan`

Проверка 29.07.2026. Задача: вакансия по целевой роли означает, что роль на предприятии
**прямо сейчас** освободилась или расширяется. Это бьёт в главную измеренную проблему —
связка «человек – роль» протухает за 20 месяцев (см. `VERIFY-10-cepochek.md`), а вакансия
датирована по определению.

Резюме сознательно не трогались: это персональные данные, отданные для трудоустройства.
Вакансию работодатель публикует сам и специально для того, чтобы с ним связывались.

## Доступ

| Канал | Результат |
|---|---|
| `api.hh.ru` из песочницы | **403 forbidden** |
| `api.hh.ru` с сервера владельца (РФ-IP, дата-центр) | **403 forbidden** |
| `hh.ru/search/vacancy` через профиль Dolphin с мобильным прокси | **200, страница рендерится** |

То есть API закрыто не по географии, а по типу IP и отсутствию токена приложения. В коде
`enrich_contacts.py` это уже зафиксировано: «api.hh.ru отдаёт 403 без токена приложения,
заявка на модерации до 15 рабочих дней». Человеческая выдача через мобильный профиль
открывается штатно, капчи нет (`captcha_type: null`).

**Правильный путь на перспективу — дождаться токена приложения и ходить в API.** Разбор
человеческой выдачи это обход, который сломается при следующем редизайне (что уже и
произошло, см. ниже).

## `hh_vacancy_scan` сломан

Готовый op в `server/enrich_contacts.py` (строка ~3756) отработал и вернул
**`employers_found: 0`** при полностью загруженной странице:

```
"главный инженер":  {"html_len": 400000, "captcha": null, "has_serp": false, "forbidden": false}
"главный механик":  {"html_len": 400000, "captcha": null, "has_serp": false, "forbidden": false}
"главный энергетик":            {"error": "HTTPError: HTTP Error 500"}
"начальник компрессорной станции": {"error": "HTTPError: HTTP Error 500"}
```

Два дефекта, оба мелкие:

**1. Устаревшие селекторы.** HTML приходит целиком (упёрся в `html_cap` 400 000), капчи нет,
`forbidden` нет — но `has_serp: false`. Регулярки ищут `data-qa="...employer..."`,
`company-name` и `data-qa="...vacancy...title..."`; в текущей разметке hh таких атрибутов
нет.

*Как чинить:* не подбирать новые `data-qa` (сломается снова), а разбирать **`inner_text`
страницы**. Отрендеренный текст уже структурен и стабилен к редизайну. Проверено на живой
выдаче — оттуда читается без всякой разметки:

```
Главный энергетик карьера | Опыт более 6 лет | Вахта |
ООО Удоканская медь, Энергетика/ремонт, обслуживание, эксплуатация... | посёлок Удокан
```

**2. Профили не ротируются.** Op принимает список `dolphin_profiles`, но берёт только
`profs[0]` и держит его на все запросы. Два из четырёх запросов упали с HTTP 500 — конфликт
повторного запуска того же профиля. Нужно раскладывать запросы по переданным профилям.

Обе правки — в `server/enrich_contacts.py`, а раннер исполняет **серверную копию**, не
репозиторную. Значит это выкатка на боевую машину владельца, и делать её молча я не стал.

## Что дальше

1. Починить op (inner_text + ротация профилей) и выкатить — тогда полный прогон по четырём
   ролям выполним за один заход.
2. Отфильтровать шум: отсечь кадровые агентства и нецелевые «главный инженер проекта» /
   «главный механик автопарка» по тексту вакансии.
3. По каждому оставшемуся работодателю — уже проверенная цепочка через страницу
   «Руководство» (`HARVEST-rukovodstvo.md`).
4. Отдельно ценно: текст вакансии часто описывает **парк оборудования** («обслуживание
   компрессорной станции», «воздухоподготовка»). Это квалификация лида без обогащения.

## Чего здесь нет

- Полной выгрузки: собраны только счётчики и первые карточки выдачи, потому что op сломан,
  а `browser_probe` через раннер отдаёт лишь 600 символов текста и один экран скриншота.
- Оценки доли релевантных вакансий среди найденных.
- Контактных лиц из карточек вакансий: поле «контактное лицо» работодатель заполняет не
  всегда, на просмотренных карточках его не было.
- Проверки, что вакансия действительно означает смену человека, а не расширение штата.
