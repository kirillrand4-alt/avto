## Новости об авариях: что даст

**Логика**: местные СМИ при авариях на водоканале цитируют главного инженера или начальника очистных по имени ("как сообщил главный инженер Иванов И.И.").

**Шаблон поиска**:
```
"[название из name_obzvon]" "[город из address]" (авария OR отключение OR ремонт) (главный инженер OR главный механик OR начальник очистных)
```

Пример для inn=6623034200 (Водоканал-НТ, Нижний Тагил):
```
"Водоканал-НТ" "Нижний Тагил" авария главный инженер
```

**Конверсия** (грубая оценка по водоканалам):
- Найдется новость об аварии: ~70% (352 из 502) — водоканалы аварийные
- В новости назван технический специалист с ФИО: ~50% (176 из 352) — не все СМИ цитируют
- Человек еще работает (новость не старше 3 лет): ~60% (106 из 176)
- **Итого ФИО технического специалиста: ~105 из 502**
- Телефон прямо в новости: ~5% (5 из 105) — журналисты редко публикуют
- **Только ФИО без телефона: ~100 из 502**

**Трудоемкость**:
- Ручной поиск + чтение новостей: 7 минут на предприятие
- 502 × 7 минут = 58 часов = **7 рабочих дней**
- Производительность: **15 ФИО в день** (100/7)

**Проблема актуальности**: новость может быть старой, человек уволился. Фильтр по дате снизит конверсию до ~60 из 502.

## Автоматизация новостей

**Через поисковик**:
- API Яндекс.XML / Google Custom Search (если есть ключи)
- Парсинг текста новости: regex на паттерны "главный инженер [Фамилия И.О.]"
- Фильтр по дате публикации (последние 2-3 года)

**Проблемы**:
- Извлечение ФИО из неструктурированного текста: ложные срабатывания
- Новости на картинках: нужна OCR (модель читает картинку — есть в инструментах)
- Снижение конверсии при автофильтрах

**Оценка трудоемкости автоматизации**: 2-3 дня на раннер + ручная проверка результата.
