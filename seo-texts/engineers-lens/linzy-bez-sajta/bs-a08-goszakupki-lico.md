По 502 водоканалам без сайта есть три рабочих пути к техническим людям. Ранжирую по выходу на единицу труда.

**1. ЕРКНМ (контрольные мероприятия) + имеющийся телефон предприятия**

Как работает: акты проверок Роспотребнадзора, Ростехнадзора, прокуратуры содержат ФИО ответственных лиц предприятия — именно техников (главный инженер, главный энергетик, начальник очистных). ЕРКНМ позволяет фильтр по ИНН.

Действие:
- 502 запроса к ЕРКНМ по ИНН
- Парсинг актов проверок за 2-3 года (у провайдерского API для чтения текста это штатная задача)
- Извлечение: ФИО + должность из раздела "Присутствовали" или "Ответственное лицо"
- Сопоставление с имеющимися телефонами предприятий (396 из 502)

Выход: 
- ЕРКНМ покрывает примерно 40-60% предприятий (водоканалы проверяют регулярно)
- Это 200-300 ФИО техников
- Пересечение с имеющимся телефоном предприятия: 160-240 комбинаций "ФИО главного инженера + телефон водоканала"
- Секретарь переключит на Иванова И.И. охотнее, чем на "главного инженера"

Труд: 1-2 дня на автоматизацию + прогон.

Эффективность: **80-120 людей с телефоном на день труда**.

Опора на строки: у всех 502 есть inn, у 396 из 502 есть telefony_iz_obzvona (колонка заполнена, например inn=7705013033 | telefony_iz_obzvona=+7 495 923-29-01).

**2. API ЕИС zakupki.gov.ru по ИНН заказчика + парсинг документации**

Как работает: фильтр по заказчику в веб-интерфейсе ЕИС сломан, но API работает. Метод `contracts/search` и `notices/search` принимает параметр `customerInn`.

Действие:
- 502 запроса к api.zakupki.gov.ru/epz/order/extendedsearch с параметром customerInn
- Для каждого извещения: скачать документацию (ТЗ, проект контракта)
- Парсить документы через провайдерский API: искать раздел "Ответственный за приёмку", "Лицо для согласования технических вопросов", подписи в ТЗ
- Извлечь: ФИО + должность + телефон (если указан в контактах)

Выход:
- Контактное лицо заказчика есть в каждом извещении (100% покрытие), но это обычно контрактная служба
- Технический ответственный в ТЗ встречается в 15-30% закупок (опыт по другим отраслям)
- У каждого водоканала 10-50 закупок за 2 года (по колонке stages: у большинства есть etp, значит закупки ведутся)
- Итого: 502 × 20 закупок × 20% попадание техника в ТЗ = **~2000 упоминаний техников**, но с дедупликацией (один главный инженер во многих закупках) это **100-200 уникальных людей**
- Телефон в ТЗ указывают редко (20-30% случаев), итого **30-60 людей с прямым телефоном**
- Остальные 140 — через общий телефон предприятия

Труд: 3-5 дней (502 запроса × 20 закупок × скачивание документации × парсинг).

Эффективность: **10-20 людей с телефоном на день труда**.

Опора на строки: колонка stages содержит etp у большинства (например inn=6445029380 | stages=checko,etp). Это значит, закупки есть.

**3. Tender.pro по ИНН**

Как работает: площадка уже дала 306 технических людей по промышленности в целом. Tender.pro агрегирует закупки и иногда парсит контакты заказчика лучше, чем сам ЕИС.

Действие:
- 502 поиска на Tender.pro по ИНН
- Извлечение контактов из карточек заказчика

Выход:
- По аналогии: если 306 техников собрано по всей промышленности, то доля водоканалов в этой базе — примерно 10-15% (водоканалов 502 из примерно 4000-5000 промышленных предприятий с нужным оборудованием)
- Это **30-45 технических людей с телефонами**

Труд: 1 день (502 поиска + извлечение контактов).

Эффективность: **30-45 людей с телефоном на день труда**.

Опора: в контексте прямо сказано "Tender.pro (по ней уже собрано 306 технических людей по промышленности в целом)". Инструмент работает, нужно применить к этим 502.

---

**Итоговое ранжирование:**

1. ЕРКНМ + телефон предприятия: **80-120 на день** (приоритет)
2. Tender.pro: **30-45 на день**
3. API ЕИС + парсинг документации: **10-20 на день**, но даст самое полное покрытие при наличии времени (3-5 дней)

По труду: ЕРКНМ быстрее всего окупается. API ЕИС — резерв для полноты.
