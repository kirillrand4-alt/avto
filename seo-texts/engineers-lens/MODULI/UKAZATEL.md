# Указатель модулей 2-й сессии

Задача владельца: «вбиваю компанию либо ИНН, и по ней ищется вся информация: тендеры, контактные
лица, новости. Чтобы каждый модуль можно было запустить ОТДЕЛЬНО друг от друга по списку компаний.»

Карточка на каждый модуль лежит рядом отдельным файлом. Описание собрано провайдером из фактов,
снятых с кода и с диска программой `karta_moduley.py`: пути к файлам с реальным числом строк,
вызовы провайдера и раннера, аргументы командной строки, имена функций. Провайдеру запрещено
добавлять числа и имена файлов, которых нет во входе, и код сверяет ответ с тем, что нашёл сам.
Выдумок на 127 карточках: 0.

## ГЛАВНОЕ ЧИСЛО ДЛЯ СБОРКИ СИСТЕМЫ

**86 модулей из 127 нельзя запустить по одному ИНН.** Они работают обходом всей базы: путь к
входному файлу зашит, фильтра по списку нет. Это и есть основная работа по превращению набора
скриптов в систему, где вбивают одну компанию.

Разбор по ролям: обогащение 55, проверка 33, сбор из внешнего источника 19, сборка витрины 12,
классификация 5, инфраструктура 3. Провайдера вызывают 55 модулей из 127.

## Порядок запуска цепочки

1. **сбор** из внешних источников → файлы в `engineers-lens/centro/`;
2. **сборка базы фактов** `svod_tri_sostoyaniya.py` → `SVOD-tri-sostoyaniya.csv`;
3. **классификация** `tip_mashiny.py` (тип машины и среда) и `sreda_dobor.py` (доузнавание среды
   провайдером) → `OCHERED-centrobezhnye.csv`;
4. **обогащение людьми**: каналы добычи контактов;
5. **сборка витрины** `svodnaya_centrobezhnye.py` и `sborka_dlya_paneli.py` → файл для панели;
6. **проверка** `proverka_otseva.py`, `obratnyy_audit.py`.
