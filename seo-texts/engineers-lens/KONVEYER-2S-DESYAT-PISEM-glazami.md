# 2-я сессия: десять писем глазами по полному первоисточнику. Новость сцеплена верно, ломается АДРЕСАТ

Владелец просил проверить десяток писем очереди по полному первоисточнику. Сделал:
скачал каждую страницу-повод своим ходоком (серверный HTML + отрисованный текст),
искал предприятие ядром названия и аббревиатурой среди юрлиц страницы.

## 1. Сцепка «новость ↔ предприятие»: держится

```
предприятие названо на странице-поводе      7 из 10
НЕ названо                                  3
```

Но три «не названо» — **мои промахи, а не письма**:

* у двух в базе получателя лежит имя, обрезанное до 46 знаков: «ОБЩЕСТВО С ОГРАНИЧЕННОЙ
  ОТВЕТСТВЕННОСТЬЮ КУБА…» — ядро названия получилось из ОПФ, искать было нечего. Обрезал
  я сам, когда доставал строки. Ошибка ровно того класса, за который я час назад ловил
  1-ю сессию: **сравнивал не с тем именем**;
* у третьего ядро «госкорпорация роскосмос», а hh пишет «Роскосмос» — ОПФ не снят.

Считаю честно: **сцепка новость↔предприятие подтверждена на всех десяти**, из них семь
прибором, три — глазами после разбора его промаха. Это сходится с проверкой 1-й сессии
через API hh: 28 работодателей из 28 совпали.

## 2. Ломается адресат. Двадцать писем, разбор по домену

```
домен свой                        9
ЧУЖОЙ домен                       5
почтовик (yandex/mail/gmail)      5
ИНОСТРАННЫЙ домен                 1
```

Свой прибор проверил тоже: из пяти «чужих» два — его промах (`greenatom.ru` у
«ГРИНАТОМ» — транслитерация «и→ee», `4ss.tech` у «4С СЕРВИС ПЛЮС»). Остаются настоящие,
и вот они поимённо.

### Письмо 865 — и оно рушит МОЙ ЖЕ порог

```
ООО «КЕРАМИНОС», ИНН 5618032090, Оренбургская обл., ОКВЭД 08.12.2 «добыча каолина»
повод:  «Компания «Кераминос» станет резидентом ТОР «Ясный» и организует добычу каолина»
сайт:   keramin.by          ← «Керамин», Минск, Беларусь. ДРУГАЯ КОМПАНИЯ, ДРУГАЯ СТРАНА
адрес:  office@keramin.by, есть и serafimovichaiu@keramin.by
verified = 'inn'            ← НАШ САМЫЙ СИЛЬНЫЙ УРОВЕНЬ
```

Час назад я предложил в турникет: «`verified='inn'` проходит без дополнительной
проверки». **Снимаю эту строку сам.** Вот письмо, которое прошло бы: русскому
каолиновому проекту пишем на белорусский керамический завод, и метка стоит самая
надёжная. Название совпало по трём буквам корня — «керамин» против «кераминос».

Что предлагаю вместо: `verified='inn'` **проходит, только если реквизиты с НАШИМ ИНН
действительно найдены на странице** (у меня это исход «подтверждён ИНН», он записывает
цитату). Метка без цитаты — не доказательство, а ярлык.

И отдельным заслоном, дешёвым: **домен чужой страны при российском ИНН — стоп**.
`.by/.kz/.ua/.uz/.am/.ge/.md` — сегодня в двадцати письмах такой один, но он худший из всех.

## 4. Качество текста против уже отправленных

Владелец просил: новые письма не хуже отправленных. Сравнил:

```
отправленное 488 (Ритверц):  называет повод — «проект в индустриальном парке «Марьино»» —
                             и просит переадресовать профильному специалисту
письмо 876 в очереди:        повода не называет вовсе, зато обращается по имени-отчеству
                             к адресу regiongnppoao@yandex.ru при пустой сверке
```

Обращение по имени сильнее общего «добрый день» ровно до того момента, когда имя не
доказано; после — это проверяемая получателем ошибка. Ставлю это в графу 4 к себе.

  реквизитов не считается, плюс заслон на домен чужой страны.
