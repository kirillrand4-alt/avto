## 1. Росаккредитация — реестр деклараций и сертификатов ТР ТС 010/2011

деклараций о соответствии», раздел «Декларации». Открывается без регистрации, HTTP 200.

### Как пришлось искать (и почему не напрямую)

Поиск в этом реестре — это инлайн-фильтры в шапке таблицы Angular-приложения; чтобы ими
воспользоваться, нужно ввести текст в поле. Три прогона `browser_probe` с аргументами `fill`
и `fill_seq` вернули HTML без единого признака того, что патчи отработали: в ответе **нет
ключей `fill_used`, `fill_seq_done`, `fill_seq_err`**, длина HTML не изменилась (295 648 →
296 425 байт), в тексте по-прежнему случайные товары. Вывод: патчи
`patch_browser_probe_fill*.py` **не установлены в ту копию `browser_probe.py`, которую
запускает служба** (см. ловушку про два Python в HANDOFF). Задача `fetch_url` умеет только
GET, а поисковый API реестра принимает POST.

Поэтому проверка сделана по зеркалу того же реестра — `vaskov.pro/sertifikaty`
(«ГосАналитика», в карточке стоит ссылка «Карточка на pub.fsa.gov.ru», источник указан как
`fsa.gov.ru`, объём 7 199 951 документ: 4 941 679 деклараций и 2 258 272 сертификата,
«Реестр обновлён: 29.07.2026»). Запрос:

```
https://vaskov.pro/sertifikaty/search?product=центробежный%20компрессор&doc_type=all&page=N
заголовок HX-Request: true (иначе отдаётся оболочка страницы без результатов)
```

Счётчик применился: «Найдено **335** документов · показаны 1–50», 7 страниц выгружены
полностью, разобрано 335 строк.

### Вердикт

**Как список владельцев — не брать.** Реестр отвечает на вопрос «кто вывел машину на рынок»,
а не «у кого она стоит».

**Как список конкурентов и как датировка — брать.** Из выгрузки видно, кто сегодня ввозит и
производит центробежные машины в Россию (190 юрлиц), с датами и странами происхождения; это
прямой конкурентный срез рынка. Побочно виден редкий, но ценный сигнал: если завод
declarant — значит он ввозил машину сам, и дата декларации = дата появления машины на
площадке (случай Салавата — 2012 год, машина CKD).

Выгрузка: `istochnik-fsa-centro-deklaranty.csv` (335 строк, колонки тип, номер, продукт,
изготовитель, декларант, статус, страна, дата, ссылка на карточку).

## 2. Надзор: есть ли публичный реестр предписаний

### Чего нет

**Отдельного реестра предписаний у Ростехнадзора нет.** Проверено:

* `gosnadzor.ru` из песочницы отдаёт `HTTP 403` на любой странице (включая с браузерным
  User-Agent) — гео-отсечка, не отсутствие страницы. Через раннер открывается;
* набор открытых данных, который по названию выглядит как искомый, —
  `https://www.gosnadzor.ru/opendata/7709561778-rasporyazheniya/index_od.php`,
  заголовок H1: **«Перечни решений, распоряжений и предписаний Ростехнадзора»**. Страница
  открывается (200, 224 020 байт), но ведёт на четыре файла на `data.gov.ru` от 10.09.2019:

  ```
  https://data.gov.ru/opendata/7709561778-rasporyazheniya/data-20190910T1226-structure-20190910T1226.csv
  ```

  Все четыре — `http=404 size=0`. Портал data.gov.ru как источник мёртв, набор не переехал.

### Что есть вместо этого: ЕРКНМ

Настоящий действующий реестр — **ФГИС «Единый реестр контрольных (надзорных) мероприятий»**,
`https://proverki.gov.ru/portal/public/public-search`, оператор — Генпрокуратура. Ростехнадзор
там присутствует как один из органов контроля.

Веб-поиск закрыт капчей: API `/public/api/inspections/find?...` требует заголовок `token`,
который выдаётся только после решения капчи (`/public/api/inspections/token?captcha=...`);
без него ответ `HTTP 400`.

**Но открытые данные ЕРКНМ отдаются без капчи и без регистрации:**

```
GET https://proverki.gov.ru/public/api/opendata/list?isFederalLaw248=true
{"years":[2021,...,2027],"months":{"2026":[1,...,12]}}

GET https://proverki.gov.ru/public/api/opendata/2026/6?isFederalLaw248=true
"datasetName":"Проверки на Июнь 2026 года", владелец — Генеральная прокуратура РФ,
"dataZipUrl":"https://proverki.gov.ru//blob/erknm-opendata/2026/6/data-20260729-structure-20220125.zip"
```

Месячный архив — 338 935 463 байта (Content-Length подтверждён HEAD-запросом), сервер
поддерживает Range. Прочитаны первые 40 МБ архива → 184 594 367 символов XML →
**31 854 записи КНМ**. Из них по надзору в области промышленной безопасности — **241**.

### Что лежит в записи

Структура (XSD `structure-20220125.xsd`): `SUBJECT` (ИНН, ОГРН, название проверяемого),
`OBJECT` (тип, вид, адрес, категория риска), `KIND_CONTROL` (вид надзора), `KIND_KNM`,
`KNO_ORGANIZATION` (какое управление), `INSPECTOR` (ФИО и должность инспектора),
`REASON`, `WARNING_INFO/CAPTION` — полный текст предостережения, `RESULT`, даты, ERPID.

### Ищется ли по слову

По слову — только полнотекстом по выгруженному XML, поиска на стороне сервиса без капчи нет.
Замер на срезе (31 854 записи): слово «компрессор» встречается в 9 записях, и из них по
промбезопасности — 2. То есть **прямой поиск «компрессор» по ЕРКНМ почти ничего не даёт**:
модель оборудования в структурированных полях не хранится, она попадает только в свободный
текст предостережения.

Работающий способ — **обратный: фильтр по нашим ИНН.** На срезе (≈12 % одного месяца)
из наших 347 компаний нашлись **65 ИНН, 163 записи КНМ**, из них 12 — по промышленной
безопасности. Разбивка по видам надзора: жилищный 25, пожарный 20, фитосанитарный 17,
экологический 16, промбезопасность 12, стройнадзор 9.

### Вердикт

**Брать, приоритет высокий.** Это единственный найденный источник, который смотрит на нашу
цель со стороны государства и датирует событие. Практическая схема:

1. качать месячные архивы ЕРКНМ (12 файлов по ~340 МБ на год) — ссылка получается из
   `/public/api/opendata/{год}/{месяц}?isFederalLaw248=true`;
2. фильтровать `SUBJECT/@INN` по нашим 347 (и по 324 из `epb-kompressor-expiring.csv`);
3. оставлять `SUPERVISION_ID` = надзор в области промышленной безопасности;
4. в тексте `CAPTION` искать «компрессор», «истекшим сроком», «не соответствует требованиям».

Отдельно: в `epb-centro-vse.csv` вывод **«не соответствует» стоит всего у 10 заключений на
8 ИНН** (против 7 442 «соответствует» и 298 «не в полной мере»). Это самый короткий и самый
острый список, который у нас есть, и случай НЛМК показывает, что за таким заключением в
течение недель приходит надзор. Компании: ЕВРАЗ ЗСМК (2), ПАО «ЕВРАЗ» (2), АО «КНПЗ»,
ПАО «Казаньоргсинтез», ПАО «Северсталь», ООО «Газпром трансгаз Чайковский», ПАО «НЛМК»,
АО «АНХК».

Выгрузка: `istochnik-erknm-nashi-347.csv` (163 строки, поля ИНН, наше название, название в
ЕРКНМ, вид надзора, вид КНМ, статус, дата, орган, адрес объекта, ERPID, текст
предостережения).

## Не проверено

1. **Авито, раздел промышленного оборудования** — содержание не увидено: 403 + Яндекс
   SmartCaptcha и из песочницы, и с мобильного прокси Dolphin. Проверить может владелец руками
   за две минуты: открыть
   `avito.ru/all/promyshlennoe_oborudovanie?q=центробежный компрессор` и посмотреть, есть ли
   объявления от юрлиц и виден ли продавец.
2. **Поиск по самому `pub.fsa.gov.ru` не выполнен**, данные взяты с зеркала. Чинится точечно:
   применить `seo-texts/server/patch_browser_probe_fill_v3.py` к той копии `browser_probe.py`,
   которую запускает служба (сверить `nssm get rusprom-runner Application`, ставить в
   `Python312`), после чего инлайн-фильтр колонки «Общее наименование продукции» открывается
   селектором `input[data-pc-name="pcfilterinputtext"] >> nth=3`. Отдельно стоило бы добавить
   раннеру задачу с методом POST — сейчас `fetch_url` только GET, из-за чего недоступны
   поисковые API и ФСА, и ЕРКНМ.
3. **ЕРКНМ выгружен на 12 %**: прочитаны первые 40 МБ из 339 МБ архива за июнь 2026, другие
   месяцы и годы (2021–2027 доступны) не трогались. Полный прогон по 12 месяцам × наши 347 ИНН
   не делался — это следующая работа, и она даст на порядок больше 163 найденных записей.
4. **Не измерена доля живых предприятий среди 243 советских заказчиков НЗЛ**, которых нет в
   наших 347. Часть переименована (три случая нашлись вручную в выборке из 20 — Дорогобуж,
   Томскнефтехим, ММК), часть не существует. Пока названы обе версии, но доля не посчитана.
5. **Не взяты отраслевые PDF НЗЛ** (газовая, нефтяная, химическая, металлургическая отрасли,
   энергетика, экспорт — семь файлов) — они охватывают всё оборудование, а не только
   компрессоры, и могут добавить объекты и годы по тем же предприятиям.
6. **Не проверены территориальные управления Ростехнадзора** по отдельности: у некоторых на
   сайтах есть свои разделы «Результаты проверок». Проверялся только центральный gosnadzor.ru.
7. **`bankrot.fedresurs.ru`** (торги имуществом банкротов) — `HTTP 401`, защита Qrator, не
   открывался. Это ближайший неотработанный аналог гипотезы «продаёт — значит меняет».
8. **belgiss.by** (зеркало единого реестра ЕАЭС) — из песочницы TLS сбрасывается, через раннер
   угаданный адрес API отдал `HTTP Error 404`. Правильный адрес не найден; после починки ФСА
   он и не понадобится.
9. **Ни одна из найденных компаний не обзванивалась**, ФИО инженеров ни один из четырёх
   источников не даёт вовсе — ЕРКНМ даёт только ФИО инспекторов надзора.
