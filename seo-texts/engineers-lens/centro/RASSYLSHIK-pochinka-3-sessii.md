# Починка матчинга в рассыльщике: заслон `proverka_privyazki.py`

Третья сессия. Аудит нашёл 16 мисматчей из 66 (`RASSYLSHIK-otchet-3-sessii.md`). Здесь — починка
и её ЗАМЕР на той же размеченной сотне пар.

## Что сделано

Модуль `proverka_privyazki.py` — три ступени перед постановкой письма в кампанию:

1. **Механика (бесплатно).** ИНН компании найден в тексте первоисточника → привязка доказана,
   модель не нужна.
2. **Судья (модель).** Судит по тексту первоисточника + профилю (ОКВЭД, регион).
   Модель `deepseek-v4-pro` по правилу владельца (свободный текст → факты).
3. **Адверсариальная защита.** Отказ судьи перепроверяется вторым вызовом, который пытается
   ОПРАВДАТЬ привязку. Оправдание НЕ даёт автоотправки — уводит на ручную.

## Замер на 66 размеченных парах

| | было (без заслона) | стало |
|---|---:|---:|
| писем уходит | 66 | 16 |
| **из них ошибочных** | **16** | **0** |
| точность рассылки | 76% | **100%** |
| заблокировано мисматчей | 0 из 16 | **16 из 16** |
| ушло на ручную (не выброшено) | — | 47 |

Цена честная и её надо назвать: из 47 на ручной **34 привязки верные** — они задержаны зря и
ждут человека. То есть заслон осторожен: он не теряет данные (ничего не выбрасывается), но
сокращает автопоток вчетверо. Для холодной рассылки это правильный размен: письмо не тому
адресату дороже задержанного письма.

## Три ошибки, найденные при настройке самого заслона

1. **Механический отказ «имени нет в тексте» убивал ВЕРНЫЕ привязки.** «КСК МК» в посте назван
   «КСК Металлкомплект» — дословного совпадения нет, привязка верная. Замер: 5 верных из 50
   зарублено. Механика больше не отвергает сама, а передаёт судье.
2. **Судья в одиночку слишком свиреп:** 15 мисматчей из 16, но 33 ложных отказа из 50 —
   отвергал даже там, где имя стоит прямо в тексте («Кремне-магниевый завод»).
3. **Адверсариальный слой слишком мягок:** оправдал 5 настоящих мисматчей (АУРУС, Моторика,
   Бурлак, Воллкрафт). Поэтому оправдание переведено в «на ручную», а не в отправку.

## Как включить в рассыльщик

```python
from proverka_privyazki import проверить
в_рассылку, уровень, причина = проверить({
    'inn': …, 'name': …, 'okved': …, 'region': …, 'what': …, 'src': текст_первоисточника})
```
Ставить перед `db.add_signal` в `newsco_op.применить()` либо перед постановкой в кампанию.
Уровни: `инн`, `модель-подтвердила` → в рассылку; `мисматч-подтверждён`, `механика-отказ` →
отказ; `ручная`, `оправдана-но-на-ручную` → очередь человеку.

**Важно:** уровень `ядро` из `newsco_op.привязка()` больше не должен пускать в кампанию сам по
себе — это и был корень 9 тёзок из 16.
