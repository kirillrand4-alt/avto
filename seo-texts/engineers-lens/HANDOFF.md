## 1. Задача в одном абзаце

Владелец продаёт промышленные компрессоры (ООО «Руспром», prokompressor.ru). Нужно найти
**инженеров с привязкой к конкретным предприятиям** — не перепись инженеров страны, а
**company-first**: от списка целевых заводов к людям в закупочно-значимых ролях внутри
каждого. Цель — продать машину, а не обслужить, поэтому ФИО нужно, одного отдела снабжения
мало.

Целевые роли по убыванию влияния: главный инженер, технический директор, директор по
производству → главный механик, главный энергетик, начальник компрессорной станции →
руководитель предприятия → закупщик.

## 2. Главные выводы, которые нельзя переоткрывать заново

1. **Личность и контакт дают два источника: страница «Руководство» в госсегменте и голос
   у частников.** Ни один агрегатор, реестр или площадка третьего пути не дал.
2. **44-ФЗ не источник инженеров** — ч. 17 ст. 48 не требует ФИО и должностей в протоколе.
   223-ФЗ работает, но только когда протокол печатается **своим шаблоном заказчика**, а не
   машинной формой площадки.
3. **Связка «человек–роль» живёт мало.** Замерено по вебархиву на 20 позициях: через 5 лет
   на месте 6 человек из 20, через 2,8 года — 3 из 7. Каждая запись обязана нести дату.
4. **Окно замены даёт реестр ЭПБ**, а не догадки о дате покупки. Экспертизу делают на
   машины, выработавшие срок; у заключения есть дата конца.
5. **Закупки санкционных и частных заказчиков в ЕИС не попадают** (ПП № 301 и отсутствие
   субъектности). Всё, что построено поверх ЕИС, нефтехимию и металлургию не видит.
   Путь к ним — площадка холдинга.
6. **Схема корпоративной почты ненадёжна даже внутри одного домена**: в `anhk.rosneft.ru`
   сосуществуют `KorobitsynaAP@` и `mv_butakova@`.

Подробности и цифры — в `README.md`, разбор по способам — в `SPOSOBY-POISKA.md`.

## 3. Инфраструктура: чем работать

### Раннер на сервере владельца (РФ-адрес)

Песочница геоблочена почти для всех российских сайтов. Всё ходит через сервер владельца.

- Клиент из песочницы: `run_on_server.py` в рабочем каталоге сессии (подписывает задание
  HMAC, кладёт на дроп, ждёт `result-<id>.json`).
- Файлообменник: `seo-texts/server/drop_client.sh` (`list | up | down | del`).
- Задачи: `browser_probe` (Playwright + профили Dolphin Anty), `fetch_url` (скачать файл),
  `verify_company` (реквизиты по ИНН через checko), `smtp_probe` (проверка адресов),
  `hh_vacancy_scan`, `ping` и др.

**Ключевые аргументы `browser_probe`:**

```
url, wait_ms, return_html, html_cap, screenshot, proxy, ignore_https_errors,
dolphin_profile, dolphin_keep, click, card_wait_ms,
fill        {"selector": "...", "value": "...", "click_after": "...", "enter": true}
fill_seq    {"steps":[{...},{...}], "submit": "...", "open_first": "..."}
```

`fill` и `fill_seq` добавлены в этой сессии тремя патчами
(`seo-texts/server/patch_browser_probe_fill*.py`). `fill` ищет поле во всех фреймах.
`fill_seq` заполняет несколько полей подряд — нужно там, где кроме строки поиска надо
поменять фильтр.

**Профили Dolphin Anty** (мобильные приватные прокси, у владельца):
`829115286`, `829115353`, `829115344`, `829115332`. В части профилей выполнен вход в hh
и B2B-Center.

### Ловушка окружения: на сервере два Python

Служба раннера запущена интерпретатором **`C:\Program Files\Python312\python.exe`**
(проверять `nssm get rusprom-runner Application`), а `python.exe` из PATH — это **3.11**.

Из-за этого установка модуля через `& "C:\Program Files\Python311\python.exe" -m pip install …`
проходит успешно, в консоли всё работает, а задача раннера **молча не видит библиотеку**.
Так потерян час на `smtp_probe`: `dnspython` встал в 3.11, задача крутилась на 3.12 и
отдавала «MX не найден» даже для `yandex.ru`.

**Любую установку модулей делать в `Python312`.** Диагностика — сравнить
`nssm get rusprom-runner Application` с тем, куда ставил pip.

### Провайдерский API

`seo-texts/gen_provider.py` (`make_client`, `call`), модель `claude-fable-5`. Правило
владельца: тяжёлую генерацию гонять через него, квоту беречь. Контекст про шлюз — в
корневом `CLAUDE.md`, читать перед использованием.

## 5. Ловушки, на которых эта сессия ошибалась (повторять не надо)

**В8 — «ноль результатов» почти всегда своя ошибка, а не пустой источник.** Пять случаев
за сессию, каждый по своей причине:

| Что дало ноль | Настоящая причина |
|---|---|
| Фабрикант «403» | неверный адрес; рабочий — `/procedure/search?query=` |
| Росэлторг «не отвечает» | отсечка датацентровых IP; открывается через Dolphin |
| ТЭК-Торг «пусто» | искал слово «найдено», страница пишет «893 закупки найдены» |
| Вебархив «7 → 0 ФИО» | новая вёрстка разносит ФИО по ячейкам таблицы |
| ТЗ Коршуновского ГОКа «пусто» | документ отсканирован, текстовый слой — 1 символ |
| Сбербанк-АСТ «0 компрессоров» | HTML упёрся в `html_cap`, страница весит 2 МБ |

**Правило: перед выводом «источник пустой» проверить, что запрос вообще применился** —
искомое слово есть в тексте, счётчик найден, длина HTML не равна лимиту.

Прочие ловушки — В1–В9 в `SPOSOBY-POISKA.md`. Особо: телефоны участников закупки в тексте
протокола (не заказчика), сдвиг привязки ФИО↔должность при парсинге таблиц, кодировка
windows-1251 в старых снимках вебархива, куки-баннер, прячущий контент.

**Не начато:**
- официальные PDF-каталоги выставок (веб-списки проверены — пусто);
- региональные малые закупки за пределами Портала поставщиков Москвы;

  содержательнее — вся выборка по газетам была из холдингов.

**Измерено частично:**
- доля кадровых агентств среди 422 работодателей hh: по названию 3 (0,7 %), по признаку
  «2+ инженерных роли» 48 (11,4 %). Настоящая доля не измерена — оба признака косвенные;
- доля шума в патентной выдаче по заявителю — не измерена (`assignee:` для русских юрлиц

  потому что **в выгрузке hh нет ИНН** — это надо чинить.

**Не проверено ни разу:** ни один собранный телефон не набран, ни один адрес не проверен
отправкой. Всё, что есть, — данные с экрана.

## 8. Как разговаривать с владельцем

Он проверяет утверждения руками и присылает скриншоты. За сессию он опроверг четыре моих
вывода, и все четыре раза был прав. Практические следствия:

- **не объявлять источник мёртвым по одной попытке** — сначала показать ему адрес, который
  пробовал, и спросить, что видно у него;
- **выборка из одного примера не принимается** — он прямо требует 3–5 наблюдений;
- **цифры называть с указанием фильтра**, иначе 994 и 6 298 выглядят противоречием;
- ошибки исправлять прямо в документах, не заметая: он читает коммиты.
