### 10.2. КЛЮЧ ДЕДУПА ФАКТА ИЗМЕНЁН — находка 2-й сессии

```
было:  inn + tip + marka + model + data
стало: inn + tip + marka + model + zavodskoy_nomer + data
+ zavodskoy_nomer TEXT      + srok_do TEXT
```

Довод 2-й: заводской номер — единственный ключ, отличающий машину от такой же соседней, и
ни один другой источник его не даёт. Без него **два одинаковых компрессора на одном заводе
схлопывались бы в один факт**, а это две машины и две продажи.

`srok_do` («действует до» из заключения ЭПБ) в прошлом = ресурс выработан. Заносится в
раздел 5.1 как признак ранга **D+**, выше «класса машины без модели»: срок датирован
документом, класс — догадка по типу.

### 10.5. КРИТИЧЕСКИЙ РИСК — подтверждён 1-й, проверка обязательна ДО вливания

В ЭПБ **две колонки ИНН**: `inn` (завод) и `inn_eo` (экспертная организация). Склейка по

**Дороже, чем `master.equipment`:** тот виден сразу, 161 тысяча строк одного вида. Этот
постфактум почти неотличим. Проверка в одну строку SQL:
`count(distinct inn)` против `count(distinct inn_eo)` на всех 20 870 строках.
