# Линза: Доказательство и датировка связки человек-компания

_Сгенерировано claude-fable-5 через провайдерский эндпоинт. Это идеи модели, а не проверенные факты._

---

## Иерархия доказательств привязки человек-компания

**Уровень 1 (сильнейшее доказательство):**
- Корпоративный email на домене компании (i.ivanov@zavod.ru) — человек физически имеет доступ к инфраструктуре работодателя
- Подпись под официальным документом (договор, техзадание, письмо на бланке) — юридически значимое действие от лица компании
- Прямое заявление в профиле или резюме с указанием "работаю сейчас" — самоидентификация

**Уровень 2 (сильное):**
- Упоминание в корпоративной новости/пресс-релизе компании с указанием должности
- Запись в профессиональных реестрах СРО (проектировщики, энергетики), где работодатель — обязательное поле
- Участие в тендере как представитель компании (данные в zakupki.gov.ru)
- Контакт на официальном сайте компании в разделе "Контакты" или "Руководство"

**Уровень 3 (среднее):**
- Упоминание третьей стороной (отраслевое СМИ, партнёр, клиент) — "главный энергетик Иванов из Завода N"
- Активность в профессиональных сообществах/форумах с указанием места работы
- Участие в отраслевых мероприятиях как представитель компании (список участников конференции)

**Уровень 4 (слабое):**
- Косвенные признаки: геолокация постов + специализация компании + должность в профиле без названия компании
- Связь через общих контактов в соцсетях (коллеги из той же компании в друзьях)

## Датировка и срок жизни привязки

**Обязательные временные метки:**
- `observed_at` — когда доказательство получено (дата парсинга, скачивания, получения письма)
- `published_at` — когда источник опубликовал информацию (дата новости, дата обновления профиля, дата документа)
- `valid_from` — с какого момента привязка действует (из текста: "работает с 2023 года")

**Типовые сроки актуальности по ролям:**
- Главный инженер/энергетик крупного завода: 3-5 лет (высокая инертность)
- Главный механик среднего предприятия: 2-3 года
- Начальник цеха/участка: 1-2 года (чаще ротация)
- Снабженец: 1-1,5 года (высокая текучесть)
- Технический директор: 4-7 лет (топ-менеджмент)

Без даты наблюдения запись превращается в археологию. Привязка от 2019 года в 2025-м — скорее мусор, чем актив.

## Сигналы разрыва привязки

**Прямые:**
- Автоответ "не работаю в компании с DD.MM.YYYY"
- Hard bounce корпоративной почты (5.1.1 User unknown)
- Резюме человека на hh.ru/Superjob с пометкой "ищу работу" (особенно если указан период работы в компании, который закончен)
- Появление другого человека в той же роли в новостях компании

**Косвенные:**
- Человек появился в составе руководства другой компании
- Запись в реестре СРО обновлена, работодатель изменён
- Профиль ВКонтакте/Telegram изменил место работы

## Защита от ложных срабатываний

**Проблема однофамильцев:**
- Сопоставлять ФИО + отрасль/регион + диапазон возраста (по дате рождения или косвенно)
- Для распространённых фамилий требовать минимум 2 независимых источника
- При наличии отчества использовать его обязательно
- Если в одной компании два Иванова И.И., обогащать дополнительными атрибутами (фото, образование, стаж)

**Правило комбинирования противоречий:**
Если источник А (дата 2025-01-15) говорит "работает в Заводе X", а источник Б (дата 2025-01-10) — "работает в Заводе Y", побеждает более свежий с более сильным уровнем доказательства. При равном уровне — более свежий. Старую привязку помечать `status: outdated`, не удалять (история полезна для понимания карьерного пути).

## Дешёвая периодическая перепроверка

**Автоматизируемые проверки без рассылки:**
1. **Мониторинг корпоративных новостей** (RSS компании, Google Alerts по "Имя + Компания") — трудоёмкость 1-2 часа/неделю на настройку, далее автоматика
2. **Парсинг обновлений zakupki.gov.ru** — API доступен, можно отслеживать контактные лица в заявках. НЕ ПРОВЕРЕНО: лимиты API
3. **Проверка корпоративной почты через SMTP VRFY** (если сервер разрешает) — технически 1 запрос = 1 сек, но многие серверы запрещают
4. **Мониторинг hh.ru/Superjob на появление резюме** — можно через RSS поиска "главный энергетик + город", НЕ ПРОВЕРЕНО: стабильность RSS у hh.ru
5. **Отслеживание изменений реестров СРО** — ежеквартальная выгрузка, сравнение дифа

**Периодичность:**
- Топ-100 самых ценных контактов: ежемесячно
- Остальная база: ежеквартально
- Контакты, по которым была активность (клик, ответ): еженедельно

## Структура записи привязки

```
person_company_link:
  person_id: uuid
  company_inn: string
  role: string  # "главный энергетик", "технический директор"
  
  proof_level: int  # 1-4 по иерархии выше
  proof_type: enum  # corporate_email | official_document | self_declared | 
                    # company_news | registry | tender | third_party | indirect
  proof_source: string  # URL, название документа, ID записи в реестре
  proof_artifact: blob  # скриншот, PDF, JSON ответа API
  
  observed_at: datetime  # когда мы получили доказательство
  published_at: datetime  # когда источник опубликовал (если известно)
  valid_from: date  # с какой даты работает (если известно)
  
  status: enum  # active | outdated | needs_verification | conflicted
  confidence: float  # 0-1, вычисляется по proof_level + возрасту + количеству подтверждений
  
  last_verified_at: datetime  # последняя перепроверка
  next_verification_due: datetime  # когда проверять следующий раз
  
  contacts:
    corporate_email: string
    corporate_phone: string
    
  meta:
    source_campaign: string  # откуда привязка попала (обзвон, парсинг, обогащение)
    operator_confirmed: boolean  # подтверждена ли оператором вручную
    notes: text
```

## 3 самые сильные идеи этой линзы

**1. Многоуровневая система доказательств с весами**
Превращает размытое "вроде там работает" в измеримую метрику надёжности. Позволяет автоматически приоритизировать: контакт с корпоративной почтой (уровень 1) + подтверждением в новости (уровень 2) стоит 10 звонков по контактам уровня 4. Прямо влияет на конверсию рассылки — меньше писем в никуда.

**2. Обязательная датировка и автоматический lifecycle**
База без дат — это свалка. С датами можно построить конвейер: свежая привязка → горячий лид, 6 месяцев → тёплый (перепроверить), 18 месяцев → холодный (требует обогащения), 3 года → архив. Экономит время на выбрасывание мёртвых контактов и фокусирует усилия на актуальных.

**3. Дешёвая перепроверка через публичные источники**
Новости компаний, zakupki.gov.ru, реестры СРО, hh.ru RSS — всё бесплатно и парсится. Один раз настроить мониторинг (2-3 дня работы) — получить постоянный поток обновлений. Для команды из одного человека это единственный способ держать базу живой без армии операторов.

## Чего эта линза не видит

**1. Неформальных влиятелей**
Официально — начальник отдела, фактически решает его зам или главный специалист. Привязка по должности видит только формальную иерархию, не видит реальных decision makers.

**2. Изменение полномочий внутри той же роли**
Человек остался главным энергетиком, но после реорганизации потерял бюджет на закупки, и теперь решает технический директор. Привязка "актуальна", но бесполезна.

**3. Временно исполняющих обязанности**
"И.о. главного механика" в новости — это привязка на 2-3 месяца, но источник не маркирует её как временную. Линза датировки фиксирует момент, но не ловит специфику статуса.

**4. Закрытые предприятия оборонки и инфраструктуры**
Нет новостей, нет сайта, в тендерах — номер через коммутатор. Публичных доказательств привязки просто не существует, вся информация внутри периметра.

**5. Холдинговые структуры**
Иванов числится в "ООО Завод", но заказ размещает централизованная закупка холдинга через "ООО Управляющая компания". Привязка технически верна, но не та сущность для коммерческой работы.
