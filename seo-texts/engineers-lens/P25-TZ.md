# P25 · ПОКУПАТЕЛИ 2025 → ЛПР → база user3. Рабочее ТЗ

Приложение с обоснованиями каждого правила: **`P25-TZ-PRILOZHENIE-otkuda-pravila.md`**.
Общие правила обеих задач: **`PRAVILA-OBSHCHIE.md`** — соблюдать целиком, в этом файле они
не повторяются.

## Задача

Книга продаж 2025: **491 ИНН, 2 045 операций, 2,69 млрд ₽** — это наши покупатели. По каждому
достать ЛПР с рабочим контактом и влить в **отдельную базу user3**.

Что уже есть: 43 в центробежной очереди, 35 с людьми, 22 с техническим, **3 с техническим и
личным мобильным**. 456 без единого человека — 89 % суммы.

## Мера и порядок

* **Мера успеха:** технических ЛПР (1–2 круг) с личным мобильным. Снабженцы — отдельной
  строкой отчёта, в главную меру не идут.
* **Порядок предприятий:** строго по сумме покупок. Единственная сортировка. «Есть человек»
  отсекается фильтром панели, вкладок не заводим.
* **Круги ЛПР:** 1) главный инженер, механик, энергетик, техдиректор; 2) начальник цеха,
  производства, главный технолог, АСУ/КИПиА; 3) закупки и МТО; 4) руководство — только если
  выше никого.
* **Роль ставится по ПОДРАЗДЕЛЕНИЮ, а не по слову в должности.**
* **Предприятие закрыто,** когда есть либо технический с личным мобильным, либо доказанное
  отсутствие: шесть площадок и сайт пройдены, ссылки на пустые ответы сохранены.

## Первоисточник — условие приёмки

1. Три источника — **три отдельные ссылки**, каждая кликабельна. Нужна таблица наблюдений
   `contact_source(inn, contact_value, person, source, source_url, date_observed, quote)`,
   завести **до первой строки данных**.
2. **Дата принадлежит наблюдению, а не номеру.** Один номер, найденный в 2019 и подтверждённый
   в 2025 — две строки.
3. **Для контактного лица закупки дата наблюдения = дата процедуры.** Это полноценная свежая
   строка, а не «дата не определена».
4. Форма ссылки проверяется **без сети**; запросом — **по одному образцу на каждый шаблон
   адреса**. Каждую ссылку сетью не гоняем.
5. Ссылка ведёт туда, **где видно имя** (на вложение, а не на страницу закупки).
6. Подтверждение должности **старше двух лет** — не звонить как действующему, перепроверить.
7. Личные номера — только из открытого источника и всегда со ссылкой.
8. **Повод для звонка из реестра проверок брать нельзя.**

## Кто что делает

**1-я сессия — база и приёмка.**
1. **Второй экземпляр службы** со своей парой файлов баз (не признак задачи: `assign_new`
   раздаёт любой новый ИНН по кругу между всеми продавцами).
2. Таблица наблюдений (см. выше) — до первой заливки.
3. **Точка записи называется одной строкой в журнал до первой заливки** — куда именно пишем.
4. Все 491 назначить на user3. Сумму покупок положить **колонкой** в карточку.
5. DaData → ОГРН → чеко по ОГРН. Ликвидированные помечать, не выбрасывать; искать
   правопреемника по ЕГРЮЛ, адресу и руководителю.
6. **Ключ сшивки выдаёт 1-я сессия:** человек = ИНН + фамилия + инициалы (нормализованные),
   контакт = ИНН + 10 цифр номера.
7. Ответственная за свод: отвечает на вопрос, почему в итоге такое число.

**2-я сессия — площадки и сайты.**
8. Обход по ИНН: ЭТП ГПБ, Росэлторг, ТЭК-Торг, Портал Москвы, РТС, Сбербанк-АСТ. Порядок — по
   сумме покупок. Отдача по личным мобильным: ЭТП ГПБ 16 %, Росэлторг 7 %, Портал 4 %.
9. Контактные лица с карточек закупок: ФИО, телефон, почта, предмет, ссылка, дата процедуры.
10. Сайты — шесть методов (см. ниже).
11. **Первую двадцатку по сумме отрабатываю вручную и до конца**, одновременно с машинным
    проходом по остальным.

**3-я сессия — обратный ход.**
12. Поиск номера по ФИО для всех без личного мобильного. Яндекс первым, Google запасным.
    Отдача 3 %. **Ёмкость канала: 10 потоков Яндекс + 10 Google = 1 200 запросов в час.**
    Исключений по «уже есть номер» нет — ищем всех заново.
13. Перед большим прогоном — строка в журнал «беру канал на N минут»: пулы общие на три сессии.
14. Общий номер — три слоя: решает фамилия (не строка целиком), не число ИНН, и отдельный
    признак для номеров из реквизитов, где фамилии нет.
15. **Возврат добытого файлом сразу**, а не в конце смены.

## Шесть методов по сайту предприятия

1. **Найти страницы по карте, а не угадывать пути.** Порядок: `robots.txt` → строка
   `Sitemap:` → карта (в т.ч. `.gz`) → `sitemap_index` → меню главной → перебор путей.
   У заводов на «Битриксе» карта часто только про товары — там меню надёжнее. Фильтр адреса:
   `contact|kontakt|struktur|podrazdelen|rukovod|management|team|about|upravlen|otdel|sluzhb|personal|sotrudnik`.
   Потолок и лог «взято N из M» обязательны.
2. **Разбор страницы ОТ ФИО** (не от почты): ФИО строкой, под ней должность, под ней телефон;
   заголовок подразделения запоминается сверху; следующий ФИО обрывает блок. На Каустике —
   14 человек, 14 прямых номеров.
3. **Запрос «предприятие + должность»** в кавычках, название из ЕГРЮЛ и с сайта.
   **Отдача не замерена никем — первым делом замер на 20 предприятиях**, потом планирование.
4. **Новости о назначениях** — самый свежий источник должности. **Только с заслоном
   принадлежности страницы:** хост = сайт предприятия, либо имя предприятия в адресе, либо
   предприятие названо в тексте, либо это карточка закупки. Закупочные площадки — исключение,
   они не «чужие страницы».
5. **Раскрытие и отчётность:** e-disclosure, годовой отчёт, состав закупочной комиссии.
6. **Разбор провайдером** — со списком ссылок и обязательной цитатой. Принимается только
   строка, чья цитата найдена в тексте **после нормализации обеих сторон** (пробелы, ё→е,
   регистр, мягкие переносы, ноль-ширинные). Цитата содержит **фамилию И номер**; сам номер
   проверяется отдельно поиском в тексте. Роль и среду провайдер не решает.

## Сбор с нуля, сверка — последним шагом

Ничего из центробежной базы не переносим: копия затащила бы наши старые ошибки. Сверка в
конце даёт два результата — ускорение дозвона и **поиск ошибок по расхождению** двух
независимых замеров. Сверять по **фамилии внутри ИНН**; расхождение не разрешать автоматически,
оставлять обе записи с обеими ссылками.

## Приёмка и отчёт

* Каждые **50 закрытых предприятий** — 15 **случайных** карточек глазами: чего нет в панели,
  но есть у нас; что записано с ошибкой; где первоисточник говорит другое; мусор. Результат
  числом в журнал, даже нулевой.
* Отчёт раз в смену **тремя колонками состава**: личный мобильный / городской с именем /
  общий без имени. Плюс закрыто предприятий и по какому условию.
* Результат каждого прогона пишется **на сервер и в `.jsonl` с fsync**, не только в песочницу.
* Сторож — 25 минут, шесть проверок, требует **число из базы, а не слово**.
