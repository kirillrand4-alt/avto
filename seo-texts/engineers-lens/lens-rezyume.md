# Линза: Рынок труда и профессиональные сети

_Сгенерировано claude-fable-5 через провайдерский эндпоинт. Это идеи модели, а не проверенные факты._

---

## HeadHunter и API

**HH.ru** — крупнейший источник. API публичный (api.hh.ru, документация hh.github.io/api), OAuth 2.0. Без авторизации отдаёт список вакансий с фильтрами по городу, специализации, дате публикации. Каждая вакансия содержит название компании, адрес, иногда ИНН работодателя. Резюме соискателей через публичный API **недоступны** — требуется работодательский аккаунт с оплаченным доступом к базе резюме (НЕ ПРОВЕРЕНО: от 50 тыс. руб./мес., зависит от региона и пакета).

**Легальная схема через вакансии**: собираешь свежие вакансии «главный энергетик», «главный механик», «инженер-проектировщик промышленных объектов», «начальник компрессорной станции». Название компании + город + должность = триггер для обновления записи в твоей базе. Если год назад в базе был Иванов на заводе X главным энергетиком, а сейчас X публикует вакансию главного энергетика, то Иванов скорее всего уже не там. Вакансия не даёт ФИО нового человека, но даёт сигнал для проверки контакта и поиска через другие каналы (корпоративный сайт, соцсети).

Объём: ~200–300 релевантных вакансий по промышленному оборудованию ежедневно по России. Автоматизация через API тривиальна. Данные протухают быстро (вакансии закрываются за 1-3 месяца), но триггер актуален именно когда свежий.

**SuperJob** (api.superjob.ru) — аналогично HH, меньше покрытие промышленного сектора. API требует регистрации приложения, резюме закрыты без работодательского доступа. Стоимость доступа к базе резюме (НЕ ПРОВЕРЕНО: сопоставима с HH). Вакансии доступны, логика триггера та же.

## Работа.ру и Хабр Карьера

**Работа.ру** (zarplata.ru, rabota.ru) — третий по размеру. API слабо документирован или отсутствует публично (НЕ ПРОВЕРЕНО). Вакансии доступны через веб-интерфейс, можно парсить. Промышленных вакансий меньше, чем на HH. Трудоёмкость: средняя, если делать парсер вместо API.

**Хабр Карьера** (career.habr.com) — IT-фокус, для промышленных инженеров-механиков почти бесполезен. Может дать проектировщиков АСУ ТП, инженеров-программистов промышленной автоматизации, но не главных энергетиков. Объём для твоей ниши: 10-20 релевантных вакансий. API есть (НЕ ПРОВЕРЕНО: требует токен). Низкий приоритет.

## Telegram-каналы и чаты

Профильные каналы по промышленной автоматизации, энергетике, эксплуатации: поиск через tgstat.ru, telemetr.me. Примеры тематик: «Энергетика России», «Главные энергетики», «Промышленная автоматика», «Компрессорщики». Участники часто указывают должность и предприятие в bio Telegram-аккаунта или в подписях к сообщениям.

**Как собирать**: вступить в 20-30 крупных чатов (1000+ участников), выгрузить список участников (возможно через Telegram API при наличии прав администратора чата или через сторонние сервисы парсинга, юридический статус серый — формально Telegram не запрещает, но условия использования ограничивают массовый сбор). Из каждого чата 10-50 человек с релевантными должностями в профиле. Итого 200-1500 контактов за подход. Данные протухают медленно (люди редко обновляют bio), но покрытие неполное — не все инженеры сидят в Telegram-чатах.

**Юридический статус**: ФИО + должность + город из публичного профиля Telegram не являются персональными данными, если человек сам их опубликовал открыто. Рассылка в личку Telegram без согласия — нарушение ФЗ-38 и может трактоваться как спам. Данные годятся для пополнения базы, но не для прямого контакта без согласия.

Трудоёмкость: 2-4 дня на поиск чатов, вступление, выгрузку, ручную фильтрацию. Повторять раз в квартал.

## Отраслевые форумы

Форумы по промышленности, энергетике, компрессорам: **energoboard.ru** (энергетика), **forum.abok.ru** (вентиляция, кондиционирование, смежно с компрессорами), **elec.ru/forum** (электрооборудование). Пользователи регистрируются с подписью вида «Иван Петров, главный энергетик, завод "Заря", Самара».

**Как собирать**: парсинг профилей пользователей и сообщений с подписями. Объём: 500-2000 активных пользователей на крупном форуме, из них 50-200 с релевантной подписью. Данные протухают медленно (подписи обновляются редко), но активные участники форума = люди с высокой экспертизой, хороший таргет.

**Юридический статус**: публичные данные, допустимо собирать. Трудоёмкость: 1-2 дня на написание парсера для одного форума, затем 1 час на форум при повторном запуске.

## Сообщества ВКонтакте

Группы «Энергетики России», «Главные механики», «Промышленность и производство». Участники 10-100 тыс. человек. Часть подписчиков указывают текущее место работы в профиле ВК.

**VK API** (dev.vk.com): доступ к публичной информации о пользователях (имя, город, место работы) через methods.users.get, но требует токен приложения и соблюдения лимитов (3 запроса/сек). Место работы в API-ответе есть, если пользователь заполнил и сделал публичным. Покрытие: из 50 тыс. участников группы реально заполненное место работы у 5-10%, то есть 2500-5000 записей. Из них релевантных 10-20%, итого 250-1000 контактов на крупную группу.

Трудоёмкость: 1 день на написание скрипта, затем автоматизация. Данные протухают медленно (люди обновляют профиль раз в год-два). Юридически: публичные данные, сбор допустим. Рассылка в личку ВК без согласия — спам, нарушение ФЗ-38.

## Обратный сигнал: вакансии как триггер устаревания

Логика: компания публикует вакансию «главный энергетик» → предыдущий главный энергетик либо уволился, либо повысился, либо на пенсию. Твоя база содержит контакт человека на этом предприятии → нужно проверить актуальность. Если контакт утратил актуальность, нужно найти нового через:

- Корпоративный сайт предприятия (раздел «Руководство», иногда есть ФИО главного энергетика).
- Поиск «главный энергетик завод X» в Яндексе — может дать упоминания в новостях, презентациях, статьях.
- Звонок на предприятие в общий отдел (законно, публичная информация).

Вакансия не даёт ФИО нового человека напрямую, но превращается в сигнал для обновления записи. Автоматизация: ежедневный парсинг вакансий → сопоставление названия компании с базой → флаг «требует проверки».

Объём триггеров: 50-100 релевантных вакансий/неделю по России. Трудоёмкость: автоматизация 1 день, затем 1 час/неделю на ручную проверку флагов.

## Реестры СРО и профессиональных ассоциаций

**НЕ ПРОВЕРЕНО**: Ассоциация инженеров энергетиков, Российское теплоэнергетическое общество, СРО проектировщиков. Реестры членов иногда публикуются на сайтах (ФИО, организация, город). Объём: сотни-тысячи записей, но не всегда с актуальным местом работы. Данные протухают медленно. Доступ: публичные сайты, иногда требуется регистрация.

Трудоёмкость: 1-2 дня на поиск реестров и выгрузку. Приоритет средний, так как покрытие неполное.

## 3 самые сильные идеи этой линзы

1. **Вакансии HH/SuperJob как триггер обновления базы**. Даёт не новые контакты, а сигнал актуальности существующих. Автоматизируется через API, покрытие по всей России, юридически чисто. Связывает динамику рынка труда с актуальностью твоей базы. Ежедневно 200+ триггеров, обработка 1 час/неделю после автоматизации.

2. **Telegram-чаты профильные**. Живые люди, часто указывают должность и предприятие. 200-1500 контактов за подход, данные свежие (кто активен в чате, тот и работает). Юридически серая зона по методу сбора, но сами данные публичные. Повторяемость раз в квартал. Высокая релевантность — люди в чате по компрессорам сами относятся к целевой аудитории.

3. **Отраслевые форумы с подписями**. Эксперты с высокой вовлечённостью, часто принимают решения. Подпись «главный энергетик, завод X» = готовый лид. 50-200 релевантных контактов на форум, 3-5 крупных форумов. Парсинг автоматизируется, повторять раз в полгода. Юридически безопасно.

## Чего эта линза не видит

- **Закрытые корпоративные контуры**. Инженеры крупных холдингов не сидят на HH и редко на форумах. Их контакты живут внутри корпоративных справочников.
- **Людей без цифрового следа**. Главный энергетик завода в глубинке, который не пользуется соцсетями и форумами, невидим для этой линзы.
- **Актуальность ФИО без места работы**. Вакансии дают триггер, но не дают нового ФИО. Нужна дополнительная работа (звонок, поиск на сайте).
- **Легальность прямого контакта**. Собрать данные можно, но рассылка без согласия = нарушение ФЗ-38. Линза даёт базу для дальнейшего обогащения (поиск email, телефона, запрос согласия), но не готовые контакты для холодной рассылки.
- **Промышленные гиганты с текучкой**. На крупных предприятиях инженеры меняются часто, но публичных следов мало. Вакансия есть, а кто пришёл — неизвестно без внутреннего источника.
