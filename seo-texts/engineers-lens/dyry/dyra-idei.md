# Находки по классам ошибок

## Критичные: могут сделать собранные данные неверными

### 1. Идея 1: "291 обозначение Невского завода"

**Цитата:** "точность вместо охвата: «К-1500-62-2» — гарантированно воздушный турбокомпрессор"

**Класс:** 2 (подсказка из промпта)

**Проблема:** В разделе "Часть 3" записано: "в промпте классификатора было сказано, что серии К- и Н- Невского завода воздушные. Подсказка оказалась неверной — серия Н газовая, 17 из 20". Откуда гарантия про К-1500-62-2? Если из того же промпта — все 291 обозначения под вопросом.

**Проверка:** Взять 20 случайных марок из 291, найти в каталогах Невского завода или патентах независимое описание среды. Сравнить с классификацией.

### 2. Идея 5: "ИНН в выгрузку hh через DaData"

**Цитата:** "ИНН у 295 из 422 через DaData (suggest/party, токен в ключнице, из песочницы открыто)"

**Класс:** 4 (нерепрезентативная выборка) + новый класс "сервис подсказок вместо реестра"

**Проблема:** DaData suggest/party возвращает самое похожее по названию, не гарантируя точность. Это не ЕГРЮЛ. Пересечение "12 с нашими 543" может содержать ложные срабатывания — тот же класс, что давал "пивзавод против водоканала" (цитата идея 3).

**Проверка:** Взять 30 строк с самым низким score от DaData, сверить названия с выпиской ЕГРЮЛ по полученному ИНН. Посчитать долю несовпадений.

### 3. Идея 29: "Порог --min-len 6 подобран на глаз"

**Цитата:** "Порог --min-len 6 подобран на глаз"

**Класс:** 6 (порог по краю)

**Проблема:** "«К-100-61-1» дал 369 заключений у 62 предприятий — короткая марка работает как широкий запрос". Произвольный порог режет данные без обоснования.

**Проверка:** Построить гистограмму длин обозначений vs число найденных заключений. Найти точку перегиба, где короткие марки начинают давать шум. Проверить 10 самых частых марок длиной 5-7 символов — реальные или мусор.

### 4. Идея 64: "570 предприятий из процессных терминов признаны шумом"

**Цитата:** "570 предприятий из процессных терминов... признаны шумом по признаку «машина не названа в тексте». Другим способом наличие компрессора у них не проверялось"

**Проблема:** "По признаку «машина не названа в тексте» из epb-processy.csv выброшены 43 живых записи Росэнергоатома с названными марками (305ВП-16/70, 7ВП-20/220), у 43 из 46 стоит «подтверждено текстом»".

**Класс:** 3 (замер сломанным инструментом) + новый класс "отбор по косвенному признаку выбросил целевые данные"

**Проверка:** Взять epb-processy.csv, найти все записи со статусом "подтверждено текстом" или где длина текста заключения >200 символов. Пересечь с выброшенными 570. Посчитать, сколько целевых предприятий потеряно.

## Важные: могут не собрать данные

### 5. Идея 38: "Патенты по заявителю — упёрлось в HTTP 503"

**Цитата:** "упёрлось в HTTP 503 Google Patents; нули по шести компаниям недостоверны"

**Класс:** 1 (неправильный объект) + 3 (сломанный инструмент)

**Проверка:** Зайти на fips.ru → "Поиск" → "Изобретения и полезные модели" → поиск по заявителю. Проверить те же 6 компаний. Если найдены патенты — источник работает, вывод неверен.

### 6. Идея 23: "Декларации ПБ публикуются редко"

**Цитата:** "обход 7 предприятий из наших списков, 24 страницы разделов промбезопасности/экологии/раскрытия со ненулевым счётчиком «безопасн» — ноль деклараций"

**Класс:** 4 (нерепрезентативная выборка)

**Проблема:** 7 из 347 = 2%. Топ по выручке публикует больше, чем средние.

**Проверка:** Взять топ-50 по выручке из своей базы 347, проверить наличие деклараций на сайтах. Посчитать долю. Если >10% — вывод "редко" неверен.

### 7. Идея 67: "Мосводоканал отсутствует в списке 683"

**Цитата:** "АО «Мосводоканал» (ИНН 7701984274) отсутствует в списке 683 водоканалов... Сколько ещё крупных операторов пропущено — не измерено"

**Класс:** 4 (нерепрезентативная выборка) + новый класс "пропуск крупных игроков"

**Проблема:** Если Мосводоканал пропущен, выборка по ОКВЭД 36/37 неполна. Холдинги могли иметь другой основной ОКВЭД.
