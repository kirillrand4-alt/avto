# Массовый прогон обогащения (xmlriver → сайт → контакты)

**Запущено:** 2026-07-21, автономно. Финальная задача владельца: «ставь xmlriver на поиск
сайтов + выгрузку контактов по всей базе без сайта + новостным компаниям».

## Что делает
Для каждой компании БЕЗ сайта (126 642 из 161 761): xmlriver находит официальный сайт
(knowledge-graph карточка Яндекса → органика, фильтр агрегаторов) → краул главной + страниц
контактов → извлечение email с ролями (mailto/JSON-LD/деобфускация + провайдер на текст) →
MX-проверка. **По убыванию выручки** (лучшие лиды первыми). Резюмируемо.

## Как устроено (САМОЧЕЙНИНГ — не зависит от песочницы)
Песочница реапит любые фон-процессы → драйвер в песочнице ненадёжен. Поэтому прогон
**самоперпетуируется на сервере**:
- Задание `enrich_contacts` с `chain:true` в НАЧАЛЕ обработки пишет СЛЕДУЮЩИЙ подписанный
  job на дроп (`job-<ts>-chain<pid>.json`). Раннер серийный → преемник запускается после
  текущего чанка, его done-set уже включает сделанные ИНН.
- **Резюмируемость:** done-set из `enrich_stream_mass.jsonl`, дублей нет. Данные на сервере.
- **Стоп-кран:** положить файл `mass_stop.flag` на дроп (`drop_client.sh up`) → следующий чанк
  не зачейнит → цепочка завершится. Либо пул опустеет (чанк обработает 0 → стоп).
- Пишется в начале чанка → переживает таймаут раннера (1800с): даже если чанк убьют,
  преемник уже в очереди.

## Параметры текущего запуска (самочейнинг)
Стартовый job: `{mass_base:true, chain:true, cap:150, workers:20, channels:12,
no_browser:true, no_fallback:true, pace 0.4-1.2, stream_file:enrich_stream_mass.jsonl}`.
cap=150/чанк, workers=20 (прячет медленные сайты), channels=12 (безопасно, 0 ошибок каналов).

## Как ПЕРЕЗАПУСТИТЬ, если цепочка прервалась (сервер рестартнул на середине чанка)
Цепочка рвётся ТОЛЬКО если сервер упал ровно в момент между чанками. Проверить и
перезапустить одним заданием:
```bash
cd /home/user/avto/seo-texts/server
python3 -c "import run_on_server as R; R._load_secret_from_drop(); print(R.submit('enrich_contacts', {'mass_base':True,'chain':True,'no_site':True,'cap':150,'workers':20,'channels':12,'no_fallback':True,'no_browser':True,'pace_min':0.4,'pace_max':1.2,'stream_file':'enrich_stream_mass.jsonl','source':'mass','write_db':True}, wait=False))"
```
done-set пропустит сделанное. Проверка живости цепочки: на дропе есть `job-*-chain*.json`.

## Скорость / масштаб / стоимость (честно)
- Пропускная способность ~0.10 компании/сек (xmlriver делает реальный Яндекс-SERP, ~медленно).
- Вся база без сайта (126.6k) ≈ **~14 дней** непрерывного прогона. НО лучшие (высоковыручные)
  лиды готовы в первые 1-2 дня — дальше «хвост» мелких компаний с падающим выходом (много
  «сайт не найден», т.к. у микрокомпаний нет сайта).
- **xmlriver платный** (запрос ≈ копейки, но 126k запросов — заметная сумма; хвост часто = 0
  сайта = потраченный запрос). **Решение владельца:** гнать весь хвост или остановить на
  топ-N по выручке — можно прервать в любой момент (данные сохранены).

## Мониторинг
- `tail seo-texts/server/mass_loop.out` — прогресс пачек (обработано/сайтов/email).
- Итоги на сервере: `enrich_stream_mass.jsonl` + `enrich.db` (op `rebuild` восстанавливает БД).
- Забрать выгрузку: задание `enrich_db` (экспорт) или скачать jsonl (нужен пуш на дроп).

## Новостные компании (вторая часть задачи)

из событий (передать `enrich:true`+`dadata_token` в news_scan, либо отдельным прогоном).
