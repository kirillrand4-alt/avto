# Коллектор Федресурс (fedresurs.ru, ЕФРСФДЮЛ)

Задача 3 из `TZ-RANNEE-SOBYTIE.md`. Код: `collector_fedresurs.py`.
Всё, что ниже, снято живыми запросами с РФ-сервера владельца (внешний IP
91.206.14.169) 16.09.2026 через `run_script_on_server.py`. Коды ответов и куски
тел — настоящие, не по памяти.

---

## 1. Зачем этот источник

У остальных восьми коллекторов `news_scan.py` самое дорогое место — догадаться,
о какой компании новость, и приклеить ИНН через dadata. Здесь этой задачи нет
вовсе: **ИНН лежит внутри сообщения**, потому что юрлицо публикует сведения о
себе по закону (ст. 7.1 129-ФЗ), и в карточке стоят ИНН, ОГРН и полное имя всех
сторон сделки. `inn_conf` сразу `high`, dadata не вызывается — приёмка задачи 3
закрывается этим.

Второе отличие: это не новость. Новость выходит, когда режут ленточку. Лизинг
публикуется в день подписания договора, залог — в день возникновения, лицензия —
до пуска. Это как раз те два-три шага раньше, ради которых писалась ЧАСТЬ 2 ТЗ.

## 2. Что открыто бесплатно, а что нет — честно

### 2.1 Открыто и работает без всякого договора

`https://fedresurs.ru/backend/...` — это JSON-API, которым пользуется сам сайт
(SPA). Он отвечает обычному HTTP-клиенту, без ключей и без регистрации.
Более того, **спецификация опубликована**: `/backend/swagger/v1/swagger.json`
отдаёт 200 и 366 КБ OpenAPI 3.0.1 (`title: "Fedresurs"`, 199 путей). То есть это
не «нашли дырку», а документированный интерфейс, просто не разрекламированный.
(Сам `swagger/index.html` при этом закрыт: 403.)

### 2.2 Что закрыто

| Что | Как проявляется |
|---|---|
| HTML-страницы сайта | `GET https://fedresurs.ru/` -> **401**, `Server: QRATOR`, тело — JS-челлендж `qauth_utm_v2d_v9118.js`. Парсить HTML бессмысленно и не нужно: JSON-ручки при этом отвечают 200 |
| Запрос без `Referer` | **403** от nginx (`403 Forbidden`, тело 548 байт). Referer с домена fedresurs.ru обязателен на каждом запросе |
| `bankrot.fedresurs.ru` | из контейнера — `Connection reset by peer`; с РФ-сервера отвечает, но отдельный старый контур, нам не нужен |

### 2.3 Чего в бесплатном API НЕТ

**Сквозной ленты сообщений ЕФРСФДЮЛ «все сообщения такого-то типа за период» в
API нет.** Это главный вывод разведки, и он определяет всю конструкцию
коллектора. Проверено перебором: сообщения отдаются только в разрезе конкретной
компании — `/backend/companies/{guid}/publications`. Все попытки угадать ленту
(`/backend/sfactmessages`, `/backend/sfacts`, `/backend/messages`,
`/backend/publications`, `/backend/sfact-messages/search`, `/backend/search/*`,
`/backend/licenses/search`, `/backend/reorganizations/search` и ещё два десятка)
дают **404**, и в полном списке из 199 путей OpenAPI такой ручки тоже нет.

Единственная сквозная лента — `/backend/encumbrances` (залог, лизинг, факторинг,
гарантия). Она отвечает 200 и отдаёт свежие сообщения по всей стране. **Но она
прямо запрещена в robots.txt этого сайта** — см. раздел 6.

### 2.4 Что стоит денег

Разделять надо аккуратно, потому что «Федресурс платный» — правда только
наполовину.

| Услуга | Плата | Нам нужна? |
|---|---|---|
| **Чтение** сведений через `/backend/...` (то, что делает коллектор) | бесплатно, договора не требует | да, это наш путь |
| **Публикация** своего сообщения в ЕФРСФДЮЛ | 1 061,76 ₽ за сообщение (тариф оператора 2026, с НДС); банкротные — 530,88 ₽; безлимит для нотариусов — 9 694,8 ₽/мес | нет, мы ничего не публикуем |
| Электронная выписка о размещении сообщения | 115,62 ₽ — **цифра из самого API**: `GET /backend/orders/prices` -> `{"sum":115.62,"type":"SfactMessageDigitalConfirmation"}` (+ комиссия ЮMoney 2,68%) | нет, это юридическая справка о факте публикации |
| Доставка на email | 0,00 ₽ (там же в прайсе) | нет |
| **«Сервис получения сведений»** — официальный договорной API оператора (АО «Интерфакс»): SOAP-веб-сервис для ЕФРСФДЮЛ и REST для ЕФРСБ с 15.04.2024 | заключается договор с АО «Интерфакс»; **публичного прайса нет** — см. ниже | нет, пока хватает открытого |

Про договорной API — что установлено и чего установить не удалось. Оператор
реестра — АО «Интерфакс» (с 2011 года). Спецификации выложены открыто:
`https://fedresurs.ru/helps/bankrupt/Service_rest_1.3.0.pdf` (REST для ЕФРСБ),
`https://fedresurs.ru/helps/Sfacts/Федресурс. Памятка. Сервис получения
сведений.pdf` (ЕФРСФДЮЛ), рядом лежит шаблон договора
`Федресурс.  Договор. Сервис получения сведений.doc`. Порядок подключения:
демо-контур -> тестовое подключение к промышленному -> договор с АО «Интерфакс»
-> работа. **Тарифа в открытом доступе я не нашёл**: ни на сайте, ни в
документах цена не названа, публичной оферты с числом нет. Честный ответ
владельцу: порядок цены назвать не могу, её дают по запросу в
`bhelp@interfax.ru`. Что можно сказать точно — **на текущую задачу платный
доступ не нужен**: всё, что перечислено в ТЗ (лизинг, залоги, лицензии,
реорганизации, увеличение УК, концессии), открытый API отдаёт целиком, включая
предмет лизинга и суммы.

Ориентир для сравнения, если владелец всё же захочет договорной канал: у
соседних коммерческих витрин по тем же данным (СПАРК-Интерфакс) вход считается
десятками тысяч рублей в год. Это НЕ цена API Федресурса, а только рамка
ожиданий — выдавать одно за другое нельзя.

## 3. Точные эндпоинты

База: `https://fedresurs.ru/backend/`. Обязательный заголовок:
`Referer: https://fedresurs.ru/...` (иначе 403). Параметры — **PascalCase**
(`Limit`, `Offset`, `SearchString`, `DateStart`); это не косметика: `limit`/
`publishDateStart` в нижнем регистре ASP.NET примет, а вот `types=` вместо
`Group=` тихо проигнорируется, и покажется, что фильтр не работает.

### 3.1 Рабочая цепочка коллектора

**Шаг 1. ИНН -> guid компании**

```
GET /backend/companies?SearchString=6665002150&Limit=5&Offset=0
Referer: https://fedresurs.ru/search/entity?searchString=6665002150
-> 200 {"found":1,"pageData":[{"guid":"...","ogrn":"1026600930707","inn":"6665002150",
        "name":"АО \"КУМЗ\"","egrulAddress":"...","status":"...","okvedName":"Производство алюминия","isActive":true}]}
```

`SearchString` понимает ИНН, ОГРН и имя (`КУМЗ` -> found 11, `компрессор` -> found
337 — ищет по названию). **По ОКВЭД не ищет**: `SearchString=28.13` -> `found: 0`.
Есть ещё `RegionNumber` и `IsActive`.

**Шаг 2. guid -> сообщения за период** (один запрос на компанию)

```
GET /backend/companies/{guid}/publications?OnlySfact=true
    &DateStart=2026-06-18&DateEnd=2026-09-17&Limit=15&Offset=0
Referer: https://fedresurs.ru/company/{guid}
-> 200 {"found":39,"pageData":[
     {"publicationType":"SfactMessage","guid":"4ac90c3d-...","number":"38015918",
      "datePublish":"2026-07-31T13:28:08.870245","isAnnulled":false,"isLocked":false,
      "type":"Прекращение договора финансовой аренды (лизинга)","participants":[...]}]}
```

Полный набор параметров: `SearchString, DateStart, DateEnd, OnlyPublisher,
OnlySfact, OnlyBankrupt, Group (int), Type (код типа), OnlyReports, ActType,
Limit, Offset`.

Ловушка: в списке `type` — **русское название**, а не код. Код есть только в
карточке. Поэтому коллектор один раз забирает справочник
`/backend/reference-book/message-types` (199 записей `{code,name,project,isOld}`)
и отбирает нужное по названию — иначе пришлось бы либо тянуть карточку каждого
сообщения, либо гонять `&Type=<код>` по всем двум десяткам типов, то есть 20
запросов на компанию вместо одного.

**Шаг 3. карточка сообщения** (только для прошедших отбор)

```
GET /backend/sfact-messages/{guid}
Referer: https://fedresurs.ru/sfactmessages/{guid}
-> 200 {"messageType":"FinancialLeaseContract2","typeName":"Заключение договора...",
        "number":"...","datePublish":"...","publisher":{...},"relatedMessages":[...],
        "content":{...},"docs":[],"isPublisherInSanctionList":true}
```

Живой пример `content` договора лизинга (АО «КУМЗ»):

```json
{"financialLeasePeriod":{"startDate":"2023-12-26T00:00:00","endDate":"2026-12-31T00:00:00"},
 "subjects":[{"identifier":"BTRM023I00052",
              "classifier":{"code":"0106013","description":"Специализированная техника"},
              "description":"Самоходная техника (ПСМ)"}],
 "contractInfo":{"number":"AA027414021","date":"2023-08-04T00:00:00"},
 "lessees":[{"fullName":"ОАО \"КУМЗ\"","inn":"6665002150","ogrn":"1026600930707","type":"Company"}],
 "lessors":[{"fullName":"Сведения скрыты в соответствии с требованиями постановления
              Правительства РФ от 12.01.2018 г. №5","type":"Company"}]}
```

Отсюда коллектор берёт ИНН (готовый!), предмет лизинга и срок. Часть сторон
бывает закрыта постановлением Правительства РФ №5 от 12.01.2018 (санкционная
защита) — тогда вместо имени стоит эта формулировка, а ИНН пуст. Это нормальный
ответ, а не ошибка.

Схема `content` у каждого типа своя, поэтому коллектор не перечисляет поля, а
обходит дерево:

* залог `CreationRightOfPledge2`: `mortgagorCompanies`, `pledgeeCompanies`,
  `pledgeBond`, `subjects[{classifierCode, classifierName, description}]`
  (описание многострочное: «Баржа-кормораздатчик\n2012 год постройки\nмодель...»);
* гарантия `IssueIndependentGuarantee`: `principal`, `beneficiaries`,
  `mainObligationDescription`, **`guaranteeAmount: {amount: 260000000.0,
  currency:{code:"RUB"}}`** — тут сумма есть всегда;
* чистые активы `FirmAssetsValue`: `assetsValue: 10157161079.54`;
* реорганизация `FirmReorganization`: `reorganizationKind`, `dateDecision`,
  `reorganizationCompanies[]` — **со всеми ИНН участников**;
* лицензия `FirmLicenseGranted`: `licenseNumber`, `licenseType`, `dateGranted`,
  `licensingCompany`, `providedServices`;
* лизинг сумму **не содержит** — там срок, предмет и номер договора.

### 3.2 Полезные соседние ручки

| Ручка | Что даёт |
|---|---|
| `GET /backend/companies/{guid}/publication-type-groups` | сводка «что у компании вообще есть» с количествами по типам, одним запросом, но без дат — дешёвый предфильтр |
| `GET /backend/companies/{guid}/encumbrances` | все обременения компании, сгруппированные («Лизинг», «Залог», ...), без фильтра по датам. robots.txt эту ручку НЕ запрещает |
| `GET /backend/companies/{guid}/licenses` / `/reorganizations` / `/networth` | лицензии, реорганизации, чистые активы отдельными витринами |
| `GET /backend/reference-book/message-types` | справочник типов: `{code, name, project, isOld}` |
| `GET /backend/reference-book/encumbrances-groups` | `Pledge, Leasing, ContractOfSale, Factoring, Guarantee, BuyBack, RestrictionOfRightsUnderContract, RightOfItemRetention` |
| `GET /backend/reference-book/regions` | 90 субъектов: `{"code":"22","description":"Алтайский край"}` |
| `GET /backend/orders/prices` | официальный прайс платных выписок |
| `GET /backend/monitorings`, `/backend/monitoring-subscribers/*` | у Федресурса есть собственная подписка-мониторинг по списку компаний (регистрация, логин, уведомления). Не пробовал: требует завести учётку, а это уже не «только чтение». Отдельная возможность на будущее — оператор сам будет присылать события по нашим ИНН |

### 3.3 Сквозная лента обременений (по умолчанию ВЫКЛЮЧЕНА)

```
GET /backend/encumbrances?Group=Leasing&PublishDateStart=2026-08-18
    &PublishDateEnd=2026-09-17&Limit=50&Offset=0
Referer: https://fedresurs.ru/search/encumbrances
-> 200 {"found":10000,"pageData":[
     {"number":"39065011","guid":"...","publishDate":"2026-09-16T13:19:38",
      "type":"StopFinancialLeaseContract2",
      "weakSide":[{"type":"Company","role":"Lessee","name":"ООО \"АНСАР\"",
                   "inn":"7735177303","ogrn":"1187746645680","isHidden":false}],
      "strongSide":[{"role":"Lessor","isHidden":true,"name":"","inn":""}]}]}
```

`weakSide` — лизингополучатель или залогодатель, то есть ровно наш потенциальный
клиент, с готовым ИНН. Технически идеальный источник. Ограничения: `found`
упирается в 10 000, `Offset` больше ~50 даёт **400**, то есть лента читается
только узкими окнами по датам. И главное — она в Disallow (раздел 6).

## 4. Какие типы сообщений полезны нам и почему

Полный справочник — 199 типов, из них 125 банкротных. Ниже — отобранное,
`TIPY_CAPEX` в коде. Колонка «стадия» — шкала задачи 5 ТЗ (1 проект, 2 стройка и
закупка, 3 пуск, 4 действующее/расширение).

### 4.1 Деньги уже превращаются в технику

| Код | Название | Стадия | Почему это наш сигнал |
|---|---|---|---|
| `FinancialLeaseContract2` | Заключение договора финансовой аренды (лизинга) | 2 | Лизингодатель обязан опубликовать договор. В карточке — **предмет** вплоть до модели, и это единственное место, где видно, ЧТО именно компания покупает в долг. Если в предмете «компрессорная установка» — повод написать сегодня |
| `ChangeFinancialLeaseContract2` | Изменение договора лизинга | 2 | досрочный выкуп или добор предметов: парк меняется |
| `CreationRightOfPledge2` | Возникновение права залога | 2 | кредит под залог движимого имущества — станки, линии, транспорт. Деньги взяты под технику, часто одновременно с покупкой |
| `ChangeRightOfPledge2` | Изменение права залога | 2 | перезалог или довнесение предмета — признак новой кредитной сделки |
| `IssueIndependentGuarantee` | Выдача независимой гарантии | 2 | банковская гарантия под исполнение крупного контракта или аванс; **сумма в карточке есть всегда** |
| `FinancingMonetaryRequirement`, `...Client` | Факторинг | 2 | резкий рост оборота: компания не успевает за спросом |
| `ConclusionContractOfSale`, `CreationContractWithRetainOwnershipForSubject` | Договор с сохранением права собственности на товар | 2 | рассрочка на оборудование: техника уже у покупателя, право собственности ещё нет |

### 4.2 Решения о создании и перестройке производств — самая ранняя точка

| Код | Название | Стадия | Почему |
|---|---|---|---|
| `FirmCreated` | Создание юридического лица | 1 | новое юрлицо под проект; оборудование ещё не выбрано вообще |
| `FirmReorganization` | Реорганизация | 1 | выделение или присоединение под новую площадку. В карточке перечислены **все участники с ИНН** — готовый материал и для задачи 4 (доопределение компании) |
| `FirmAuthorizedCapitalIncrease` | Увеличение уставного капитала | 1 | в ООО деньги на стройку заводят именно так. Раньше любой новости |
| `ConclusionConcessionAgreement` | Заключение концессионного соглашения | 1 | инвестиционный договор с публичной стороной: концессионер обязуется **построить** объект. Ранняя стадия с подтверждённым бюджетом — то самое, что ТЗ называет «сведения об инвестиционных договорах» |
| `ChangeConcessionAgreement` | Изменение концессии | 1 | сдвиг условий стройки |
| `FirmAutonomousInstitutionCreation` | Создание автономного учреждения | 1 | бюджетный проект с капвложениями |
| `SaleOrLeaseEnterprise2` | Продажа предприятия или передача в аренду | 4 | сменился хозяин имущественного комплекса — новый почти всегда вкладывается в модернизацию |

### 4.3 Лицензии и разрешения

| Код | Название | Стадия | Почему |
|---|---|---|---|
| `FirmLicenseGranted` | Получение лицензии | 3 | лицензию берут **перед** пуском нового объекта: взрывопожароопасные производства, фарма, пищёвка, обращение с отходами |
| `FirmLicenseReissued` | Переоформление лицензии | 3 | переоформляют, когда появился новый адрес/объект или новый вид работ — то есть открылась площадка |
| `FirmLicenseRenewed` | Продление лицензии | 4 | рутина, держим только для полноты |

### 4.4 Масштаб (в скоринг, не в повод написать)

`FirmAssetsValue` — стоимость чистых активов, единственный тип с гарантированной
суммой. Рост активов год к году = идёт капстройка. `MandatoryAssessmentCustomer`
— обязательная оценка имущества перед крупной сделкой, залогом или взносом в УК.

### 4.5 Чего в реестре НЕТ, вопреки формулировке ТЗ

В ТЗ сказано «намерение совершить крупную сделку». **Такого типа сообщения в
ЕФРСФДЮЛ нет.** Я прошёл весь справочник из 199 типов: слово «намерение»
встречается только в банкротном и почтовом контексте —
`CreditorIntentionGoToCourt` и `DebtorIntentionGoToCourt` (намерение обратиться
в суд с заявлением о банкротстве, сигнал ровно обратного знака),
`RussianPostIntentionToRegisterOwnership`, `IntentionOfDemandsFulfilment`,
`IntentionInheritanceOfLandProperty`. Крупные сделки как таковые здесь не
раскрываются. Ближайшее по смыслу, что реестр действительно даёт, —
`ConclusionConcessionAgreement`, `FirmAuthorizedCapitalIncrease` и
`SaleOrLeaseEnterprise2`; они и включены. Подменять отсутствующий тип похожим и
молчать об этом было бы неправильно.

### 4.6 Стоп-сигналы (`TIPY_STOP`, собираются только при `stop_tipy=True`)

`AppearanceOfBankruptcySigns`, `BankruptcyArticle8`, `BankruptcyArticle9`,
`CreditorIntentionGoToCourt`, `DebtorIntentionGoToCourt`, `FirmLiquidation`,
`FirmRegisterExclude`, `AssetImpairment`, `FirmLicenseProhibited`,
`UnreliableInformation`, `FirmStopActivity`.

Это не лиды, это подавление: компании с такими сообщениями не до покупки
компрессора. Тот же ход уже описан в `lens-06-redteam.md` («проверка ЕФРСБ по
ИНН -> исключить или понизить приоритет»), только теперь он делается на нашей
стороне одним запросом. Полезно прогнать по всей рассылочной базе отдельно от
поиска лидов.

## 5. Как фильтровать по ОКВЭД и региону

**У самого Федресурса такого фильтра нет.** Проверено: `SearchString=28.13` ->
`found: 0`; в OpenAPI у `/companies` только `SearchString`, `IsActive`,
`RegionNumber`, `Limit`, `Offset`; у `/companies/{guid}/publications` фильтра по
отрасли нет вовсе.

Поэтому фильтруем **на своей стороне, до запроса** — и это как раз удобно, потому
что база уже есть: `enrich.db`, таблица `companies`, 169 704 юрлица с полями
`okved`, `region`, `division`. Функция `inn_iz_bazy()`:

```python
inn_iz_bazy(okved=['28','10','11'], regions=['66','16'], division='meyer', limit=1500)
```

* `okved` — двузначные разделы, как `ICP_OKVED` в `news_scan.py`
  (сравнение `substr(okved,1,2)`);
* `regions` — коды субъектов; сверяется поле `region`, а если оно пустое — первые
  две цифры ИНН (код субъекта регистрации);
* `division` — `kc` или `meyer`, чтобы гонять только своё направление;
* порядок — по `pxr` убыванием, то есть крупные первыми;
* база открывается **только на чтение** (`file:...?mode=ro`), ничего не пишется.

`RegionNumber` у `/backend/companies` есть, но он нужен для поиска по имени, а не
для нашего случая: мы и так знаем ИНН.

Фильтр по ОКВЭД делает вторую полезную вещь. Лизинговый поток на две трети —
автопарк и дорожная техника (в замере это АО «ДСК „АВТОБАН“» и
«Трансстроймеханизация» с десятками экскаваторов и катков за квартал). Отбор по
ОКВЭД срезает это до запроса, а `_hotness()` дополнительно гасит такие предметы:

* предмет содержит компрессор / азот / кислород / пневмо / фотосепаратор /
  рентген -> `hotness=5`;
* любая другая промышленная техника (станок, линия, пресс, печь) -> `4`;
* автомобиль, экскаватор, каток, самосвал, прицеп, баржа -> `2`.

## 6. robots.txt — что можно и чего нельзя

Файл отдаётся с 200, вот он целиком:

```
User-agent: *
Disallow: /backend/companies/search
Disallow: /backend/persons/search
Disallow: /backend/nonresidentcompanies/search
Disallow: /backend/encumbrances
Disallow: /backend/realestate/search
Disallow: /backend/fnp-search
Disallow: /cookie-js-info.html
Disallow: /company/d28f7684-ddcf-41b7-8c48-f8fa1ce32619
Disallow: /persons/770c93c7-8d49-46e9-96ce-654bbf41d247
```

Что из этого следует:

* **`/backend/encumbrances` — та самая сквозная лента лизинга и залогов — прямо
  запрещена.** Она отвечает 200, но владелец сайта попросил роботов её не
  обходить. Поэтому в коде это отдельный режим `rezhim='lenta'`, **выключенный по
  умолчанию**, с предупреждением в самом модуле. Включать — решение владельца, а
  не моё.
* Три записи (`companies/search`, `persons/search`, `nonresidentcompanies/search`,
  `realestate/search`) указывают на **старые имена маршрутов**: в текущем API их
  нет (404), поиск компаний живёт по `/backend/companies`. Путь, который мы
  используем, под запрет по префиксу не попадает.
* **Ничего из нашей рабочей цепочки в Disallow не входит**: ни
  `/backend/companies`, ни `/backend/companies/{guid}/publications`, ни
  `/backend/sfact-messages/{guid}`, ни `/backend/reference-book/*`, ни
  `/backend/companies/{guid}/encumbrances` (per-company витрина — не тот путь,
  что запрещённая лента).

## 7. Лимиты и темп — что намерено

**`Limit` — белый список значений.** Перебором 1..20 и 25/45/49/50/55: 200
отвечают ровно шесть значений — **1, 3, 5, 8, 15, 50**. Все остальные дают
**451 с пустым телом**, детерминированно (повтор трижды — тот же 451). Это
легко принять за бан: 451 «Unavailable For Legal Reasons» выглядит грозно, а на
деле это просто «такой размер страницы не предусмотрен». В коде есть `_limit()`,
который округляет вниз до допустимого.

**`Offset`.** У `/companies/{guid}/publications` работает до 1000 (проверено
0/20/100/500/1000 -> 200), на 10000 -> 451. У ленты `/backend/encumbrances`
`Offset` > ~50 даёт **400**, а `found` упирается в 10 000.

**Темп.** 120 запросов подряд с паузой 0,3 с (за 119 с) — **120 ответов 200, ни
одного 429 и ни одного отказа**. Отдельно 40 запросов с паузой 0,25 с — тоже
все 200. То есть ~3 запроса в секунду держатся уверенно. Публикации 2022 года
про «блок после 100 запросов с одного IP» на сегодняшнем поведении **не
подтвердились**; по умолчанию в коллекторе всё равно стоит консервативная пауза
0,35 с — источник чужой, и ломиться незачем.

**Стоимость полного обхода базы.** 2 запроса на компанию (поиск + окно
публикаций) плюс карточки только для отобранных. На 169 704 компании это
~340 тысяч запросов, порядка **28 часов** при паузе 0,3 с. Поэтому нормальный
режим — не сплошной обход, а срез: `okved` + `division` + `limit_inn`,
инкрементально по `offset_inn`, с кэшем ИНН -> guid (`.fedresurs_guid_cache.json`,
пишется атомарно с `fsync`, переживает рестарт — ровно тот урок durability, что
записан в `CLAUDE.md`).

## 8. Что делать при блокировке

Признаки и что они значат:

| Что видим | Что это | Что делать |
|---|---|---|
| **403**, тело `403 Forbidden ... nginx`, 548 байт | нет заголовка `Referer` | это не бан: поставить Referer. Коллектор ставит всегда |
| **451**, тело пустое | недопустимое значение `Limit` (или `Offset`=10000) | взять значение из `LIMIT_OK`. Тоже не бан |
| **400** на ленте обременений | `Offset` глубже ~50 | сузить окно дат, а не наращивать Offset |
| **401**, `Server: QRATOR`, в теле `qauth_show_c` | JS-челлендж Qrator | так отвечают HTML-страницы **всегда**, и это нормально. Если то же самое начнёт приходить на `/backend/*` — вот это уже настоящий бан |
| **429** или сплошные 401/403 на JSON-ручках | нас начали ограничивать | коллектор поднимает `Blok` и **останавливается сам**, не долбит |

Порядок действий при настоящей блокировке — по убыванию правильности:

1. Снизить темп (`pause=1.0`) и уменьшить срез, подождать час. Скорее всего
   этого хватит: ограничение по IP обычно временное.
2. Работать инкрементально: `days=7..14` вместо 90 и регулярный небольшой
   прогон вместо одного большого. Меньше запросов — меньше поводов.
3. Если закрылись совсем — **это нормальный результат, а не задача на обход**.
   Капчу и антибот не обходим. Тогда выбор владельца из двух: договорной API
   оператора (раздел 2.4, цену спрашивать у `bhelp@interfax.ru`) либо штатная
   подписка-мониторинг самого Федресурса (`/backend/monitorings`), где оператор
   сам присылает события по списку наших ИНН.

Чего **не** делаем: не крутим прокси, чтобы обойти лимит по IP; не притворяемся
браузером сверх обычного User-Agent; не решаем челлендж Qrator. Источник
государственный, ходим по нему честно и медленно.

## 9. Как запускать

```bash
# разведочный прогон: 60 компаний из базы, окно 180 дней
python run_script_on_server.py collector_fedresurs.py 240

# из другого скрипта
import collector_fedresurs as F
items = F.col_fedresurs(days=90, max_items=300,
                        okved=['10','11','20','21','22','23','24','25','27','28','35'],
                        regions=['66','16','52'], division='kc',
                        limit_inn=1500, offset_inn=0, pause=0.35)
```

Параметры: `days`, `max_items`, `tipy` (коды типов; по умолчанию все капекс-типы),
`okved`, `regions`, `inns` (явный список — тогда база не читается), `rezhim`
(`inn` / `lenta`), `db_path`, `limit_inn`, `offset_inn`, `pause`, `detali`
(тянуть ли карточки — без них нет `sum` и предмета, зато вдвое меньше запросов),
`stop_tipy`, `division`. Сводка прогона — в `col_fedresurs.summary`.

Item на выходе:


## 10. Что стоит доделать после интеграции

1. **Писать в `signals` с `inn_conf='high'` и без вызова dadata** — это и есть
   приёмка задачи 3. `source='Федресурс'`, `event_type` = русское название типа,
   `what` = предмет лизинга/залога, `sum` = найденная сумма, `source_url` = link.
2. **Стоп-лист.** Отдельный прогон со `stop_tipy=True` по всей рассылочной базе:
   компании с признаками банкротства — в `suppression` панели.
3. **Задача 4 (доопределение компании).** `FirmReorganization` и
   `ConclusionConcessionAgreement` дают ИНН всех сторон — это готовый способ
   превратить безымянную новость «инвестор построит завод» в юрлицо.
4. **Подписка-мониторинг Федресурса** вместо опроса: `/backend/monitorings`.
   Требует завести учётную запись, зато снимает вопрос о темпе совсем.
5. **Сплошной обход** базы (28 часов) запускать отдельным процессом с
   `DETACHED_PROCESS` и резюмом по `offset_inn`, а не через раннер: тот режет
   задание по 30 минутам.
