# VK API с сервера без дельфина: как получить рабочий токен

Задача владельца 29.07.2026: «напиши, как авторизоваться и получить ключи по ВК
через сервер, чтобы не надо было вообще использовать дельфин для API ВК».

## Что уже есть на сервере (проверено 29.07.2026)

В `C:\sender\panel.env` лежит `VK_TOKEN` (71 символ) — это **сервисный ключ**
приложения. Прямой вызов с серверного IP, без дельфина:

| метод | результат |
|---|---|
| `users.get` | ок |
| `groups.getById` | ок |
| `groups.search` | **Access denied** |

Вывод: **привязки к IP у этого токена нет**, дельфин для API VK не нужен уже
сейчас. Единственное, чего не хватает, — `groups.search`: сервисному ключу этот
метод недоступен by design, нужен пользовательский токен. Всё остальное ниже —
только ради поиска сообщества по названию.

Нет в `panel.env`: `VK_APP_ID`, `VK_APP_SECRET`, `VK_SERVICE_TOKEN`,
`VK_TOKEN_USER`, `VK_USE_DOLPHIN`.

## Почему был нужен дельфин

В коде `enrich_contacts.find_vk_group_contacts` вызовы VK идут через
`_vk_api_via_dolphin`, а флаг `VK_USE_DOLPHIN=1` включён по умолчанию. Причина
записана прямо в комментарии у `_VK_PIN_PROFILE`: **токен `VK_TOKEN_USER`
привязан к IP профиля `829115401`**. Такое бывает у токенов, выданных
Implicit Flow прямо в браузере: VK помечает выдачу IP-адресом сессии, и вызов с
другого адреса возвращает ошибку. Отсюда и дельфин — он ходит с «того самого» IP.

Прокси у профиля `829115401` протух (владелец 29.07), поэтому VK-путь сейчас
не работает вовсе. Чинить нужно не прокси, а способ выдачи токена.

## Что даёт нужный результат

Токен, выданный **Authorization Code Flow**, обменивается на
`access_token` **запросом с сервера**, а не в браузере: VK видит серверный IP и
привязывает токен к нему. Плюс `scope=offline` делает токен бессрочным.
Дельфин после этого для API не нужен совсем — остаётся только прямой путь,
который в коде уже есть (`VK_USE_DOLPHIN=0`).

Второй вариант, ещё проще, но уже по возможностям: **сервисный ключ доступа**
(его выдаёт страница настроек приложения). Он не привязан ни к какому IP и
работает сразу, но не ко всем методам — в документации VK у каждого метода
указано, годится ли сервисный ключ. Нам нужен `groups.search`, а он
**сервисным ключом не работает** — нужен пользовательский токен. Поэтому
сервисный ключ держим как запасной для `groups.getById` и подобных.

## Порядок действий

### 1. Приложение VK (один раз)

1. Открыть <https://dev.vk.com/> → «Мои приложения» → «Создать» → тип
   **«Standalone-приложение»** (для веб-флоу подойдёт и «Веб-сайт»).
2. В настройках приложения записать:
   - **ID приложения** (`client_id`);
   - **Защищённый ключ** (`client_secret`) — он нужен ТОЛЬКО серверу, в браузер
     его не вводить и никуда не выкладывать;
   - **Сервисный ключ доступа** — пригодится как запасной.
3. В «Доверенный redirect URI» добавить `https://oauth.vk.com/blank.html`.

Положить на сервер в `C:\sender\panel.env`:

```
VK_APP_ID=<ID приложения>
VK_APP_SECRET=<защищённый ключ>
VK_SERVICE_TOKEN=<сервисный ключ>
```

### 2. Разовый вход владельца в браузере

Запросить ссылку у скрипта (он соберёт её из `VK_APP_ID`):

```
python ops/vk_token.py url
```

Ссылка вида:

```
https://oauth.vk.com/authorize?client_id=<ID>&display=page
  &redirect_uri=https://oauth.vk.com/blank.html
  &scope=groups,offline&response_type=code&v=5.199
```

Владелец открывает её в СВОЁМ браузере, входит под своим аккаунтом и
подтверждает доступ. VK перебросит на `blank.html`, и в адресной строке
появится `?code=xxxxxxxxxxxxxxxx`. Нужен только этот `code`.

Важно: `code` живёт около минуты и одноразовый. Если не успели — открыть
ссылку заново.

### 3. Обмен кода на токен НА СЕРВЕРЕ

```
python ops/vk_token.py exchange <code>
```

Скрипт делает серверный запрос к `https://oauth.vk.com/access_token` с
`client_secret`, получает `access_token`, сразу проверяет его боевым вызовом
`groups.search` с серверного IP и, если вызов прошёл, дописывает в
`C:\sender\panel.env`:

```
VK_TOKEN_USER=<новый токен>
VK_USE_DOLPHIN=0
```

`VK_USE_DOLPHIN=0` — то самое переключение на прямой путь: после него
`find_vk_group_contacts` ходит в API напрямую, дельфин не участвует.

### 4. Проверка

```
python ops/vk_token.py check
```

Печатает, каким токеном ходит, проходит ли `groups.search` и `groups.getById`
с серверного IP.

## Чего этот способ не решает

- **Лимиты VK никуда не деваются**: 3 запроса в секунду на пользовательский
  токен. Массовый обход всё равно надо держать на паузах.
- **Токен можно отозвать**: смена пароля владельца или отзыв доступа в
  настройках VK убьёт его. Тогда повторить шаги 2–3, приложение пересоздавать
  не нужно.
- **`scope=offline` не спасает от блокировки за поведение.** Если бить в API
  чаще лимита, VK ответит `Too many requests`, а при упорстве — временно
  заблокирует. Это не чинится ни прокси, ни дельфином.
- **Метод должен быть доступен пользовательскому токену.** Если VK когда-то
  закроет `groups.search` для обычных приложений (так уже было с рядом
  методов), путь придётся менять целиком, а не токен.

## Если владелец не хочет отдавать серверу свой аккаунт

Тогда остаётся сервисный ключ и методы, которые с ним работают:
`groups.getById` (по известному короткому имени или id группы),
`wall.get` для открытых сообществ. Поиск группы по названию (`groups.search`)
в этом варианте недоступен — придётся находить сообщество иначе: по ссылке с
сайта компании или через обычный поиск, а VK API использовать уже для разбора
найденной группы. Это рабочий компромисс, но охват будет меньше.
