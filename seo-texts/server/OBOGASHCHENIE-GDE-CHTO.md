## 2. Роли контактов — главное узкое место

Роль режется ДВАЖДЫ, и второе важнее первого.

### 2.1. Промпт даёт модели закрытый список из семи ролей

`seo-texts/server/enrich_contacts.py:1420` — `def extract_roles(text, company)`:

```
"emails":[{"email":"","role":"директор|снабжение/закупки|гл.инженер|
продажи|бухгалтерия|приёмная|общий","person":"ФИО или пусто"}]
```

Модель физически не может вернуть «главный энергетик» — его нет в списке.

### 2.2. Канон схлопывает даже то, что вернулось

`seo-texts/server/enrich_db.py:284` — `_ROLE_CANON`, применяется на ЗАПИСИ в `emails`
(`_canon_role`, строка 295):

```python
(('инженер','техни','энергетик','главный механик','гл.мех','производств'), 'гл.инженер'),
...
return 'общий'          # всё, что не попало ни в одно правило
```

Следствие, названное прямо:

```
главный энергетик      -> гл.инженер
главный механик        -> гл.инженер
начальник производства -> гл.инженер
начальник цеха         -> общий
АСУ/КИПиА              -> общий
техдиректор            -> общий
главный технолог       -> общий
```

### 2.3. Панель обзвона умеет различать восемь технических ролей — но данные приходят схлопнутыми

`seo-texts/obzvon-centro/routes_centro.py:490`:

```python
TECH_ROLES = ("гл.инженер", "гл.энергетик", "гл.механик", "гл.технолог",
              "техдиректор", "нач.производства", "нач.цеха", "АСУ/КИПиА")
```

Там же вес для сортировки (строка 517): гл.инженер 0, гл.энергетик 1, гл.механик 2,
техдиректор 3, нач.производства 4, гл.технолог 5, нач.цеха 6, АСУ/КИПиА 7, снабжение 8,
директор 9. Механизм готов, кормить его нечем.

### 2.4. Что реально лежит в базе (enrich.db, замер 11.08)

```
people.role ......... 19 разных значений
   директор 3362 · общий 2875 · (пусто) 1583 · гл.энергетик 611 · снабжение/закупки 564 ·
   инженер (не главный) 509 · нач.цеха 400 · гл.инженер 360 · нач.производства 215 ·
   гл.механик 173 · техконтакт 127 · бухгалтерия 127 · кадры 82 · техдиректор 68 ·
   продажи 64 · АСУ/КИПиА 41 · гл.технолог 29 · приёмная 19 · гл.конструктор 13

contacts.role ....... 39 разных значений (мобильный, техконтакт, закупки из карточки,
   приёмная, отдел, кадры, с сайта (обход), инженер (не главный), гл.энергетик,
   гл.механик, диспетчерская, нач.цеха, справочник …)

eis_arch.role ....... 1 значение (снабжение/закупки — по устройству источника)
```

**В `people` роли богатые, в `emails` бедные.** Значит в `people` пишет путь, идущий МИМО
`_canon_role`. Кто именно — стоит найти: это готовый источник тонких ролей, который уже
работает, и его правила можно перенести в канон вместо того, чтобы придумывать заново.

### 2.5. Что чинить (две мелкие правки)

1. `enrich_contacts.py:1420` — расширить список ролей в промпте до восьми технических
   из `TECH_ROLES` плюс снабжение/директор/продажи/бухгалтерия/кадры/приёмная/общий.
2. `enrich_db.py:284` — завести отдельные правила для энергетика, механика, технолога,
   начальника цеха, начальника производства, АСУ/КИПиА, техдиректора, чтобы они не
   сваливались в «гл.инженер» и «общий».

Порядок важен: без второй правки первая ничего не даст — канон всё равно схлопнет.
