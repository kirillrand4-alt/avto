### Первое, что выяснилось: у 61 % этих компаний разбор просто не запускался

Причина механическая. `razbor_stranic.py` берёт с D: только те файлы, у которых
близнец на C: уже удалён (защита от чтения недокопированного) — 1 417 компаний
в этот момент были «в пути» и остались отложенными навсегда. А кэш конвейера
(`sdelano_kesh`) по мейеру практически не прогонялся: у всех 14 691 мейеровцев
кэш есть, разобрано из него — единицы.

### Чего в списке НЕТ, хотя ожидалось

* **Битой кодировки нет.** Ни одной страницы в cp1251, прочитанной как utf-8, с
  разрушенным текстом. Адреса ASCII и пережили бы такое чтение в любом случае.
* **Экстрактор почти не виноват.** Сравнил `contact_extract.extract()` с грубым
  поиском регуляркой по сырому HTML на 150 компаниях: сырой поиск дал адрес у 98,
  экстрактор — у 96. Промах в 2 случаях из 98 (адрес только внутри `<script>`,
  который экстрактор вырезает: 5402535566, 9723200625). Ловить mailto, JSON-LD,
  data-атрибуты и «собаку» он умеет — проблема не в нём.
* **Cloudflare-шифрование адресов (`data-cfemail`)** в выборке не встретилось ни
  разу. Класса нет.

### Найденный дефект: фильтр мусора убивает весь `@mail.ru`

В `razbor_stranic.py`:

```python
МУСОР_ДОМЕН = re.compile(r'@(?:example|test|domain|mail|email|site|company|...)\b', re.I)
```

`@mail\b` совпадает с `@mail.ru` (точка — граница слова). То же с `@email.`,
`@site.`, `@company.`, `@your...`. То есть **любой адрес на mail.ru
выбрасывается как мусор** — в русской промышленной базе это самый частый
корпоративный домен. Живые примеры выброшенного: `vniiss@mail.ru` (3625000930),
`sibelectrod@mail.ru` (1903013436), `carbon_co2@mail.ru` (2627016003),
`kzms@mail.ru` (1660077562), `abcplast@mail.ru` (1686011252).

Масштаб: у 5 % компаний это ЕДИНСТВЕННЫЙ адрес на сайте (класс в таблице), а
хотя бы один адрес теряется у ~15 % компаний с находками. Правка — одна строка:
привязать домены-заглушки к концу (`@example\.(com|org)`, `@test\.`,
`@yourdomain`, `@mysite`) и убрать `mail|email|site|company` из списка.

Пересчёт на 6 193: **~1 220 компаний (20 %)** имеют на скачанной странице ссылку
на нескачанную страницу контактов. Для 322 из них это ЕДИНСТВЕННАЯ причина
пустоты (у остальных адрес и так найдётся или сайт мёртв). Примеры:

2462075597 → `zapad24.ru/feedback.html`, 2724217805 → `vetli.ru/.../about`,
3525091130 → `akkond.ru/company/about/`.

Добор дешёвый: одна страница на компанию, ~1 200 запросов.

## Что делать — по убыванию отдачи

1. **Прогнать `razbor_stranic.py --delat --kesh` по мейеру + подобрать 1 417
   компаний с файлами на `C:\...\razobrano`.** Отдача: **~2 455 компаний с
   почтой и ~2 180 с телефоном**, страницы уже на диске, сеть не нужна. Это самый
   дешёвый шаг из всех — работа уже оплачена скачиванием.
   ⚠️ Осторожно: в кэше конвейера попадаются страницы справочников, а не сайта
   компании (в пробе дважды вылез `info@che-cko.ru` у разных ИНН). Перед заливкой
   в `enrich.db` нужен гейт принадлежности: домен = сайт компании либо ИНН найден
   на странице (`inn_na_stranicah` уже это умеет).
2. **Починить `МУСОР_ДОМЕН` в `razbor_stranic.py` (`@mail\b` → `@mail.ru` больше
   не мусор) и перезалить находки.** Отдача: **+322 компании** получают
   единственный адрес, ещё у ~15 % компаний прибавляются потерянные адреса.
   Цена — одна строка, перечитывать страницы не нужно.
3. **Разобрать кэш и для 2 437 уже разобранных из сырья.** Кэш собирался другим
   обходом и в другое время. Замер по 200 компаниям: адрес у 14 %, телефон у

4. **Докачать по одной странице контактов для ~1 220 компаний.** Отдача:
   **~210 компаний**, у которых это единственная причина пустоты, плюс лучшие
   роли у остальных. Список URL строится из уже скачанных страниц, без обхода.
5. **Повторный заход на 1 016 доменов, которые «не открылись».** По кэшу 28 %
   таких доменов в другой момент отвечали нормально → **~285 живых, ~120 с
   почтой**. Ставить в очередь низким приоритетом, одна попытка.
6. **Рендеринг JS для ~896 сайтов-каркасов.** Дорого (Зенка с исполнением
   скриптов), отдача ~125 почт. Делать последним и только если исчерпаны 1–5.
7. **Не трогать:** ~600 мёртвых доменов (парковка, продажа, перехват,
   приостановка), 297 живых сайтов без адреса, 122 «только форма», 148 чужих/
   иноязычных до пересверки привязки сайта к ИНН. По ним закрывать потребность
   телефоном: он уже известен у 87 % всех «пустых» компаний.
