### 1.4. Обязательные привычки (каждая — урок)
1. **Durability и резюм.** Все шаги дописывают `jsonl` с fsync и при перезапуске продолжают с места:
   поиск — по (движок, страница, запрос), разбор — по домену/url, обход — по (ИНН, домен). Остановили
   и перезапустили — ничего не теряется.
2. **Ошибка ≠ «пусто».** Ответ «закончились средства» — стоп и сообщение владельцу: он пополнит. Пустые
   вердикты после сбоя провайдера удалить, чтобы шаг их переделал.
3. **Балансы:**
   - xmlriver ≈ 0,025 ₽ за запрос; поиск сам останавливается при балансе ниже резерва `PILOT_REZERV`;
   - DaData — 10 тыс. в сутки, общие с news-scan; `POISK_NE_ZHDAT=1` — не ждать полуночи;
   - провайдер — следить, что ответы не пустые.
4. **Проверки по ходу.** Ставь себе проверку (`send_later` / фоновый опрос) каждые 30–60 минут. Смотри
   не только «идёт ли», но и долю ошибок в логах.
5. **Коммитить скрипты по ходу.** Ветка та же, без моделей в тексте коммитов.

### 2.2. ИНН не определён — НЕ выкидываем (владелец 08.10)

проходят обход контактов, как все. Опровергатели и проверка сайта их не трогают: компания определена
самим сайтом.

### 2.3. Сайт не открылся — список «для Зенки» (владелец 08.10)

### 2.4. Роли и ЛПР — для всех сегментов
- **ЛПР — по принципу, а не по закрытому списку.** Это человек, который отвечает за покупку оборудования

  семеноводов, заведующий элеватором, главный обогатитель тоже ЛПР.
- **Колонки в «Контактах»:**
  - «Должность (как на сайте)»;
  - «Роль» — строго из справочника;
  - «ЛПР по оборудованию» — да / возможно / нет;
  - «Почему ЛПР» — до 10 слов.
- **Справочник** (`kc_kontakty.РОЛИ`, менять только с согласия владельца):
  - роли с ЛПР «да»: Руководитель, Техдиректор / главный инженер, Механик / энергетик / ремонт,

  4. прочие;
  5. общие.

  - **Запросы про рыбу выкидываются** (регэксп `pilot_zadachi.РЫБА`).
  - **Остальные виды — не поисковые:** `типы_предприятий`, `минус_слова` (фильтр разбора),

- **Генерация задач** — `pilot_zadachi.py` (режим `полный` — образец). Для полного прогона:

- **Глубина и движки — по итогам пилота (п. 7):**
  - xmlriver отдаёт 10 результатов на страницу, параметр `groupby=100` он ИГНОРИРУЕТ.

- **Названия выставок, союзов и реестров** агенты частично писали по памяти. Пустые запросы видно в

## 4. Правила качества (нарушать нельзя)
1. **Источник номера или почты** — только живая страница сайта самой компании, или холдинга с пометкой,
   или карточка закупки, где компания — заказчик (ИНН на карточке). checko, rusprofile, list-org, СМИ и
   каталоги — только для поиска компаний и ОКВЭД.
2. **Каждый вывод модели или агента проверяет скрипт** по заново скачанной странице.
3. **Чужие контакты** (дилеры, магазины, горячие линии, ведомства, другие заводы группы) — в «Снято» с
   причиной.
4. **Сайт подтверждён**, если выполнено одно из трёх:
   - ИНН на сайте;
   - модель «та же / группа»;
   - агент с цитатой.

   И при этом опровергатель не нашёл ловушки: ИНН в новости, ИНН студии, другой компании, агрегатор,
   устаревший сайт. Отклонённый сайт в колонку «Сайт» не ставится. «Сомневаюсь» — лист «Спорные».
5. **0 сделок и запретов панели.** Повторы с файлами Meyer 1–6 — колонкой, а не удалением.
6. **Перед выдачей:**
   - проверки раздела 4 `PLAN-AGENTY-POISK-NOMEROV.md`;
   - 20 строк глазами (открыть ссылку, найти номер и подпись);
   - выборка 30 вердиктов опровергателей: если ложных опровержений больше 10%, ужесточить промпт и
     перепрогнать.

## 6. Порядок работы новой сессии
1. **Окружение.** Проверить окружение, ветку, `drop_client.sh list` и балансы (`_balans_xmlriver.py`,
   `_probe_provider.py`).
2. **Бюджет.** Назвать владельцу бюджет полного прогона цифрой (п. 7) и попросить пополнить xmlriver.
3. **Набор.** Выбрать имя набора (например `meyer7`). Сгенерировать задачи на все регионы по правилам
   глубины из п. 7, положить их на дроп.
4. **Импорт.** Доставить все скрипты (`dostavit.py`) и проверить импорт `_test_importy_pilot.py`.
5. **Запуск.** Запустить поиск, ранний разбор и оркестратор. Каждые 30–60 минут — статус и доля ошибок.
6. **Промежуточный отчёт после отбора.** Число компаний по сегментам, «На решение», Зенка. Полнота по
   реестру — по сегментам, где она ниже 50%, добрать запросами.
7. **После агентов:** сборка Excel, проверки п. 4, файл на дроп, владельцу — подпись «откуда и что
   внутри» и ссылка на дроп.
