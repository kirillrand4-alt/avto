### 2.3. Роли и ЛПР
ЛПР — по принципу: отвечает за покупку оборудования или влияет на неё. Колонки в «Контактах»:
- «Должность (как на сайте)»;
- «Роль» — справочник `kc_kontakty.РОЛИ`;
- «ЛПР по оборудованию» — да / возможно / нет;
- «Почему ЛПР».

ЛПР «да» по умолчанию у ролей:
- Руководитель;
- Техдиректор / главный инженер;
- Механик / энергетик / ремонт;
- Производство;
- Технолог;
- **Качество / лаборатория** (владелец 09.10: «оставь»);
- Закупки / снабжение.

Агрономия и Хранение — «да» у семеноводов, элеваторов, ягод и орехов. Обогащение — «да» у руд, угля и нерудных.
Коммерция и Прочее — «возможно». Продажи, Финансы, Кадры, Общий номер — «нет».

**Порядок в Excel:**
1. ЛПР «да» с ФИО;
2. ЛПР «да» без ФИО;
3. «возможно»;
4. прочие;
5. общие.

Внутри групп мобильный и добавочный выше городского.

## 3. Поиск — ЭКОНОМНЫЙ (по данным пилота)

**Что показал пилот** (24,9 тыс. выдач; подробно — п. 8):
- xmlriver отдаёт 10 результатов на страницу, `groupby=100` игнорирует. Листание: Яндекс `page=N-1`, Google
  `page=N`.
- **Страницы 2–3** дали ~16% компаний, которых нет на первой.
- **Google** — ~10% компаний, которых не дал Яндекс.
- **Простая остановка** «10 запросов без новых — стоп» теряет 40–50% компаний: новые приходят неравномерно. Поэтому
  отбор запросов идёт по **отдаче, измеренной в пилоте**, а остановка по насыщению — мягкая страховка.

**Правила экономного поиска** (`pilot_zadachi.py экономный <набор> 600 200` + `pilot_poisk.py`):
1. **Без региона** — все запросы каталога, кроме давших 0 компаний в пилоте: «по стране», реестры, выставки, кейсы,
   операторы `site:`. У них самая высокая отдача: 300–400 компаний на 100 запросов. Google — топ-300.
2. **«Под регион»** — топ-600 шаблонов по отдаче в пилоте (`meyer-zaprosy/pilot-rang-vse.json`) × 89 регионов РФ +
   7 РБ; у видов `беларусь_*` — только РБ.
   - Яндекс — стр. 1; стр. 2 — только если стр. 1 дала ≥2 новых сайтов.
   - Google — стр. 1 для топ-200 шаблонов.
3. **Поток «регион × вид запроса»** идёт по рангу. Если 20 запросов подряд дали меньше 3 новых сайтов — поток
   останавливается. Константы: `pilot_poisk.ОКНО`, `МИН_НОВЫХ`, `ПОРОГ_СТР2`.
4. **Объём:** ~50 тыс. задач, ~65–70 тыс. запросов, **≈2 тыс. ₽** xmlriver, ~11–12 часов (≈100 запросов в минуту,
   10 потоков). Полный каталог для сравнения — ~680 тыс. запросов, 17–29 тыс. ₽, больше 100 часов.
5. **Сверка с реестром обязательна.** Поиск в пилоте нашёл только 43% компаний из наших баз (от 30 млн, в
   сегменте). Ненайденные из реестра добавляются в список (`pilot_otbor`, `POISK_REGIONY_SVERKI=все`,
   `PILOT_LIMIT_REESTR`).
6. **Страницы каталогов** разбираются только у справочников ИНН и УНП, у B2B-каталогов (лимит 60 и 40 страниц на
   домен), а также если ИНН в адресе — такие страницы не скачиваются. Без ограничения в пилоте вышло 58 тыс. страниц
   (≈9 часов). Каталоги дают ~45% компаний, совсем без них нельзя.

## 5. Правила качества (нарушать нельзя)
1. Номер или почта — только с живой страницы сайта самой компании, сайта холдинга (с пометкой) или карточки
   закупки, где компания — заказчик. checko, rusprofile, СМИ и каталоги — только для поиска компаний и ОКВЭД.
2. Каждый вывод модели или агента скрипт проверяет по заново скачанной странице.
3. Чужие контакты, горячие линии, дилеры, ведомства, другие заводы группы — в «Снято» с причиной.
4. Сайт подтверждён (ИНН на сайте, или модель «та же / группа», или агент с цитатой) **и** опровергатель не нашёл
   ловушки. Отклонённый сайт в колонку «Сайт» не ставится; «сомневаюсь» — лист «Спорные».
5. 0 сделок и запретов панели. Повторы с файлами Meyer 1–6 — колонкой.
6. Перед выдачей:
   - проверки раздела 4 `PLAN-AGENTY-POISK-NOMEROV.md`;
   - 20 строк глазами;
   - 30 вердиктов опровергателей. Если ложных больше 10% — ужесточить промпт.

## 6. Порядок работы новой сессии (команды)
1. **Проверка окружения.**
   - `git checkout claude/detailed-study-7j12hg`;
   - `bash drop_client.sh list`;
   - `_balans_xmlriver.py` — на балансе нужно ≥3 тыс. ₽ с запасом;
   - `_probe_provider.py`;
   - `_test_importy_pilot.py`.
2. **Бюджет.** Назвать владельцу бюджет цифрой (п. 7) и попросить пополнить xmlriver и провайдера.
3. **Задачи поиска.** Выбрать набор, например `meyer7`.
   - `python3 pilot_zadachi.py экономный meyer7 600 200`;
   - `bash drop_client.sh up meyer7-zadachi.json`.
4. **Доставка и проверка импорта.** Доставить все скрипты (`dostavit.py`), проверить импорт. Скопировать лаунчеры и
   статус-скрипт под свой набор (`sed`: `pilot` → `meyer7`, в `env` — `POISK_NABOR=meyer7`, для сверки по стране —
   `POISK_REGIONY_SVERKI=все`).
5. **Запуск.** Поиск, через ~1 час — ранний разбор, затем оркестратор. Каждые 30–60 минут — статус, траты, ошибки.
6. **Промежуточный отчёт после отбора.**
   - компании по сегментам;
   - «На решение» — показать владельцу;
   - список для Зенки;
   - полнота по реестру.

   Затем шаг 3а (сайты по названию).
7. **После обхода** — шаг 4а, затем шаги 5–11.
8. **Excel и выдача.**
   - сборка (`pilot_analiz.py` → `analiz.json`, `pilot-slabye.json`, `pilot_xlsx.py`);
   - проверки п. 5;
   - дроп;
   - сообщение владельцу.

## 7. Бюджет и время (оценка на ~100 тыс. компаний; реально может выйти 60–120 тыс.)

| Статья | Экономный режим | Комментарий |
|---|---|---|
| xmlriver: поиск | ≈2 тыс. ₽ | п. 3, ~65–70 тыс. запросов |
| xmlriver: сайты по названию, агенты, проверка сайта | ≈2–3 тыс. ₽ | ~30 тыс. + ~60 тыс. запросов |
| Провайдер: Luna (отбор, обход, чей номер, доп. ОКВЭД, опровергатели) | ≈$100–300 | с учётом ×2,7 за Pro/Enterprise |
| Провайдер: Sol (проверка сайта, агенты) | ≈$1,5–3 тыс. | агенты ~60% суммы; ограничить крупными (`KC_AGENT_LIMIT`) — до ≈$0,5 тыс. |
| DaData | бесплатно, но лимит | ОКВЭД ~50 тыс. ИНН — из наших баз; DaData — 5+ суток |
| Время | ~3–4 суток | поиск ~12 ч; разбор ~4–6 ч; отбор ~2 ч; обход ~100 тыс. компаний при ~150/мин ≈ 12–15 ч; проверки и агенты ~10–20 ч |

Для сравнения: те же шаги на Fable через router.cheap обошлись бы примерно в $70 тыс., на Sonnet 4.6 — в ~$7,5 тыс.
