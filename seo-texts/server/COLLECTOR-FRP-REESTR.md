# Реестр займов ФРП: где он лежит на самом деле

Задача 2 из `TZ-RANNEE-SOBYTIE.md`. Всё ниже — замер 16.09.2026 с боевого
сервера владельца (`run_script_on_server.py`), с кодами ответов. Где вывод
модели, а не факт с сервера, — так и написано.

Код коллектора: `collector_frp_reestr.py`, ручка `col_frp_reestr(days, max_items)`.

---

## 1. Главный вывод

**Публичного реестра профинансированных проектов у ФРП больше нет.** Он был:
раздел `frprf.ru/klienty/` с карточками заёмщиков, 706 штук, они до сих пор
перечислены в sitemap. Сегодня и сам раздел, и каждая карточка отвечают
`301 → https://frprf.ru`. Карта проектов на главной тоже мертва: скрипты карты
подключены, но данные (`region_js`) в HTML не отдаются, а ссылки внутри карты
ведут на тот же закрытый `/klienty/?region=`.

**JSON-ручки нет.** Сайт на Bitrix; единственные XHR в разметке — счётчик
конверсий и перезагрузка капчи. RSS тоже нет (все варианты — 404).

Поэтому «реестр займов» в коллекторе **восстанавливается из ленты пресс-центра**
— единственного живого публичного раскрытия, где ФРП объявляет займы поимённо, с
суммой и регионом. Лента берётся не как новости, а как реестр: пагинация,
штатный фильтр по датам, разбор каждой карточки на поля.

## 3. Живой источник: лента пресс-центра как реестр

**База:** `https://frprf.ru/press-tsentr/novosti/`

**Пагинация:** 6 карточек на страницу, параметр `PAGEN_1=N`. Номер за пределом
диапазона отдаёт первую страницу с кодом 200 (а не 404) — поэтому обход
останавливается по «нет новых ссылок», а не по коду.

**Фильтр по датам (штатный, Bitrix, проверен — реально режет выборку):**

```
https://frprf.ru/press-tsentr/novosti/?set_filter=y
  &arrFilter1_DATE_ACTIVE_FROM_1=18.06.2026     # с
  &arrFilter1_DATE_ACTIVE_FROM_2=16.09.2026     # по
  &PAGEN_1=1
```

**Разметка карточки** (её и разбирает `_cards`):

```html
<div
     class="item-news " id="bx_..." data-entity="items-row">
  <div class="date">15 сентября 2026 г.</div>
  <div class="title">
      <a  href="/press-tsentr/novosti/v-permi-.../">В Перми благодаря займу ФРП ...</a>
  </div>
  <p>Объем производства высокотехнологичных насосов вырос в 3 раза</p>
```

Две грабли, на которых прогон молча даёт ноль карточек: `<div` отделён от
`class=` переносом строки, а в ссылке **два пробела** — `<a  href=`. Регексы с
одиночным пробелом не срабатывают, и это выглядит как «новостей нет».

**Троттлинг.** При заливе залпом (около 30 запросов подряд) сайт начинает
отдавать `503`. В коллекторе: общий пейсинг 0.7 с на все потоки (`FRP_PACE`),
ретраи на 429/5xx, битая страница не обрывает обход, а пропускается и попадает в
телеметрию `LAST_WALK['страниц с ошибкой']`. Урок из замера: один `503` на шестой
странице тихо обрезал годовое окно до трёх месяцев (36 новостей вместо 115) — по
выводу это было неотличимо от «столько и есть».

**Детальная страница релиза** даёт то, чего нет в анонсе: заёмщика, сумму займа
ФРП отдельно от бюджета проекта, программу, регион. Коллектор качает её сам и
кладёт в `full_text` — конвейеру `news_scan.fetch_article` второй GET уже не
нужен.

## 4. Как часто обновляется и сколько там записей

Замер по ленте с фильтром дат:

| окно | всего новостей | из них про займы |
|---|---|---|
| год, 16.09.2025 – 15.09.2026 | 115 (≈ 2,2 в неделю) | **84** (≈ 7 в месяц) |
| 90 дней, 18.06 – 16.09.2026 | 34 | **24** |

Годовые 84 посчитаны фильтром «это заём» до того, как в него добавили отсев
сводных новостей; из этих 84 четыре штуки — сводки вида «профинансировано
100 проектов на 126 млрд» и одна про изменение ставок, то есть чистых
персональных займов за год примерно **79**.

Сколько всего займов у ФРП — по словам самого Фонда (цитаты из заголовков его же
ленты, проверяемые по ссылкам):

* «ФРП профинансировал промышленные проекты **1 500 российских предприятий**» —
  22.12.2025;
* «ФРП с 2025 года профинансировал **более 300 новых промышленных проектов**» —
  29.05.2026 → темп примерно **210 проектов в год**;
* «ФРП профинансировал по программе „Автокомпоненты“ 100 проектов на 126 млрд ₽»
  — 09.06.2026.

**Покрытие: реестр против новостей.**

| | записей | что внутри |
|---|---|---|
| закрытый реестр `/klienty/` | **706 карточек** (состояние на декабрь 2020, когда sitemap перестал обновляться) | заёмщик, программа, регион, сумма — полями |
| реальный поток займов ФРП | ≈ **210 в год**, всего ≈ 1 500 предприятий | — |
| лента пресс-центра | **84 займовых новости в год** | те же поля, но текстом |
| старый коллектор `col_frp` | **6 ссылок за прогон** (замер 16.09: одна страница, без пагинации и дат) | только заголовок и ссылка |

То есть лента освещает примерно **40 % реальных займов** (84 из ~210), а
переключение коллектора на неё даёт рост в **4 раза по объёму за 90 дней**
(24 против 6) и в **14 раз за год** (84 против тех же 6, потому что старый
коллектор не умеет уходить вглубь ленты вообще).

## 5. Что отдаёт коллектор

Item — контракт коллекторов `news_scan` плюс реестровые поля:

```
{title, link, pubDate, source='ФРП', tier=2, collector='frp_reestr', query}
+ company_name   заёмщик, именительный падеж (ОПФ + ядро из кавычек)
+ company_hint   то же имя под именем поля, которое news_scan.enrich_ev уже
                 берёт как фолбэк компании — интеграция без правок
+ inn            если ИНН есть в тексте (с проверкой контрольной суммы); почти всегда пусто
+ sum, sum_rub   сумма ЗАЙМА («72 млн ₽», 72000000)
+ project_sum    бюджет всего проекта, если назван отдельно
+ region         субъект РФ (словарь 89 субъектов + крупные города)
+ otrasl         отрасль по словарю (19 категорий)
+ program        программа займа («Проекты развития», «Комплектующие изделия», …)
+ stage, stage_code   стадия: 1 одобрено / 2 стройка / 3 пуск / 4 расширение / 0 не определена
+ budget_confirmed=True
+ full_text, article_chars   текст релиза (конвейеру не нужен второй GET)
+ detail_code                код детальной страницы (200 = поля полные)
```

**Замер прогона за 90 дней** (`python collector_frp_reestr.py 90`, сервер, 22–96 с
в зависимости от троттлинга):

| показатель | значение |
|---|---|
| событий | 24 |
| с именем заёмщика | 23 (96 %) |
| с суммой займа | 23 (96 %) |
| с регионом | 24 (100 %) |
| с отраслью | 17 |
| с программой | 10–16 (плавает: часть релизов программу не называет) |
| с ИНН | 0 — в релизах ФРП ИНН не пишут, ИНН добирает dadata в конвейере |
| сумма займов в окне | 44 млрд ₽ |
| стадии | пуск 15, расширение 6, **одобрено 2**, не определена 1 |

**Честно про раннюю стадию.** Приёмка задачи 2 («событий кратно больше, у каждого
есть сумма, `budget_confirmed` стоит») выполняется. Но ради чего всё затевалось —
стадия «бюджет есть, оборудование ещё не выбрано» — в ленте редка: ФРП пишет
про одобрение займа в основном волнами на выставках (ПМЭФ 3–4 июня, Иннопром
7–8 июля), а в остальное время публикует «открыли цех / нарастили выпуск», то
есть постфактум. За год таких «ФРП предоставит N млн» набралось **8 из 84**
(≈ 10 %). Закрытый реестр `/klienty/` был бы здесь сильно лучше, но его нет.
Что можно сделать дальше — раздел 8.

## 6. Запуск и интеграция

Ручной прогон (только чтение сети, ничего не пишет):

```bash
cd seo-texts/server
python run_script_on_server.py collector_frp_reestr.py 400   # окно по умолчанию 90 дней
```

Печатает 10 примеров и сводку последней строкой (вывод раннера режется сверху),
в stderr — ход обхода по страницам и состояние закрытого реестра. Локально из
контейнера запускать бесполезно: геоблок 403.

Встраивание в `news_scan.py` (я его не трогал, это за владельцем сессии):

```python
from collector_frp_reestr import col_frp_reestr
...
if 'frp_reestr' in enabled:
    raw += col_frp_reestr(days=days, max_items=max_items * 3)
```

Три замечания к интеграции:

1. Старый `col_frp` можно оставить включённым — дубли схлопнет штатный дедуп по
   канон-URL (`_news_key`), ссылки у обоих коллекторов одинаковые. Смысла в этом
   мало: новый коллектор возвращает надмножество.
2. В `enrich_ev` поле `sum` берётся только из ответа модели:
   `'sum': ev.get('sum')`. Сумма из реестра надёжнее (она вытащена регексом из
   релиза с разделением «заём» и «бюджет проекта») — имеет смысл написать
   `ev.get('sum') or it.get('sum')`.
3. `budget_confirmed` в item уже стоит; чтобы он доехал до `lead_scoring`, его
   надо протащить в `rec` и в `signals` — сейчас в `rec` такого поля нет.

## 7. Ограничения и риски

* Источник — пресс-релизы, а не реестр: если ФРП о займе не написал, события не
  будет. Потолок покрытия ≈ 40 % займов.
* Разбор текста регексами. Имя заёмщика берётся из кавычек («ПермНефтеГаз»,
  `ООО «Тандер»`); программы займа тоже пишутся в кавычках и отсекаются
  чёрным списком — при появлении новой программы список надо пополнить
  (`_PROGRAMS`).
* Сводные новости («профинансировал 100 проектов на 126 млрд») отсеиваются
  отдельным фильтром: в них есть и слово «заём», и сумма, но заёмщика нет.
* Вёрстка ленты может поменяться — тогда `_cards` вернёт ноль. Признак в выводе:
  «лента: 0 новостей» при `полный обход: true`.
* `FRP_PACE` ниже 0.5 с приводит к 503 и неполной выборке.
* Если ФРП когда-нибудь вернёт `/klienty/`, это увидит `registry_alive()` (сейчас
  печатает `{"code": 301, "alive": false}` при каждом ручном прогоне) — тогда
  коллектор надо переключать на реестр: там были поля, а не текст.

## 8. Соседние реестры: СПИК, СЗПК, субсидии Минпромторга

Проверено тем же способом, кодами ответов. Кода под это не писал — это разведка
для следующих задач.

| источник | URL | код | вывод |
|---|---|---|---|
| ГИСП, реестр СПИК | `https://gisp.gov.ru/spik/` | 200, **1 775 б** | отдаёт только SPA-заглушку со спиннером: данные подгружает JS. Без браузера (`browser_probe.py`, Playwright на сервере) не взять |
| ГИСП, прочие разделы | `/spik-registry/`, `/opendata/`, `/documents/` | 200, 1.8 КБ | то же самое — весь gisp.gov.ru так устроен |
| Минпромторг, СПИК | `/activities/gosudarstvennaya-podderzhka/spik/` | 200, 77 КБ | обычная страница: описание механизма, реестра заключённых СПИК на ней нет |
| Минпромторг, открытые данные | `/opendata/` | 200, 122 КБ | наборы есть, но не про деньги: «Меры поддержки ГИСП», «Реестр российской промышленной продукции», «Реестр лицензий на лекарства». Реестра субсидий и СПИК среди наборов нет |
| СЗПК, Минэкономразвития | `/material/directions/investicionnaya_deyatelnost/mehanizm_szpk/` | **404** | старый адрес раздела умер; публичного реестра соглашений найти не удалось |
| ГИС «Капиталовложения» | `https://gisk.veb.ru/` | DNS не резолвится | хоста нет |
| Электронный бюджет, субсидии | `https://promote.budget.gov.ru/` | таймаут | с сервера не отвечает (дважды) |
| Электронный бюджет, портал | `https://budget.gov.ru/` | 200, 289 КБ | жив, но нужный раздел — за SPA, требует отдельного разбора |

**Единственная полноценная находка — реестр ФНС**, и он лучше всего, что есть у
самого ФРП по структурности:

`https://rmsp-pp.nalog.ru/` — Единый реестр субъектов МСП-получателей поддержки.
На главной: **12 658 265 фактов поддержки, 3 303 566 получателей**, обновляется
ежемесячно (на сайте — срезы на 15-е число каждого месяца с 20.12.2020).

У него есть **открытая JSON-ручка** (проверено, 200):

```
https://rmsp-pp.nalog.ru/search-proc.json?query=<строка>&page=<N>
```

Ответ: `{pageCount, rowCount, pageSize, data:[…]}`, по 20 строк. Поля строки —
ровно то, что нужно лидогенерации:

```
subject_inn, subject_ogrn, subject_name, subject_nptype (UL/IP), subject_region,
provider_inn, provider_organization,        ← кто дал поддержку
support_form_value ("Финансовая поддержка"), support_kind_value,
support_value_1 (сумма, число), dt_support_begin, dt_support_period,
support_violation_b (были ли нарушения)
```

Пример реальной строки из выдачи:

```json
{"id": 16879556, "dt_create": "20.12.2020", "provider_inn": "7707329152",
 "subject_inn": "781190015220", "subject_name": "- ЗАБИУЛЛА МУХАММЕД ЯКУБ",
 "support_form_value": "Финансовая поддержка",
 "support_kind_value": "Предоставление субсидий и грантов",
 "support_value_1": 36390.0, "dt_support_begin": "08.07.2020", "subject_region": "78"}
```

Что это даёт и чего не даёт:

* **даёт ИНН сразу** — единственный из проверенных источников, где не нужен шаг
  dadata (как Федресурс из задачи 3);
* **даёт сумму и дату поддержки** — то есть подтверждённый бюджет;
* **не даёт** ничего по крупным заёмщикам: реестр по закону только про МСП, а
  типичный заёмщик ФРП с займом на 500 млн ₽ — не МСП;
* поиск в ручке идёт **только по получателю**: в форме единственное поле
  `query`, а подсунутые `provider_inn` / `providerInn` / `provider_organization`
  / `support_kind_code` ручка молча игнорирует — проверено, все четыре вернули
  ту же первую страницу, что и пустой запрос. Фильтра «по организации,
  предоставившей поддержку» в публичном API нет;
* зато `provider_inn` есть в каждой строке ответа, а полная выгрузка лежит в
  открытых данных ФНС: `https://www.nalog.gov.ru/opendata/7707329152-rsmppp/`
  (200). Там помесячные срезы, каждый — ZIP с XML на **175–235 МБ** (например
  `https://file.nalog.ru/opendata/7707329152-rsmppp/data-20211215-structure-20201220.zip`,
  235 116 251 байт, HTTP 200). Последнее изменение набора — 15.09.2026, дата
  следующей актуальности — 15.10.2026, то есть обновление ежемесячное. Отбор
  «все получатели поддержки от ФРП» делается по `provider_inn` в такой выгрузке:
  качать на сервер (не в песочницу), разбирать потоково;
* на первой странице выдачи поставщики выглядят так: ФНС (7707329152),
  Корпорация МСП (7750005919), региональные фонды поддержки МСП — то есть массив
  смещён в сторону мелкой МСП-поддержки, и сколько там строк именно от ФРП, по
  публичному API не посчитать. Это проверяется только на полной выгрузке.

Итог по разделу: отдельным коллектором в ближайшую очередь стоит брать
**реестр ФНС** (ИНН + сумма + дата, без dadata), а СПИК/СЗПК — только через
браузерный обход ГИСП, отдельной задачей.
