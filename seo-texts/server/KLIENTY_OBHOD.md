# Обход доменов: все клиенты КЦ/Meyer и их закупки

Готовый инструмент, 23.10. Полный проход зоны пока **отложен владельцем**: есть риски для основного сервера.
Список рисков в конце файла.

Основа инструмента:
- комбайн тендерной сессии (репозиторий `tender`, `server/tender_crawl_all.py`, описание в `server/CRAWL_ALL.md`):
  закупочные разделы, внешние ЭТП, планы закупок, вердикт без модели;
- наш поиск реквизитов (`_fsa_deshevo.проверить`, `kc_kontakty`): ИНН и ОГРН с проверкой контрольных сумм, телефоны, почты.

Отсюда видно и кто клиент (сайт → ИНН → ОКВЭД → сегмент), и как он закупает.

## Файлы
| Файл | Что делает |
|---|---|
| `klienty_obhod.py` | Обход списка доменов по частям (crc32), с продолжением после остановки |
| `_klienty_pusk.py` | Лаунчер на сервере: N отсоединённых частей. Параметры в `KLIENTY_PUSK.json` |
| `klienty_razbor.py` | Разбор: ИНН → выручка и название (ФНС revexp) → ОКВЭД (enrich.db, checko) → сегмент Meyer/КЦ → Excel |

## Что делает обход на каждом домене (бюджет 45 с)
1. DNS. Если адреса нет — домен пропускается.
2. Главная страница: https, затем http, затем https без проверки сертификата.
3. Заглушки и «не похоже на сайт компании» — только главная, глубже не идём.
4. ИНН, ОГРН, телефоны и почты с главной.
   - Если ИНН нет, открываем до 4 страниц: реквизиты, политика или оферта, контакты, «о компании».
   - Сначала берём ссылки из меню, затем типовые пути (`/rekvizity/`, `/contacts/`…).
   - Останавливаемся на первом найденном ИНН.
5. Закупки, как в комбайне:
   - ссылки уже открытых страниц;
   - разделы меню;
   - `sitemap.xml`;
   - типовые пути (`/zakupki/`, `/tenders/`…).
   - На найденной странице — второй уровень: внешний портал и лоты.
6. Вердикт закупок, один из:
   - своя ЭТП;
   - страница с лотами;
   - внешняя ЭТП;
   - ссылка на внешний портал;
   - план закупок;
   - страница закупок без лотов;
   - не закупки.

## Запуск
Список доменов: `C:\sender\_tmp\domains\delegated.txt`, 6,9 млн доменов R01 (.ru, .рф, .su).
Его выгрузила тендерная сессия, обновлять через `tender/server/tender_zones_worker.py`.
Подойдёт любой файл «домен в строке»: выгрузка панелей, домены почт базы обзвона и т. п.

```
python klienty_obhod.py K N T [файл_доменов] [--limit=M]   # одна часть
python _klienty_pusk.py                                      # все части; параметры — KLIENTY_PUSK.json
```

Повторный запуск продолжает с места остановки: пройденные домены каждой части записаны в `klienty-sK-done.txt`.
В комбайне так продолжались только домены с находками.

## Где результат (durable: на диск сервера, с fsync)
- `C:\sender\server\klienty\klienty-sK.jsonl` — домены с находками (ИНН, ОГРН или закупки).
  Поля совместимы с комбайном: `host`, `links`, `ext_links`, `ext_etp`, `pages`, `plans`, `verdict`.
  Добавлены поля `inn`, `inn_page`, `ogrn`, `phones`, `emails`.
- `klienty-sK-done.txt` — все пройденные домены.
- Дроп `klienty-sK-progress.json` — счётчики:
  - done, found, с_ИНН, с_закупками;
  - причины отсева;
  - вердикты;
  - нагрузка.
- Разбор: `python klienty_razbor.py` → `klienty\klienty-itog.xlsx` и копия на дроп. Листы:
  - Клиенты Meyer;
  - Клиенты КЦ;
  - Закупки (все с ИНН);
  - Закупки без ИНН;
  - Все ИНН;
  - Сводка.
- ИНН без ОКВЭД попадают в дроп `klienty-checko-vhod.json`. Дальше:
  1. `CHECKO_VHOD=klienty-checko-vhod.json python fsa_meyer_checko.py` (прокси checko только из `checko-proxies.json`);
  2. `klienty_razbor.py` ещё раз.
- Разбор закупок моделями — инструменты тендерной сессии: `tender/tools/sites_postprocess.py` и `recheck_sites.py`.
  Входной формат у них тот же, нужен JSON-список, а не jsonl.

## Проверка 23.10 (42 домена с заранее известным ИНН)
- **Песочница:** верный ИНН найден у 33 из 40 (82%), 8–40 с на сайт.
- **Сервер:** 42 домена за 44 с в 24 потока, ИНН у 35, признаки закупок у 5.
- **Разбор на сервере:**
  - выручка ФНС у 35 из 35;
  - ОКВЭД у 35 из 35;
  - Meyer 31, КЦ 2;
  - в базе обзвона уже 21.
- **Не нашли ИНН у 7 доменов.** Причины: сайты на JS, медленные, или ИНН только в картинке или PDF.

## Скорость (оценка)
Комбайн без реквизитов шёл ~800 доменов/мин на процесс в 96 потоков. Наш обход тяжелее: до 4 страниц реквизитов,
но только у сайтов компаний. Ожидаем ~400–600 доменов/мин на процесс. 12 частей → вся зона примерно за 1–1,5 суток.

## Риски (почему полный проход отложен)
1. **Жалобы и блокировка хостером (Селектел).** На основном сервере работают:
   - панель;
   - дроп;
   - трекинг и отписки;
   - обзвон;
   - тендеры.

   Блокировка остановит всё сразу. Лучше отдельная VPS: скопировать три файла и `delegated.txt`, сделать `KLIENTY_DIR`/`KLIENTY_DROP` локальными,
   результаты передать через дроп.
2. **Репутация IP основного сервера.** Капчи и 403 начнутся для нашего обычного обогащения.
3. **Нагрузка.** Сторож ставит потоки на паузу при памяти или ЦП ≥ `KLIENTY_CAP` (90%). Сервер и так загружен:
   - Зенка;
   - ~10 ГБ памяти держит какой-то драйвер;
   - tendery-web и tendery-worker.

   Число частей и потоков подбирать по `load` в прогрессе.
4. **Список R01** не публиковать и не передавать третьим лицам.
