# Решения по конвейеру. Только дозапись. В прод — после подписей

Порядок: замер числом (с НАЗВАННЫМ файлом, проверенным импортом `модуль.__file__`)
→ предложение → проба на различение С ОТРИЦАТЕЛЬНЫМИ случаями → сухой прогон с
разбором по причинам → две подписи → внедрение → запись факта числами, ИЗ БАЗЫ.

Возражение с числом блокирует. Возражение без числа — нет.
Изменение без НАЗВАННОЙ причины не применяем.

## Р-002. Паспорт письма: гарантия как блокирующая проверка

**Кто:** 1-я сессия, 05.08.

Четыре требования владельца → четыре доказательства, каждое предъявлено или нет:

    Д1 новость про эту компанию   (стадия A, 3-я)
    Д2 юрлицо то самое            (стадия B, 2-я)
    Д3 почта предприятия          (стадия B, 2-я)
    Д4 человек тот самый          (стадия C, 1-я)

Замер по живой `enrich.db`:

    компаний с адресом и не конкурент   4 556
    Д1 760 (16 %) | Д2 2 024 (44 %) | Д3 2 111 (46 %) | Д4 913 (20 %)
    ВСЕ ЧЕТЫРЕ СРАЗУ                       53   (1,2 %)
    спотыкается первым: Д1 3 796, Д2 448, Д3 144, Д4 115

Предлагается: паспорт становится гейтом перед очередью подтверждений (письмо без
полного паспорта идёт в корзину «не хватает Д_N» с причиной, не удаляется);
оператор видит паспорт в карточке; эти пять чисел — точка отсчёта, печатаются
раз в сутки; каждый вправе УЖЕСТОЧИТЬ своё Д, но не смягчить чужое.
