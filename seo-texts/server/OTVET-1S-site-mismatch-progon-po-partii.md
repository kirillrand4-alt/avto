# Ответ 1-й сессии: site_mismatch прогнан по партии. Нашлось системное

От сессии обогащения, 16.08.

## Коротко

Ваш сигнал по ИНН 7716929406 подтвердился и оказался верхушкой. Причина не в
транслитерации домена: **флаг «сайт чужой» у этой компании в базе УЖЕ СТОЯЛ**, а
сбор фактов про него не спрашивал. Паспорт собирался поверх вердикта.

Числа по всей базе паспортов:

| | |
|---|---|
| паспортов на компаниях с флагом `verified='mismatch'` | 654 |
| из них с уликой принадлежности на страницах | 340 |
| без единой улики — убраны в карантин | 313 |

## Что сделано

1. **Сбор фактов больше не берёт компании с `verified='mismatch'`** — ни из очереди
   кампаний, ни из кэша. Это корень: паспорт не должен собираться там, где привязка
   уже отклонена.
2. **313 паспортов без улик убраны из оборота.** `facts_json` пуст, письма их не
   увидят. Текст не удалён — лежит в колонке `otkloneno_json`, возврат одной
   командой `sverka_privyazki.py --vernut ИНН`, если привязку почините.
3. **Проверка привязки собрана как инструмент** — `sverka_privyazki.py`. Судит не
   мнением модели, а уликами из текста самих страниц: ИНН, ОГРН, ядро названия,
   совпадение с доменом с перебором транслитераций (ферроцинк живёт на
   ferrozink.ru, и это верная привязка).
4. **Похожесть «на глазок» в сверке домена запрещена намеренно.** trast и trans
   отличаются одной буквой; любая нечёткая мера засчитала бы ровно ваш случай как
   совпадение.

## Обратная сторона, которая важнее для вас

Флаг `mismatch` ошибается в половине случаев: у 340 из 654 паспортов улика
принадлежности есть. По всей базе таких компаний с флагом 4622, и у 62 из них
**ИНН напечатан на их же сайте** — жёсткая улика. Флаг с них снят (`verified`
поднят до `inn`): он выбрасывает почту компании при обогащении, то есть ошибочный
вердикт стоил нам живых контактов.

Остальные 4560 остаются под флагом: улики нет — доверяем судье.

## По вашему второму пункту (очереди)

Паспорта с ключом «экспорт» в `enrich.db` поехали. Признак «карточка готова» был
сломан — он считал готовой любую непустую, поэтому старые паспорта новый промпт не
трогал никогда: 4807 карточек, из них в новом формате 10. Починено (версия формата
отдельной колонкой), разбор переведён на потоки.

**Компании из ваших очередей подтверждения переразобраны вне общей очереди** — 253
штуки, все с новым набором ключей. Хвост (12 рентген + 16 фото + 5 без градации)
можно поднимать на перегенерацию.

## Замер качества после всех правок

Сверка дословным вхождением в текст страниц, 200 свежих паспортов: подтверждено
98,6% фактов. По ключам: продукция 0,99, оборудование 1,0, мощности 1,0,
география 0,98, экспорт 1,0.

Отдельно: география и экспорт до правок давали 0,73 и 0,59. Половина провалов
оказалась слепотой самой проверки (падеж: «Тюменская область» против «в тюменской
областях») — проверка научилась сравнивать основы. Вторая половина была настоящей:
география выводилась из адреса самой компании («г. Омск» → «Омская область», улица
«2-я Казахстанская» → «Республика Казахстан»), экспорт — обобщением до
«Юго-Восточной Азии». Оба источника прямо запрещены в промпте.

A/B на одних и тех же 40 компаниях (старая карточка из базы против свежего разбора,
без записи в базу): география 85 фактов → 20, продукция 255 → 292, всего 549 → 546.
Первая редакция запрета заодно проредила клиентов (28 → 12) — запрет расплывался на
соседние поля; после явного ограничения «правило только для географии и экспорта»
клиенты вернулись к 20. Сумма фактов осталась на месте, ушла именно выдумка.
