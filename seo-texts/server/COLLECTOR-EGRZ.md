## 1. Главное: адрес в ТЗ неверный

В ТЗ написано `egrz.gov.ru`. **Такого хоста не существует**, это не блокировка:

```
dns  egrz.gov.ru   FAIL gaierror: [Errno 11001] getaddrinfo failed
dns  egrz.ru       ok 37.18.114.13
tls  egrz.ru       ok proto=TLSv1.3
GET  https://egrz.ru/   code=200  <title>ГИС ЕГРЗ</title>
```

Рабочий портал ГИС ЕГРЗ — **`https://egrz.ru`**, Angular-SPA. Никакой капчи,
никакого Cloudflare, регистрация для просмотра реестра не нужна.

## 2. Откуда данные: открытый OData-сервис

SPA берёт данные из `main.bundle.js`; в конфиге бандла:

```
PublicPortal        = https://egrz.ru/
PublicPortal_API    = https://open-api.egrz.ru/      <- n.publicAPI
PrivatePortal       = https://lk.egrz.ru/            (личный кабинет, по ЭП)
publicRegistrationBook = publicAPI + "api/PublicRegistrationBook"
```

**Базовый URL: `https://open-api.egrz.ru/api/`.** Это ASP.NET Web API с OData v4.
Сервис-документ `GET /api/` отдаёт наборы:

```
News, PublicRegistrationBook, LawAndRegulation, Analytics, Page, Statistic
```

Нужен только `PublicRegistrationBook` — публичная книга регистрации заключений.
Авторизация не требуется, ключ не нужен, заголовки — обычные:

```
GET https://open-api.egrz.ru/api/PublicRegistrationBook?$top=1&$count=true
-> 200, {"@odata.context":"http://open-api.egrz.ru/api/$metadata#PublicRegistrationBook",
         "@odata.count":596906, "value":[{...}]}
```

596 907 заключений на 16.09.2026, за последние 90 дней — 17 682.

Схема доступна: `GET https://open-api.egrz.ru/api/$metadata` (EDMX).

## 4. Сметной стоимости в источнике НЕТ (доказательство)

Поля стоимости у сущности нет, сервер прямо это говорит:

```
GET /api/PublicRegistrationBook?$top=1&$select=EstimatedCost
-> 400 {"error":{"message":"The query specified in the URI is not valid.
        Could not find a property named 'EstimatedCost' on type
        'K2IT.Xrm.EGRZ.Infrastructure.Common.Models.PublicRegistrationBook...'"}}
```

То же для `SmetaCost`, `Cost`, `SmetnayaStoimost`, `Price`, `Sum`, `TEP`, `Tep`.

Проверены и обходы внутри самого ЕГРЗ — тоже пусто:

* `POST /api/ObjectPassport/getHtml` с номером заключения → 200, но это **пустой
  бланк** «Паспорта ОКС»: объект из реестра в тексте не встречается, в графе
  «общая сметная стоимость, млн. рублей» — прочерк. Сервис предназначен для
  отображения ЗАГРУЖЕННОГО паспорта, а не для выдачи данных по номеру.
  `getPassport` на любые payload'ы отвечает `500 NullReferenceException`,
  GET на все четыре ручки — `405`.
* `GET /api/dictionary/getTepValues` → `404 No HTTP resource was found`.
* Выгрузки `PublicRegistrationBook/{openDataFile,excelDataFile,xmlDataFile}`:
  POST → `405`, GET без параметров поиска не отвечает за 12 с (судя по всему,
  генерирует дамп всего реестра). Как массовый экспорт — не используем.
* В бандле ЛК поля «Общая сметная стоимость, млн. рублей» и «Сведения о проверке
  достоверности определения сметной стоимости» ЕСТЬ — то есть в системе смета
  хранится, но отдаётся только в личном кабинете (вход по ЭП/ЕСИА).

**Вывод: `col_egrz` возвращает `sum=''` и не выдумывает число.**
Приёмка ТЗ «в `signals` появляется source='ЕГРЗ' с непустым `sum`» на публичном
ЕГРЗ невыполнима. Чем закрывать сумму, если она нужна:

1. **ЕИС/zakupki** — у застройщика с найденным ИНН смотрим закупки по 223-ФЗ:
   цена лота по тому же объекту. Коллектор `zakupki` уже есть.
2. **ГИР БО (bo.nalog.ru)** по ИНН — «незавершённое строительство» год к году;
   это не смета, но масштаб капекса (фаза 2 из `NEWS-SOURCES-PLAN.md`).
3. **Главгосэкспертиза (gge.ru)** — пресс-релизы по крупным объектам часто
   содержат сметную стоимость; хост с сервера открывается (200).
4. **ФРП, реестр займов** (задача 2) — сумма займа как подтверждённый бюджет.
5. Личный кабинет ЕГРЗ — только по доверенности застройщика, нам недоступен.

Сумма для нас вторична: стадия «проект» + ИНН + объект — уже достаточный повод
для звонка, а масштаб видно по названию объекта («цех на 4800 свиноматок»).

## 5. Фильтрация: как отбираем промышленные объекты

### 5.1 Классификатор КОСФН (поле `FunctionalPurpose`)

Формат: `06.03.005.003 Здание цеха по производству масложировой продукции`.
Разделы (замер по реестру за 90 дней, `startswith(FunctionalPurpose,'NN.')`):

|---|---|---|
| 01 | среда населённых пунктов | 6 802 |
| 02 | образование, культура | 2 800 |
| 03 | здравоохранение, спорт | 1 122 |
| 04 | транспорт | 1 744 |
| 05 | энергетика (ЛЭП, подстанции) | 255 |
| **06** | **сельское хозяйство, пищепром** | **294** |
| **07** | **химическая промышленность** | **85** |
| **08** | **добывающая промышленность (нефть, газ, руда)** | **304** |
| **09** | **металлургия** | **39** |
| **10** | **металлургия (вторая редакция классификатора)** | **66** |
| **11** | **машиностроение и обработка** | **173** |
| 12 | инженерные сети (котельные, водопровод) | 2 266 |
| 19 | жильё | 60 |
| 20 | дороги | 82 |

Внимание: в `api/Kosfn` лежат **две редакции** классификатора с разной
нумерацией (есть и «09 Металлургия», и «10 Металлургия»), поэтому берём оба
номера — в данных встречаются оба.

Берём (`SECTIONS_PROM` в коде): разделы `06. 07. 08. 09. 10. 11.` плюс два
промышленных вкрапления раздела 01:

* `01.01.006` — объекты промышленных площадок (промпарк, логистический центр) — 160;
* `01.06.001` — производственно-техническое здание, склад, АБК — 99.

Не берём по умолчанию `05.` (энергосети) и `12.` (коммуналка) — это не
производство; кому нужно, есть `SECTIONS_ENERGO` (`05.`, `12.01.001.002`
здание котельной), 100+ записей за 90 дней.

### 5.2 Остальные условия запроса

* `ExpertiseConclusionDate gt <дата>` — глубина `days`;
* `ExpertiseResultType eq 'Положительное заключение'` — за 90 дней 16 890
  положительных против 792 отрицательных (отрицательное = проект завернули);
* `WorkType` — берём `Строительство` и `Реконструкция`. Распределение за 90
  дней: капитальный ремонт 9 098, строительство 6 578, реконструкция 1 726,
  сохранение ОКН 177, снос 103. Капремонт отбрасываем: там нового оборудования
  почти не берут;
* `regions` — коды субъектов (`'22'`, `'34'`) уходят в серверный фильтр
  `SubjectRfCode eq '..'`, названия («Московская область») фильтруются на нашей
  стороне по `SubjectRf`;
* `keywords` — необязательное `contains(tolower(ExpertiseObjectName),tolower('…'))`.

### 5.3 Клиентский отсев

`_STOP_RE` выбрасывает жильё, соцобъекты и дороги, если они просочились в
отраслевой код (например аптека с кодом фарм-производства): жилой/многоквартирный,
общежитие, детский сад, школа, больница, поликлиника, аптека, храм, стадион,
бассейн, благоустройство, автомобильная дорога, улица, тротуар, освещение и т.п.
За 90 дней так отсеивается 30 записей из 1 156.

Флаг `require_prod_kw=True` включает жёсткий гейт по производственной лексике
(завод/цех/производство/линия/элеватор/…): 161 → 126 записей за 14 дней.

## 6. Технические ограничения сервиса (замерено)

| что | значение |
|---|---|
| `$top` | **максимум 150**; `$top=200` и выше → `400` |
| `$skip` | работает, проверено на `$skip=100000` |
| `$top` внутри `$apply/groupby` | максимум 150; без `$top` groupby молча режется на 150 группах |
| `$skip` вместе с `$apply` | `400` — не поддерживается |
| `$filter=Key eq <guid>` | `400` (несовместимые типы), фильтровать по `ExpertiseNumber` |
| капча / 429 | не наблюдались: залп из 15 запросов подряд — все `200` |
| скорость | полная выборка за 90 дней (8 страниц, 1 126 записей) — **4,1 с** |
| TLS | сертификат Russian Trusted CA → ходим мимо системного прокси с неверифицирующим контекстом (как в `news_scan._get`) |
| доступность | **только с российского IP**; из контейнера сессии — `CONNECT tunnel failed 502` |

## 8. Как запускать и как встроить

```bash
# ручной прогон на сервере владельца (из seo-texts/server)
python run_script_on_server.py collector_egrz.py 300     # печатает первые 10 + сводку

# регрессия параметров (импортирует уже залитый модуль из C:\sender\_tmp)
python run_script_on_server.py _probe_egrz_16.py 330
```

Локально (из РФ) модуль работает и сам: `python collector_egrz.py [days] [max_items]`.

Встраивание в `news_scan.py` (делает главная сессия, здесь только рекомендация):

* добавить `egrz` в список коллекторов, вызов `col_egrz(days=args.days, max_items=…)`;
* **капекс-предфильтр `_CAPEX_KW` для этого коллектора не нужен** — реестр уже
  отфильтрован по КОСФН, как у `zakupki`/`frp`;
* при записи в `signals`: `inn` брать из item напрямую, dadata **не звать**
  (`inn_conf='high'`), `stage='проект'`, `event_date` уже в ISO (задача 6 ТЗ),
  `sum` оставить пустым;
* `company_name` — наименование как в ЕГРЮЛ (именительный, капсом);
  `company_name_short` — то же с аббревиатурой ОПФ (`ООО "…"`) для заголовков;
* дедуп: ключ — `link` (он содержит `Key` заключения), он же канон-URL.

Побочный эффект в пользу задачи 4 ТЗ (доопределение компании): по названию
объекта из безымянной новости можно искать в ЕГРЗ
(`contains(tolower(ExpertiseObjectName),tolower('<объект>'))`) — в заключении
застройщик назван юрлицом с ИНН.

## 9. Что делать, если сломается

Ломаться может ровно в трёх местах, чинится по порядку:

1. **Сменился базовый URL API.** Запустить `_probe_egrz_5.py` — он скачивает
   `https://egrz.ru/main.bundle.js`, вытаскивает все `*.egrz.ru`-адреса и
   присваивания конфига (`PublicPortal_API`, `publicAPI` и т.д.). Подставить
   новый адрес в `API` в `collector_egrz.py`. Если поменялись и сами ручки —
   `_probe_egrz_3.py` вытаскивает из бандлов полный список путей `api/…`.
2. **Сменились имена полей или лимиты.** Запустить `_probe_egrz_13.py` —
   он печатает лимиты `$top`/`$skip`, счётчики по разделам КОСФН и долю записей
   с ИНН. Актуальную схему всегда даёт `GET /api/$metadata`, а на неверное поле
   сервис отвечает `400` с перечислением типа — имя поля видно из ошибки.
   В коде предусмотрен **фолбэк**: если составной `$filter` отвергнут (`400`),
   `col_egrz` перезапрашивает только по дате и фильтрует разделы/регионы
   на своей стороне — поток не встаёт, просто медленнее.
3. **Сменился фронт (ссылка на карточку).** Маршрут
   `organisation/reestr/detail/:key` берётся из `path:"…"` в бандле — искать там
   же, `_probe_egrz_14.py` удалён, но однострочник тот же:
   `re.findall(r'path\s*:\s*"([^"]{0,60})"', bundle)`. Данные от этого не
   страдают: ломается только человеческая ссылка, API отдельно.

Вёрстку HTML не парсим вообще — работаем с JSON-API, поэтому смена вёрстки
портала на коллектор не влияет.

## 10. Ограничения, о которых надо помнить

* **Только российский IP.** Из контейнера сессии источник недоступен
  (`curl: (56) CONNECT tunnel failed, response 502`); всё гонять через
  `run_script_on_server.py`.
* **Нет сметы** (раздел 4) — это ограничение источника, не кода.
* **Реестр публикует заключение, а не проект.** Между заключением и стройкой
  обычно месяцы, но бывает и отказ от проекта — это гипотеза о капексе
  с подтверждением от экспертизы, а не гарантия стройки.
* **Негосударственная экспертиза (7 329 из 17 682 за 90 дней)** попадает
  в реестр так же, как государственная, — оба типа берём.
* **Застройщик ≠ будущий покупатель в 100% случаев:** на промплощадках
  застройщиком иногда выступает УК парка или ДЗО. ИНН при этом верный,
  ОКВЭД проверяется на нашей стороне (`icp_fit`/`division`).
* 8% записей без ИНН застройщика — обычно иностранные лица и физлица;
  для них остаётся обычный путь `dadata_suggest` по имени.
* Лимиты по частоте формально не объявлены и не встречены, но сервис
  государственный: пейсинг не наглее текущего (страница 150 записей, 8 запросов
  на полную выборку за 90 дней).
