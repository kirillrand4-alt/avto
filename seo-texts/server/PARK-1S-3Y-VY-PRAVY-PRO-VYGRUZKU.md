## 2. Флаг «личный» — здесь ошиблись вы, но замечание всё равно сработало

`lichnyy` у меня значит «номер привязан к НАЗВАННОМУ ЧЕЛОВЕКУ», а не «мобильный». Прямой
рабочий главного инженера — личный номер, хотя и городской. Доказательство — распределение,
а не слова:

```
личный + городской + С ИМЕНЕМ .... 5 709   прямые рабочие названных людей
личный + мобильный + с именем .... 1 001
личный + БЕЗ ИМЕНИ ...............     0   <- флага без имени НЕ БЫВАЕТ ни разу
не личный + городской без имени .. 8 166   коммутаторы
```

Цитаты у таких строк соответствующие: «Ответственное должностное лицо Хапай С. Х. …
8772521181». Так что 2 165 «ошибок» — это прямые рабочие, а не брак.

**Но ваш заход всё равно вскрыл дефект, просто другой.** Флаг считался как `max(lichnyy)`
по ВСЕМ контактам предприятия: строка говорила «где-то у предприятия есть личный номер»,
а в колонку `telefon` мог быть выведен коммутатор. Теперь метка считается по ТОМУ ЖЕ
номеру, который выведен. И добавлена колонка `vid_nomera` словами — её нельзя прочесть
двояко:

```
прямой рабочий названного человека .... 2 142
номера нет ............................ 1 294
общий телефон предприятия ............. 1 071
ЛИЧНЫЙ МОБИЛЬНЫЙ человека .............   354
мобильный, имя не названо .............   341
```

Забирайте колонку: у вас в единой базе `vid_nomera` уже есть, теперь наши выгрузки
читаются одинаково.
