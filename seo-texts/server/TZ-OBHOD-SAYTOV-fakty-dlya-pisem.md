# ТЗ на обход сайтов: факты о продукции для холодных писем

Кому: сессии, которая ведёт новый инструмент обхода.
От кого: 1-я сессия (панель рассылки).
Дата: 2026-08-13.

## Для чего это нужно

Письма Meyer и КЦ пишутся не «вообще», а под конкретное предприятие: во втором
абзаце письмо называет, что это предприятие выпускает. Сейчас генератор берёт
единственное поле `companies.activity` из enrich.db, и когда там пусто или одна
строка — модель начинает пересказывать **название ОКВЭД** как продукцию. Это
выглядит как знание, а на деле догадка, и она бьёт по доверию сильнее, чем
шаблон.

Замерено 13.08 на живой очереди:

* «Машины Сладости» — мы написали «производит конфеты-суфле **и какао-порошок**».
  Какао-порошка у них нет: это название кода ОКВЭД 10.82 «производство какао,
  шоколада и сахаристых кондитерских изделий».
* «Грилата» — приписали «сухари и печенье», хотя на деле замороженные
  хлебобулочные с начинкой для HoReCa.
* «Благодар-НН» — «продукция из птицы», хотя птица там не основное.
* Снабженческому кооперативу — «консервы и полуфабрикаты», которых нигде нет.

Слепое сравнение наших писем с письмами живого редактора (провайдерская модель
судит, карточка компании перед глазами): по оси «конкретность к получателю» у
редактора 4,11, у нас 2,89. Разрыв ровно в одном — она **открывает сайт** и
пишет про их продукт, а мы пересказываем классификатор.

Показательный случай: АО «Пивкомбинат „Балаковский“». По вывеске — пиво, по
основному ОКВЭД 10.72.31 и по сайту — печенье, пряники, вафли, зефир, мармелад.
Редактор это увидела и написала про кондитерку, попав точно. Никакая работа с
ОКВЭД такого не даёт — только текст сайта.

Дальше эти факты идут в две точки: в промпт генератора (можно утверждать только
то, у чего есть источник) и в гейт (утверждение без источника — брак письма).

## Какие страницы сохранять

По каждому домену, в порядке приоритета. Достаточно 5-8 страниц на компанию.

1. **Главная** — всегда.
2. **Каталог / продукция / ассортимент** — самое ценное.
   Пути и куски URL: `catalog`, `produkciya`, `produkty`, `product`, `tovar`,
   `assortiment`, `nashi-produkty`, `shop`.
   Если каталог разбит на группы — сохранить и **второй уровень**: страницы
   групп («печенье», «пряники», «замороженные полуфабрикаты»). Карточки
   отдельных SKU не нужны, достаточно групп.
3. **Производство / технологии** — `proizvodstvo`, `production`, `tehnologii`,
   `zavod`, `moshchnosti`.
4. **О компании** — `about`, `o-kompanii`, `o-nas`, `company`, `history`.
5. **Качество и сертификаты** — `kachestvo`, `quality`, `sertifikat`,
   `certificate`, `haccp`, `iso`, `laboratoriya`.
6. **Новости** — `news`, `novosti`, `press`, `smi`, `blog`, `sobytiya`:
   последние 5-10 записей вместе с датами. Подробнее — отдельным разделом ниже.

Контакты обходить не надо — они уже собраны другим конвейером.

Сохранять и **сырой текст** страницы (без тегов), и её URL: по тексту потом
перепроверяются спорные факты, без него доверять нечему.

## Что из них нужно вытащить

Одна запись на предприятие, ключ — ИНН. Все значения — словами сайта, без
пересказа и без обобщений.

| Поле | Что это | Пример |
|---|---|---|
| `продукция` | до 12 позиций или групп | «печенье, пряники, вафли, зефир, мармелад» |
| `упаковка_фасовка` | в чём выпускают | «флоу-пак», «ведро 5 кг», «стеклобутылка 0,5» |
| `сырьё` | что заходит на вход | «орехи, сухофрукты, молоко-сырьё» |
| `мощности` | **только фразы с числом** | «180 тыс. тонн единовременного хранения» |
| `контроль_качества` | дословные упоминания | «ХАССП», «ISO 22000», «собственная лаборатория», «металлодетектор» |
| `новости` | до 10 записей за последний год: дата, заголовок, url, 2-3 предложения дословно (см. отдельный раздел) | |
| `свежая_новость` | первая подходящая из `новости` | «Запущена новая линия фасовки, 12.06.2026» |
| `цитата` | одна буквальная строка со страницы, подтверждающая продукцию | |
| `источники` | список URL, откуда всё взято | |
| `уверенность` | высокая / средняя / низкая | |

Пустое поле — нормальный результат. **Пустое лучше правдоподобного.**

## Новости — отдельно и подробно

Второе, чего нам не хватает, и по важности оно вровень с продукцией. Судья в
слепом сравнении дважды проиграл нам письмо одной и той же формулировкой: «нет
ни одного повода обратиться именно сейчас — ни новости, ни события, ни
публичного факта». У редактора этот повод есть, и её сильнейшие письма стоят
именно на нём:

* «Прочитал о модернизации и расширении молочного производства на „Молзаводе
  Мясниковский“ — переработка молока растёт с 200 до 350 тонн в сутки».
* «Увидел информацию о запуске новых мощностей „Башмаковского элеватора“.
  Общая мощность предприятия теперь около 180 тыс. тонн».

Новостной скан по внешним источникам у нас есть, но он ловит только тех, кто
попал в СМИ. Средний завод в СМИ не попадает, а на своём сайте про новую линию
пишет обязательно — поэтому сайт тут не дубль внешнего скана, а основной
источник.

**Что сохранять по каждой новости:**

| Поле | Пояснение |
|---|---|
| `дата` | как на сайте; без даты новость бесполезна — «недавно» писать нельзя |
| `заголовок` | дословно |
| `url` | прямая ссылка на запись |
| `текст` | первые 2-3 предложения, дословно |

Глубина — записи **за последние 12 месяцев**, до 10 штук. Если на сайте есть
архив за годы, старше года не тянуть.

**Что для нас ценно** (по этим поводам письмо и строится):

* запуск, модернизация, расширение линии, цеха, склада, элеватора;
* рост мощности или объёма переработки — особенно **с числом**;
* новый продукт, новая упаковка, новое направление;
* сертификация: ХАССП, ISO 22000, халяль, органик, «прошли аудит сети»;
* новое оборудование любого рода — прямой сигнал, что предприятие вкладывается;
* выход в новую сеть или регион, экспорт;
* награда на отраслевой выставке (Продэкспо, Агропродмаш, ЮГАГРО).

**Что шум и в письме бесполезно:** поздравления с праздниками, дни рождения,
корпоративы, «мы работаем в штатном режиме», перепечатки чужих отраслевых
новостей, вакансии не по профилю.

**Формат в записи предприятия:** массив `новости[]` c полями выше, отсортированный
по дате, свежая первой. Поле `свежая_новость` из таблицы — просто первая
подходящая из этого массива.

**Почему важна дословность и дата.** Письмо в режиме НОВОСТЬ начинается с
пересказа события своими словами: «Прочитал о запуске цеха переработки ягоды в
Балашихе». Если событие пересказано неточно или оно двухлетней давности, письмо
превращается в позор на весь отдел продаж — получатель отвечает «это было в
2024 году». Поэтому дата обязательна, а текст берётся дословно: пересказывать
будем мы, а не обходчик.

### Три запрета, без которых работа теряет смысл

1. **Ничего не выводить из ОКВЭД.** Код — классификатор, а не ассортимент.
2. **Ничего не выводить из названия компании.** «Пивкомбинат» может делать
   печенье, «Молзавод» — мороженое.
3. **Не обобщать до отрасли.** «Молочная продукция» вместо «масло, крем-сыр,
   сыр» бесполезна: такая фраза подходит любому заводу и в письме читается как
   массовая рассылка.

## Куда складывать

`C:\sender\enrich.db`, таблица уже заведена:

```sql
CREATE TABLE IF NOT EXISTS site_facts(
    inn TEXT PRIMARY KEY,
    facts_json  TEXT,   -- поля из таблицы выше
    sources_json TEXT,  -- список URL
    site TEXT,
    ts   TEXT,          -- когда собрано
    note TEXT           -- почему пусто, если пусто
);
```

Если у инструмента своё хранилище — годится любое, лишь бы по ИНН, с URL и
цитатой, и чтобы результат лежал на СЕРВЕРЕ (песочница при рестарте
откатывается, файлы-накопители пропадают).
