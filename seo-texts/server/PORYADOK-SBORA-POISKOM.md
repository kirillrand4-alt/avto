# Сбор компаний с нуля поиском — как это было сделано (07–08.10)

Результат: база КЦ (383 компании от 1,5 млрд, 281 с номером) и файл 6 Meyer (1 049 компаний, 578 с номером)
по 6 отраслям: молоко, сыры, мясо, хлеб, корма, напитки (напитки — только КЦ).

Все «агенты» — серверные процессы на машине владельца (C:\sender\server), запускаются детачем,
пишут результат в `*.jsonl` с fsync и продолжают с места при перезапуске. Модель — через провайдерский
API, поиск — xmlriver (Яндекс). Оркестраторы: `poisk_konveyer.py` (КЦ), `meyer6_konveyer.py` (файл 6).

## Правила, которые держались на всех шагах

- Номер — только с живой страницы сайта самой компании (или её холдинга, с пометкой) или с карточки
  закупки, где компания — заказчик. Справочники (checko, rusprofile, list-org) — только для поиска
  компаний и ОКВЭД, не для номеров.
- Каждый вывод модели или агента проверяет скрипт по реально скачанной странице.
- Сделки и запреты панели, ликвидированные — исключены; проверено по готовому файлу.
- Тяжёлая работа модели — через провайдерский API; всё — durable на сервере, с резюмом.

## Что пошло не так и чем исправлено

- Ночью встал отбор: на сервере не было `meyer_baza.py` (тесты шли через раннер и его не замечали) →
  проверка импорта всех агентов в «фоновом» режиме перед запуском.
- Совпадение названия принимало чужие сайты (общие слова, однофамильцы) → проверка сайта моделью.
- Сайт холдинга с несколькими ИНН считался каталогом (mlkgroup.ru) → «кандидат сайт группы» + модель.
- Модель проверяла только подписанные номера → проверка всех номеров.
- Кончились балансы xmlriver и провайдера → остановка конвейера, удаление пустых вердиктов,
  продолжение с того же шага после пополнения.
