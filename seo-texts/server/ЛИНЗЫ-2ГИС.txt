**Ключ во всех файлах — одно и то же значение, дословно:**

- `_ops_map_2gis.py`: `КЛЮЧ = 'ruxlih0718'`
- `_ops_map_2gis2.py`: `КЛЮЧ = 'ruxlih0718'`
- `_ops_map_2gis3.py`: `КЛЮЧ = 'ruxlih0718'`
- `_ops_map_probe0.py`: `демо = 'ruxlih0718'`
- `_ops_map_probe1.py`: `КЛЮЧ = 'ruxlih0718'`
- `_ops_map_probe2.py`: `КЛЮЧ = 'ruxlih0718'`
- `_ops_map_probe3.py`: `КЛЮЧ = 'ruxlih0718'`
- `_ops_map_probe4.py`: `КЛЮЧ = 'ruxlih0718'`

**Это публичный демо-ключ. Признаки:**

1. В `_ops_map_probe0.py` автор сам называет переменную `демо`: `демо = 'ruxlih0718'` — прямая авторская маркировка.

2. В `_ops_map_probe3.py` скрипт *ищет боевой ключ* в JS-бандлах 2ГИС, используя паттерн `r'\b(ru[a-z]{4}\d{4})\b'`. Сам ключ `ruxlih0718` точно подпадает под этот же паттерн (`ru` + 4 буквы + 4 цифры) — то есть он уже был известен до разведки, а скрипт пытается найти **другой**, небоевой/боевой ключ веб-приложения. Это означает: `ruxlih0718` — стартовая точка (демо), боевой ключ ищется отдельно.

3. В `_ops_map_probe3.py` намерение сформулировано в заголовке раздела: `# ---------- (a) боевой ключ веб-приложения` — противопоставление демо-ключу явное.

**Вывод:** все замеры (probe0–probe4, замер 1–3) сделаны ОДНИМ ключом `ruxlih0718`, который автор кода идентифицировал как демо-ключ. Замеры поключу не независимы: если демо-ключ урезает `contact_groups.contacts[].comment`, этоограничение одинаково затронуло все восемь скриптов.

**Где берётся подпись — дословная цитата**

Во всех трёх измерительных файлах функция `контакты()` идентична:

```python
out.append((c.get('type'), c.get('value') or '',
            (c.get('comment') or '').strip(),
            c.get('text') or '', c.get('url') or ''))
```

Подпись — это `c.get('comment')`, поле `comment` объекта контакта из `contact_groups[].contacts[]`ответа API.

Затем «телефон с подписью» в _ops_map_2gis.py и _ops_map_2gis2.py:

```python
тел = [(v, ком) for (тип, v, ком, t, u) in кс if тип == 'phone']
подп = [(v, ком) for v, ком in тел if ком]
```

В _ops_map_2gis3.py:

```python
if ком:
    ст['тел_подпись'] += 1
```

Условие одно: `тип == 'phone'` и `ком` (непустой `comment`).

---

**Откуда подпись берётся — только из API**

Подпись не берётся из:
- названия карточки (`it.get('name')`)
- рубрики (`items.rubrics`)
- адреса
- текста страницы (scraping не применяется в измерительных файлах)

Источник строго один: поле `comment` в API-объекте контакта.

---

**Расхождение: probe4 vs измерительные файлы**

В _ops_map_probe4.py при поиске «а есть ли подписи вообще» используется более широкое выражение:

```python
подпись = (c.get('comment') or c.get('description')
           or c.get('label') or '').strip()
```

В измерительных файлах (_ops_map_2gis.py /2gis2.py / 2gis3.py) — только `c.get('comment')`. Если реальные подписи лежат в `description` или `label`, измерительный код их пропустит и занижает счётчик.

---

**Может ли в подпись попасть лишнее**

С точки зрения кода — нет: подпись — это исключительно API-поле `comment` у контакта с `type == 'phone'`, никакая другая часть карточки туда не подмешивается. Что именно 2ГИС кладёт в это поле (тип организации, название филиала, адрес) — кодом не проверяется и не доказано.

**Какой прогон мог дать «86 телефонов с подписью»**

Подходят все три основных файла: `_ops_map_2gis.py`, `_ops_map_2gis2.py`, `_ops_map_2gis3.py`. Все три считают счётчик `тел_подпись` и по умолчанию берут `n = 20` компаний:

```python
n = int(sys.argv[1]) if len(sys.argv) > 1 else 20
```

**Что именно считалось**

В `_ops_map_2gis.py` и `_ops_map_2gis2.py` логика одинакова:

```python
тел = [(v, ком) for (тип, v, ком, t, u) in кс if тип == 'phone']
подп = [(v, ком) for v, ком in тел if ком]
ст['тел_подпись'] += len(подп)
```

`тел_подпись` — телефоны из сматченных карточек, у которых поле `comment` непустое. В `_ops_map_2gis3.py` то же, но по всем найденным карточкам организации, а не первой:

```python
ifком:
    ст['тел_подпись'] += 1
```

**Есть ли знаменатель**

Да, счётчик `тел_всего` явно объявлен и печатается в ИТОГ. В `_ops_map_2gis.py` и `_ops_map_2gis2.py`:

```python
ст = {'компаний': len(пул), 'карточка': 0, 'тел_всего': 0, 'тел_подпись': 0, ...}
```
```python
ст['тел_всего'] += len(тел)
```
```python
P('ИТОГ 2ГИС: ' + json.dumps(ст, ensure_ascii=False))
```

В `_ops_map_2gis3.py` аналогично: `'тел_всего': 0` и `ст['тел_всего'] +=1` внутри цикла по контактам.

**Вывод**

Число 86 — рантаймовый результат, его в коде нет. Что код считал — доказано: `тел_подпись` = телефоны с непустым `comment` по сматченным карточкам. Знаменатель `тел_всего` в коде присутствует и выводится в тот же ИТОГ. Если в отчёте `тел_всего` рядом с «86» не приведён — это упущение отчёта, а не отсутствие в коде.

**1. Совместимость с наблюдением в браузере**

Возможен — и код именно для этого сравнивает оба источника. В `_ops_map_probe3.py`:

Код прямо строит сравнение: API-ответ по `items/byid` против живой страницы через браузер. Логика probe3 предполагает, что они могут расходиться.

**3. Есть ли в коде доказательство, что подпись хоть раз пришла НЕПУСТОЙ**

Не доказано. Код содержит механизм сбора примеров (если они есть), но не фиксирует конкретных значений.

В `_ops_map_probe4.py`:

подпись = (c.get('comment') or c.get('description')
           or c.get('label') or '').strip()

**Рубеж «телефон отдела vs. телефон компании»**

В коде есть только один фильтр: наличие непустого `comment` у контакта.

`_ops_map_2gis.py`:
```python
подп = [(v, ком) for v, ком in тел if ком]
ст['тел_тех'] += sum(1 for v, ком in подп if ТЕХ.search(ком))
```

`_ops_map_2gis2.py`:
```python
подп = [(v, ком) for v, ком in тел if ком]
ст['подпись_тех'] += sum(1 for v, k in подп if ТЕХ.search(k))
```

`_ops_map_2gis3.py`:
```python
ifком:
    ст['тел_подпись'] += 1
    подписи.append((канд[0][:24], v, ком))
    if ТЕХ.search(ком):
        ст['подпись_отдел'] += 1
```

Итого: «телефон отдела» = телефон с непустым `comment`, совпадающим с ТЕХ-регуляркой. Это слабый критерий — 2ГИС можетставить `comment` и на общий номер («Многоканальный», «Справочная»).

---

**Проверка «найденный номер ≠ уже известный»**

Не доказано. Ни в одном из трёх файлов нет кода, который вычитает `c['phones']` из найденных телефонов перед подсчётом.

Напротив, `c['phones']` используется исключительно для верификации карточки:

`_ops_map_2gis.py`:
```python
if c['phones'] and (тел10 & set(c['phones'])):
    карта, чем = it, 'телефон'
    break
```

`_ops_map_2gis2.py`:
```python
elif c['phones'] and (тел10 & set(c['phones'])):
    карта, чем, запрос = it, 'телефон', q
```

После того как карточка принята, все её телефоны идут в счётчик без вычитания уже известных:

`_ops_map_2gis.py`:
```python
тел = [(v, ком) for (тип, v, ком, t, u) in кс if тип == 'phone']
ст['тел_всего'] += len(тел)
```

**Следствие:** номер из `c['phones']`, которым карточка была верифицирована, учитывается в `тел_всего` и, если у него есть подходящий `comment`, попадает в `тел_тех` / `подпись_отдел`. Источник мог «находить» те же номера, что уже есть в базе, и засчитывать их как новые находки — ограничитель против этого в коде отсутствует.

ЛИНЗА: вердикт  (64.6 с)
======================================================================
**Что доказано кодом:**

Структура извлечения подписей существует и последовательна во всех трёх замерах. В функции `контакты()` (одинаковой в `_ops_map_2gis.py`, `2gis2.py`, `2gis3.py`):
```python
out.append((c.get('type'), c.get('value') or '',
            (c.get('comment') or '').strip(),
            c.get('text') or '', c.get('url') or ''))
```
Поле `comment` читается; счётчики `тел_подпись`, `тел_тех`, `подпись_отдел` определены и накапливаются. Регекс ТЕХ для фильтрации «ценных» подписей присутствует. Зонд `probe4.py` специальноищет примеры подписей в широком скане100+ карточек и печатает их. Это доказывает: **архитектура для получения подписей корректна**.

**Что прямо опровергнуто кодом:**

Докстринг `_ops_map_probe3.py` — дословно:
```
"""Шаг 3: демо-ключ 2ГИС отдал ОДИН телефон без подписи. Это правда или урезка?"""
```
Это зафиксированный факт исполнения, а не гипотеза. На демо-ключе `ruxlih0718` подписей **не было**. Весь `probe3` написан, чтобы выяснить, ключ урезает данные или их нет вовсе.

**Что не доказано:**

- Вывода (`ИТОГ 2ГИС:`, `ИТОГ 2ГИС2:`, `ИТОГ 2ГИС3:`, `(1) карточек просмотрено:`) в коде нет — только код печати. Реальных цифр `тел_подпись > 0` или конкретных примеров подписей нигде не видно.
- Подтверждения, что платный ключ снимает ограничение, нет. `probe3`ищет боевой ключ из бандлов 2ГИС (`(a)`) и рендерит живую страницу (`(c)`) именно для проверки этой гипотезы — но результаты исполнения отсутствуют.
- «Телефоны отделов» как отдельные карточки проверяются в `probe2.py` и `2gis3.py`, но счётчик `карточек_отдел_в_имени` без итогов ничего не доказывает.

**Вердикт:**

Утверждение «2ГИС даёт телефоны отделов с подписями» кодом **не подтверждается**. Доказано только то, что поле `comment` существует в схеме API и код умеет его читать. Против: на демо-ключе подписей не было (зафиксировано в docstring). Являетсяли это ограничением демо-ключа — открытый вопрос; код написан для его проверки, но результатов проверки нет. Покупать платный ключ на основании этого кода **не обосновано**: нет ни одного зафиксированного примера подписи, полученной через API.
