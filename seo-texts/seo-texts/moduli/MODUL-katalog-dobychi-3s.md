# Что мешает собрать «вбил ИНН — получил всё» прямо сейчас

Перечислено по убыванию цены доработки.

1. **`sender/company_card.py` не имеет CLI.** Готовая функция `build_company_card(inn)` возвращает всё, что у нас есть в двух базах, одним dict — нужна обёртка на 15 строк. Это дешевле любого нового модуля.
2. **`mpb_harvest.py` не разбирает страницу заказчика.** Скрипт сам строит адрес `monitor-pb.ru/customer/<ИНН>` в колонку `istochnik_zakazchik` (`mpb_harvest.py:97`), то есть страница «все заключения по этому ИНН» существует и известна. Разбора нет. Это единственный реестр, где по ИНН сразу видно, какие машины у предприятия и когда кончается срок.
3. **`tenderpro_harvest.py` не пользуется полем `company_name`.** Запрос к `/api/tenders/list` уже содержит `company_name` и `company_id`, оба захардкожены пустыми (`:215–219`). Одна строка правки — и площадка становится по-компанийной.
4. **Три модуля указывают в мёртвую песочницу** `520847fd-7699-5483-869b-cf6d49851f67`: `razdely_probe.py:6`, `razdely_razbor.py:13`, `lica_stranic.py:27`, плюс `inn_po_nazvaniyu.py:40` (`master-base.sqlite`) и умолчание `RUNNER_CLIENT` в `tender_centro_scan.py:90`. Переменной окружения для подмены нет ни у одного, кроме последнего.
5. **Сведение читает зашитые списки файлов.** `svesti_obzvon.py:121–155`, `svesti_vseh_lyudej.py:115–171`, `accumulate_contacts.py:37–42`+`:175`, `doobogatit_obhod.py:82`. На этом уже обожглись: `svesti_obzvon.py` читал 5 файлов из 10 и дал 385 строк вместо 3 727.
6. **`XMLRIVER_USER`/`XMLRIVER_KEY` у владельца, не у сессий.** Без них закрыты `lpr_serp.py`, `sayty_dlya_celey.py`, `serp_only_3s.py`, `people_sources.py`, `newsco_op.py` — то есть вся группа «выдача», а это единственная группа, где технического руководителя вообще называют по должности.
