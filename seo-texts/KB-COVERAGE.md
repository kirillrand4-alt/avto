# Аналитика базы знаний: вероятность упустить важное при генерации

Дата: 2026-07-16. Метод: не прикидка, а замеры - стресс-тест ретрива писем на
56 сценариях, сконструированных из самой базы, + грепы готовых текстов + матрица
подключения активов к конвейерам.

## 1. Письма (email-ассистент)

Ретрив - главное место потерь: модель отвечает только той фактурой, которую
ей достали из базы. Замер попаданий (сценарии из реальных моделей/брендов/отраслей):

| Сценарий письма | До фиксов | После фиксов |
|---|---|---|
| Бренд + модель («интересует Berg ВК-10Е») | 100% | 100% |
| Только артикул («нужен КМ-АДСГ-10.5») | **10%** | **100%** |
| Бренд кириллицей («по компрессорам ремеза») | 50% | 100% |
| Отрасль без модели («мы рыбхоз, что посоветуете») | 100% | 100% |

Фиксы: модельный индекс на 24 117 нормализованных токенов (kp-база 1588 моделей
+ 27к названий битрикса, включая биграммы «Formula I 45-10» / «РВ 500.11.02»),
транслитерация кириллических брендов + алиасы (абак->abac, кезер->kaeser).

**Остаточная вероятность упустить фактуру ретривом: <5%** (опечатки в артикулах,
сленг («воздушник на 500 литров»), модели, которых нет ни в КП, ни на сайте).

Но есть категории, где упущение пока ГАРАНТИРОВАНО (данных нет в базе):

| Категория | Риск | Что сделать |
|---|---|---|
| Наличие на складе | 100% - данных нет | выгрузка остатков (1С/битрикс) на дроп |
| Сроки поставки по брендам | 100% - данных нет | таблица от менеджеров |
| Снятые серии (клиент просит снятое) | 100% - не подключено | подключить kb/snyatye-verdict.json стоп-листом (готов) |
| Модель у поставщика, но нет на сайте | 100% - не подключено | подключить gap-анализ («можем под заказ») |
| Матрица скидок/полномочий | 100% - данных нет | от владельца |

Второй слой потерь - модель получила фактуру, но не использовала. Контроль:
поле used_facts в ответе + QA-гейт + спарринг с менеджерами (этап 5б плана).
По сухому прогону: 2 случая из 14, когда факты были в базе, но в черновик не
попали / попали выдуманные (замена модели не из базы, ценовой якорь). Лечится
жёстким правилом в плейбуке («замены только из базы») - внесено.

## 2. Тексты (759 каталожных, гост-посты, будущая карточная программа)

Матрица «актив базы -> подключён ли к конвейеру»:

| Актив | 759 текстов | Гост-посты | Карточки (буд.) |
|---|---|---|---|
| payload страниц (цены, счётчики) | ДА | - | нужно |
| brand_facts (гейт достоверности) | ДА | вручную | нужно |
| Проекты (1017) | ДА (59 ссылок вплетено) | вручную (case) | нужно |
| КП-база (гарантии, блоки, claims) | ЧАСТИЧНО* | НЕТ | нужно |
| Фотобанк (351 карточка, alt) | НЕТ | НЕТ | нужно |
| Снятые серии (стоп-лист) | НЕТ | НЕТ | КРИТИЧНО |
| Энгер топ-10 фактов | НЕТ | НЕТ | нужно |

*Замер по готовым 759: винтовые блоки (HANBELL/BAOSI/GHH) упомянуты в 552
текстах (пришли через brand_facts), расширенная гарантия 5 лет/60 мес - только
в 137. КП-база создана ПОСЛЕ генерации, так что глубокая фактура (конкретные
серии, claims, параметры моделей) в текстах отсутствует закономерно.

**Вероятность упущения для НОВЫХ текстов** (гост-посты, карточная программа),
если конвейер не менять: факты КП-базы/фотобанка - упускаются с вероятностью
~100% (физически не в промпте). После подключения - определяется ретривом,
и его можно замерить так же, как для писем.

**Главный операционный риск: снятые серии.** Ни один конвейер сейчас не знает,
что Fini TERA или старые Dali DL сняты - текст или письмо могут их рекламировать.
Стоп-лист из 17 подтверждённых серий готов (kb/snyatye-verdict.json), подключение -
одна проверка в QA-гейте.

## 3. Приоритет действий

1. Стоп-лист снятых серий в QA-гейт текстов И писем (полчаса, риск-фикс).
2. Выгрузка остатков склада + сроков поставки на дроп (от тебя) - закрывает
   самый частый тип письма «наличие/сроки».
3. Блок «фактура бренда из КП-базы» в промпт генерации новых текстов
   (гост-посты уже в очереди - успеть до масштабирования).
4. Для карточной программы - собрать retrieval как у писем (модельный индекс
   уже есть) + фотобанк.
5. Ежемесячный автозамер ретрива (скрипт готов) при обновлении базы.
