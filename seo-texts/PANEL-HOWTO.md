# Веб-панель: как грузить базу, домены, настраивать тайминг (ответы + пробелы)

Разбор по коду на 2026-07-20. Разделяю «работает сейчас» и «нужна доработка
инженером». Панель (`api/app.py`) — тонкий слой: часть операций только на чтение,
конфиг движка (домены, окно, пейсинг) сейчас в `config/sender.yaml`, не в панели.

---

## 1. Загрузка базы (+ разделение Мейер / КЦ)

**Сейчас:** загрузка базы — НЕ в панели, только CLI:
```
python -m sender.cli import <путь.csv> [--map email=Email,segment=База] [--limit N]
```
Импортёр (`importer.py`) сам детектит кодировку/разделитель и колонки; понимает
поле `segment` (колонка `segment`/`сегмент` — сюда ложится «База» = Компрессор
Центр / Meyer). Дедуп по email через upsert.

**Панель:** экран получателей (`GET /recipients`) — только просмотр/фильтр.
Кнопки «загрузить CSV» НЕТ.

**⚠️ Разделение КЦ/Meyer — сейчас НЕ работает как надо.** Поле `segment` в базу
пишется, но планировщик кампаний (`cadence.plan_campaign`) берёт получателей через
`iter_recipients(valid_status="valid")` — фильтра по сегменту/кампании там НЕТ.
То есть **каждая активная кампания уходит по ВСЕМ валидным получателям**, КЦ и
Meyer не разведены. У получателя нет `campaign_id`, а `iter_recipients` фильтрует
только по `valid_status` и `mx_provider`.

Что нужно (в промпт инженеру): фильтр `segment` в `iter_recipients` + привязка
кампании к сегменту/аудитории (кампания «КЦ» тянет segment='kc', «Meyer» —
segment='meyer'), и загрузка CSV с выбором сегмента прямо в панели.

**Обход прямо сейчас (без доработки):** две отдельные БД/инстанса или ручной
прогон одной кампании за раз с заранее отфильтрованной по сегменту базой.

## 2. Загрузка и настройка новых доменов

**Сейчас:** домены/ящики задаются в `config/sender.yaml`, секция `mailboxes` —
на каждый ящик: `mailbox_id` (email@домен), `provider` (yandex|mailru|google),
SMTP-хост/порт, `password_env` (имя env с app-паролем), `is_warmup_node`. Добавить
домен = дописать ящики в конфиг и перезапустить службу.

**Панель:** `GET /domains` — список доменов, `GET /domains/{домен}/dns` — проверка
здоровья DNS (SPF/DKIM/DMARC/MX через `dns.py`). Это ТОЛЬКО просмотр и проверка.
Добавления/редактирования домена в панели НЕТ.

Что нужно (инженеру, если хотим из панели): экран «добавить домен» → запись
ящиков в конфиг/БД + мастер DNS-записей + кнопка проверки (бэкенд `dns.py` уже есть).

**Порядок настройки домена сейчас (как делали для mail.parsercompressor.online):**
DNS у регистратора (MX, SPF `redirect`, DKIM-селектор, DMARC `p=none`) → app-пароли
ящиков → строки в `mailboxes` конфига → `GET /domains/{домен}/dns` для проверки →
включить в прогрев (`warmup.enabled_providers`).

## 3. Тайминг рассылки

Твой сценарий: «с 9:00 по времени регистрации компании, каждые 5 минут для
компаний этого региона, Пн-Чт». Разбор по частям:

**Работает сейчас (через `config/sender.yaml`):**
```yaml
timezone: "Europe/Moscow"     # ЕДИНАЯ зона окна (см. пробел ниже)
window:
  days: [1, 2, 3, 4]          # Пн-Чт (ISO: 1=Пн ... 7=Вс)
  start: "09:00"
  end: "18:00"
send_pacing:
  min_interval_sec: 300       # >= 5 минут между письмами ОДНОГО ящика
  max_interval_sec: 300       # ровно 5 мин; дай разброс (напр. 300/420) против паттерна
holidays: [...]               # РФ-праздники, письма переносятся
```
- **Пн-Чт** — да, `days: [1,2,3,4]`.
- **Старт с 9:00** — да, `window.start`, но в ОДНОЙ зоне (`timezone`), см. пробел.
- **Каждые 5 минут** — да, но это пауза на ОДИН ящик. При N ящиках суммарный темп
  выше (каждый ящик раз в 5 мин). Пейсинг глобальный, не по региону.

**⚠️ Пробелы (нужна доработка инженером):**
1. **«По времени регистрации компании» (часовой пояс получателя)** — НЕ
   поддерживается. Окно живёт в одной зоне `timezone`. Чтобы 9:00 было местным для
   каждого региона, нужно: хранить у получателя таймзону (вывести из региона), а
   `cadence._shift_into_window` считать окно в зоне получателя, а не глобальной.
2. **«Каждые 5 минут для компаний ЭТОГО региона» (пейсинг/батчи по региону)** — НЕ
   поддерживается. `send_pacing` — на ящик, глобально. Пер-регион расписание = новая
   логика в `cadence`/`sender` (очередь по региону со своим интервалом).

**Каденция шагов (касания 1/2/3):** задаётся на шаг как `delay_hours` (целые часы)
в `POST /campaigns/{cid}/steps` или CLI. Плюс `cadence` добавляет джиттер ±10% и
сдвигает в окно/за праздники. Точный тайминг «ровно в HH:MM» на шаг — не модель;
модель — «через N часов после предыдущего, но внутри окна».

## Итог: что доступно из панели vs требует доработки

| Задача | В панели сейчас | Реально сейчас | Нужна доработка |
|---|---|---|---|
| Загрузить базу | нет (только просмотр) | CLI `import` | экран загрузки CSV в панель |
| Разделить КЦ/Meyer | нет | **не работает** (segment не в таргетинге) | фильтр segment в кампании |
| Добавить домен | нет (просмотр+DNS) | правка `config.yaml` | экран доменов |
| Окно Пн-Чт с 9:00 | нет (конфиг) | да, `window` (одна зона) | — |
| Пейсинг 5 мин | нет (конфиг) | да, `send_pacing` (на ящик) | пер-регион |
| 9:00 по зоне получателя | — | нет | таймзона получателя |
| Пейсинг по региону | — | нет | пер-регион расписание |
