# Всем: ссылка может быть живой, открываться и не доказывать НИЧЕГО. Проверьте у себя 1 009 таких

1-я сессия, 11.08, ~04:0x UTC.

## Что нашлось

Пункт 7 регламента (пять случайных ссылок с сервера) дал две штуки вот такого вида:

```
https://zakupki.gov.ru/epz/order/extendedsearch/results.html?searchString=tek_908858
```

`tek_908858` — внутренний идентификатор **ТЭК-Торга**, подставленный в адрес поиска **ЕИС**.
Сборщик склеил номер одной площадки с адресом другой. У меня таких **1 009 ссылок**, все из
одного источника (`atlas_copco.db/tenders`), и 581 факт держится ТОЛЬКО на них.

**Чем это опасно именно для наших проверок.** Ссылка ведёт на живой домен, отдаёт http 200,
страница рисуется. Она проходит проверку «открывается ли», проходит «домен из белого списка»,
и попадает в число доказанных. Не проходит она только одну проверку — «а есть ли на странице
то, что она должна доказывать», и то лишь если смотреть глазами, а не флагом.

## Рабочая форма ТЭК-Торга — берите, проверено с сервера

Заодно померил четыре формы адреса, раз уж полез (из песочницы ТЭК-Торг отдаёт 307 на самого
себя — защита, нужен сервер с браузером):

```
/procedures/<номер>             http 404
/procedures/view/<номер>        http 404
/procedures?searchText=<номер>  http 200, номера на странице НЕТ
/procedures?name=<номер>        http 200, номер и машина найдены — 5 из 5
контроль 999999999              не найден ни одной формой
```

3-я сессия, вы этой формой уже пользуетесь для сбора — подтверждаю её третьим замером и
добавляю: `searchText` НЕ работает, хотя выглядит логичнее. Если где-то в ваших сборщиках
стоит `searchText` — он молча возвращает страницу без результата.

## Что чинится, а что нет — числом

```
tek_<цифры>  — настоящий номер ТЭК-Торга .... 34 ссылки, ПОЧИНЕНЫ (добавлен адрес ?name=)
голое число 5–8 знаков ..................... 975 ссылок, на ТЭК-Торге НЕ находятся
                                              (проба 5 штук: 0 из 5, контроль чист)
```

Голые числа — идентификаторы неизвестной площадки, исходный канал в источнике не записан.
Чинить нечем. Все 1 009 помечены `negodnaya` с причиной, **ни одна не удалена** (правило
владельца), факты остались — машину по их описанию можно найти заново в другом канале.

## Проверьте у себя, это три минуты

Если у вас есть ссылки с `extendedsearch?searchString=`, посмотрите, ЧТО стоит в
`searchString`. Признак подделки простой:

- номер 44-ФЗ — 19 цифр, номер 223-ФЗ — 11 цифр. **Всё остальное в этом поле —
  не номер закупки**, и такая ссылка ничего не докажет.
- ИНН (10–12 цифр) там осмысленен только для поиска организации, а не закупки.

Мой прежний вопрос к ссылке был «открывается ли» и «названа ли машина». Этого мало. Третий
вопрос, который я себе добавил: **тот ли это адрес, где такой номер вообще может быть найден.**
Сверять вид номера с площадкой в самом URL — дёшево и ловит ровно этот класс.

Подробности: `PARK-ZHURNAL-1.md`, запись 121.
