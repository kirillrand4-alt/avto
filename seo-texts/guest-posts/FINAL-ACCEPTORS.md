# Финальный список акцепторов кампании (отсев владельца: все главные — вон)

## ⚠️ ПРАВИЛО РАСКЛАДКИ (владелец 03.08.2026; читать перед КАЖДОЙ закупкой/генерацией)

Приоритет ниже — это ПОРЯДОК ОЧЕРЕДИ, а не веса. **Запрещено отдавать топ-1
все размещения.** Раскладка строго проходами (round-robin):

1. **Проход 1:** каждый URL ядра №1–15 получает свою ПЕРВУЮ ссылку — раньше,
   чем любой URL получает вторую.
2. **Проход 2:** вторая ссылка — только №1–10 (при бюджете 25 статей это и есть
   вся квота ядра: 15 + 10).
3. **Третьей ссылки не существует**, пока не закрыты проходы 1 и 2 целиком.
4. **Дилерский слой идёт ПАРАЛЛЕЛЬНО ядру** (своя очередь из 6 сайтов, по кругу),
   а не «после ядра» — иначе он не начнётся никогда.
5. Поверх — лимиты темпа (низ документа): ≤1 ссылка на URL в 2 недели, ≤2 новых
   домена на сайт/нед (молодым ≤1), пакетные сегменты — с разных доноров.

**Как выбрать следующее размещение:** открыть `PLACEMENTS-LOG.md` (журнал, лежит
рядом) → взять САМЫЙ ВЕРХНИЙ по приоритету URL с наименьшим числом уже полученных
ссылок, не нарушающий лимиты темпа → записать в журнал ДО закупки. Если журнал
говорит «у №1 уже есть ссылка этого прохода» — идёшь к №2, без исключений.

Дата: 2026-08-03. Решения владельца: (1) главные страницы не качаем ни на одном
сайте — их конверсия заражена обзвоном (DATA-QUALITY §11), их «органика» —
навигационка; (2) двухслойная схема: ядро по живому небрендовому спросу
(кликовая модель v4.1) + дилерский слой на создание видимости (показная v3.1).

## Темп и объём

Ядро 15×2 = 30 ссылок + дилерский 6×1.5 ≈ 9 → **~39 размещений** (~16–18 недель
при лимитах). При бюджете 25 статей: ядро №1–10 по 2 + №11–15 по 1 + дилерский
слой по 1 у berg-c/zif/dali/remeza/ac. Правила: ≤2 новых домена на сайт/нед
(enger, prokompressor), ≤1 — молодым; ≤1 ссылка на URL в 2 нед; точных
коммерческих ≤2 из 6 анкоров; [пакет]-сегменты — с разных доноров в соседние
недели. Пилоты: prokompressor винтовые (№10), пневмоаудит — интервал 2+ нед
от публикации.
