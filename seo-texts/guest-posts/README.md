`[\w.\-]` без пробелов (иначе зальётся, но не скачается). Генерация:
```bash

## 4. gen_provider.py — клиент шлюза (что обязан знать вызывающий)

Точки входа: `make_client()`, `call(client, messages, model='claude-opus-4-8', attempts=8,
effort=None)`, `parse_json(msg)`. SDK-клиент — рудимент для совместимости: реальные запросы
идут сырым SSE через httpx (`_raw_stream`, `gen_provider.py:253-313`), потому что шлюз
шлёт кадры, на которых SDK-аккумулятор падает.

Ловушки, каждая стоила денег или времени:

1. **Подмена мёртвых моделей** (`resolve_model`, `gen_provider.py:218-240`): замер
   27.07.2026 — `claude-fable-5` и `claude-opus-5` на шлюзе отдают только ping-кадры.
   Просишь fable-5 → **молча уходит `claude-opus-4-8`** (предупреждение один раз в stderr).
   Вернуть fable: `PROVIDER_DEAD_MODELS=''`. Статус «мёртв» после 27.07 НЕ перепроверялся —
   перед большим прогоном перепроверить (это меняет и качество, и цену).
2. **Ретраи**: до 8 попыток, паузы 15→30→60→120→150… с; полный цикл ≈ 11 минут. Для
   необязательных вызовов (ревью, вердикты) ставить `attempts=2` — так делает
   `regen_driver.py:90`.
3. **Фикс `a5fb992` (30.07)**: короткий ответ со `stop_reason='end_turn'` больше НЕ
   считается сбоем (`gen_provider.py:345-352`) — раньше законные короткие ответы жгли
   8 оплаченных ретраев. На это можно полагаться в вердиктах-однострочниках.
4. **`max_tokens=16000` захардкожен** в `call()` (`gen_provider.py:331`).
5. **Дедлайны стрима**: `PROVIDER_STREAM_DEADLINE_SEC=420`, `PROVIDER_FIRST_TOKEN_SEC=90`
   — обязательная защита от зависших стримов (ping-кадры не ловятся httpx-таймаутом).
   Обрыв стрима с накопленным текстом НЕ теряет его: вернётся `stop_reason='incomplete'`.
6. **`parse_json` хрупок** (`gen_provider.py:366-378`): срезает ```-ограждения, при
   JSONDecodeError ищет жадно `\{.*\}`; если скобок нет — `AttributeError` на
   `m.group(0)`; если вырезанный кусок битый — `JSONDecodeError` наружу. Именно так
   потерялась тема `dizel-na-strojke`. Вызовы `parse_json` оборачивать try/except.
7. **Анти-тире страховка parse_json чистит только ключи `title`/`description`/`text_html`**
   (`gen_provider.py:375-377`). gp_gen получает от модели ключ **`html`** — его страховка
   НЕ чистит, длинное тире ловится только нашим QA.
8. `effort` прокидывается как `output_config.effort` (low|medium|high|xhigh|max, дефолт
   high) — `gen_provider.py:265-266`. gp_gen зовёт с `effort='xhigh'`.
9. 403 от шлюза = в том числе исчерпанный баланс (докстринг `_raw_stream`).
10. **Отказ 03.08.2026 на генерационных промптах** (воспроизведён ~10 раз, все модели:
    opus-4-8, sonnet-5, fable-5): на полноразмерном промпте генерации статьи (~15 КБ +
    задание «верни JSON со статьёй») шлюз ФОРСИРУЕТ thinking (даже при thinking=False),
    модель сжигает ~9k токенов раздумий и завершается `end_turn` с ПУСТЫМ text - токены
    биллятся, результата нет. НЕ помогает: thinking=False, `budget_tokens` (игнорируется
    шлюзом), max_tokens=32000, prefill ассистента, смена модели. РАБОТАЕТ в тот же день:
    ревью-промпты ~9 КБ с длинным markdown-ответом (4 линзы по 5-10k токенов), короткие
    JSON-ответы (~800 токенов текста при thinking ~2.6k). Похоже на скрытый потолок
    thinking ~9k, до достижения которого текст должен успеть начаться. Обход для
    генерации не найден; вероятное направление - двухшаговая схема (короткий каркас →
    дописывание частями) или дождаться починки шлюза. Диагностика: сырой SSE-дамп в
    истории сессии 03.08; рецепт ревью - `review_gp.call_robust` (thinking=False, effort
    не передавать - с effort=xhigh thinking съедает бюджет и на ревью-промптах).

Стоимость: в коде тарифов нет; проектная константа из смежных скриптов —
fable $10/$50 за 1M in/out (консервативно; соответствие реальным тарифам шлюза не
проверялось). Ориентир из каталожного регена: ~$1/страница с доводками. Учёт токенов —
`msg.usage` (input/output/cache_read/cache_write).

## 5. Мех-QA: qa_text.py и qa_article()

`gp_gen.qa_article(html, acceptor)` (`gp_gen.py:78-99`) использует из `qa_text.py`:
`BANNED` (стоп-слова, первые 5 хитов), `refinement_check(low)` (инженерные ошибки:
канцелярский пассив, инверсия давление/производительность, адсорбция-«химия», порядок
цепочки подготовки воздуха, «пневмоаудит» >1), `naturalness(html, text, low)` (CV длин
абзацев ≥0.30, мосты-связки ≤3/500 слов, «данный» <2). Свои проверки: объём 5200–9800
знаков (текст ошибки врёт «6000-9000»), запрет `—`, **ровно 1 href = акцептор**
(конфликт со стайлгайдом v3, см. §6), запрет `<ul>/<li>`, ссылка не в крайних абзацах.

Ловушки BANNED против наших тем:
- `'гарантия 5 лет'` — стоп-слово (`qa_text.py:9`), а тема `enger-brend-obzor` содержит
  «гарантия до 5 лет» (не матчится, но на грани; писать «до 5 лет»);
- `'берите'` — на нём завалилась `podbor-vintovogo`;
- «пневмоаудит» ≤1 раза — тесно для темы `utechki-szhatyj-vozduh`, где пневмоаудит — суть.

Из qa_text НЕ используется, но стоит взять при доработке: `keyword_density_issue`
(переспам ключа), SEO-жаргон (тег/фасет/листинг/выдача), псевдотеги/`<script>`,
«витринные» конструкции, длина description 110–175 (когда появится Description),
паттерн `allowed_links`/`require_links` (образец для «1-2 акцепторных + 1-2 нейтральных»).

## 6. Генератор gp_gen.py: устройство и ВСЕ известные баги

Устройство: 5 тем в `THEMES` (slug, angle, acceptor, anchor, case, skeleton). Промпт =
весь стайлгайд + задание, ответ — JSON `{"title","html"}`. `gp.call(model='claude-fable-5',
effort='xhigh')` (реально уйдёт opus-4-8, см. §4.1), 3 воркера. До 3 попыток с доводкой
«Исправь ТОЛЬКО это». Байлайн приклеивает код (`gp_gen.py:74-75`): «Игорь Волков,
технический директор ООО «Руспром», более 5580 проектов…».

Пилот 16.07 (коммит `5c792b8`): `enger-brend-obzor` 6070 зн чисто, `osushitel-tochka-rosy`
6713 чисто, `utechki-szhatyj-vozduh` 5578 чисто, `podbor-vintovogo` 6068 стоп-слово
«берите», `dizel-na-strojke` — упала (JSONDecodeError). **Хронология: все 4 статьи сделаны
по стайлгайду v1 за час до появления v2/v3** — их несоответствие текущему стайлгайду
не баг, а порядок работ. Перед сдачей на площадки — перегенерация.

Баги/долги генератора (сверено с кодом 03.08):

1. **Ссылки**: стайлгайд v3 требует 1–2 акцепторных + 1–2 нейтральных (ГОСТ/ISO,
   производитель станков), QA заваливает всё, где `href != 1` (`gp_gen.py:89-91`) —
   нейтральные ссылки физически невозможны.
2. **Формат поставки**: площадкам нужен TITLE ≤70 + Description 150–160 + Анонс 2–3
   предложения + тело; генератор делает только `title` + `html`.
3. **Нет инженер-проверки** через API (стайлгайд её требует; готовый паттерн — §7).
4. **`gp.parse_json` без try/except** (`gp_gen.py:110`) — невалидный JSON рвёт тему
   целиком (ловится в `main()` как строка, файлы не пишутся).
5. **Нет CLI на одну тему, нет кэша**: `main()` всегда гонит все 5 THEMES и перезапишет
   готовые статьи.
6. Мульти-доменные правила v3 (макс 2 наших домена в разных ролях, ротация пар) в коде
   никак не отражены.
7. Фактура кейсов — голый текст в THEMES, гейт брендовых фактов не подключён (§7).
8. При `data=None` после 3 неудачных QA-попыток `data['html']` упадёт TypeError
   (`gp_gen.py:119`) — до этой строки пока не доходило (parse_json падает раньше).

**Гейт фактов брендов**: `brand_facts_lib.py` поверх `kb/brand-facts-clean.json`

| Бренд темы | В базе | Важное |

| enger | ДА (rodnoy) | богатый блок (завод Хуэйчжоу, блоки BAOSI/HANBELL, OFS…); caveat «НЕ утверждать гарантийные сроки» — конфликт со скелетом темы «техника (блоки, гарантия)», разруливать в промпте |

## 8. Акцепторы: какой странице дать ссылку

**`../frog/acceptor_value.py`** (403 строки) — коммерческое ранжирование акцепторов:

```
value = gain × feasibility(pos) × чек/1e6 × brand_boost          # :281-284
gain  = eff_shows × (ctr(3) − ctr(pos))                          # цель — топ-5
```
- `ctr(p)` (`:23-30`) — B2B-кривая: топ-1 5.5%, топ-5 4.5%, топ-10 3.5%, 11–15 1.4%,
  16–20 0.9%, дальше 0.6% (внутри топ-10 плоско, обрыв на 2-й странице);
- `feasibility(p)` (`:33-37`) — реалистичность подъёма ссылками: ≤10 → 1.0, 11–15 → 0.7,
  16–20 → 0.5, 21–30 → 0.3;
- `eff_shows` (`:207-231`) — показы без ботов: implied = clicks/ctr(pos); срез бот-кликов
  berg-compressor.com (`:244-259`);
- чек — каскад `resolve_chek` (`:143-168`): payload страницы → битрикс-категория →
  бренд+категория → бренд → медиана прайс-сегмента (`price-map.json`);
- `brand_boost` (`:235-241`): enger ×1.5, berg/dali/crossair/hansmann ×1.25.
- Кандидаты: позиции 3.5–30, показы ≥30, индексируемые URL. Бонус-блоки: «доминирование
  выдачи» (сегменты с ≥2 нашими сайтами в зоне 4–30 — качать пакетом) и дыры по станциям.

**Готовая база — `../frog/acceptor-value.json`** (555 КБ): `candidates` (url, site,
segment, price, pos, shows, eff_shows, gain, value…), `domination`, `gaps`, `bot_coefs`.
Ей можно пользоваться сейчас. Пересчитать под новый период НЕЛЬЗЯ без свежей выгрузки
Вебмастера от владельца: вход захардкожен на мёртвый uploads-путь (`acceptor_value.py:18`,
период выгрузки 16.06–15.07). Чистые функции (ctr, feasibility, resolve_chek) работают
без XLSX — value по изменённой формуле пересчитывается из готового JSON.

**`FORECAST-RISKS.md`** — уровень кампании: вероятность топ-5 за 3–4 мес при 2–3 ссылках:
50% с позиций 6–10, 35% с 11–15, 20% с 16–20, 10% с 21–30; конверсии владельца: заявки 6%
кликов, квал-лиды 2.7%; сценарий «Шорт-25»: +254 клика/мес. **Правила темпа (обязательны
при закупке)**: ≤2 новых ссылающихся домена/нед на сайт (молодым дилерам ≤1), ≤1 ссылка
на один URL-акцептор в 2 недели, с одного донора ≤1–2 статьи на сеть с интервалом от
месяца; коммерческий анкор ≤25–30%; футпринт (один байлайн + похожая структура +
одинаковые даты = сетка глазами асессора).

## 10. Правила владельца (обязательны, из CLAUDE.md)

1. **Вся тяжёлая работа — через провайдерский API** (`gen_provider`), не токенами сессии.
   Тяжёлые прогоны — в трекаемом фоне харнесса, с кэшем и резюмируемостью.
2. **Durability**: песочница при рестарте откатывается — результаты коммитить в git
   (или на дроп), состояние прогона не держать только в scratch.
3. **Перед необратимым — подтверждать.** Для нас: отправка статьи на площадку/закупка
   размещения = действие вовне, только по явному ОК владельца.
4. Правила текстов: без длинных тире, без `<ul>` (и в гост-постах — стайлгайд), байлайн
   гост-постов — «Игорь Волков, технический директор ООО «Руспром», более 5580 проектов…»
   (приклеивает код, модели писать запрещено), числа — только из проверенной фактуры.
5. Структура бизнеса для ссылок: prokompressor.ru (каталог), enger-air.ru (родной бренд),
   16 дилерских; «Компрессор Центр» и «Meyer» — направления ООО «Руспром», не отдельные
   юрлица. Анти-аффилиат правила — в `STYLE-GUIDE-GUEST.md` (макс 2 наших домена/статья,
   только в разных ролях, пара «Enger + прокомпрессор» ≤1 статьи из 3–4).
