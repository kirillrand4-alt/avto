# Конвейер гостевых постов: от отобранного донора до опубликованной ссылки

Инструкция для сессии, которая делает следующую волну. Здесь весь путь по шагам:
какой скрипт вызывать, что он читает и пишет, какие переменные окружения нужны
и где грабли, на которые уже наступали.

`README.md` в этом же каталоге описывает **пилотную** эпоху (`gp_gen.py`, пять тем).
Он не устарел по правилам владельца и по акцепторам — но конвейер там другой.
Актуальный путь — этот файл.

---

## Схема пути

```
доноры отобраны            fit_score.py → assign_jobs.py
        ↓
джобы                      dispatch_pages.py → jobs_export.py → wave-jobs.py
        ↓
генерация                  gen_wave.py            (провайдерский API, мех-QA, до 3 кругов)
        ↓
приёмка                    finalize_gp.py         (17 линз, правки, детектор конфликтов)
        ↓
ручная вычитка             ГЛАЗАМИ. Линзы этого не делают — см. §6
        ↓
проверка серии             series_check.py --texts
        ↓
выгрузка на биржу          make_miralinks_zip.py --ready-only --wave-only
        ↓
план выкладки              plan_placements.py
        ↓
после публикации           ГРАФИК-РАЗМЕЩЕНИЙ.xlsx, лист «Проверка публикации»
```

Единица работы — **джоба**: одна статья на одного донора с одной-двумя нашими
ссылками. Всё, что ниже, оперирует слугом джобы.

---

## Переменные окружения

| Переменная | Кто читает | Зачем |
|---|---|---|
| `PROVIDER_API_KEY`, `PROVIDER_BASE_URL` | `../gen_provider.py` | доступ к шлюзу; без них голый `KeyError` |
| `JOBS_MODULE` | `gen_wave.py` | имя модуля с джобами БЕЗ `.py`: `JOBS_MODULE=wave-jobs`. Без него берётся встроенный список волны 1 |
| `PROVIDER_DEAD_MODELS` | `../gen_provider.py` | список моделей через запятую, которые пропускать. Пустая строка = не пропускать ничего |
| `PROVIDER_FIRST_TOKEN_SEC` | `../gen_provider.py` | сколько ждать первый токен. На длинных промптах ставить 300 |
| `PROVIDER_STREAM_DEADLINE_SEC` | `../gen_provider.py` | общий дедлайн стрима, для генерации 900 |
| `GP_MAX_TOKENS` | `gen_wave.py` | потолок выхода, по умолчанию 24000 |
| `PROVIDER_MODEL` | `../gen_provider.py` | принудительно одна модель вместо цепочки |
| `GP_EFFORT` | `gen_single.py` | усилие рассуждения, по умолчанию `xhigh` |

Дефолты, о которые спотыкаются: `PROVIDER_FIRST_TOKEN_SEC` = 90,
`PROVIDER_STREAM_DEADLINE_SEC` = 420. Для генерации длинных статей обоих мало —
поэтому в командах ниже они подняты явно.

Скрипты планирования пишут результат в файл, имя которого берут из своей переменной.
Полезно, когда надо прогнать вариант, не затирая рабочий: `JOBS_OUT`, `GENRE_OUT`,
`FIT_OUT`, `DISPATCH_OUT`, `FINAL_OUT`, `DEDUP_OUT`, `ANCHOR_OUT`, `SECOND_OUT`,
`SERIES_OUT`. Отдельно `ANCHORS_TAKEN` — список занятых якорей, передаётся
в `anchor_fix.py` при переигровке конфликта.

Куки внешних сервисов: `GBS_COOKIE_FILE` (групбай Ahrefs), `SR_COOKIE_FILE` (Semrush),
`ML_COOKIE_FILE` (карточки Miralinks). **Класть только в скратчпад с `chmod 600`** —
в git и на дроп они не попадают.

**`JOBS_MODULE` нужен почти всем скриптам** — они импортируют `JOBS` из `gen_wave`.
Забыли — молча возьмётся волна 1, и вы будете работать не с теми статьями.

## Шаг 1. Джобы

Джоба — словарь. Поля и что в них:

| Поле | Что это |
|---|---|
| `slug` | имя статьи. **Только латиница**: он идёт в имена файлов и на биржу как рекомендация URL |
| `donor` | площадка |
| `links` | список `(url, инструкция по якорю)`. 1–2 штуки, лимит площадки |
| `auth_allow` | сколько авторитетных ссылок разрешено сверх наших (обычно 1 или 0) |
| `angle` | о чём статья и для кого. Самое важное поле — из него растёт весь текст |
| `case` | кейс для статьи или строка `Не нужен` |
| `skeleton` | скелет разделов через `->` |
| `donor_note` | профиль аудитории площадки. Подставляется в линзы `platform`, `audience_level`, `genre_bridge` |
| `seo` | запросы, из них же собирается `metakeywords` для биржи |
| `mode` | `тематический` или `жанровый` |

### `mode` — не косметика

Линза `genre_bridge` (честность перехода к промышленной теме) судит **только**
статьи с `mode='жанровый'`. Если донор нетематический, а в джобе стоит
`тематический`, единственная проверка на натянутый мост отключается.

Так уже случилось: календарь праздников и туристический сайт стояли тематическими,
и статья для календаря вышла с одним предложением про праздник и восемью тысячами
знаков разбора техники. Проверять раскладку так:

```bash
JOBS_MODULE=wave-jobs python3 -c "
from gen_wave import JOBS
for j in sorted(JOBS, key=lambda x: x.get('mode','')):
    print(f\"{j.get('mode','?'):12s} {j['donor']:32s} {j['slug']}\")"
```

Глазами пройти список: если донор не про промышленность — режим должен быть жанровый.

### Откуда джобы берутся: восемь фаз

Фазы пронумерованы в докстрингах самих скриптов. Все пишут в общий
**`final-jobs.jsonl`** — он и есть рабочий файл волны, его последовательно правят
фазы 4–8:

| Фаза | Скрипт | Что делает | Пишет |
|---|---|---|---|
| — | `plan_jobs.py` / `genre_jobs.py` | агент на донора: акцептор, угол, якоря | `planned-jobs.jsonl`, `genre-jobs.jsonl` |
| 1 | `fit_score.py [донор ...]` | оценка фита донора ко ВСЕМ шести нашим сайтам, 0–10 | `fit-scores.jsonl` |
| 2 | `assign_jobs.py [порог]` | аукционное распределение доноров по сайтам с квотами | `assignment.json` |
| 3 | `dispatch_pages.py` | раскладка ссылок по конкретным страницам | `dispatch.json` |
| 4 | `final_jobs.py [донор ...]` | финальные джобы под назначенные страницы | `final-jobs.jsonl` |
| 5 | `dedup_jobs.py` | развести пересекающиеся углы (агент видит все джобы разом) | правит `final-jobs.jsonl` |
| 6 | `anchor_fix.py [донор ...]` | якоря из живых запросов, по агенту на пару | правит `final-jobs.jsonl` |
| 7 | `series_check.py` | проверка серии на однообразие | `series-check.json` |
| 8 | `second_link.py [донор ...]` | вторая ссылка там, где лимит карточки позволяет | правит `final-jobs.jsonl` |

Дальше `jobs_export.py` превращает `final-jobs.jsonl` в модуль `wave-jobs.py`:

```bash
python3 jobs_export.py --check          # только проверить, код 1 при замечаниях
python3 jobs_export.py --live           # плюс дёрнуть каждый URL curl'ом
python3 jobs_export.py                  # записать wave-jobs.py
```

Предполётные проверки `jobs_export.py`: слеш в конце URL (без него 301 и потеря веса),
живой якорь, служебные формулировки, при `--live` — существование страницы. Квота
авторитетных считается там же: `auth_allow = max(0, min(1, лимит_карточки − наши_ссылки))`.

**Правки джоб вносить в `final-jobs.jsonl`, а не в `wave-jobs.py`.** Первая строка
`wave-jobs.py` об этом и говорит: файл сгенерирован, следующий прогон `jobs_export.py`
его перезапишет.

### `ASSIGN` живёт в трёх местах

Словарь «донор → наш сайт» продублирован: `plan_jobs.ASSIGN`, `genre_jobs.ASSIGN`
и результат `assign_jobs.py` в `assignment.json`. Расхождение между ними тихо ломает
раскладку — при правке трогать все три.

### Как рождается угол статьи

Угол не выдумывается свободно — это пересечение трёх входов:

1. **Предмет** — тема страницы-акцептора: дизельные, азотные, безмасляные.
2. **Призма** — аудитория донора: промгород → стройка и цех; агро → хранение урожая
   и мехдвор; техно-площадка → данные и экономика.
3. **Слова** — живые запросы акцептора из Вебмастера.

Один акцептор на разных донорах даёт **разные** углы: азотная страница для агро —
«азот при хранении зерна», для промгорода — «азот в цеху». Если пересечение предмета
с аудиторией пустое, донора откладываем. Тему не натягивать — это правило владельца.

При пакетном планировании идти **от доноров**: каждому назначить лучший допустимый
акцептор, из пары вывести угол. Так релевантность максимальна у каждой пары,
и топ-акцептор не забирает все размещения.

### Семантика — из живых данных, не из головы

Живые запросы каждой страницы лежат в `../frog/acceptor-top100.xlsx`, колонка
«Топ-запросы» — выгрузка Вебмастера с позициями:

```python
import openpyxl
ws = openpyxl.load_workbook('../frog/acceptor-top100.xlsx').active
rows = list(ws.iter_rows(values_only=True))
iu, iq = [i for i, h in enumerate(rows[0]) if h in ('URL', 'Топ-запросы')]
print([(r[iu], r[iq]) for r in rows[1:] if r[iu] and 'НУЖНЫЙ-СЛАГ' in str(r[iu])])
```

Из них собирается поле `seo`: главный ключ, 3–5 живых фраз для H2 и текста,
LSI-термины предметки. Правила вхождений уже зашиты в промпт генератора —
переспам хуже недоспама.

Отдельная ценность — **дотягиваемая полоса позиций 8–30**: запросы, по которым
страница уже показывается, но не в топе. Их и берёт `anchor_fix.py` под якоря.

## Шаг 2. Генерация — `gen_wave.py`

```bash
cd seo-texts/guest-posts
JOBS_MODULE=wave-jobs PROVIDER_FIRST_TOKEN_SEC=300 PROVIDER_STREAM_DEADLINE_SEC=900 \
  python3 gen_wave.py <slug> [<slug> ...]        # без слугов — вся волна
```

Пишет `gp-<slug>.html` (тело с `<h1>`) и `gp-<slug>.meta.json`
(title, description, anons, donor, links).

**Модели.** `DRAFT_MODELS` — черновик, `FIX_MODELS` — доводки. Первым стоит
`claude-opus-4-8` по решению владельца: flash отдаёт статью за 16 секунд против двух
минут, но если черновик проходит мех-QA с первого раза, доводки не будет и в
публикацию уйдёт текст flash целиком. На статьях с расчётами это плохо кончается.

**Контракт ответа — НЕ JSON.** Шлюз на генерационных промптах JSON не отдаёт
(пустой `text` после ~9k thinking). Поэтому первая строка `TITLE: ...`, дальше
голый HTML.

**Мех-QA (`qa_multi`) на каждом круге.** Что проверяет: объём 5200–14000 знаков,
стоп-слова и хеджи, длинное и короткое тире, голые `<` и `&`, баланс блочных тегов,
целостность `<a>`, разрешённые теги, позиции ссылок (не в первом и не в последнем
абзаце), дубли ссылок, квоту авторитетных. Не прошло — доводка, до трёх кругов.

### Грабли генерации

- **Короткое тире `–`** визуально неотличимо от дефиса и лезло в статьи. Запрещено
  наравне с длинным, нормализуется на входе приёмки.
- **Голые `<` и `&`** («deltaE < 2», «R&D») — статья уезжает в чужую CMS, и что та
  сделает с таким фрагментом, предсказать нельзя. Проверка добавлена в гейт.
- **Незакрытый `</p>`** дошёл до приёмки: раньше проверялась целостность только
  `<a>`. Теперь считается баланс всех блочных тегов.
- **Авторитетные ссылки не ставятся сами.** Промпт говорит «по желанию» и
  заканчивается «нет уверенности в адресе — не ставь вовсе». Модель слушается
  буквально: на волне из 24 статей их было ноль при квоте 19. Ставить руками
  с проверкой адреса — см. §7.

## Шаг 3. Приёмка — `finalize_gp.py`

```bash
JOBS_MODULE=wave-jobs PROVIDER_DEAD_MODELS='claude-opus-5' \
  python3 finalize_gp.py <slug> [<slug> ...]

# дозапуск отдельных линз на уже принятых статьях
JOBS_MODULE=wave-jobs python3 finalize_gp.py --only numbers_chain --from-ready <slug>
```

Пишет `ready/gp-<slug>.final.html` (принято) или `.NEEDS-REVIEW.html` (нужен человек),
плюс `ready/gp-<slug>.finalize-log.md` — полная история: какая линза что правила
и почему.

### Как это работает

17 линз по очереди. Каждая возвращает вердикт и точечные правки «цитата → замена»,
код применяет их детерминированно. До трёх кругов; во второй круг идут только
провалившиеся, и там подставляется CONFIRM_NOTE («статья уже исправлена, подтверди
приёмку, FAIL — только при критической проблеме»).

**Правки внутри круга применяются последовательно.** Линза N видит текст после
линз 1..N−1. Отсюда дребезг: `neutral` убирает оценочное слово, идущая следом
`language` считает получившееся корявым и пишет обратно. Обе правки применятся,
обе попадут в лог, и в статью попадёт вариант той, что стояла позже — **не потому
что она права**. Для этого есть детектор конфликтов: он помечает зону, за которую
дрались две линзы, и статья уходит на ручной разбор.

**Конфликт правок = автоприёмки нет.** Даже если все линзы в итоге дали PASS.

### Защиты (не убирать)

| Защита | Что делает | Почему появилась |
|---|---|---|
| `_kills_link` | отклоняет правку, вырезающую нашу ссылку | линза `platform` убрала обе ссылки статьи, гейт поймал постфактум |
| `_relink` | если линза правила ТЕКСТ якоря и потеряла разметку — тег восстанавливается, правка принимается | на жанровых отклонялось по 4–9 правок на статью, и почти все были согласованием падежа |
| `_tags_intact` | отклоняет правку, ломающую разметку ссылки | цитата захватывала середину тега, тег превращался в мусор, три линзы весь круг чинили обломок |
| `_overlaps` | детектор конфликтов зон | см. выше |

### Линзы, которые не сойдутся никогда

`audience_level` и `teh_skeptik` на жанровых статьях иногда выносят FAIL
с единственным требованием — убрать оплаченную ссылку, на третьем круге уже без
правки вообще. Удовлетворить их нельзя: ссылка есть цель размещения.

**Это штатное состояние.** Правильная реакция — посмотреть глазами, действительно ли
ссылка висит заплаткой. Если да — переписать абзац так, чтобы он отвечал на вопрос
читателя, а ссылка стояла справкой ВНУТРИ ответа. Работающий пример: в статье
о рабочих профессиях абзац про компрессорную заменён на рассказ о машинисте
компрессорных установок — это профессия из ЕТКС, и в такой статье ей место по праву.

## Шаг 4. Ручная приёмка: как оформлять

Если статью принимаете руками (переименовали `NEEDS-REVIEW` → `final`), **обязательно
допишите в конец лога машиночитаемый итог**:

```
**Итог: ГОТОВ К ПУБЛИКАЦИИ (принято человеком после разбора выше).
Файл: ready/gp-<slug>.final.html**
```

Без этой строки `make_miralinks_zip.py` считает статью незавершённой: он определяет
готовность по последнему итогу в логе, а шапка описывает прошлый автоматический
прогон. На волне из 24 так выпали 13 статей.

Проверка после ручных правок — обязательна:

```bash
JOBS_MODULE=wave-jobs python3 -c "
import re
from gen_wave import JOBS, qa_multi
for j in JOBS:
    h=open(f\"ready/gp-{j['slug']}.final.html\",encoding='utf-8').read()
    b=re.sub(r'<h1>.*?</h1>\s*','',h,flags=re.S)
    iss=qa_multi(b,j['links'],j.get('auth_allow',0))
    miss=[u for u,_ in j['links'] if u not in h]
    if iss or miss: print(j['slug'], iss, miss)"
```

## Шаг 5. Чего линзы не проверяют

Главный вывод волны 20.08: **линзы проверяют внутреннюю связность текста, но не
сверяют его с внешним миром.** Всё перечисленное прошло 16 линз и было найдено
только сплошной вычиткой.

| Что | Пример из волны |
|---|---|
| **Факты о реальном мире** | все шесть биографий российских звёзд в статье выдуманы целиком, с живыми подробностями |
| **Модельные ряды и характеристики** | индекс Atlas Copco XAS — это литры в секунду, а статья читала его как кубометры в минуту: все цифры завышены вдвое, и читатель проверил бы по нашей же ссылке |
| **Атрибуция цитат** | монолог в «Престиже» произносит Майкл Кейн, а не Кристиан Бэйл; у Эдисона в оригинале «вдохновение», а не «талант» |
| **Выполнение обещания заголовка** | «30+ цитат» при 21 в тексте |
| **Валюта и локаль** | тариф на электричество в долларах в статье для российского цеха |
| **Числа между разделами** | вступление расходилось с расчётом на порядок; сценарий противоречил формуле самой статьи |
| **Контекст ссылки** | оплаченная ссылка стояла в абзаце «наше оборудование давит шумом даже через защиту» |

Для последнего пункта добавлена линза `numbers_chain` — сквозная сверка чисел между
разделами. Она ставится последней в очереди и на первом же прогоне нашла четыре
ошибки, пропущенные при ручной вычитке. Но остальное линзой не лечится: нужен доступ
к фактам, а не ещё одно мнение модели.

**Правило: всё, что можно проверить в источнике, проверять в источнике.**
Биографии, модельные ряды, ГОСТы, высоты, веса, цитаты — через поиск и живой каталог.

### Быстрые проверки, которые стоит гонять всегда

```bash
# названные модели и бренды — их надо сверить с каталогом
python3 -c "
import re,glob
for f in sorted(glob.glob('ready/*.final.html')):
    t=re.sub(r'<[^>]+>','',open(f,encoding='utf-8').read())
    m=set(re.findall(r'\b[A-Z]{2,5}[\s-]?\d{2,4}\b', t))
    if m: print(f.split('/')[-1][3:-11], sorted(m))"

# живые ли наши ссылки: код и число редиректов
JOBS_MODULE=wave-jobs python3 -c "
from gen_wave import JOBS
for j in JOBS:
    for u,_ in j['links']: print(u)" | sort -u | while read u; do
  printf '%s  %s\n' "$(curl -s -o /dev/null -w '%{http_code} ред:%{num_redirects}' \
    -L --max-time 20 -A 'Mozilla/5.0' "$u")" "$u"
done
```

Смотреть надо не только код: **301 съедает вес**, а чужой `canonical` уводит его
на другую страницу. Полный разбор с canonical и `noindex` — в `LINKS-CHECK.md`.
Две страницы prokompressor.ru всегда дают 403: это WAF сайта против датацентровых
адресов, а не поломка — Googlebot их получает, проверено в Search Console.

## Шаг 6. Проверка серии — `series_check.py`

```bash
JOBS_MODULE=wave-jobs python3 series_check.py --texts ready
```

Считает общие пятисловные фразы между статьями, одинаковые начала заголовков,
повторяющиеся якоря, статьи с превышением лимита ссылок.

**Гонять по ГОТОВЫМ текстам (`--texts`), а не по джобам.** На волне из 24 нашлось
143 общие фразы, из них 22 в трёх и более статьях: одинаковые перечисления ступеней
подготовки воздуха, совпадающие обороты про удельную мощность. Числа — факты и не
меняются, переписывать надо формулировки. После правки стало 125 и 12; остаток —
голые величины вроде «0,5–0,8 бар», развести которые нельзя, не соврав.

Отдельно `series_check` оценивает структурное однообразие. На волне вердикт был
«два чётких кластера, каждый по своему шаблону» — это сильнее фразового следа
и линзой не лечится, чинится переработкой скелетов в джобах.

## Шаг 7. Авторитетные ссылки

Ставятся руками. Порядок:

1. Взять список джоб с `auth_allow > 0`.
2. Подобрать по одному источнику на статью — на термин, который предложение и так
   объясняет.
3. **Проверить существование страницы через API**, а не на глаз. Прямой `curl`
   из песочницы Википедия режет (HTTP 429) — брать через инструмент `WebFetch`
   с таким адресом (заголовки через `|`, всё в percent-encoding):

```
https://ru.wikipedia.org/w/api.php?action=query&format=json&redirects=1&titles=<заголовки>
```

В ответе смотреть три вещи: `"missing"` у страницы — её нет; секция `redirects`
показывает, что заголовок уводит на другой (ссылаться надо сразу на цель:
«Горная болезнь» → «Высотная болезнь»); `normalized` — что заголовок нормализован.
На волне из 24 так отсеялись две несуществующие статьи и один редирект.

4. Поставить в абзац, где **нет нашей ссылки**, и не в первый и не в последний.
5. Проверить итоговые адреса запросом на 200.

**Куда не ссылаться:** `docs.cntd.ru` уводит через SSO-редирект, читатель попадёт
на авторизацию. `consultant.ru` отдаёт 200 даже на выдуманный адрес — проверить
существование страницы там нельзя.

## Шаг 8. Выгрузка на биржу — `make_miralinks_zip.py`

```bash
JOBS_MODULE=wave-jobs python3 make_miralinks_zip.py --ready-only --wave-only \
  -o ARTICLES-MIRALINKS-<волна>.zip
```

- `--ready-only` — только прошедшие приёмку;
- `--wave-only` — только текущая волна, без статей прошлых волн.

Формат биржи владелец присылал 06.08 и воспроизводится побайтно: плоский архив
`art_N.txt`, внутри блоки `[__ключ__]`, UTF-8 без BOM, CRLF, пустая строка между
блоками. Поля: title, description, metatitle, metakeywords, metadescription, slug,
snippet, content, ground, video_links, video_requirements.

Указатель «файл ↔ статья» пишется в `MIRALINKS-INDEX.md` **рядом** с архивом,
а не внутрь: шаблон биржи содержит только `art_N.txt`, лишний файл может сломать
разбор на их стороне.

Ограничения, о которые уже спотыкались: анонс не длиннее 255 знаков (скрипт режет
по границе предложения), `<h1>` из тела убирается — биржа ставит его из `title`.

## Шаг 9. План выкладки — `plan_placements.py`

```bash
JOBS_MODULE=wave-jobs python3 plan_placements.py                    # тот же план
JOBS_MODULE=wave-jobs python3 plan_placements.py --seed 777         # другая раскладка
JOBS_MODULE=wave-jobs python3 plan_placements.py --start 2026-09-01
```

Пишет `placement-plan.json`. Правила зашиты в скрипт, он проверяет их сам и падает,
если план нарушен:

1. Не больше 2 статей в неделю на один акцепторный домен (решение владельца 20.08).
2. Темп рандомный: 1 или 2 в неделю, в среднем 1,8.
3. Не больше 2 публикаций в календарный день по всей кампании.
4. Один URL акцептора — не чаще раза в 14 дней.
5. Не меньше 2 дней между статьями на один акцептор.
6. Только будни.
7. Жанровые и тематические чередуются.
8. У каждого домена, кроме крупнейшего, одна статья придержана на вторую половину.

Старт получается плотным: акцепторные домены не мешают друг другу, и в первую
неделю они стартуют параллельно.

## Грабли, которых нет выше

1. **`fable-5` жив на ревью, мёртв на генерации.** Промпт ревью 4–9 КБ он держит,
   генерационный — нет. Первым судьёй в линзах — да, генератором — нет.
2. **Судьи протаскивают в правки длинное тире и цитируют HTML с кавычками.**
   Санитизация и парсер цитат в `finalize_gp` есть, но новые форматы возможны:
   NEEDS-REVIEW с «НЕ НАЙДЕНА цитата» — признак такого случая.
3. **Gemini норовит поставить ссылку на `docs.cntd.ru`.** Гейт режет по белому списку.
   Туда и не надо: сайт уводит через SSO-редирект.
4. **Кейсы в статьях — только обезличенные.** Юрлицо клиента в покупной статье это
   и согласие клиента, и рекламный след.
5. **Норма объёма 6000–13000 знаков — наша внутренняя.** Потолок площадки уточнять
   при согласовании: некоторые режут длинное.
6. **`shots/` пуст, `donor_eyes.py` требует поднятого Дельфина** на сервере владельца.
   18.08 отвечал `WinError 10061` — сервис не запущен.
7. **Слуг только латиницей.** Он идёт в имена файлов, в URL и на биржу; кириллица
   внутри латинского имени незаметна глазом и ломает выгрузку.
