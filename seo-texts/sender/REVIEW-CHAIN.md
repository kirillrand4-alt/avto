# Ревью-конвейер ответных писем автоответчика

Решение владельца (2026-07-20): **каждое сгенерированное ответное письмо проходит
ВСЕ 8 ревьюеров ПЕРЕД отправкой/сохранением черновика.** Есть критическое
замечание — письмо НЕ уходит, идёт на перегенерацию. (Прежняя идея «лёгкая
связка из 3 в пилоте» отклонена — время терпит, качество важнее.)

Двухслойная страховка (как QA у SEO-текстов + ревью-прогоны движка).

## Слой 0 — механический гейт (без LLM, мгновенный, бесплатный)

`qa_reply()` по образцу `qa_text.py`: длинные тире; незаполненные `{плейсхолдеры}`;
длина > 1 экрана; наличие байлайна «ООО «Руспром»»; подпись менеджера (не «ИИ»);
стоп-слова; тема не пустая. Провал → сразу на перегенерацию, ревьюеров не тратим.

## Слой 1 — 8 LLM-ревьюеров (провайдерский API, по одной линзе = один вызов)

Каждый возвращает строгий JSON: `{verdict: PASS|WARN|CRITICAL, problems:[...], fixes:[...]}`.

**Блокирующие (CRITICAL = вето, письмо не уходит):**
1. **Факт-чекер против базы** — каждая цифра/модель/срок сверяется с `answer-kb`
   (КЦ) / фактами брендов (Meyer). Не из базы / выдуманная модификация → CRITICAL.
   (Главный риск по дрйрану — фактура.)
2. **Юрист ФЗ-38/152** — атрибуция ООО «Руспром»+ИНН в письме, нет незаконной
   оферты, корректная работа с ПД, отписка не сломана.
3. **Эскалация-гейт** — «робот вообще ДОЛЖЕН на это отвечать?»: торг, рекламация,
   >1 млн ₽, госзакупки, лизинг, юр-вопрос, агрессия → человеку (не текст, а само
   решение отвечать).
4. **Классификация-скептик** — перепроверяет класс входящего: не спутан ли
   deferred с not_interested, redirect с auto_reply (2/7 ошибок coldy = потери).

**Совещательные (WARN не блокирует, но копится; CRITICAL могут и они):**
5. **Продажник-квалификатор** — двигает к цели по лестнице контакта: выявлена
   потребность? 1 уточняющий вопрос (не 3)? телефон вовремя? следующий шаг конкретен?
6. **Клиент-адвокат** — симуляция ЛПР-получателя: раздражает? отвечает на ЕГО
   вопрос или толкает наш? риск жалобы?
7. **Тон-редактор** — «инженер-практик»: без канцелярита/восторгов, 1 экран,
   подпись менеджера, без длинных тире.
8. **Спам-техник** — спам-триггеры в теме/теле, подозрительные ссылки,
   текст/ссылки баланс — чтобы ответ не жёг репутацию ящика.

## Судья-скептик (финал)

Видит письмо + 8 вердиктов → одно из:
- **SEND** — критики нет (для авто-типов уходит; иначе кладётся черновиком).
- **FIX** — есть CRITICAL/значимые WARN → конкретные правки → перегенерация.
- **ESCALATE** — человеку с пояснением.
По умолчанию недоверчив: сомнение = не слать.

## Петля перегенерации (инженерная страховка)

`review_chain(email, ctx) -> (decision, final_email, verdicts)`:
1. qa_reply гейт; 2. 8 линз параллельно; 3. судья.
- FIX → генератор получает список fixes, **перегенерирует. Лимит 2 попытки.**
- После 2 неудачных → **ESCALATE человеку** с письмом и всеми вердиктами (не
  крутить вечно). ESCALATE от эскалация-гейта — сразу, без перегенераций.
Точка встраивания: между `render_reply()` и любым Action `reply_auto|reply_draft`.
`reply_auto` разрешён ТОЛЬКО при decision=SEND и пустых CRITICAL.

## Режимы и стоимость

- **pilot**: конвейер работает, но результат = ЧЕРНОВИК оператору (reply_auto
  понижен до reply_draft) — ревью копит золотые пары.
- **auto** (после пилота): reply_auto уходит сам, если судья дал SEND.
- Один вызов = короткий JSON, кэшируемо; при флаки-шлюзе — ретраи+фолбэк.

## Тест-сет (golden)

14 писем дрйрана email-assistant (`dryrun-letters.json`), где скептик уже ловил
проблемы. Конвейер ОБЯЗАН поймать: незакрытый горячий торг №9 (→ESCALATE),
неподтверждённые цифры №3/№5/№12 (→CRITICAL факт-чекер). Метрика: %SEND с первой
попытки, recall реальных ошибок.

## Источники сценариев (два пакета над общим ядром)

- **Ядро**: 11 поведенческих классов + план действий (направление-независимо).
- **Meyer-пакет**: few-shot из coldy-кампании (REPLY-TAXONOMY).
- **КЦ-пакет**: `email-assistant/PLAYBOOK.md` (7 типов + лестница контакта),
  `answer-kb.json` (цифры/модели), стоп-темы эскалации. Готов ~70%, подключить.
