# Что делать ПОСЛЕ добавления A-записей (запуск редиректора)

Контекст: A-записи `@` и `www` всех 11 активных доменов уже направлены (или
направляются) на IP твоего Linux-сервера. Дальше — три шага, всё остальное
делает скрипт `setup-redirects.sh`.

Куда какой домен будет редиректить (для сверки):

| Домены (7 шт) | Цель |
|---|---|
| kompressor-air-trade.ru, kompressor-pro-expert.ru, kompressor-air-expert.ru, compressor-air-expert.ru, kompressor-expert.ru, kompressor-pro-trade.ru, compressor-store.ru | → https://prokompressor.ru |

| Домены (4 шт) | Цель |
|---|---|
| sort-inspection.ru, optic-sort.ru, zernosort.ru, sort-systems.ru | → https://meyer-corp.ru |

(3 домена RU-CENTER на холде — в конфиг не входят, добавим когда решишь.)

## ⚠️ Прежде чем запускать: какой это сервер

- Скрипт рассчитан на **Linux** (Ubuntu/Debian, root, порты 80 и 443 свободны
  или заняты именно nginx-ом).
- Если A-записи ты направил на **parsercompressor.online (виндовый сервер с
  дропом)** — bash-скрипт там НЕ запускать: на 443 уже живёт дроп, и это
  Windows. Напиши мне, что там отдаёт HTTPS (nginx for Windows? Caddy? IIS?) —
  дам конфиг под него, тоже без ручной возни с сертами.

## Шаг 0. Проверить, что DNS доехал (5 минут - пара часов после правок)

С любой машины (или просто напиши мне «проверь редиректы» — прогоню чекер по
всем доменам сам):

```bash
curl -s "https://dns.google/resolve?name=kompressor-trade.ru&type=A"
# в ответе должен быть IP твоего сервера
```

Проверь по одному домену с каждого регистратора (Beget, REG.RU, Timeweb).
**Ждать все 11 не обязательно** — скрипт выпустит сертификаты на доехавшие,
остальные подхватишь повторным запуском (шаг 3).

## Шаг 1. Скопировать 2 файла на сервер

Нужны `setup-redirects.sh` и `redirects-nginx.conf` из `sender/deploy/`
**в одну папку** на сервере. Любым удобным способом:

```bash
# с машины, где клонирован репозиторий:
scp seo-texts/sender/deploy/setup-redirects.sh \
    seo-texts/sender/deploy/redirects-nginx.conf user@СЕРВЕР:/tmp/
```

(или через WinSCP / файловый менеджер панели хостера — главное, оба файла рядом).

## Шаг 2. Запустить скрипт

```bash
ssh user@СЕРВЕР
cd /tmp
sudo bash setup-redirects.sh
```

Хочешь получать письма Let's Encrypt об истечении сертов на свою почту:

```bash
LE_EMAIL=kirillrand4@gmail.com sudo -E bash setup-redirects.sh
```

Что скрипт сделает сам (и напишет по шагам 1/6…6/6):

1. Поставит nginx и certbot, если их нет.
2. Положит конфиг редиректов в `/etc/nginx/conf.d/rusprom-redirects.conf`
   (443-блок временно выключен) и поднимет http-редирект.
3. Откроет 80/443 в ufw (если ufw активен).
4. DNS-префлайт: проверит каждый домен и перечислит, кто уже смотрит на этот
   сервер, а кто «не доехал».
5. Выпустит ОДИН сертификат Let's Encrypt на все доехавшие имена (+www).
6. Включит https-редирект и поставит хук автопродления.

Успех выглядит так: `ГОТОВО. Проверь: curl -I https://…`
Если ни один домен не доехал — скрипт остановится и скажет об этом (это не
поломка: подожди DNS и запусти снова).

## Шаг 3. Проверить результат

```bash
curl -I http://kompressor-air-trade.ru/
# HTTP/1.1 301 Moved Permanently
# Location: https://prokompressor.ru/

curl -I https://kompressor-air-trade.ru/
# HTTP/2 301  + Location: https://prokompressor.ru/  (и без ошибок сертификата)

curl -I https://zernosort.ru/
# Location: https://meyer-corp.ru/

sudo certbot certificates
# один серт, в Domains перечислены все доехавшие имена, Expiry ~90 дней
```

Либо просто напиши мне **«проверь редиректы»** — прогоню DoH-чекер по всем 11
доменам и скажу, что зелёное, а что осталось.

## Если часть доменов «не доехала»

Скрипт их перечислит в конце. Когда DNS доедет (обычно минуты-часы, максимум
сутки) — **просто запусти его ещё раз**:

```bash
sudo bash setup-redirects.sh
```

Он идемпотентный: ничего не сломает, до-выпустит серт на новые имена
(`--expand`) и перезагрузит nginx.

## Частые проблемы

| Симптом | Причина → что делать |
|---|---|
| certbot: Timeout during connect | Порт 80 закрыт фаерволом хостера → открыть 80 и 443 в ЛК хостера, перезапустить скрипт |
| certbot: Invalid response / NXDOMAIN | A-запись не доехала или ведёт не туда → проверить шаг 0 |
| nginx: address already in use | 80-й порт занят другим веб-сервером (apache/панель) → напиши мне, разрулим |
| nginx warning: conflicting server name | Домен уже упомянут в другом conf-файле сервера → убрать дубль |
| Beget/Timeweb всё ещё показывают заглушку | A-запись заменили не полностью (осталась вторая) или DNS-кэш → проверить записи, подождать TTL |
| https ругается на серт у одного домена | Домен доехал позже выпуска серта → перезапустить скрипт |

## После того как всё зелёное

Ничего поддерживать не надо: сертификат продлевается сам (systemd-таймер
certbot + хук перезагрузки nginx уже поставлены скриптом). Финальную сверку
можно сделать чекером: `python3 sender/tools/check_domains.py` — у всех 11
доменов пропадёт претензия к редиректу.
