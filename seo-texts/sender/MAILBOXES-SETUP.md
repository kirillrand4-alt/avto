# Ящики на доменах-двойниках — создание в Я360/VK и вайринг в сендер

Объём на старт: **2 ящика на домен = 28 ящиков** (16 в Яндекс 360 на 8 доменах,
12 в VK WorkSpace на 6). Третий ящик на домен — потом, при масштабировании.
Ориентир по деньгам: ~250 ₽/ящик/мес (тарифы сверить в биллинге организаций),
итого ~7 тыс ₽/мес.

Отправная точка (по факту DNS-проверки): организации УЖЕ существуют — у 7
Я360-доменов и 4 VK-доменов стоят verification-TXT и DKIM, значит они
подтверждены в панелях. Осталось добавить в организации 3 домена RU-CENTER:
compressor-pro-systems.ru → Я360; kompressor-trade.ru, rentgen-detektor.ru → VK.

## 1. Яндекс 360 (admin.yandex.ru)

### 1.1. Добавить compressor-pro-systems.ru

Настройки организации → «Домены» → «Добавить домен» → панель выдаст
`yandex-verification: <код>` → внести TXT в зону на nic.ru → «Проверить».
После подтверждения на вкладке домена появится DKIM → включить подпись,
выданный ключ внести TXT-записью `mail._domainkey` на nic.ru.
MX/SPF — по шаблону из DOMAINS-SETUP.md (тоже на nic.ru).

### 1.2. Создать 16 ящиков (по 2 на каждый из 8 доменов)

«Пользователи» → «Добавить» → «Добавить сотрудника»:
- **Имя/Фамилия** — реального менеджера отдела продаж (28 человек — хватает 1:1);
- **Логин** — латиницей `и.фамилия` (i.petrov);
- **Домен адреса** — выбрать из списка нужный двойник (основной адрес должен
  быть именно на своём домене, не на первом попавшемся);
- пароль — временный, менеджеру не раздавать (ящик обслуживает сендер).

Каждый новый пользователь = платное место в тарифе — при добавлении биллинг
попросит оплатить/расширить.

### 1.3. На каждом ящике: IMAP + пароль приложения

1. Войти в ящик (mail.yandex.ru) под его логином (первый вход — принять условия).
2. Почта → «Все настройки» → «Почтовые программы»: включить
   «С сервера imap.yandex.ru по протоколу IMAP» и «Пароли приложений и OAuth».
3. id.yandex.ru → «Безопасность» → «Пароли приложений» → создать для
   «Почта (IMAP, POP3, SMTP)» → выданную строку сохранить в менеджер паролей —
   это и есть значение для env `BOXn_PASSWORD`. Обычный пароль аккаунта
   в сендер НЕ идёт.

### 1.4. Алиас dmarc@

«Пользователи» → выбрать ПЕРВЫЙ ящик (любой служебный) → «Алиасы» → добавить
алиас `dmarc`. В Я360 алиас действует на всех доменах организации — то есть
`dmarc@<каждый-из-8-доменов>` должен приезжать в этот один ящик. Проверить
тестовым письмом на dmarc@двух-трёх доменов; если на каком-то домене не дошло —
завести алиас на первом ящике того домена отдельно.

## 2. VK WorkSpace (biz.mail.ru)

### 2.1. Добавить kompressor-trade.ru и rentgen-detektor.ru

Админка → «Домены» → «Добавить» → выдаст `mailru-domain: <код>` → TXT на
nic.ru → подтвердить → включить DKIM (выдаст ключ `mailru._domainkey`) → TXT
на nic.ru. MX/SPF — по шаблону из DOMAINS-SETUP.md.

### 2.2. Создать 12 ящиков (по 2 на каждый из 6 доменов)

«Пользователи» → «Добавить»: имя/фамилия реального менеджера, логин латиницей,
домен адреса — свой двойник. Каждый пользователь — платное место тарифа.

### 2.3. На каждом ящике: пароль для внешних приложений

У Mail.ru обычный пароль для IMAP/SMTP НЕ работает в принципе:
1. Войти в ящик (e.mail.ru).
2. Настройки → «Безопасность» → «Пароли для внешних приложений» → создать
   (тип «Полный доступ» или «Почта») → строку в менеджер паролей → env.
3. Если в настройках почтовых программ есть переключатель IMAP — включить
   (обычно включён по умолчанию).

### 2.4. Алиасы dmarc@

Админка → пользователь (первый ящик домена) → «Алиасы» → добавить `dmarc`
на домене этого ящика. Повторить для каждого из 6 доменов (если панель
позволяет выбрать домен алиаса — можно повесить все на один ящик).
Проверить тестовым письмом.

## 3. Правила именования (важно и для доставляемости, и для юр-чистоты)

- Ящики — от имени РЕАЛЬНЫХ сотрудников ООО «Руспром» (отдел продаж, 28 чел):
  адрес `i.petrov@…`, from_name «Иван Петров, Руспром», подпись в письме — тот
  же человек. Ответ клиента попадает в лид-деск и закрывается этим же отделом.
- НЕ роль-адреса (sales@, info@, zakaz@) — хуже и по спам-фильтрам, и по
  конверсии, и выглядят как рассылка.
- Один менеджер может «владеть» ящиками на 1-2 доменах — без пересечений имён
  на одном домене.

## 4. Пароли и секреты

- Каждый пароль приложения → env-переменная на боевом сервере:
  `BOX1_PASSWORD` … `BOX28_PASSWORD` (маппинг ящик↔переменная фиксируется в
  yaml поле `password_env`).
- Хранить в `panel.env`/env-файле systemd (`chmod 600`), в git НЕ коммитить
  (правило репо: секреты только через env).

## 5. Вайринг в сендер (config.yaml → mailboxes)

На каждый ящик — блок (полный пример: `config/sender.example.yaml`):

```yaml
# Я360-ящик
- mailbox_id: "i.petrov@kompressor-air-trade.ru"
  provider: yandex
  smtp_host: smtp.yandex.ru
  smtp_port: 465
  imap_host: imap.yandex.ru
  imap_port: 993
  login: "i.petrov@kompressor-air-trade.ru"
  password_env: BOX1_PASSWORD
  from_name: "Иван Петров, Руспром"
  pool: pool_yandex

# VK-ящик
- mailbox_id: "a.smirnov@kompressor-trade.ru"
  provider: mailru
  smtp_host: smtp.mail.ru
  smtp_port: 465
  imap_host: imap.mail.ru
  imap_port: 993
  login: "a.smirnov@kompressor-trade.ru"
  password_env: BOX2_PASSWORD
  from_name: "Алексей Смирнов, Руспром"
  pool: pool_mailru
```

- Пулы: `pool_yandex` (шлёт получателям на Яндексе/своих корп-доменах),
  `pool_mailru` (шлёт на Mail.ru/VK) — провайдер-сплит уже в движке.
- Запись состояния ящика в БД создаётся автоматически при первом использовании
  (orchestrator), руками ничего инициализировать не надо.
- Готовность видно в панели: экран «Ящики» (/mailboxes/readiness) — коннект
  SMTP/IMAP, лимиты, паузы.

## 6. Смоук после подключения (до любых кампаний)

1. С каждого домена (хватит одного ящика из двух) отправить тест-письмо на
   свои контрольные ящики Яндекса и Mail.ru.
2. В полученном письме открыть «Свойства письма»/оригинал: SPF=pass,
   DKIM=pass (домен двойника), DMARC=pass. Письмо в инбоксе, не в спаме.
3. Убедиться, что imap_watcher видит ящик (панель «Ящики» зелёная).
4. Тест алиаса: письмо на dmarc@домена дошло до сборщика.

## 7. Не лить сразу — прогрев

Новые ящики стартуют с ramp-плана (`ramp.py`): маленькие дневные лимиты,
рост по дням, гейты bounce/complaint режут при первых проблемах. Холодную
базу подключать только после прогрева и смоука — по плану WARMUP/ROADMAP.
