## Часть 2: живой логин + доставка — ТОЛЬКО на боевом сервере

Из сессии наружу SMTP/IMAP (465/993) закрыты — аутентификацию каждого
ящика и реальную доставку проверить отсюда нельзя. Скрипт для сервера
(РФ-IP, порты открыты): `tools/smoke_boxes_live.py`.

```bash
# только логины (ничего не отправляет):
python3 sender/tools/smoke_boxes_live.py --config /opt/sender/config.yaml
# + тест-письмо на СВОЙ контрольный ящик (не по базе!):
python3 sender/tools/smoke_boxes_live.py --config ... --send you@yandex.ru
```

Проверяет по каждому ящику: SMTP-логин (пароль приложения принят),
IMAP-логин (автоответчик сможет читать входящие), опц. доставку. После
`--send` — глазами в контрольном ящике: инбокс/спам, в свойствах письма
**SPF=pass, DKIM=pass (домен ящика), DMARC=pass**.

## Находки

1. **Подписи менеджера в теле НЕТ как отдельного механизма.** «Подпись»
   письма — это From-name («Имя, Компрессор Центр») + безусловный юр-футер
   ООО «Руспром», ИНН. Персональной подписи («С уважением, Иван Петров,
   тел…») движок в тело не вставляет — если нужна, класть в шаблон `body`
   кампании (поле `signature_ref` в конфиге сейчас декоративное). Решение
   владельца.
2. **Трекинг-домен пикселя = unsub-домен по умолчанию.** Если не задан
   `tracking.base_url`, пиксель и ссылка отписки идут с
   `parsercompressor.online` (сервер владельца, рабочий). Для лучшего
   выравнивания с доменом рассылки задать `tracking.base_url` на поддомен
   двойника (напр. `link.kompressor-air-trade.ru`) — пример в
   `sender.example.yaml`, секция tracking.
3. **DMARC ещё не поднят.** Смоук доставляемости даст честный pass только
   после починки DMARC (сейчас записи в DNS с задвоенным именем
   `_dmarc.домен.домен` — исправить имя на `_dmarc`, см. DOMAINS-SETUP.md).
