# Ручная живая отправка (manual send)

Правило владельца: **живьём уходит только то, что оператор одобрил руками**.
Всё остальное — оркестратор, автоответчик, регенераторы — умеет ТОЛЬКО ставить
письма в очередь подтверждений. Нажал «Отправить» → письмо тут же проходит
реальный SMTP-диалог. Не нажал — ничего никуда не уходит.

## Два класса отправки

| | Ручная (оператор в очереди подтверждений) | Автоматика (orchestrator, autoresponder) |
|---|---|---|
| Что делает | `approve`/`edit` → **реальная отправка немедленно** (при `confirm.live_send: true`) | Только `submit`/`submit_reply` → черновик в `confirm_reviews` |
| Окно отправки (`window`) | **обходится** — оператор решает «сейчас» | соблюдается |
| Пейсинг ящика (интервал между письмами) | **обходится** | соблюдается |
| Межрегиональный зазор | **обходится** | соблюдается |
| Suppression (отписка/жалоба/бан) | **соблюдается** — блокирует даже ручную | соблюдается |
| has_reply-стоп | соблюдается (для исходящих) | соблюдается |
| Kill-switch / пауза ящика | **соблюдается** | соблюдается |
| Дневной лимит ящика | **соблюдается** | соблюдается |
| List-Unsubscribe, байлайн, юр-гейты | соблюдаются | соблюдаются |

Обходится только «когда» (тайминг), никогда — «можно ли» (комплаенс).

## Ответы клиентам (kind='reply')

Входящее письмо → `ReplyPipeline.draft_for_incoming()`:
автоответчик планирует (pilot / suppressed учтены), рендерит ответ, гоняет
review-chain через провайдерский API — и кладёт ЧЕРНОВИК в очередь.
Оператор в панели видит карточку «ОТВЕТ клиенту» с входящим письмом,
правит/одобряет → `sender.send_reply()`:

- уходит в тред (`In-Reply-To`/`References`), без окна и пейсинга;
- без `List-Unsubscribe` (это диалог, не рассылка);
- 90-дневный guard пропускается (клиент сам инициировал диалог);
- отписка/жалоба и kill-switch — по-прежнему блокируют.

## Как включить живую отправку (боевой сервер)

По умолчанию `confirm.live_send` ВЫКЛЮЧЕН — approve только помечает письмо
к отправке очередью (`status='approved'`). Для живого режима в `config.yaml`:

```yaml
confirm:
  mode: all          # каждое письмо через оператора
  live_send: true    # approve/edit = реальный SMTP немедленно
autoresponder:
  enabled: true      # входящие → черновики ответов в очередь
  mode: pilot        # автоответчик НИКОГДА не шлёт сам
```

`live_send` строит отдельный боевой `Sender(dry_run=False)` — панельный
`dry_run` на него не влияет. ⛔ На сессионной машине наружу SMTP закрыт;
живой режим — только на боевом сервере.

## Интерфейсы оператора

- **Веб-панель** `/confirm`: очередь, диффы, `[Enter] Отправить`; шапка
  показывает «режим ЖИВОЙ отправки» / «режим очереди» и тип карточки
  («ОТВЕТ клиенту» / «исходящее»).
- **CLI**: `confirm-queue`, `confirm-show <id>`, `confirm-decide <id> ...`,
  `confirm-run` — тот же бекенд `ConfirmSend`, полный паритет с панелью.

## Доказательство

`tests/test_confirm_live_smtp.py` — поднимает НАСТОЯЩИЙ SMTP-сервер
(aiosmtpd, 127.0.0.1) и проверяет: approve исходящего → письмо прошло
реальный MAIL FROM/RCPT TO/DATA, в приёмнике корректные Subject и
List-Unsubscribe; approve ответа → письмо в треде (`In-Reply-To`),
байлайн «ООО «Руспром»» в теле.

Попутно этим тестом пойман и починен реальный баг доставки:
`smtplib.sendmail` для bytes НЕ конвертирует LF→CRLF, сервер отвечал
«Line too long (RFC5321 4.5.3.1.6)». Фикс — `_build_mime` сериализует
через `email.policy.SMTP` (CRLF-переводы строк).
