# Спека: open-tracking (колонка «Открыл», как у coldy)

Решение владельца 2026-07-20: добавить отслеживание открытий писем — колонка
«Открыл» в панели/аналитике, аналогично coldy. С ЧЕСТНОЙ пометкой про РФ (см. ниже).

## Зачем и оговорка (обязательна в UI)

74% базы — Mail.ru/Яндекс, они **проксируют картинки** в письмах: открытие
либо не считается (картинки выключены), либо **накручивается** (провайдер сам
грузит пиксель для антиспам-проверки → ложное «открытие» без участия человека).
Поэтому open — **справочный сигнал, НЕ основа решений**:
- показывать в ленте/аналитике с пометкой «в РФ приблизительно»;
- гейты каденции/приоритеты вести по **ответу/клику**, НЕ по открытию
  (это уже заложено в REVIEW-FINDINGS: engagement по click/reply);
- в отчётах open_rate давать отдельно, не подмешивая в «вовлечённость».

## Что реализовать

1. **Трекинг-пиксель.** 1×1 прозрачный GIF на трекинг-домене. Расширить
   существующий `unsub_server` новым роутом `GET /o/<token>` (рядом с `/u`),
   отдающим `image/gif` (43 байта), всегда 200, кэш off.
2. **Токен.** Подписанный (тем же `UNSUB_SIGNING_SECRET`/HMAC, как unsub),
   кодирует `message_id` (+recipient_id, campaign_id). Стойкий к подделке.
3. **Вставка пикселя.** В `personalize`/сборку письма добавлять
   `<img src="https://<track>/o/<token>" width="1" height="1" alt="">` перед
   `</body>`. Только для HTML-писем. Уважать флаг «open-tracking выкл» (config
   per-campaign, как `isOpenTrackingDisabled` у coldy).
4. **Событие.** При загрузке пикселя писать `event_type='open'` в `events`
   (новая константа `EVENT_OPEN = "open"`). Дедуп: первое открытие на письмо
   (UNIQUE по message_id+type), плюс опц. счётчик повторных. НЕ считать
   открытием запрос в первые ~2-3 сек после отправки (отсев провайдер-префетча).
5. **Аналитика.** `analytics`: `open_count`, `open_rate=_pct(opens, sent)` в
   `CampaignReport`/`dashboard()`. НЕ включать open в bounce/complaint-гейты.
6. **API + панель.** Отдать open в эндпоинтах кампании/ленты; в UI — колонка
   «Открыл ✉N» (как на скрине coldy) с тултипом-оговоркой про РФ.

## Тесты (обяз.)

- пиксель отдаёт валидный GIF + 200 на любой токен-запрос;
- валидный токен → пишет `open`, повторный → не дублирует (или инкремент);
- поддельный/битый токен → 200 GIF, но событие НЕ пишется;
- префетч-отсев: запрос < N сек после отправки не засчитан;
- `personalize` вставляет пиксель только в HTML и только при включённом трекинге;
- analytics: open_rate считается, в bounce/complaint НЕ попадает.

## Границы

Не гейтить отправку по открытиям. Не хранить IP/UA сверх необходимого (ФЗ-152).
Трекинг-домен — тот же, что `unsub_base_url` (или поддомен), TLS обязателен.
