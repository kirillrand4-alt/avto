# Сендер-сервис: состояние и как продолжить

Свой сервис холодной B2B-рассылки для ООО «Руспром» — замена coldy (SMTP-отправка
с наших Яндекс360/VK ящиков, IMAP-приём/ответы, свой живой прогрев, юр-гейты
ФЗ-38/152, стык с AI reply-desk). Причина «своего»: база не уезжает на сторону,
контроль, экономия тарифа. Разбор coldy и вывод — в `FEATURES-PLAN.md`.

## Что готово (в этом каталоге, [git])

- **`FEATURES-PLAN.md`** — все фичи coldy + наш модульный план P0/P1 + ответ по
  тест-домену (реальный домен нужен только на финальном smoke-тесте; разработка и
  автотесты — на локальном SMTP-песочнике).
- **`CONTRACT.md`** — контракт интерфейсов (820 строк): SQLite-схема (8 таблиц),
  публичный API 13 модулей, DTO, YAML-конфиг, инварианты безопасности. Проверен:
  идемпотентность (sha256-ключи, UNIQUE, ON CONFLICT), резюм после рестарта (lease
  + recover_stale), закрытая гонка «ответил→не слать дубль», hard/soft bounce,
  юр-гейт (List-Unsubscribe + RFC 8058 one-click), kill-switch с min_volume.

## Что генерится (13 модулей, изолированно по контракту)

Порядок: config, store, suppression, validation, personalize, gates, sender,
imap_watcher, cadence, unsub, analytics, warmup, orchestrator. Каждый — свежий
изолированный вызов провайдера (видит только CONTRACT + свой фокус), + pytest-тесты,
+ компиляционная проверка. Скрипт генерации: `scratchpad/gen_modules.py`
(резюмируемый по кэшу). Готовый код → `scratchpad/sender-build/sender/`, после
баг-ханта переносится СЮДА (`seo-texts/sender/`) и коммитится.

## Что дальше (план до результата)

1. Дождаться генерации всех 13 модулей (фон).
2. **Механический прогон pytest** на локальном SMTP/IMAP-песочнике (aiosmtpd +
   IMAP-mock): лимиты, рамп, стоп-на-ответ, bounce, дедуп, резюм после рестарта.
   Без API.
3. **Баг-хант через провайдера**: независимые линзы (корректность/гонки, логика
   делайверабилити, безопасность/ПД, edge-cases кодировок/заголовков,
   отказоустойчивость) × loop-until-dry с потолком; фиксы через провайдера;
   перепрогон тестов после каждого круга.
4. Перенести финальный код в `seo-texts/sender/`, закоммитить.
5. Финальный smoke-тест доставляемости на реальном домене с 2 ящиками (перед
   пилотом): SPF/DKIM/DMARC pass + попадание в инбокс.

## Как продолжить в НОВОЙ сессии

> Работаем над сендер-сервисом. Читай `seo-texts/sender/SENDER-STATE.md`,
> `CONTRACT.md`, `FEATURES-PLAN.md`. Код в `scratchpad/sender-build/` эфемерный —
> если новая сессия, сначала подними его из git/drop или перегенерируй
> `gen_modules.py`. Продолжай с шага <N>. Тяжёлое — через провайдер, фон.

⚠️ Код в scratchpad ЭФЕМЕРЕН. Перед закрытием сессии он должен быть либо
закоммичен сюда, либо залит на drop — иначе новая сессия его не увидит.
