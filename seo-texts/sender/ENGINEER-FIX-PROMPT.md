# Промпт для сессии инженера: исправление ошибок ревью (sender)

Ты — инженер проекта самописного B2B cold-email рассыльщика (`seo-texts/sender/`), РФ, под
ФЗ-38 «О рекламе». **ХОЛД активен: боевую отправку/прогрев НЕ запускать.** Задача — починить
дефекты, найденные ревью, не запуская отправку. Полный список — `REVIEW-FINDINGS.md`
(+`.json`), сгенерирован провайдер-ревью (sonnet-5) и частично спот-верифицирован.

## Как работать с каждым пунктом

1. **Сначала верифицируй** — прочитай реальный код по `file:line`, воспроизведи сценарий
   (или напиши падающий тест). Если это ложное срабатывание — отметь «не баг + почему» и не трогай.
2. **Чини минимально** — не рефактори широко, только дефект.
3. **Тест** — на каждый подтверждённый баг добавь/поправь тест в `sender/tests/` (падал до, зелёный после).
4. **Ничего не отправляй** — HOLD. Прогоняй только unit/integration в песочнице.

## Приоритет 1 — ЮРИДИКА (ФЗ-38: отписка соблюдается НАВСЕГДА). Чинить первыми.

Это сквозная тема — «подавленный/отписавшийся адрес всё ещё можно отправить». Корни:

- **Нормализация email рассинхронизирована** (главное): `store.upsert_recipient` НЕ нормализует
  email (strip/lower), а `suppression.value`/`log_consent` — нормализуют → точное сравнение
  `s.value = r.email` промахивается → письмо уходит отписавшемуся. Чинить единообразно:
  `store.py:394` (UNIQUE на сырой email), `store.py:710/706`, `store.py:979`, `suppression.py:259`.
  → Нормализовать email в ОДНОЙ точке (при записи recipient И suppression), добавить
  функциональный индекс/сравнение по `lower(trim(email))`. Тест на разный регистр/пробелы/plus.
- **Отписка может истечь/быть удалена** (`suppression.py:271`, `suppression.py:407`,
  `store.py:1566`): записи `reason='unsubscribe'` должны быть ВЕЧНЫМИ. → `is_suppressed` не
  должна возвращать None для истёкшей unsubscribe-записи; `suppression_remove` должна
  запрещать удаление `reason='unsubscribe'`; upsert не должен перезатирать unsubscribe
  competitor-записью с TTL. Гарантировать `expires_at IS NULL` для unsubscribe на уровне store.
- **Импорт CSV не сверяется с подавлением** (`importer.py:261`): `bulk_upsert_recipients` без
  джойна с suppression → ранее отписавшийся снова в очереди. → Фильтровать по suppression на импорте.
- **one-click отписка рапортует успех при неудаче** (`unsub_server.py:118`, `unsub_server.py:152`,
  `unsub.py:194`): всегда 200 OK / проглоченная ошибка log_consent. → Проверять результат
  `handle_one_click`, отдавать не-200 при неудаче записи; не терять журнал согласия молча.
- **Проверка подавления только на claim, не перед SMTP-send** (`store.py:973`, `suppression.py:267`,
  `store.py:971`): отписка в окне между claim и отправкой не учитывается. → Перепроверять
  `is_suppressed`/`has_reply` в SMTP-воркере НЕПОСРЕДСТВЕННО перед `DATA`.
- **Юр-атрибуция рекламодателя (ИНН) может не проставиться** (`personalize.py:284`,
  `personalize.py:312`, `sender.py:710`): подстрочное совпадение отменяет футер; `extra`
  перетирает `legal_entity`; слепая перезапись `List-Unsubscribe`. → Жёстко проставлять
  legal-поля рассыльщика, не давать `extra` их перетирать, не затирать `List-Unsubscribe`.

## Приоритет 2 — ДОСТАВЛЯЕМОСТЬ / ЦЕЛОСТНОСТЬ (обход лимитов/рампы, дубли)

- **Header injection** (`personalize.py:404`, `sender.py:706`): merge-поля с `\r\n` в subject/
  headers → инъекция заголовков. → Санитизировать CR/LF/управляющие во всех подстановках в заголовки.
- **STARTTLS на 587 не вызывается** (`sender.py:732`): `use_ssl` только для 465 → пароль/тело
  открытым текстом или недоставка. → Вызывать `starttls()` на 587.
- **Гонки счётчиков → превышение лимита/рампы** (`store.py:1268` increment_sent lost-update,
  `warmup.py:295`/`warmup.py:329` warmup ramp, `cadence.py:105` canary 2×N, `orchestrator.py:268`
  обнуление счётчиков при parallel bootstrap): → `BEGIN IMMEDIATE`/атомарный `UPDATE ... SET x=x+1`,
  блокировка на mailbox_id, ON CONFLICT в upsert_mailbox_state.
- **TZ в дневном ключе/рампе** (`store.py:1279`, `store.py:346`, `cadence.py:254`): naive/UTC vs
  локальный день → рампа/лимит считаются не на той границе. → Явная TZ (МСК) для day_key, aware datetime.
- **Каденция** (`cadence.py:163` next_step всегда step0 → повторная отправка;
  `cadence.py:340` skip выпадает навсегда + сжатие интервала; `cadence.py:198` bounce по всему
  домену блокирует валидных): → чинить логику выбора шага, defer вместо drop, bounce по получателю.
- **fail-open вместо fail-safe при ошибке чтения паузы** (`orchestrator.py:344`, `orchestrator.py:231`,
  `orchestrator.py:322`, `gates.py:320`): транзиентная ошибка → ящик считается не-паузнутым/гейт
  no-op → шлём с заблокированного по bounce ящика. → При ошибке чтения состояния — считать paused
  (fail-safe), не маскировать TypeError в 0.
- **mailbox None → письмо висит 15 мин** (`orchestrator.py:404`): → возвращать в scheduled сразу.
