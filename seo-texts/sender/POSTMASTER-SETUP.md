## Шаг 1. Подтвердить домены в кабинете (делается один раз)

Mail.ru считает статистику **по домену из DKIM-подписи**, поэтому добавлять
надо ВСЕ домены-отправители, а не один:

```
compressor-air-expert.ru   compressor-store.ru        kompressor-air-expert.ru
kompressor-air-trade.ru    kompressor-expert.ru       kompressor-pro-expert.ru
kompressor-pro-trade.ru    optic-sort.ru              sort-systems.ru
zernosort.ru
```

1. Зайти на https://postmaster.mail.ru под рабочим аккаунтом Mail.ru
   (запомнить, под каким — токен будет привязан именно к нему).
2. «Добавить домен» → способ подтверждения **DNS-запись** (у наших доменов
   сайтов нет, только редиректы, поэтому файл/мета-тег не подходят).
3. Кабинет выдаст TXT-значение. Его нужно внести в зону домена у
   регистратора (reg.ru) — так же, как вносили DMARC.
4. Повторить для каждого домена. Подтверждение занимает от минут до суток.

Если TXT-записи проще внести мне — пришли доступ к DNS или сами значения,
и я подготовлю точный список записей.

## Шаг 2. Получить refresh-токен (2 минуты)

Будучи залогиненной в mail.ru под тем же аккаунтом, открыть в браузере
ОДНОЙ строкой:

```
https://o2.mail.ru/login?client_id=postmaster_api_client&response_type=code&state=rusprom&redirect_uri=https%3A%2F%2Fpostmaster.mail.ru%2Fext-api%2Foauth%2F
```

Страница вернёт JSON примерно такого вида:

```json
{"refresh_token":"...", "access_token":"...", "expires_in":3600}
```

Нужен **`refresh_token`** — он бессрочный. `access_token` живёт час, панель
будет обновлять его сама.

## Шаг 3. Передать токен

Прислать мне строкой `POSTMASTER_REFRESH_TOKEN=<значение>` — я положу его в
`panel.env` через `panel_env_set` (файл секретов, не в git) и перезапущу
панель. Либо вписать самостоятельно в `C:\sender\panel.env` и выполнить
`Restart-Service SenderPanel -Force`.

## Шаг 4. Проверка (моя сторона)

```
python _ops_postmaster_probe.py     # reg-list → troubles → stat-list
```

Ожидаем: список подтверждённых доменов, пустой список проблем и суммарная
статистика за неделю. После этого репутация из Mail.ru выводится на дашборд
рядом с нашими отказами и жалобами.

## Что даёт Постмастер сверх того, что мы уже видим

| Метрика | Есть у нас | Даёт Постмастер |
|---|---|---|
| Отправлено, отказы, жалобы по IMAP | да | — |
| Открытия (пиксель) | да | — |
| Доля писем, попавших **в спам** | нет | да |
| Жалобы «это спам» от пользователей Mail.ru (FBL) | частично | да, точно |
| Репутация домена глазами Mail.ru | нет | да |
| Проблемы SPF/DKIM/DMARC глазами Mail.ru | только свои проверки | да |

Главное — колонка «в спам». Свои метрики показывают, что письмо **принято**
сервером, но не показывают, легло оно во «Входящие» или в «Спам». Это
единственный способ увидеть разницу, не считая ручных смоук-писем на
контрольные ящики.

## Технические детали API (для будущих сессий)

- База: `https://postmaster.mail.ru` (НЕ `/api/v1`).
- Заголовок нестандартный: `Bearer: <access_token>` (не `Authorization`).
- Методы: `/ext-api/reg-list/`, `/ext-api/troubles-list/`,
  `/ext-api/stat-list/`, `/ext-api/stat-list-detailed/`.
- Параметры статистики: `date_from` (обязателен, YYYY-MM-DD), `date_to`,
  `domain`, `msgtype`.
- Обновление токена: `POST https://o2.mail.ru/token` с
  `client_id=postmaster_api_client&grant_type=refresh_token&refresh_token=…`.
- Лимит: 10 запросов в минуту на домен по группе методов.
