## Зачем этот источник

Проектная документация проходит экспертизу ДО того, как объявлена закупка
оборудования. Заключение ЕГРЗ это самое раннее ГОТОВОЕ событие в цепочке: проект
уже есть, закупки ещё нет, конкурентов на объекте ещё нет. В записи стоит ИНН
застройщика, то есть предприятие опознаётся однозначно.

Чего в ЕГРЗ НЕТ и не будет: людей. Ни ФИО ответственных, ни телефонов, ни почт
(проверено прямым поиском по всей выгрузке, числа ниже). Это источник
ПРЕДПРИЯТИЙ и СОБЫТИЙ, а человека по добытому ИНН надо искать другими путями.

### Ловушки канала, каждая проверена прямым замером

**1. TLS.** `egrz.ru` требует legacy renegotiation. Лечится конфигом OpenSSL, НЕ
отключением проверки сертификата. Переменная `OPENSSL_CONF` читается OpenSSL при
инициализации библиотеки, то есть раньше нашего кода, поэтому правка
`os.environ` в начале скрипта уже опаздывает. Клиент перезапускает сам себя с
нужным окружением (`podgotovit_tls`), конфиг пишет сам, серверный раннер не
нужен. Проверено запуском с полностью пустым `OPENSSL_CONF`.

**2. `$top` больше 100 это HTTP 400, а не усечение.** Проверено на 500, 1000,
5000 - все три дали 400. Страница строго 100 записей.

**3. Ограничение сложности запроса: `node count limit of '100'`.** Фильтр из 32
условий `contains(tolower(...))` через `or` сервер отверг с HTTP 400 и текстом
«The node count limit of '100' has been exceeded». То есть длинный список слов в
один `$filter` не помещается. Поэтому в клиенте есть режим `vygruzka-po-slovam`:
каждое слово тянется отдельным запросом, результаты сшиваются по `Key`. Побочная
выгода - провенанс: видно, каким словом найдена каждая запись, и записи,
найденные тремя словами, отличимы от найденных одним (`nayden_po`,
`nayden_slov`).

**4. Хост рвёт соединение.** `Connection reset by peer` прилетает в среднем
каждые полторы-две страницы. Лечится ретраями (в клиенте 7 попыток с растущей
паузой), но скорость упирается примерно в **500 записей в минуту**. Полная
выгрузка всех 70 тысяч свежих заключений это около двух часов непрерывной
работы - за одну смену не укладывается, поэтому сделано возобновление.

**5. Оборванная выгрузка выглядела как успешная.** Первый прогон на 70 235
записей встал на `skip=6600`, исчерпав ретраи, и при этом завершился **кодом 0**
и надписью «выгрузка окончена». Это моя ошибка, и она хуже самого обрыва:
вызывающая сторона не могла отличить обрыв от успеха. Исправлено - неполная
выгрузка теперь печатает «НЕПОЛНАЯ (оборвана)» и выходит кодом 2.

## Две ошибки, которые поймали контроли, и обе меняли числа

### `contains()` регистрозависим

Прямой замер по слову «компрессорная» в поле `ExpertiseObjectName`:

| написание | найдено |
|---|---|
| `компрессорная` строчными | 208 |
| `Компрессорная` с заглавной | 65 |
| `КОМПРЕССОРНАЯ` прописными | 1 |
| `tolower(поле)` + строчные | **274** |

четверть находок** и при этом выглядит как нормально сработавший фильтр. Везде в
клиенте используется `tolower(поле)`.

## Ограничения канала, честно

1. **Скорость.** Около 500 записей в минуту из-за разрывов соединения. Полная
   выгрузка 70 тысяч свежих заключений - порядка двух часов.
2. **Сплошная выгрузка за 12 месяцев НЕ ДОВЕДЕНА до конца.** Скачано 11 500 из
   70 239. Файл и состояние сохранены, прогон возобновляем командой ниже.
3. **Реестр пополняется во время выгрузки**, поэтому возобновление по `$skip`
   годится, чтобы дотянуть прерванный прогон в тот же день, но для регулярного
   повтора «раз в неделю за свежим» надо брать не `$skip`, а дату: запускать с
   `--s-daty <дата прошлого прогона>`. Дубли по `Key` клиент отсекает в любом
   случае.
4. **Людей в источнике нет вовсе** - ни одного телефона, ни одной почты на 523
   записи. ЕГРЗ даёт предприятие и событие, не контакт.
5. **Марка машины почти не встречается** (4 %), то есть по ЕГРЗ нельзя понять,
   центробежный компрессор в проекте или винтовой. Тип машины надо добирать из
   другого источника.

## Как повторять

```bash
cd seo-texts

# контроли прибора (выдуманное слово + сходимость регистра)
python3 egrz_client.py kontrol

# отдача каждого слова по одному
python3 egrz_client.py proba-slov --slova-fayl slova.txt \
    --s-daty 2025-09-16 --tolko-polozhitelnye

# рабочая выгрузка: пословно, с накоплением источников
python3 egrz_client.py vygruzka-po-slovam --slova-fayl slova.txt \
    --s-daty <дата прошлого прогона> --tolko-polozhitelnye --compact \
    --vyhod /путь/выгрузка.jsonl

# дотянуть прерванную сплошную выгрузку с места обрыва
python3 egrz_client.py vygruzka --s-daty 2025-09-16 --tolko-polozhitelnye \
    --compact --prodolzhit --vyhod /путь/egrz-12mes-polozh.jsonl
```

Неполная выгрузка выходит кодом 2 - это надо проверять, иначе обрыв неотличим от
успеха.
