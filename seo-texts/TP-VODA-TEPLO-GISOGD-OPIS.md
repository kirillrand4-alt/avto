# Вода, канализация, тепло и градостроительные системы: что там есть и чего нет

Замер 17.09.2026. Участок этой сессии — **водоканалы, теплосети и ГИСОГД/ИСОГД**.
Электросети и газ копали соседние сессии, сюда не лезем.

Вопрос ко всякому источнику один и тот же: **есть ли в нём ЗАЯВИТЕЛЬ** — имя юрлица,
которое строит и просит подключения, а не имя сетевой организации, которая раскрывает
информацию о себе. Владелец дословно: «пока 0 не доказан я в него не верю», поэтому
каждый ноль ниже доказывается **отсутствием колонки**, а не пустотой первых строк.

Скрипт: `seo-texts/tp_voda_teplo.py`. Все команды воспроизводимы:
`env | samoprover | kontrol | probe | karta | hunt | razbor | bundle | api | gisogd | tarifspb`.

## 4. Что лежит ВМЕСТО реестра: разбор самих файлов по колонкам

Ноль доказывается тем, что нужной КОЛОНКИ нет, а не тем, что первые строки пусты.
Разобрано файлов: 16 (вода) + 18 (тепло) = 34, из них открылись и разобраны 20.

### 4.1. Формы раскрытия водоканала — это шаблон ЕИАС ФАС, а не реестр

`Раскрытие информации Печерские пески подкл к ВС.XLSX`, Нижегородский водоканал,
870 085 байт. Прибор напечатал шапку:

```
листов в книге ......... 89
код отчёта ............. PP108.OPEN.INFO.REQUEST.CONNECTION, версия 1.1.1
лист «Титульный» ....... 79 непустых строк
   Наименование ЮЛ / ИП .......... АО "ОКО"
   ИНН ........................... 5257087027
   КПП ........................... 525701001
   Субъект РФ .................... Нижегородская область
   Дата подачи заявления ......... 2026-08-05
   Номер заявления ............... исх-19664
   Период регулирования .......... 2026-08-05 — 2028-02-05
лист «ХВС. Т-подкл» .... 75 строк: «Наименование тарифа», «Территория действия»,
                         «Добавить протяжённость водопроводной сети», «Добавить
                         подключаемую нагрузку», «Добавить диапазон диаметров»
лист «Перечень тарифов»  146 строк, все — названия ВИДОВ тарифов, не объектов
```

Что это значит без прикрас. **Юрлицо и ИНН тут ЕСТЬ — но это организация, которая
просит у регулятора установить плату**, а не застройщик, который просит подключения.
Это ровно та ловушка, о которой предупреждали: «наименование юрлица» в форме
раскрытия оказывается самой регулируемой компанией. Заявитель-застройщик в книге
из 89 листов **не назван ни одной колонкой**. Косвенно остаётся только имя объекта —
«Печерские пески» — в НАЗВАНИИ ФАЙЛА, а не в данных.

**как поля для заполнения заявителем**, и ни в одном опубликованном файле они не
заполнены — заполненного реестра нет.

**Колонки «заявитель» в форме нет вообще.** Есть пять параметров и их значения.
Адреса в строках 5.1–5.8 — это адреса СВОИХ котельных теплосети, а не объектов
заявителей. Так устроены все 13 файлов этого вида у ГУП ТЭК СПб (23–49 строк
каждый, определитель заявителя дал по ним пустой список — `заявитель-слова=[]`).

Это и есть доказательство нуля по правилу владельца: не «первые строки пусты», а
**в форме отсутствует колонка**, в которую заявителя можно было бы записать.

### 4.4. Орган тарифного регулирования: акты есть, «индивидуального порядка» нет

Проверена гипотеза, что заявителя назовёт РЕГУЛЯТОР: индивидуальная плата за
подключение устанавливается под конкретный объект. Комитет по тарифам СПб,
`tarifspb.ru/documents/acts/`, прочитано 70 страниц реестра актов:

```

из них со словом «плата» ............... 56
со словом «подключение» ................ 41
со словом «в индивидуальном порядке» ... 0
со словом «водоснабжение» .............. 27
со словом «теплоснабжение» ............. 60
КОНТРОЛЬ «щварцкопфер» ................. 0
```

Открыт один акт целиком (распоряжение № 83-р от 04.09.2026): плата устанавливается
**для теплоснабжающей организации** («…к системе теплоснабжения общества с
ограниченной ответственностью „Инновационная теплоэнергетика“»), заявитель-застройщик
в акте не фигурирует. То есть и здесь названо юрлицо-сеть, а не юрлицо-заявитель.

### 5.3. ЕИСЖС наш.дом.рф: 403 отдаёт WAF, и он не различает запросы

```

api/kn/object ................... 403, 45 633 байта
api/kn/developer ................ 403, 45 633 байта
КОНТРОЛЬ api/kn/shvarckopfer .... 403, 45 633 байта  <- ТОТ ЖЕ ОТВЕТ
```
Контроль здесь решает всё: **выдуманный путь получает тот же 403 и тот же размер**,
значит 403 говорит о заслоне на входе, а не об отсутствии данных. Это не «источника
нет», это «нас не пускают» — и с сервера владельца, и из песочницы одинаково.
Источник остаётся непроверенным, а не опровергнутым.

## 8. Куда смотреть дальше на этом участке

По итогам замера ранжирую по тому, сколько личных номеров это может дать.

1. **ЕИСЖС наш.дом.рф через браузерную пробу на сервере.** Единственный из
   проверенных федеральных сервисов, где застройщик и ИНН заявлены по описанию.
   Заслон — WAF на заголовках, а не отсутствие данных.
2. **Ключ к apidata.mos.ru.** Набор разрешений на строительство Мосгосстройнадзора —
   это объект, адрес и застройщик по Москве. Ключ бесплатный, выдаётся по заявке;
   это не техническая, а организационная задача владельца.
3. **Индивидуальная плата за подключение у ДРУГИХ регуляторов.** У Комитета по
   тарифам СПб таких актов 0 из 700, но регион выбран один. Там, где плата
   устанавливается в индивидуальном порядке, в акте появляется конкретный объект,
   а за ним — застройщик. Проверять надо реестры актов РЭК/РСТ по регионам, где
   строятся промышленные площадки.
4. **Имя объекта из имени файла.** Слабый, но рабочий ход: файлы вида «Раскрытие
   информации по заявлению от 05.08.26 (Печерские пески подкл к ВС)» называют
   ОБЪЕКТ. Объект → застройщик ищется в ЕГРЗ, где у нас уже 495 записей с ИНН.
   То есть водоканальный след годится не как источник контактов, а как СОБЫТИЕ,
   которое датирует стройку.

**Чего на этом участке искать НЕ надо** (проверено, ноль доказан колонками):
реестров выданных ТУ, журналов заявок и перечней договоров о подключении
водоканалы и теплосети не публикуют. 41 организация, 532 страницы, 50 разобранных
файлов, 0 находок, 0 ложных срабатываний контроля.
