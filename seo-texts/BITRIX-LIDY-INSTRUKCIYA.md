# Лиды в Битрикс24 из своей панели — инструкция для другой сессии (15.10.2026)

Так сделано и проверено для панели обзвона Meyer (`/obzvon-meyer`, порт 8016, `C:\centro2`). Задача — сделать то же
для **панели рассылки** (`panel.parsercompressor.online` / `zernosort.ru`, Caddy → `127.0.0.1:8091`): лид из панели
сразу появляется в Битриксе с нужными полями, источником и ответственным.

## 1. Вебхук (секрет)
* Входящий вебхук владелец уже выдал. Ссылка лежит **только на сервере**: `C:\centro2\data\bitrix-webhook.secret`
  (одна строка вида `https://bitrix-po22.ru/rest/<id>/<код>/`). Читай её оттуда (или скопируй в настройки своей
  панели на сервере — не в репозиторий, не на дроп). **Никогда не печатай ссылку** в вывод/журналы/коммиты — только
  домен `bitrix-po22.ru`.
* Права вебхука — только `crm`, от имени пользователя «MEYER MARKETING SERVICE» (id 12396, не админ).
  Проверено 14–15.10:
  * **может:** `crm.lead.add` (лид создаётся), читать справочники: `crm.lead.fields`, `crm.status.list`,
    `crm.dealcategory.list` (видны все 23 воронки), `crm.dealcategory.stage.list`, `crm.deal.fields`, `crm.requisite.fields`;
  * **не может:** читать лиды/компании (`crm.lead.list`, `crm.lead.get`, `crm.company.list` → ошибка/пусто), удалять
    (`crm.lead.delete` → «Access denied»), видеть пользователей (`user.*` — нет scope `user`). Значит: проверки дублей по
    ИНН на нашей стороне через Битрикс нет; тестовые лиды удаляет владелец вручную.
* Вызовы — с сервера (у песочницы выхода на портал может не быть): `python3 seo-texts/zapusk_na_servere.py <скрипт>`;
  POST JSON: `urllib.request.Request(B + 'crm.lead.add.json', data=json.dumps({'fields': f, 'params':
  {'REGISTER_SONET_EVENT': 'Y'}}).encode(), headers={'Content-Type': 'application/json'})`.

Обязательных полей у лида через API нет. На любой новый лид в Битриксе срабатывают бизнес-процессы «Лид из Marquiz» и
«Автозакрытие лида» — владелец в курсе, проверь на тестовом лиде, что они не закрывают его раньше времени.

## 3. Ответственные
* ID менеджеров панели обзвона: `seo-texts/bitrix_polzovateli_meyer.json` (meyer1…meyer9 → bitrix_id).
* Тестовый пользователь владельца: **Баданина Ксения Андреевна, id 7981** — все тесты только на неё.
* ID другого человека владелец даёт ссылкой профиля `https://bitrix-po22.ru/company/personal/user/<ID>/`.
* Хорошо бы в панели давать выбрать ответственного перед отправкой (по умолчанию — тот, кто работает с лидом).

## 4. Как тестировать (порядок, который владелец одобрил)
1. Только чтение: права (`scope`), поля, стадии, источники — образец `seo-texts/fixBX_proverka.py`, воронки —
   `seo-texts/fixBX_voronki.py`.
2. **Один** тестовый лид **по команде владельца**, ответственная — 7981, в названии «ТЕСТ — …», в комментарии
   «ТЕСТ … — лид можно удалить». Образец — `seo-texts/fixBX_test_lid.py` (`--sozdat <ИНН>`): берёт реальную
   компанию панели, ЛПР с мобильным, собирает поля по таблице выше, печатает ID и ссылку
   `https://bitrix-po22.ru/crm/lead/details/<ID>/`. Пример 15.10: лид 379865 (Урицкий молокозавод) — владелец удаляет
   вручную (вебхук удалять не может).
3. Владелец смотрит лид в Битриксе → только после его «ок» — отправка из панели для всех.

## 5. В самой панели (план)
Кнопка «Создать лид в Битриксе» в карточке (или автоматически на нужном событии — спроси владельца), выбор
ответственного, очередь отправки с повторами (Битрикс недоступен — отправить позже), журнал, ID и ссылка на лид в
карточке, защита от повторной отправки той же компании. Код панели менять под её правилами (замок, проверка, перезапуск).

## 6. Безопасность
Ссылка вебхука — только в файле на сервере; не в репозитории, не на дропе, не в выводе. Номера телефонов в скриптах
репозитория — только заглушки. Тестовые лиды — только с согласия владельца и только на 7981.
