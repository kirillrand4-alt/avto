# Генерация SEO-текстов каталога prokompressor.ru

Документ описывает область «генерация текстов»: сборка входных данных (payload), вызов
провайдерской модели, механический QA, регенерация, пост-фиксы, сборка микроразметки и CSV
для импорта в Битрикс.

Проверено на коммите `b2f9d5c`, ветка `claude/seo-texts-enrichment-prompt-449lyw`, рабочее
дерево чистое (`git status` пуст).

## 1. Что это и зачем

На сайте prokompressor.ru есть 759 страниц каталога (бренды и фасеты: давление, мощность,
производительность, страна, привод…). Задача — на каждую написать уникальный SEO-текст
2300–5000 знаков с FAQ-аккордеоном, внутренней перелинковкой и блоком авторства, не
попав под фильтры за шаблонность и не наврав в технике.

Схема работы: сырьё краула → **payload** (JSON с фактами страницы) → **LLM-генерация с
самопроверкой по QA внутри цикла** → **пост-фиксы по всему корпусу** → **publish/** (два
варианта HTML: без разметки и с JSON-LD) → **два CSV** для импорта.

Текущее состояние: все 759 страниц сгенерированы, отпостфикшены, собраны в `publish/` и
в оба CSV. Работа считается закрытой, ждёт вычитки владельцем
(`REMAINING-WORK.md:88-91` — по SEO-текстам открытых задач нет, есть только задачи по
schema-разметке шаблонов Битрикса).

## 2. Точки входа и как запустить

### 2.0. Что нужно до запуска

Генерация ходит в провайдерский API (Anthropic-совместимый шлюз). Нужны переменные
окружения `PROVIDER_API_KEY` и `PROVIDER_BASE_URL` (`gen_provider.py:118-133`: сначала
читается опциональный файл `seo-texts/.env`, затем `os.environ` перекрывает его).
В текущей сессии обе переменные заданы в окружении, файла `.env` нет — этого достаточно.

**Питон-зависимости: `anthropic` и `httpx`.** В этой песочнице они НЕ установлены —
`python3 -c "import gen_provider"` падает на `ModuleNotFoundError: No module named 'anthropic'`
(`gen_provider.py:6-7`). Значит, здесь и сейчас генерацию запустить нельзя; локально работают
только модули без внешних зависимостей (`qa_text`, `compare_texts`, `postfix_corpus`,
`patch_ranges`, `build_schema`, `make_csv*`, `build_payloads`, `enrich_payloads`).

### 2.1. Одна страница (отладка)

```
cd /home/user/avto/seo-texts
python3 gen_provider.py <slug>
```

Аргументы (разбор — `gen_provider.py:463-474`, позиционный только первый — slug):

| Аргумент | Смысл | Дефолт |
|---|---|---|
| `<slug>` | берёт `gen/payload-<slug>.json`, пишет `gen/result-<slug>.json` | обязателен |
| `--payload FILE` | путь к payload (относительно каталога скрипта) | `gen/payload-<slug>.json` |
| `--out FILE` | куда писать результат | `gen/result-<slug>.json` |
| `--min-price N` | минимальная цена для проверки цены в title | берётся из `payload.price_min` |
| `--no-price` | у бренда цены «по запросу» | цена считается известной |
| `--guide PATH` | стайлгайд | `payload.guide`, иначе по категории |
| `--etalon PATH` | подмешать эталонный текст в промпт | **выключено** (`gen_provider.py:389-391`) |
| `--model NAME` | модель | `claude-opus-4-8` в CLI (`gen_provider.py:465`) |

Осторожно с дефолтом модели: в функции `run_one` дефолт другой —
`model='claude-fable-5'` (`gen_provider.py:373`), а CLI явно перебивает его на
`claude-opus-4-8`. Плюс работает подмена «мёртвых» моделей (см. §3.2).

Печатает в stdout JSON-сводку: `slug, out, category, rounds (список раундов QA с
претензиями), clean, seconds, input_tokens, output_tokens, cache_*, words`.

## 3. Как устроено внутри

### 3.1. Payload: что кладётся в промпт

Два билдера, оба читают `page-data/*.json` (764 файла — снимок краула категорий: url, slug,
h1, title_current, count, price_min/max, sample_models, brand_facets, page_brand, status).

**`build_compressor_payloads.py`** — страницы раздела `vozdushnye-kompressory` (отбор:
`build_compressor_payloads.py:238-242`). Что делает:
- определяет тип машины по h1+url (`detect_type`, строки 92-127): форма (screw/piston/spiral),
  топливо (diesel/electric), особенности (oilfree/two_stage/booster);
- по типу выбирает стайлгайд: дизельный винтовой → `gen/STYLE-GUIDE.md`, всё остальное →
  `gen/STYLE-GUIDE-ELEKTRO.md` (строки 109-113);
- формирует `typing` — список обязательных слов во вводном H2, который потом проверяет QA
  (строки 115-122);
- отличает брендовую страницу от фасета по последнему сегменту URL, сверяясь с реестром
  `KNOWN` — он собирается из `kb/brand-facts-clean.json`, брендов из `projects-index.json`,
  ручного списка и **авто-реестра** «слаг встречается в ≥2 секциях каталога → это бренд»
  (`_auto_brands`, строки 45-63);
- для фасета извлекает измерение и значение (`detect_facet`, строки 130-153): pressure/power/
  perf/receiver/voltage по регуляркам URL и h1, затем drive/country/vsd/application/booster/2stage.
  Важный порядок: `perf` проверяется ДО `receiver`, иначе «1000-l-min» уезжало бы в «ресивер
  на 1000 л» (комментарий строки 84-87);
- скелет текста сводится к тем, что знает стайлгайд:
  `{F-POWER, F-PRESSURE, F-PERF, F-DRIVE, F-COUNTRY, F-EQUIP}`, всё прочее → `F-EQUIP`
  (строки 215-216);
- брендовой странице подкладывает до 3 проектов из `projects-index.json` и фото из
  `projects-photos.json` (`pick_projects`, строки 172-184);
- мост на Enger — по типу топлива (`ENGER_BRIDGE`, строки 74-78), кроме страниц самого Enger.

**`build_payloads.py`** — все остальные разделы. Категоризация — «секция важнее подстроки»
(`categorize`, строки 55-82; комментарий прямо говорит, что иначе `kompressory-s-resiverom`
ошибочно ловится как ресивер). Подкладывает:
- досье категории из `kb/category-ref/index.json` (10 ключей: ref_dryer, ads_dryer, receiver,
  filter, n2_gen, o2_gen, separator, air_prep, spare_parts, flowmeter);
- `related_urls` — соседи по цепочке подготовки воздуха (`NEIGHBORS`, строки 31-38);
- `enger_category_url` только там, где у Enger реально есть товар (`BRIDGE_CATS`, строка 48).

**Гейт достоверности брендовых фактов** — `brand_facts_lib.py`. В payload попадает только
подтверждённое: positioning/country, серии с confidence high/medium/medium-low
(`brand_facts_lib.py:27`), safe_facts, confirmed_dependencies, и отдельным блоком
«НЕ УТВЕРЖДАТЬ» — caveats (строки 83-115). Тир тональности — `TONE` (строки 21-26):
`enger` = rodnoy; berg/atom/cross_air/dali/hansmann = druzhestvennyy; остальные = neytralnyy.

**`enrich_payloads.py`** дописывает в готовые payload поля против шаблонности:
`variant` (0..5 по md5 слага), `facet_application` (отраслевой акцент по измерению и значению
фасета, строки 19-53), `byline` + `byline_url` + `review_date`. Запускать ПОСЛЕ билдеров.
Проверено: все 759 payload сейчас имеют `variant`, `byline`, `byline_url`, `review_date`.

Покрытие полей по 759 payload (посчитано): `skeleton` 759, `count` 759, `price_min` 717,
`enger_category_url` 645, `guide`/`typing` 567 (только компрессорные), `facet_dimension` 369,
`facet_application` 359, `category_reference` 191, `brand_facts` 189, `power_range_catalog` 182,
`related_urls` 149, `projects` 108.

### 3.2. Вызов модели: `gen_provider.py`

Промпт собирается в `build_prompt` (`gen_provider.py:164-189`) из:
1. первая строка с темой раздела (`TOPIC`, строки 149-161, либо `payload.topic`);
2. **целиком стайлгайд** (`gen/STYLE-GUIDE.md` — дизельные винтовые, `-ELEKTRO.md` —
   электрические и прочие компрессоры, `-PODGOTOVKA.md` — осушители/ресиверы/фильтры/
   генераторы/сепараторы);
3. эталонный текст — по умолчанию ВЫКЛЮЧЕН (строки 389-391: «эталон раздувал промпт и
   замедлял»);
4. **весь payload как JSON** с указанием «факты бери ТОЛЬКО отсюда»;
5. четыре блока правил, зашитых в код: `SELF_CHECK` (строки 13-35 — запрет длинного тире,
   витринных конструкций, хеджей, канцелярита, требование рваного ритма), `DE_TEMPLATE`
   (38-53 — против шаблонности, ротация по `variant`), `REFINEMENT` (69-104 — инженерные
   каноны: обратная зависимость давление/производительность, порядок цепочки подготовки
   воздуха, адсорбция как физический процесс, правило объёма ресивера 10-20 % минутной
   производительности, точки росы, анти-Баден-Баден);
6. `extra` — куда `regen_driver` вставляет конкретный дефект прошлой версии.

Модель просят вернуть один JSON:
`{"slug","url","title","description","h1","text_html"}`, причём **title и description
намеренно оставляются пустыми** — их не генерируют, на сайте остаются текущие
(`gen_provider.py:189`).

**Транспорт.** Стриминг обязателен (Cloudflare шлюза рвёт молчащие соединения на 120 с).
Используется не SDK-аккумулятор, а свой SSE-парсер на httpx — `_raw_stream`
(строки 253-313), потому что шлюз иногда шлёт кадр-словарь, на котором `.model_dump()` SDK
падает. `anthropic.Anthropic` создаётся в `make_client` (136-145), но по факту raw-путь
берёт креды из env сам; клиент передаётся ради совместимости сигнатур.

Заголовки маскируются под curl (`User-Agent: curl/8.5.0` + пустые `X-Stainless-*`,
строки 138-143 и 211-215) — комментарий в коде и `CLAUDE.md` объясняют это тем, что WAF
самого шлюза отклоняет дефолтные заголовки SDK.

**Часы против зависшего стрима** (строки 243-250):
`PROVIDER_STREAM_DEADLINE_SEC` (по умолчанию 420 с на весь стрим) и
`PROVIDER_FIRST_TOKEN_SEC` (90 с на первый текстовый кадр). Без них шлюз, шлющий одни
ping-кадры, вешает вызов навсегда.

**Подмена «мёртвых» моделей** — `resolve_model` (строки 218-240). Комментарий в коде
(проверка от 27.07.2026): `claude-fable-5` и `claude-opus-5` шлюз принимает, но текста не
отдаёт; работают `claude-opus-4-8`, `haiku-4-5`, `sonnet-4-6`, `sonnet-5`. Поэтому
`_DEAD_DEFAULT = 'claude-fable-5,claude-opus-5'`, `_ALIVE_DEFAULT = 'claude-opus-4-8'`.
Управление: `PROVIDER_DEAD_MODELS` (список), `PROVIDER_MODEL` (на что менять).
**Практический вывод: код в `regen_driver.py:21` просит `claude-fable-5`, но реально
уходит `claude-opus-4-8`**, пока переменные не переопределены.

**Ретраи** — `call` (строки 316-355): до 8 попыток, пауза `min(150, 15*2^(n-1))` секунд,
`max_tokens=16000` захардкожен (строка 331). При HTTP 400 с `thinking` — повтор без
thinking (334-336). Короткий, но валидный JSON не считается обрывом (347-353). Частичный
текст при обрыве стрима не выбрасывается (307-313).

**Парсинг** — `parse_json` (358-370): срезает markdown-ограждения, при неудаче ищет
`\{.*\}` регуляркой, и в конце **страховочно заменяет все длинные тире на дефисы** в
title/description/text_html.

**Цикл авто-доводки** — `run_one` (373-460): до `max_rounds` (по умолчанию 3) итераций
«сгенерировал → `qa_text.check` → если есть претензии, отправил их модели репликой
"Исправь ТОЛЬКО перечисленное"». Перед проверкой в текст дописывается блок авторства,
если модель его не вставила (432-433). Результат пишется в `out_path` **в любом случае**,
даже если претензии остались после последнего раунда.

### 3.3. Механический QA: `qa_text.py`

Единственный QA-модуль, который реально работает в цикле генерации (импортируется
`gen_provider.py:9`, `qa_el.py:9`, `guest-posts/gp_gen.py:10`). Функция
`check(...)` (`qa_text.py:150-267`) возвращает список претензий; пустой список = чисто.

Что проверяет:

| Проверка | Где | Порог/деталь |
|---|---|---|
| Объём текста без тегов | 162 | 2300–5000 знаков |
| Стоп-слова (хеджи, штампы, AI-маркеры, канцелярит) | 6-18, 165 | 40+ фраз |
| Ритм абзацев (анти-AI) | 98-105 | CV длин абзацев ≥ 0.30 при ≥4 абзацах |
| Перебор связок «при этом/кроме того» | 106-109 | >3 на 500 слов |
| «данный/данная» вместо «этот» | 110-113 | ≥2 вхождений |
| Инженерные ошибки | 26-72 | пассив, «пневмоаудит» >1×, адсорбция как химия, инверсия давление/производительность, порядок цепочки подготовки воздуха |
| Кучность ключа H1 в первых 500 знаках | 75-89 | ≥3 повторов ядра ключа |
| Витринные конструкции «в разделе представлены» | 175-177 | regex |
| SEO-жаргон (тег/фасет/листинг/выдача) | 180-182 | regex по границам слова |
| Длинное тире | 188-190 | запрещено полностью |
| Полная типизация вводного H2 | 192-197 | `payload.typing` или `H2_TYPING[category]` (131-147) |
| Категорийные ловушки | 119-127, 200-202 | напр. «удаляет масло» для осушителей |
| `<ul>`/`<li>` | 204-206 | запрещены (CSS сайта рисует маркеры длинным тире) |

### 3.4. Регенерация: `regen_driver.py`

Запускается по очереди `regen-queue*.json` — список `{slug, phase, flagged}`. На каждой
странице (`process`, строки 111-137):
1. берёт «старую» версию из `gen-orig/result-<slug>.json` (если есть), считает её
   механическую «плохость» — `mech_badness` (63-70: число претензий refinement + naturalness
   + стоп-слова + кучность ключа + выход за 2300–5200);
2. если страница `flagged` — вставляет в промпт конкретный дефект из
   `defect-map-resolved.json` как «ОБЯЗАТЕЛЬНО ИСПРАВИТЬ» (`defect_directive`, 102-108);
3. вызывает `gp.run_one(...)`;
4. считает «плохость» новой версии; **если новая строго хуже старой — откатывает файл к
   старой** (keep-best, строки 129-134);
5. каждая 6-я готовая страница уходит на инженер-верификацию `eng_verify` (84-99) —
   отдельный вызов модели с ролью «главный инженер», который возвращает одну строку
   `critical|important|minor|clean | пояснение`. Вердикты копятся в
   `regen-state.json['eng_verdicts']`, «важные» на нефлагнутой странице пишутся в
   `regressions`.
6. бюджет: токены тарифицируются по консервативному прайсу Fable
   ($10/$1/$50 за млн in/cache/out, строки 24-26); при достижении `REGEN_BUDGET` заправка
   новых задач останавливается.

Устойчивость к обрыву — `regen-state.json`: слаги в `done` при рестарте пропускаются.

Фактическое состояние `regen-state.json`: `done` 284 слага, потрачено $282.52,
keep-old 8, регрессий 1, инженерных вердиктов 50. Хвост `regen-monitor.log` показывает
последний прогон по очереди `regen-queue-last4.json` (4 страницы) и один

`catalog__resivery__enger` — это падение `parse_json` (`gen_provider.py:364-365`), когда в
ответе нет ни одной фигурной скобки.

### 3.5. Пост-фиксы: `postfix_corpus.py`

1. `ГК «Руспром»` → `ООО «Руспром»` (17-21);
2. `<div style="clear:both">` перед первым H2/байлайном после картинки, чтобы флоат-фото

### 3.6. Микроразметка и CSV

## 5. Ограничения и грабли

1. **Билдеры payload затирают обогащение.** `build_compressor_payloads.py:249` и
   `build_payloads.py:190-191` пишут payload целиком, из нуля. Всё, что дописал
   `enrich_payloads.py` (`variant`, `facet_application`, `byline*`, `review_date`), пропадёт.
   После любого перезапуска билдеров **обязательно** гнать `enrich_payloads.py`.
2. **Поле `power_range_catalog` восстановить будет нечем.** Оно есть в 182 payload и его
   читает `patch_ranges.py:39`, но **ни один скрипт в репозитории его не пишет** — я
   искал по всему `/home/user/avto` (`grep power_range_catalog` по .py/.sh/.md находит
   только `patch_ranges.py`). Значит, поле проставил разовый скрипт вне репозитория.
   Перезапуск билдеров уничтожит его без возможности пересобрать имеющимся кодом.
3. **Модель в коде ≠ модель в запросе.** Из-за `resolve_model` (`gen_provider.py:228-240`)
   `claude-fable-5` и `claude-opus-5` молча подменяются на `claude-opus-4-8`. В stderr
   печатается предупреждение один раз на модель. Не пугаться расхождения кода и биллинга.
4. **`gen_batch.py` без флагов отбора не делает ничего** и завершается без ошибки
   (`gen_batch.py:32-57`).
5. **`gen_batch.py` не перегенерирует готовые страницы.** Чтобы перегенерировать —
   удалять `gen/result-*.json` или пользоваться `regen_driver.py`.
6. **`regen-state.json` общий для всех очередей.** Слаг, сделанный по одной очереди,
   пропускается при запуске по другой; счётчик «готово N/M» в итоговой строке сравнивает
   накопленное `done` с длиной ТЕКУЩЕЙ очереди — отсюда в логе строка «готово 284/4»
   (`regen_driver.py:206`, `regen-monitor.log`). Чтобы прогнать заново — чистить/подменять
   файл состояния.
7. **`run_one` пишет результат, даже если QA не сошёлся** (`gen_provider.py:451`). Поле
   `clean` в сводке — единственный признак; в батче такие страницы помечаются `~`/`issues`.
8. **Цена в title фактически не проверяется**: `title` намеренно генерируется пустым
   (`gen_provider.py:189`), а проверки цены и длины description срабатывают только на
   непустых полях (`qa_text.py:255-265`). Все 759 результатов имеют пустые `title` и
   `description`.
9. **Два разных текста байлайна в коде.** `gen_provider.byline_block` (107-115) жёстко
   пишет «технический директор ООО «Руспром»», а `enrich_payloads.byline_variants` (56-65)
   кладёт в payload шесть вариантов со словом «сооснователь». Поле `payload['byline']`
   генератором **не используется** — берётся только `byline_url`. В корпусе при этом
   лежат 6 разных формулировок (278 «Материал подготовил … технический директор», 83
   «Эксперт материала», 81 «Над материалом работал», 76 «Технический консультант», 66
   «Материал подготовил … сооснователь», далее мелочь). Ни один .py в репозитории не пишет
   варианты «Материал проверил»/«Технический консультант» — их проставил внешний скрипт.
   **Практический риск: регенерация любой такой страницы вернёт ей единственный вариант
   «технический директор», ротация сломается.**
10. **Дата «Обновлено» детерминирована по слагу** (`gen_provider.updated_date`, 60-66):
    равномерно разбросана по 122 дням до 15.07.2026 (проверил распределение: март 113,
    апрель 196, май 184, июнь 187, июль 79). Дата **зашита в код** — при генерации после
    июля 2026 все страницы получат прошлогодние даты, пока константу не поменяют.
11. **Порядок пост-обработки нарушать нельзя**: `postfix_corpus` → `build_schema` →
    `make_csv*`. `build_schema` копирует текст из `gen/result-*`, а CSV читают
    `publish/*`, а не результаты напрямую. Прогон CSV без пересборки `publish/` даст
    старый текст.
12. **`patch_ranges.py --dry` печатает ненулевое число замен даже когда менять нечего** —
    `re.subn` считает совпадения, а не изменения. Проверил напрямую: сейчас для всех 12
    страниц очереди результат патча побайтно равен текущему тексту, то есть правка уже
    применена.
13. Запуск диагностических скриптов меняет файлы репозитория (`similarity-report.md`,
    `patch-ranges-report.md`). Учитывать при работе в чистом дереве.
14. **`max_tokens=16000` захардкожен** в `call` (`gen_provider.py:331`) — это отмечено как
    ограничение и в `sender/SENDER-STATE.md:516`.
15. Генерация ходит во внешний платный шлюз router.cheap. Правило владельца
    (`CLAUDE.md`): тяжёлая работа — через него, квоту беречь; каждая сессия сама решает,
    выполнять ли вызовы к этому эндпоинту.
