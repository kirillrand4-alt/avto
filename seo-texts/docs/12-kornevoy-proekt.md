## 1. Что это и зачем

Задача: жать кнопку **«Запросить индексирование»** в Google Search Console
(инструмент проверки URL) сразу по многим Google-аккаунтам, чтобы протолкнуть
страницы своего сайта в индекс быстрее.

Ключевая идея — **без Google Indexing API**. API отдаёт индексацию только для
`JobPosting`/`BroadcastEvent`, поэтому здесь эмулируется ровно ручное действие
человека: залогиненный браузер (Playwright) открывает страницу инспекции URL,
кликает кнопку, читает результат. Один аккаунт даёт ~10 URL/сутки (квота
Google), поэтому проект и рассчитан на «много аккаунтов × 10 URL».

Целевой сайт по `RUNBOOK.md:14` — `dizel-compressor.ru` (это НЕ prokompressor.ru,
которым занят проект `seo-texts`). Аккаунты добавляются в GSC этого ресурса как
пользователи с полным доступом (`RUNBOOK.md:65-66`).

Раз аккаунтов много и действие формально против правил Google (об этом честно
написано в `README.md:120-121`), половина кода — это защита аккаунтов от бана:
прокси на каждый заход, проверка живости прокси перед стартом, свой отпечаток
браузера на аккаунт, антидетект-движки, человекоподобная мышь, лог-нормальные
паузы, дневные лимиты и идемпотентность («не переотправлять URL, по которому
клик уже был»).

Развёрнуто (по `RUNBOOK.md:9-13`) на Windows-сервере `parsercompressor.online`,
папка `C:\seostat\avto`, панель за Caddy на `https://parsercompressor.online/avto/`,
служба NSSM `avto-panel`. **НЕ ПРОВЕРЕНО:** работает ли это сейчас — доступа к
серверу у меня нет и по правилам сессии его трогать нельзя.

## 2. Точки входа и как запустить

### 2.1. Установка (с нуля)

```bash
cd /путь/к/репозиторию          # корень, не seo-texts/
npm install                     # ставит express + playwright
                                # postinstall сам делает: playwright install chromium
cp config.example.json config.json
cp .env.example .env             # только если нужна веб-панель
```

`package.json:13-16` — зависимости ровно две: `express ^4.22.2`,
`playwright ^1.49.0`. `package.json:11` — `"postinstall": "playwright install
chromium"`, то есть `npm install` тянет ещё и сборку Chromium (сотни мегабайт).
Файла `package-lock.json` в репозитории **нет** (проверено `ls`) — версии
зависимостей при установке не зафиксированы.

В песочнице, где я это документирую, `node_modules/` отсутствует, поэтому ничего
из этого кода запустить нельзя без `npm install`. Node в среде есть: v22.22.2,
npm 10.9.7. Синтаксис всех десяти `.mjs` файлов валиден — прогнал
`node --check` по каждому, все OK.

### 2.2. Четыре команды (npm-скрипты, `package.json:6-12`)

| Команда | Что делает | Файл |
|---|---|---|
| `npm run login` | первичный вход в Google руками (открывает видимое окно) | `src/login.mjs` |
| `npm run run` | боевой прогон отправки URL на индексацию | `src/run.mjs` |
| `npm run web` | веб-панель управления | `web/server.mjs` |
| `npm run bridge` | локальный прокси-мост | `src/proxybridge.mjs` |

Точные вызовы с аргументами:

```bash
# логин: все аккаунты по очереди или один по id
node src/login.mjs
node src/login.mjs acc1

# прогон: все аккаунты или один по id
node src/run.mjs
node src/run.mjs acc1

# мост: аргумент 1 — апстрим-прокси с кредами, аргумент 2 — локальный порт (по умолч. 11561)
node src/proxybridge.mjs "http://user:pass@host:port" 11561
#   те же значения можно задать env-переменными UPSTREAM_PROXY и BRIDGE_PORT

# панель: настройки только через .env (аргументов нет)
node web/server.mjs
```

Позиционный аргумент `acc1` — это `process.argv[2]`, фильтр по `accounts[].id`
(`src/run.mjs:35,40` и `src/login.mjs:18,22`). Никаких флагов вроде `--dry-run`,
`--limit` у скриптов нет — всё поведение задаётся `config.json`.

### 2.3. Порядок операций на боевом сервере (по `RUNBOOK.md:48-74`)

1. **Мост** — отдельное окно PowerShell, держать открытым всё время работы:
   ```powershell
   cd C:\seostat\avto
   node src/proxybridge.mjs "http://ЛОГИН:ПАРОЛЬ@89.39.105.78:11560" 11561
   ```
2. **Панель** — уже служба; перезапуск `nssm restart avto-panel`, лог
   `C:\seostat\avto\panel.log` (`RUNBOOK.md:55`). После каждого `git pull` на
   сервере службу надо перезапускать, иначе крутится старый код (`RUNBOOK.md:85-86`).
3. **Логин нового аккаунта** — `node src/login.mjs acc4` (мост должен быть
   поднят, иначе предохранитель откажет).
4. **Прогон** — кнопка в панели или `node src/run.mjs`.

Важное ограничение операторки: `login.mjs` открывает **видимое окно браузера на
самом сервере**, поэтому первичный вход делается сидя за сервером или по RDP
(`README.md:65-66`, `web/server.mjs:294`).

### 2.4. Переменные окружения панели (`.env`, читается `web/server.mjs:23-30`)

Свой мини-парсер `.env` без зависимостей; уже заданные в окружении переменные не
перетираются (`web/server.mjs:27`).

| Переменная | Дефолт в коде | Смысл |
|---|---|---|
| `PORT` | `8090` (`web/server.mjs:32`) | порт панели |
| `HOST` | `127.0.0.1` (`web/server.mjs:33`) | интерфейс; `0.0.0.0` — если без прокси |
| `BASE_PATH` | `/avto` (`web/server.mjs:34`) | подпуть монтирования; хвостовой слэш срезается |
| `ADMIN_USER` | `admin` (`web/server.mjs:35`) | HTTP Basic логин |
| `ADMIN_PASS` | `changeme` (`web/server.mjs:36`) | HTTP Basic пароль |

Дефолты `admin`/`changeme` работают **молча** — если `.env` нет, панель
поднимется с этой парой и никакого предупреждения не напечатает.

### 2.5. Публикация за обратным прокси

`deploy/Caddyfile.example` — блок `handle /avto/* { reverse_proxy 127.0.0.1:8090 }`
внутрь существующего site-блока. Именно `handle`, а не `handle_path`: приложение
само смонтировано на `/avto` (`web/server.mjs:441`), префикс нужно **сохранять**.

`deploy/nginx.example.conf` — то же на nginx: `location /avto/ { proxy_pass
http://127.0.0.1:8090; }` **без** завершающего слэша в `proxy_pass` (иначе nginx
срежет префикс), плюс `location = /avto { return 301 /avto/; }`.

`BASE_PATH` в `.env` обязан совпадать с подпутём в прокси (`README.md:86-87`).

## 3. Как устроено внутри

### 3.1. Карта модулей и кто кого вызывает

```
web/server.mjs ──spawn──> src/run.mjs      (кнопки «Прогнать»/«Прогнать все», планировщик)
      │        ──spawn──> src/login.mjs    (кнопка «Залогиниться»)
      └──import──> src/lib.mjs             (ROOT, SCREENSHOTS_DIR, loadConfig, saveConfig,
                                            loadState, todayKey)

src/run.mjs ──> src/session.mjs ──> src/lib.mjs        (builtin: свой Chromium)
            │                   ├─> src/dolphin.mjs    (движок dolphin)
            │                   └─> src/adspower.mjs   (движок adspower)
            └─> src/gsc.mjs ──> src/humanize.mjs

src/login.mjs ──> src/lib.mjs, src/dolphin.mjs, src/adspower.mjs,
                  src/session.mjs (только antidetectId)

src/proxybridge.mjs — самостоятельный процесс, НИЧЕГО не импортирует из проекта
                      и никем не запускается автоматически (только руками/из RUNBOOK)
```

Проверено: `web/server.mjs:46` — `spawn(process.execPath, [path.join(ROOT,
'src', script), ...args], { cwd: ROOT })`, где `script` — строковый литерал
`'run.mjs'` или `'login.mjs'` (`web/server.mjs:72,401,407,413`). Произвольные
скрипты запустить нельзя.

### 3.2. `src/lib.mjs` — конфиг, прокси, отпечаток, стелс

Пути (`src/lib.mjs:10-14`) все считаются от корня репозитория:
`ROOT`, `PROFILES_DIR = ROOT/profiles`, `SCREENSHOTS_DIR = ROOT/screenshots`,
`CONFIG_PATH = ROOT/config.json`, `STATE_PATH = ROOT/state.json`.

`DEFAULT_CONFIG` (`src/lib.mjs:16-38`) — единственное место, где описан полный
набор полей конфига:

| Поле | Дефолт | Смысл |
|---|---|---|
| `dailyLimitPerAccount` | `10` | сколько URL/сутки на аккаунт |
| `minDelayMs` / `maxDelayMs` | `8000` / `20000` | случайная пауза между действиями |
| `headless` | `false` | видимое окно (нужно для логина) |
| `schedule` | `{enabled:false, time:'10:00'}` | встроенный планировщик панели |
| `engine` | `'builtin'` | `builtin` / `dolphin` / `adspower` |
| `dolphin` | `{apiBase:'http://localhost:3001/v1.0', token:''}` | Local API Dolphin |
| `adspower` | `{apiBase:'http://local.adspower.net:50325'}` | Local API AdsPower |
| `allowNoProxy` | `false` | **предохранитель**: `true` разрешает запуск без прокси |
| `proxy` | `{server,username,password,rotateUrl,locale:'ru-RU',timezone:'Europe/Moscow'}` | общий прокси |
| `accounts` | `[]` | массив аккаунтов |

Аккаунт (по `config.example.json` и по коду панели `web/server.mjs:331-337`):
`{ id, label, property, profileId, urls[] }`. Плюс необязательный
`acc.proxy` (переопределение общего прокси, читается в `resolveProxy`,
`src/lib.mjs:69`) — в UI панели такого поля **нет**, только правкой файла.
Плюс исторический `dolphinProfileId` — читается как фолбэк
(`src/session.mjs:13`), а панель при сохранении ID его удаляет
(`web/server.mjs:364`).

`fingerprintFor(accountId, cfg)` (`src/lib.mjs:53-62`) — **детерминированный**
отпечаток: sha256 от `accountId`, из него индекс в пуле из 4 User-Agent
(`src/lib.mjs:41-46`, Chrome 129-131 на Win/Mac) и в пуле из 5 разрешений
(`src/lib.mjs:47-50`). Один и тот же аккаунт всегда получает один и тот же
отпечаток — это правильно (отпечаток не должен «плавать» между запусками).

`resolveProxy(cfg, acc)` (`src/lib.mjs:67-86`) — собирает опцию Playwright.
Отдельно вытаскивает логин/пароль из URL (`http://user:pass@host:port`), потому
что Chromium **не принимает** креды внутри URL прокси — их надо передавать
полями. Приоритет: `acc.proxy` → `cfg.proxy` → креды из самого URL.

`checkProxy(proxyOpt, timeout=15000)` (`src/lib.mjs:91-126`) — предохранитель.
Для HTTP-прокси делает запрос `GET http://api.ipify.org/` **через прокси** и
считает его живым **только** при 2xx и теле, похожем на IP (`src/lib.mjs:118`).
407/5xx/HTML-заглушка провайдера живым не считаются. Для SOCKS —
только TCP-connect (`src/lib.mjs:98-104`), то есть проверка слабее: отвечающий
порт ещё не значит, что трафик пойдёт.

`rotateProxyIp(cfg, log)` (`src/lib.mjs:129-140`) — дёргает `proxy.rotateUrl`
(GET, таймаут 15с), потом спит 5с. Ошибки глушатся в лог.

`loadConfig` (`src/lib.mjs:142-151`) — **бросает исключение** на битом JSON и
никогда не откатывается молча на дефолт: иначе пустой `accounts: []` мог бы
затем перезаписать реальный конфиг. `saveConfig` (`:154-159`) — атомарная запись
через `.tmp` + `rename`. `loadState` (`:162-168`) — наоборот, битый `state.json`
читает как `{}` с предупреждением, чтобы не ронять процесс.

`openAccountBrowser` (`src/lib.mjs:182-216`) — `chromium.launchPersistentContext`
на папку `profiles/<accountId>`, с флагами `--disable-blink-features=
AutomationControlled` и `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`
(анти-WebRTC-утечка, `src/lib.mjs:191-194`). Плюс `addInitScript`
(`src/lib.mjs:200-214`): прячет `navigator.webdriver`, подставляет
`navigator.languages = ['ru-RU','ru']`, фейковый `navigator.plugins` длиной 5,
`window.chrome`, патч `permissions.query` для нотификаций. Это базовый
стелс-набор образца ~2020 года; современные детекторы ловят и не такое.

### 3.3. `src/session.mjs` — абстракция «сессия браузера»

37 строк кода, единственная задача — спрятать различие трёх движков и вернуть
одинаковый объект `{ page, engine, proxy?, close() }` (`src/session.mjs:16-56`).

- `engine === 'dolphin' | 'adspower'` — берёт `antidetectId(acc)`
  (`profileId`, фолбэк `dolphinProfileId`), стартует профиль через Local API,
  подключается к его Chromium по CDP. Если получить страницу не удалось —
  закрывает браузер И останавливает профиль (`src/session.mjs:31-36`), иначе
  профиль антидетекта остался бы висеть.
- иначе — builtin: `resolveProxy` + `fingerprintFor` + `openAccountBrowser`.

### 3.4. `src/dolphin.mjs` и `src/adspower.mjs` — коннекторы к антидетектам

Оба ~40 строк, оба работают только пока на машине запущено десктоп-приложение
антидетекта в **интерактивной** сессии (не под службой) — об этом честно
написано в UI панели (`web/server.mjs:178`).

Dolphin (`src/dolphin.mjs:20-37`): `GET {apiBase}/browser_profiles/{id}/start?
automation=1[&headless=1]`, ожидает `data.automation.port`, собирает эндпоинт
`ws://127.0.0.1:{port}{wsEndpoint}` (или `http://127.0.0.1:{port}`), затем
`chromium.connectOverCDP`. Токен, если задан, уходит заголовком
`Authorization: Bearer` (`src/dolphin.mjs:15`). Стоп — `/stop` (`:40-43`).

AdsPower (`src/adspower.mjs:18-33`): `GET {apiBase}/api/v1/browser/start?
user_id=...&headless=0|1`, ждёт `code === 0` и `data.ws.puppeteer`, коннект по
CDP. Перед каждым вызовом пауза 1200 мс (`src/adspower.mjs:15`) — AdsPower
просит не чаще ~1 запроса в секунду.

Оба при падении CDP-коннекта останавливают уже запущенный профиль.

### 3.5. `src/gsc.mjs` — собственно клик по кнопке

`inspectUrl(property, url)` (`src/gsc.mjs:8-11`) строит
`https://search.google.com/search-console/inspect?resource_id=<property>&id=<url>`.
`property` — либо `sc-domain:example.com`, либо `https://www.example.com/`.

`requestIndexing(page, property, url, {min,max})` (`src/gsc.mjs:36-100`)
возвращает ровно один из пяти статусов — это главный контракт модуля:

| Статус | Когда | Что делает вызывающий (`run.mjs`) |
|---|---|---|
| `'ok'` | в тексте страницы нашлось подтверждение | помечает URL сделанным, +1 к счётчику |
| `'quota'` | нашлось «квота исчерпана» | прекращает работу по аккаунту (`src/run.mjs:130-132`) |
| `'not_logged'` | редирект на `accounts.google.com` (`src/gsc.mjs:41-43`) | стоп по аккаунту, просит перелогиниться |
| `'unknown'` | клик БЫЛ, но за 90с результат не распознан | паркует URL в «неоднозначные», +1 к счётчику, **не повторяет** |
| `'error'` | достоверный сбой ДО отправки (кнопки нет / клик не прошёл) | пропускает URL, повтор безопасен |

Локатор кнопки (`src/gsc.mjs:52-54`): основной — по стабильному
`[data-event-action="request-indexing"]` + `getByRole('button')`, он не зависит
от языка интерфейса; фолбэк — по тексту `RE_REQUEST`. Языки в регэкспах:
русский, английский **и индонезийский** (`src/gsc.mjs:18-20`) — интерфейс GSC
рендерится на языке самого Google-аккаунта, а часть купленных аккаунтов
оказалась индонезийскими.

Разбор результата (`src/gsc.mjs:77-92`): цикл до 90 секунд, каждые 2 секунды
берётся `page.textContent('body')` и проверяется на `RE_QUOTA`/`RE_SUCCESS`.
С вероятностью 0.3 за итерацию курсор лениво елозит по экрану, чтобы не
замирать неподвижно (`src/gsc.mjs:88-90`). При успехе закрывается диалог по
кнопке «Готово/OK/Close/Selesai…» (`src/gsc.mjs:83-84`).

Скриншоты на всех неудачных ветках (`src/gsc.mjs:22-27`): файл
`screenshots/<имя>-<timestamp>.png`, имена `no-request-button`, `click-failed`,
`unknown-result`.

### 3.6. `src/humanize.mjs` — человекоподобность

Самый «инженерный» файл проекта, 166 строк без единой зависимости.

- `gauss()` (Box–Muller) и `lognormal(median, sigma, softMax)`
  (`src/humanize.mjs:12-22`) — все паузы лог-нормальные: длинный правый хвост,
  без жёсткого обреза, как у реального человека.
- `buildEase(steps)` (`:26-32`) — неравномерное расписание времени по интегралу
  скорости `v(u)=u·(1-u)^1.5` с пиком около u=0.4: быстрый разгон, долгое
  торможение (закон Фиттса).
- `moveMouse(page, tx, ty)` (`:55-98`) — кубическая Безье с двумя случайными
  контрольными точками, «промах» за цель с вероятностью 0.6 при дистанции >40px
  (`:60`), 1-2 корректирующих микродвижения, посадка с остаточной ошибкой ±1-3px,
  тремор как коррелированный AR(1)-процесс (`:74-81`), координаты округляются до
  целых, потому что настоящее железо при DPR=1 отдаёт целые `clientX/clientY`
  (`:83`). Текущая позиция курсора хранится на самом объекте page в поле
  `page.__mousePos` (`:36-42`), потому что Playwright её не отдаёт; стартовая
  точка — снизу экрана, будто курсор «вошёл» снизу.
- `humanClick(page, locator)` (`:106-135`) — возвращает `true/false`. Порядок:
  `scrollIntoViewIfNeeded` → `boundingBox` → движение в случайную точку внутри
  (30-70% от габарита) → пауза → **перепроверка** `boundingBox`+`isEnabled`
  (раскладка GSC могла асинхронно поехать за секунду движения) → сырые
  `mouse.down`/`mouse.up`. Если геометрии нет или точка ушла с цели — обычный
  `locator.click()` с actionability-проверками Playwright и таймаутом 5с.
- `idleBrowse(page)` (`:138-153`) — «чтение» страницы: 1-3 раунда движений мыши,
  скролл дискретными тиками колеса (`wheelTicks`, `:45-52`), иногда откат назад.
- `humanType(page, locator, text)` (`:156-162`) — **вызывающих нет** (см. §6).

### 3.7. `src/run.mjs` — прогон

Скрипт исполняется сверху вниз, без функции `main`, top-level await
(`src/run.mjs:36,42`).

Для каждого аккаунта:
1. Ключ дня `${acc.id}:${today}` (`:46`), `done` — множество сделанных URL,
   `sentToday` — счётчик реальных обращений к Google (`:51`).
2. Ключ `${acc.id}:ambiguous` (`:55`) — **не датовый**: неоднозначные URL
   исключаются навсегда, а не до конца суток, чтобы не жечь квоту повторами.
3. `pending` = URL аккаунта минус `done` минус `ambiguous`; `budget = limit − sentToday`.
4. **Предохранитель от голого IP** (`:72-89`): для любого движка, кроме
   `dolphin`/`adspower` (условие специально написано как «не dolphin и не
   adspower», чтобы опечатка в `engine` не открыла реальный IP — `:70-73`):
   нет прокси и `allowNoProxy:false` → аккаунт пропускается; прокси не отвечает
   по `checkProxy` → аккаунт пропускается.
5. Между аккаунтами (но не перед первым) — ротация мобильного IP (`:93`),
   потом случайный сдвиг старта до 4 секунд (`:96`).
6. По каждому URL — `requestIndexing`, разбор статуса (`:124-147`), запись
   `state.json` **после каждого URL**, затем `randomDelay(min,max)`.
7. `finally { await session.close() }` (`:151-153`), в конце `process.exit(0)`.

Исключение внутри одного URL ловится и не роняет прогон (`:118-122`).

### 3.8. `src/login.mjs` — первичный вход

Открывает браузер, ведёт человека по шагам, ждёт. Для builtin (`:70-104`) —
тот же предохранитель по прокси, ротация IP перед входом (чтобы разные
аккаунты не логинились с одного IP, `:89`), затем открывает
`https://search.google.com/search-console` с `waitUntil: 'commit'` и таймаутом
90с и **ждёт закрытия окна** (`:103`, `context.on('close')`). Для
dolphin/adspower (`:39-68`) — ждёт нажатия **Enter в консоли**
(`waitEnter`, `:29-32`). Это различие критично, см. §5.

### 3.9. `src/proxybridge.mjs` — прокси-мост

Зачем: Chromium не умеет SOCKS5 с логином/паролем и плохо авторизуется на
HTTPS-прокси (`ERR_TUNNEL_CONNECTION_FAILED`, `ERR_INVALID_AUTH_CREDENTIALS`).
Мост слушает `127.0.0.1:11561` **без авторизации** и форвардит всё в апстрим,
подставляя `Proxy-Authorization` (`src/proxybridge.mjs:25-27`). Написан на голом
Node специально вместо `gost`, потому что бинарник `gost` блокировал Windows
Defender (`RUNBOOK.md:96`).

Две ветки: обычный HTTP-запрос (`:32-60`, с корректным пере-чанкованием тела,
потому что Node уже де-чанкует `req`) и `CONNECT`-туннель (`:63-97`) — основной
путь для Google. Оба закрывают апстрим-сокет при отвале клиента.

Важно про настройку панели: в поле «Прокси → Сервер» указывается
`http://127.0.0.1:11561`, а логин и пароль остаются **пустыми**
(`RUNBOOK.md:46`) — авторизацию делает мост.

### 3.10. `web/server.mjs` — веб-панель (Express)

Одна страница, серверный HTML-рендер, никакого JS на клиенте кроме
`confirm()` в форме удаления. Всё смонтировано в роутер на `BASE`
(`web/server.mjs:441`), плюс редирект `/` → `BASE/` (`:442`).

Авторизация — HTTP Basic (`:85-99`), сравнение через `timingSafeEqual`
(`:81-84`), деление строки по **первому** двоеточию, чтобы пароль мог содержать
`:`. Роутер защищён целиком (`r.use(auth)` на `:189`), включая раздачу
скриншотов (`r.use('/screenshots', express.static(SCREENSHOTS_DIR))`, `:190`).

Маршруты:

## 4. Данные и где они лежат

Ни один из рабочих файлов не в git — все в `.gitignore` (`.gitignore:1-6`:
`node_modules/`, `profiles/`, `screenshots/`, `state.json`, `config.json`, `.env`).
В песочнице их **нет** (проверено `ls`) — есть только примеры
`config.example.json` и `.env.example`.

| Путь | Что | Кто пишет | Кто читает |
|---|---|---|---|
| `config.json` | аккаунты, URL, прокси, движок, расписание | панель (`saveConfig`) | `run.mjs`, `login.mjs`, панель |
| `state.json` | дневные счётчики и «неоднозначные» URL | `run.mjs` (`:26-33`) | `run.mjs`, панель (только на чтение) |
| `profiles/<id>/` | постоянный профиль Chromium: куки и сессия Google | Chromium | Chromium |
| `screenshots/` | PNG проблемных моментов | `gsc.mjs:22-27` | человек; раздаются панелью |
| `.env` | порт, BASE_PATH, логин/пароль панели | человек | `web/server.mjs:23-30` |

Формат `state.json` (по `src/run.mjs:46-55,127,141-142`):

```json
{
  "acc1:2026-07-27": { "done": ["https://…/a", "https://…/b"], "sent": 3 },
  "acc1:ambiguous":  { "urls": ["https://…/c"] }
}
```

Тонкость, которую легко не заметить: `done` — только успешные, `sent` —
успешные **плюс** неоднозначные, и лимит считается именно по `sent`
(`src/run.mjs:49-51`). Это сделано специально: `unknown` тоже жжёт слот квоты
Google, иначе два прогона за сутки (кнопка + планировщик) суммарно превысили бы
`dailyLimitPerAccount`.

Старые датовые ключи в `state.json` **никогда не удаляются** — кода очистки нет
ни в одном файле. Файл растёт линейно по числу дней × аккаунтов.

## 5. Ограничения и грабли

### 5.1. Расхождение: панель показывает не тот счётчик, что считает прогон

`web/server.mjs:201`:
```js
const sentToday = (state[`${a.id}:${tk}`]?.done || []).length;
```
а `src/run.mjs:51`:
```js
let sentToday = state[key]?.sent ?? done.size;
```

Панель показывает длину `done`, прогон лимитирует по `sent`. Если за день был
хоть один `unknown`, бейдж в панели покажет **меньше**, чем реально потрачено
квоты (например «7/10», когда прогон уже считает 8 и остановится на 10 по
своему счёту). На поведение это не влияет, вводит в заблуждение только человека.

### 5.2. Кнопка «Залогиниться» в панели зависает для dolphin/adspower

`login.mjs:58` при движках dolphin/adspower ждёт нажатия Enter через
`readline.question` на `process.stdin`. Панель запускает скрипт через
`spawn(..., { cwd: ROOT })` без опции `stdio` (`web/server.mjs:46`), то есть
stdin — пайп, в который никто никогда ничего не пишет и который не закрывается.
Процесс будет висеть бесконечно, `job.running` останется `true`, и кнопки
«Прогнать»/«Залогиниться» у этого аккаунта останутся заблокированными
(`web/server.mjs:232,235`) до перезапуска панели.

Для движка `builtin` этой проблемы нет: там ожидание не по stdin, а по событию
закрытия окна браузера (`src/login.mjs:103`). Поскольку рабочий движок на
сервере — builtin (`RUNBOOK.md:39-40`), грабли, вероятно, ни разу не выстрелили.
**ПРЕДПОЛОЖЕНИЕ** (логика выведена из кода, живьём не воспроизводил — нет
`node_modules` и запускать браузер здесь нельзя).

### 5.3. Два прогона по одному аккаунту могут затереть друг другу state.json

`run.mjs` читает весь `state.json` один раз на старте (`:42`) и потом пишет
**весь объект** после каждого URL (`:127`). Панель блокирует повторный запуск
только по одинаковому ключу задания (`web/server.mjs:43`), но ключи `'all'` и
`'acc1'` — разные. Нажать «Прогнать все» и «Прогнать» у конкретного аккаунта
можно одновременно; тогда два процесса будут писать один файл, и тот, кто
запишет последним, потеряет чужие правки. Побочный эффект — превышение дневной
квоты и/или повторная отправка URL. Планировщик проверяет только
`jobs.get('all')?.running` (`web/server.mjs:69`), про per-account задания
не знает.

### 5.4. Планировщик перезапускается вместе с панелью и может отработать дважды

`lastAutoRun` (`web/server.mjs:59`) — обычная переменная в памяти. Если панель
перезапустить (или служба сама упадёт и поднимется) в ту же минуту, на которую
назначено расписание, автопрогон запустится второй раз за сутки. Дневной лимит
при этом всё равно удержит `state.json` (`sent` уже потрачен), так что ущерб
ограниченный. Время сравнивается локальное серверное (`:67`) — таймзоны
сервера и `.time` должны совпадать.

### 5.5. Успех/квота определяются по тексту всей страницы

`src/gsc.mjs:78-80` берёт `page.textContent('body')` целиком. Это признано в
самом RUNBOOK как нерешённый пункт (`RUNBOOK.md:118-121`): результат GSC
рендерится инлайн в панель, а не в `role=dialog`, поэтому прицельно скоупить
проверку не удалось. Риск: если в теле страницы по какой-то причине уже есть
фраза из `RE_SUCCESS`, вернётся ложный `'ok'`. `RE_QUOTA` уже чинили от той же
болезни — неограниченный `.*` заменили на `.{0,40}` (`RUNBOOK.md:116`).

Практический вывод: любое изменение вёрстки или формулировок GSC ломает разбор
молча. Диагностика — скриншоты в `screenshots/` (`README.md:122-123`).

### 5.6. Пароль прокси лежит в открытом виде и в конфиге, и в HTML

`web/server.mjs:144` рендерит `value="${esc(p.password)}"` в обычный
`<input>` — пароль прокси видно любому, кто открыл панель, и он же лежит
plaintext в `config.json`. Отдельно: **боевые креды ASocks закоммичены в
`RUNBOOK.md:43` и `RUNBOOK.md:52`** (логин, пароль, IP, порт). Если репозиторий
хоть раз был публичным или к нему есть чужой доступ — эти креды надо считать
скомпрометированными и ротировать.

### 5.7. CSRF-защиты в панели нет

Ни одна POST-форма не имеет токена, проверки `Origin`/`Referer` тоже нет
(грепом по `web/server.mjs` — ни `csrf`, ни `origin`). Единственная защита —
HTTP Basic. **ПРЕДПОЛОЖЕНИЕ:** браузеры кешируют Basic-креды на origin и
подставляют их в кросс-сайтовый POST, поэтому вредоносная страница теоретически
может удалить аккаунт или подменить прокси у залогиненного оператора. Живьём не
проверял. Смягчающее обстоятельство: панель слушает `127.0.0.1` и стоит за Caddy.

### 5.8. `checkProxy` для SOCKS почти ничего не проверяет

`src/lib.mjs:98-104` — только TCP-connect, ответ `'(socks доступен)'`. Мёртвый
SOCKS с открытым портом пройдёт проверку. Для HTTP-прокси проверка полноценная
(реальный внешний IP). Дополнительно: Chromium вообще не умеет SOCKS5 с
авторизацией — панель об этом предупреждает жёлтой плашкой
(`web/server.mjs:132-135`), и именно поэтому существует мост.

### 5.9. Прочее, что стоит знать заранее

- **Нет `package-lock.json`** — `npm install` через полгода может собрать другой
  набор версий. Playwright особенно чувствителен к версии Chromium.
- **`postinstall` тянет Chromium** — на сервере с лимитом трафика это заметно.
- **Дефолтный пароль панели `admin`/`changeme`** молча применяется при
  отсутствии `.env` (`web/server.mjs:35-36`).
- **Порт 8090** объявлен свободным в `README.md:89` для этой панели, но тот же
  8090 стоит дефолтом в шаблоне установки панели рассыльщика
  (`seo-texts/sender/deploy/nssm-panel-install.ps1:24`). По `seo-texts/docs/09`
  реально развёрнутая `SenderPanel` использует 8091, так что фактического
  конфликта, скорее всего, нет, но при переустановке рассыльщика по шаблону он
  возникнет. **НЕ ПРОВЕРЕНО** живьём — на сервер я не ходил.
- **`process.exit(0)`** в конце `run.mjs:157` и `login.mjs:108` — код возврата
  всегда 0, панель в логе покажет «завершено, код 0» даже если все аккаунты были
  пропущены из-за мёртвого прокси. Судить об успехе можно только по тексту лога.
- **Аккаунты только личные @gmail** — у Workspace-аккаунтов GSC отдаёт «service
  turned off» (`RUNBOOK.md:82,100`).
- **Разные URL по разным аккаунтам** — дублировать один URL между аккаунтами
  бессмысленно (`RUNBOOK.md:81`).
- **Прогрев**: первые 2-3 дня по 2-3 URL на аккаунт (`RUNBOOK.md:80`).

## 6. Что сломано или устарело

### 6.1. Мёртвый код

**`humanType` (`src/humanize.mjs:156-162`) — вызывающих нет.** Проверено грепом
по `src/` и `web/`: единственное вхождение имени — само объявление. Текст в
этом сценарии нигде не набирается (логин делает человек руками). Сам RUNBOOK это
признаёт (`RUNBOOK.md:122`: «Опечатки/исправления в humanType — сейчас не на
горячем пути»).

**`STATE_PATH` (`src/lib.mjs:14`)** экспортируется, но снаружи не используется:
`run.mjs` объявляет собственный `STATE_FILE` (`src/run.mjs:17`) с тем же
значением. Заодно `run.mjs:20-25` дублирует `lib.loadState` — потому что в
`lib.mjs` нет парного `saveState`, и автор сделал обе функции локально.
Дублирование безобидное, но при правке формата состояния надо помнить про **два**
места.

**`PROFILES_DIR` (`src/lib.mjs:11`)** используется только внутри самого
`lib.mjs`.

`src/proxybridge.mjs` — не мёртвый, но **никем не запускается автоматически**:
ни панель, ни `run.mjs` его не поднимают. Это ручной шаг оператора
(`RUNBOOK.md:49-53`). Если мост забыли запустить, `checkProxy` вернёт `null` и
все аккаунты будут молча пропущены с сообщением «Прокси НЕ отвечает — запущен ли
мост?» (`src/run.mjs:84`).
