# SEO чек-лист

**Легенда**

`[Я]` — только Яндекс · `[G]` — только Google · без метки — обе ПС
`[⚠️]` — требования ПС расходятся, читать оба подпункта
🔴 блокер · 🟠 важно · 🟡 желательно · ⚪ гигиена

---

## 1. Коды ответа и доступность

- [ ] 🔴 Все продвигаемые URL отдают 200
- [ ] 🔴 Несуществующие страницы отдают 404, а не 200 с текстом «не найдено» (soft 404)
- [ ] 🟠 Удалённые навсегда страницы отдают 410
- [ ] 🟠 Технические работы отдают 503 с заголовком `Retry-After`
- [ ] 🟠 Нет 5xx в логах за последние 30 дней
- [ ] 🟠 TTFB < 200 мс
- [ ] 🟡 Сервер отдаёт корректный `Last-Modified` и обрабатывает `If-Modified-Since` (304)
- [ ] ⚪ Нет ограничений по IP/User-Agent для ботов ПС
- [ ] ⚪ Боты проверены по обратному DNS (`yandex.ru`, `googlebot.com`), а не по User-Agent
- [ ] ⚪ WAF / Cloudflare / антибот не блокирует краулеров

## 2. Зеркала, протокол, редиректы

- [ ] 🔴 Выбран один канонический хост, остальные три варианта отдают 301
- [ ] 🔴 http → https везде, включая внутренние ссылки
- [ ] 🔴 Один вариант слеша в конце URL, второй — 301
- [ ] 🟠 Нет цепочек редиректов длиннее одного шага
- [ ] 🟠 Нет циклических редиректов и редиректов на 404
- [ ] 🟠 Редирект ведёт на релевантную страницу, а не на главную
- [ ] 🟠 Нет 302 там, где нужен 301
- [ ] 🟠 Верхний/нижний регистр URL не создаёт дублей
- [ ] ⚪ Сертификат валиден, цепочка полная, срок > 30 дней
- [ ] 🟡 Включён HSTS
- [ ] 🟡 Нет mixed content
- [ ] 🟡 Включён HTTP/2 или HTTP/3
- [ ] 🟡 Включено сжатие gzip / brotli

## 3. robots.txt

**Общее**

- [ ] 🔴 Доступен по `/robots.txt`, код 200, `Content-Type: text/plain`
- [ ] 🔴 CSS и JS **не закрыты** от обхода
- [ ] 🔴 Указан `Sitemap:` абсолютным URL
- [ ] 🔴 Продвигаемые разделы не попали под маску `Disallow`
- [ ] 🟠 Закрыты служебные разделы (админка, корзина, личный кабинет, поиск, печать)
- [ ] 🟠 Закрыты сортировки, отображения, служебные GET-параметры
- [ ] 🟠 Каждая спорная маска проверена в валидаторе обеих ПС
- [ ] ⚪ Нет правил для несуществующих разделов
- [ ] ⚪ Файл < 500 КБ

**[Я] Яндекс**

- [ ] 🟠 `Clean-param` прописан для UTM, `yclid`, `_openstat`, сортировок
- [ ] 🟠 `Clean-param` задан отдельно для разделов, где параметры разные
- [ ] ⚪ Директива `Host` удалена (отменена в 2018)
- [ ] ⚪ Директива `Crawl-delay` удалена (не учитывается с 2018)
- [ ] ⚪ Скорость обхода задана в Вебмастере, а не в robots.txt
- [ ] 🟡 `<noindex>` внутри HTML используется точечно или не используется вовсе

**[G] Google**

- [ ] 🔴 Страницы, которые нужно **выкинуть из индекса**, открыты для обхода и закрыты `<meta name="robots" content="noindex">` — одновременный `Disallow` + `noindex` не работает
- [ ] ⚪ Строка `noindex:` внутри robots.txt удалена (не поддерживается с 01.09.2019)
- [ ] ⚪ `Crawl-delay` не используется (никогда не поддерживался)

## 4. Sitemap.xml

- [ ] 🔴 Существует, доступен, код 200
- [ ] 🔴 Содержит все продвигаемые URL
- [ ] 🔴 Содержит **только** каноничные URL с кодом 200
- [ ] 🔴 Нет редиректов, 404, страниц с `noindex`, закрытых в robots.txt
- [ ] 🟠 Не более 50 000 URL и 50 МБ несжатого файла на файл
- [ ] 🟠 При превышении — sitemap-index
- [ ] 🟠 Разбит по типам страниц (каталог / товары / контент) для раздельной диагностики
- [ ] 🟠 `<lastmod>` в формате W3C с таймзоной и реальной датой правки
- [ ] 🟠 Генерируется автоматически по расписанию
- [ ] 🟡 Отдельный image-sitemap
- [ ] 🟡 Отдельный video-sitemap при наличии роликов

**[G] Google**

- [ ] ⚪ `<priority>` и `<changefreq>` не заполняются — игнорируются
- [ ] 🟠 `<lastmod>` достоверен; одинаковая дата на всех URL обесценивает поле целиком
- [ ] ⚪ Пинг `/ping?sitemap=` отключён (Google убрал поддержку в 2023)
- [ ] 🟠 Карта загружена в Search Console

**[Я] Яндекс**

- [ ] 🟠 Карта добавлена в Вебмастер → Индексирование → Файлы Sitemap
- [ ] 🟠 Проверено, сколько URL Яндекс из неё принял

## 5. Индексация и canonical

- [ ] 🔴 На продвигаемых страницах нет случайного `noindex`
- [ ] 🔴 `rel="canonical"` указывает сам на себя, абсолютным URL
- [ ] 🔴 Canonical не ведёт на редирект, 404 или закрытую страницу
- [ ] 🟠 Один `canonical` на страницу, в `<head>`, в исходном HTML
- [ ] 🟠 Canonical не проставляется через JS
- [ ] 🟠 `X-Robots-Tag` настроен для PDF, прайсов, архивов
- [ ] 🟠 Число страниц в индексе сопоставимо с числом URL в sitemap
- [ ] 🟠 Разобраны причины исключения страниц в обеих панелях
- [ ] 🟡 Служебные страницы (теги, архивы, версии для печати) закрыты

**Ускорение индексации [⚠️]**

- [ ] 🟠 `[Я]` Подключён IndexNow
- [ ] 🟠 `[Я]` Используется Вебмастер → Переобход страниц
- [ ] 🟠 `[G]` Точечно — GSC → Проверка URL → Запросить индексирование (~10/сутки)
- [ ] ⚪ `[G]` IndexNow не используется — Google не участвует
- [ ] ⚪ `[G]` Indexing API не используется (только JobPosting и BroadcastEvent)

## 6. Пагинация [⚠️]

- [ ] 🟠 `[G]` Self-canonical на каждой странице пагинации
- [ ] 🟠 `[G]` `rel="next"/"prev"` не используется — не поддерживается с 2019
- [ ] 🟠 `[G]` Canonical со страницы 2+ на первую **не** ставится
- [ ] 🟠 `[Я]` Допустим canonical на первую страницу, но глубокие товары тогда теряются
- [ ] 🟠 Рекомендуемый компромисс для обеих ПС — self-canonical
- [ ] 🟠 Title и H1 страниц пагинации различаются («— страница 2»)
- [ ] 🟠 Ссылки на товары присутствуют в HTML, а не только в JS
- [ ] 🟠 Первая страница пагинации доступна по базовому URL, без `?PAGEN_1=1`
- [ ] 🟡 Глубина пагинации не превышает 10–15 страниц

## 7. Фасеты и фильтры

- [ ] 🔴 В индекс открыты только фасеты, под которые есть частотность
- [ ] 🔴 Комбинации трёх и более параметров закрыты
- [ ] 🟠 Сортировки, отображение, количество на странице — закрыты
- [ ] 🟠 У открытого фасета уникальные title, description, H1
- [ ] 🟠 У открытого фасета уникальный текст, а не подстановка числа в шаблон
- [ ] 🟠 У открытого фасета непустая выдача товаров
- [ ] 🟠 Фасеты имеют ЧПУ, а не GET-параметры
- [ ] 🟠 Закрытые фасеты не съедают краулинговый бюджет (проверено по логам)
- [ ] 🟡 Есть внутренние ссылки на приоритетные фасеты

## 8. Дубли

- [ ] 🔴 Нет дублей title по сайту
- [ ] 🔴 Нет дублей H1 по сайту
- [ ] 🔴 Нет дублей description по сайту
- [ ] 🔴 `/index.php` и другие точки входа не дублируют основной URL
- [ ] 🟠 Проверены near-duplicate тексты (косинусная близость между страницами)
- [ ] 🟠 Страницы-клоны либо переписаны, либо склеены, либо закрыты
- [ ] 🟠 UTM-метки: `[Я]` — `Clean-param`, `[G]` — canonical
- [ ] 🟠 `[G]` Разобран отчёт «Страница-дубликат, Google выбрал другую каноническую»
- [ ] 🟠 `[Я]` Проверена склейка страниц в Вебмастере
- [ ] 🟡 Нет одинаковых текстов на региональных страницах

## 9. Скорость [⚠️]

**[G] Core Web Vitals — пороги по 75-му перцентилю реальных пользователей**

- [ ] 🔴 LCP ≤ 2,5 с
- [ ] 🔴 INP ≤ 200 мс
- [ ] 🔴 CLS ≤ 0,1
- [ ] 🟠 Смотрятся полевые данные в GSC, а не только PageSpeed Insights
- [ ] 🟠 LCP-изображение грузится `eager` + `fetchpriority="high"`
- [ ] 🟠 Остальные изображения — `loading="lazy"`
- [ ] 🟠 У всех изображений заданы `width` и `height`
- [ ] 🟠 Шрифты с `font-display: swap`, подгружаются `preload`
- [ ] 🟠 Тяжёлый JS отложен (`defer` / `async`), счётчики и виджеты не в `<head>` синхронно
- [ ] 🟠 Зарезервирована высота под блоки, подгружаемые после отрисовки
- [ ] 🟡 Критический CSS инлайнится
- [ ] 🟡 Изображения в WebP / AVIF
- [ ] 🟡 Подключён CDN

**[Я] Яндекс**

- [ ] 🟠 Core Web Vitals как отдельного фактора нет — скорость влияет через поведенческие
- [ ] 🟠 Проверен отчёт Вебмастер → Диагностика → Скорость сайта
- [ ] 🟠 Проверено Метрика → Мониторинг → Время загрузки страниц
- [ ] 🟠 Время ответа сервера отслеживается отдельно (влияет на скорость обхода)

## 10. Мобильная версия

- [ ] 🔴 Обе ПС индексируют мобильную версию — контент десктопа без мобильной не учитывается
- [ ] 🔴 Текст, заголовки, alt, внутренние ссылки, разметка идентичны десктопу
- [ ] 🔴 SEO-текст на мобильной не вырезан и не скрыт безвозвратно
- [ ] 🟠 Текст в спойлере присутствует в HTML и раскрывается по клику
- [ ] 🟠 Первые абзацы показаны открытыми
- [ ] 🟠 Нет горизонтального скролла
- [ ] 🟠 Шрифт ≥ 16px, тап-таргеты ≥ 48px
- [ ] 🟠 Нет перекрывающих контент межстраничных баннеров
- [ ] 🟡 Формы и фильтры работоспособны на тач-устройствах
- [ ] 🟡 `[Я]` Турбо-страницы либо отключены, либо синхронизированы с основной версией

## 11. Структура и URL

- [ ] 🟠 Любая продвигаемая страница достижима ≤ 3 кликов от главной
- [ ] 🟠 URL на латинице, транслитом, через дефис
- [ ] 🟠 Без ID, дат, параметров, кириллицы, заглавных букв
- [ ] 🔴 Существующие URL не меняются без 301 и обновления внутренних ссылок
- [ ] 🟠 Иерархия каталога логична и отражена в URL
- [ ] 🟠 Хлебные крошки на всех страницах вложенности
- [ ] 🟡 HTML-карта сайта для пользователей
- [ ] 🟡 Глубина вложенности URL не больше 4 уровней

**Регион [⚠️]**

- [ ] 🟠 `[Я]` Регион сайта задан в Вебмастере → Информация о сайте → Региональность
- [ ] 🟠 `[Я]` Регион подтверждён карточкой Яндекс Бизнеса
- [ ] ⚪ `[G]` Аналога нет; отчёт International Targeting удалён из GSC в 2022
- [ ] ⚪ `[G]` `hreflang` нужен только для многоязычных сайтов

## 12. Внутренняя перелинковка

- [ ] 🔴 На каждую продвигаемую страницу ведёт ≥ 3 внутренние ссылки
- [ ] 🟠 Нет страниц-сирот (нет входящих внутренних ссылок)
- [ ] 🟠 Анкоры разнообразные, по смыслу, не переспамленные
- [ ] 🟠 Паттерн перелинковки не идентичен на всех однотипных страницах
- [ ] 🟠 Ссылки ведут на 200, не на редиректы и 404
- [ ] 🟠 Связаны смежные разделы по логике пути клиента
- [ ] 🟡 3–8 контекстных ссылок в тексте страницы
- [ ] 🟡 Есть хабовые страницы, поднимающие глубокие разделы
- [ ] 🟡 Ссылки в HTML, а не подгружаются JS
- [ ] ⚪ Нет `nofollow` на внутренних ссылках без причины

## 13. Title [⚠️]

- [ ] 🔴 Уникален на каждой странице
- [ ] 🔴 Главный ключ в первых 1–5 словах
- [ ] 🟠 Один ключ, без перечислений через запятую
- [ ] 🟠 Есть коммерческий модификатор для коммерческих страниц
- [ ] 🟠 Не совпадает дословно с H1
- [ ] 🟠 `[G]` Длина ≈ 55–60 символов (обрезка по пикселям, ~580px)
- [ ] 🟠 `[Я]` Длина до 70–80 символов
- [ ] 🟠 `[G]` Учитывается, что Google переписывает title примерно в 2 случаях из 3
- [ ] 🟠 `[Я]` Яндекс чаще берёт title как есть — писать под Яндекс
- [ ] 🟡 `[Я]` Регион в title для геозависимых запросов
- [ ] 🟡 Отображаемый в выдаче title проверен по факту, а не по коду

## 14. Description [⚠️]

- [ ] 🟠 Уникален на каждой странице
- [ ] 🟠 140–200 символов
- [ ] 🟠 Содержит ключ, выгоду и призыв
- [ ] 🟠 `[Я]` Приоритет: Яндекс существенно чаще показывает его как сниппет
- [ ] 🟡 `[G]` Не фактор ранжирования; Google переписывает ~70% сниппетов из текста страницы
- [ ] 🟡 `[G]` Текст страницы содержит готовые к цитированию фрагменты под сниппет
- [ ] ⚪ `[G]` При необходимости заданы `max-snippet:-1` и `max-image-preview:large`
- [ ] ⚪ Нет `<meta name="keywords">` или он игнорируется осознанно

## 15. Заголовки H1–H6

- [ ] 🔴 Ровно один H1 на странице
- [ ] 🔴 H1 уникален по сайту
- [ ] 🟠 H1 отличается формулировкой от title
- [ ] 🔴 Ключ не идёт цепочкой H1 → H2 → первое предложение
- [ ] 🟠 Иерархия без пропусков уровней
- [ ] 🟠 Заголовки не используются для оформления
- [ ] 🟠 H2 отражают реальные подтемы, а не единый шаблон на всех страницах
- [ ] 🟡 Часть H2 сформулирована вопросами (под ИИ-ответы и голосовой поиск)

## 16. Текст страницы

- [ ] 🔴 Уникален относительно других страниц сайта
- [ ] 🔴 В первых 500 знаках не более 2–3 вхождений ключа
- [ ] 🔴 Первые 2–3 предложения дают прямой ответ, без разгона
- [ ] 🟠 Объём варьируется между однотипными страницами, а не одинаков
- [ ] 🟠 Структура варьируется: разное число блоков, разный порядок
- [ ] 🟠 Нет шаблонных связок, повторяющихся на большинстве страниц
- [ ] 🟠 Есть конкретика: цифры, модели, параметры, сроки
- [ ] 🟠 Нет «воды», канцелярита и общих слов
- [ ] 🟠 Покрыт основной и дополнительный интент
- [ ] 🟠 Есть анализ вариантов с плюсами и минусами
- [ ] 🟠 Есть таблицы и структурированные блоки
- [ ] 🟠 Текст размещён под листингом товаров, не над ним
- [ ] 🟡 Есть FAQ-блок с непошаблонными вопросами
- [ ] 🟡 Есть уникальный блок под тип страницы (сравнение, схема выбора, кейс)
- [ ] 🟡 Даты обновления реальные и разнесены во времени
- [ ] 🔴 Нет автогенерации без экспертной вычитки
- [ ] 🟠 Соблюдены правила стайлгайда проекта

## 17. Изображения

- [ ] 🟠 `alt` осмысленный, без переспама
- [ ] 🟠 Имя файла транслитом по смыслу
- [ ] 🟠 Заданы `width` и `height`
- [ ] 🟠 Сжатие без потери качества, современные форматы
- [ ] 🟡 Собственные фото вместо стоков
- [ ] 🟡 Изображения в image-sitemap
- [ ] 🟡 `title` у изображения там, где уместно
- [ ] ⚪ Изображения не закрыты robots.txt

## 18. Микроразметка [⚠️]

**Работает в обеих ПС**

- [ ] 🟠 `BreadcrumbList` на всех страницах вложенности
- [ ] 🟠 `Product` + `Offer` с `price`, `priceCurrency`, `availability`
- [ ] 🟠 `Organization` на главной: название, юрлицо, логотип, телефон, адрес, ИНН, `sameAs`
- [ ] 🟠 `Person` + связка `author` / `reviewedBy` для авторов
- [ ] 🔴 Разметка соответствует видимому на странице контенту
- [ ] 🟠 Разметка в исходном HTML, а не дорисовывается JS
- [ ] 🟠 JSON-LD, а не микроформаты
- [ ] 🟡 `AggregateRating` / `Review` — только на реальных отзывах
- [ ] 🟡 `VideoObject`, `ImageObject` при наличии медиа
- [ ] 🟡 `LocalBusiness` с адресом при офлайн-присутствии

**[G] Google**

- [ ] 🔴 FAQ-сниппеты отключены с 07.05.2026 — CTR-бонус от `FAQPage` не планируется
- [ ] 🟡 Разметка `FAQPage` остаётся валидной, её можно не удалять
- [ ] 🟡 `FAQPage` удаляется, только если описывает отсутствующий контент
- [ ] ⚪ `HowTo` не используется — тип удалён в 2023
- [ ] 🟠 Проверка: Rich Results Test + Schema Markup Validator
- [ ] ⚪ Отсутствие FAQ в отчётах GSC (с июня 2026) и в API (с августа 2026) — не ошибка

**[Я] Яндекс**

- [ ] 🟠 FAQ-блок сохраняет ценность для выдачи и ответов Алисы
- [ ] 🟠 Проверка: Вебмастер → Инструменты → Валидатор микроразметки

## 19. Экспертность: E-E-A-T `[G]` / ЭПОС `[Я]`

**Общее**

- [ ] 🔴 У материалов указан реальный автор
- [ ] 🔴 Один автор не подписывает весь сайт
- [ ] 🟠 Автор соответствует тематике страницы
- [ ] 🟠 Есть страницы авторов: био, фото, опыт, сертификаты, публикации
- [ ] 🟠 Даты публикации и обновления реальные, не батчевые
- [ ] 🟠 На сайте есть «О компании», «Контакты», «Оферта», «Политика»
- [ ] 🟠 Указаны реквизиты, ИНН/ОГРН, физический адрес
- [ ] 🟠 Есть портфолио, кейсы, отзывы
- [ ] 🟠 Кейсы конкретные и релевантны теме страницы
- [ ] 🟡 Собственные фото с объектов
- [ ] 🟡 Упоминания компании на отраслевых площадках

**[G] E-E-A-T**

- [ ] 🟠 Experience: личный опыт использования продукта показан явно
- [ ] 🟠 Expertise: квалификация автора подтверждаема
- [ ] 🟠 Authoritativeness: узнаваемость бренда, упоминания, ссылки

# Приложение А. Перед публикацией страницы

```
[ ] Title уникален, ключ в начале, ≤60 симв. для Google / ≤80 для Яндекса
[ ] Description уникален, с призывом
[ ] Один H1, уникален, не равен title
[ ] Ключ не идёт цепочкой H1 → H2 → первое предложение
[ ] В первых 500 знаках ≤ 2-3 вхождения ключа
[ ] Первые 2-3 предложения дают прямой ответ
[ ] Нет шаблонных связок из стоп-листа
[ ] Объём и структура отличаются от соседних страниц
[ ] Есть уникальный блок под тип страницы
[ ] Кейсы и примеры релевантны теме страницы
[ ] Числа и факты проверены по источнику
[ ] Соблюдён стайлгайд проекта
[ ] Дата обновления реальная, не совпадает с соседями
[ ] Автор соответствует тематике
[ ] 3-8 внутренних ссылок, анкоры разные
[ ] Цена и статус наличия видны
[ ] CTA присутствует
[ ] Текст под листингом товаров
[ ] Разметка: BreadcrumbList + Product/Offer
[ ] Разметка соответствует видимому контенту
[ ] Мобильная версия содержит тот же текст, он доступен
[ ] Canonical сам на себя, нет случайного noindex
[ ] Страница отдаёт 200 и попала в sitemap с реальным lastmod
```

# Приложение Б. После публикации

```
[ ] Страница добавлена в sitemap
[ ] [Я] Отправлена на переобход / через IndexNow
[ ] [G] Проверена через инспектирование URL
[ ] Через 7 дней: попала в индекс обеих ПС
[ ] Через 14 дней: появились показы
[ ] Через 4-6 недель: замер позиций, сравнение с baseline
[ ] Проверено отсутствие склейки с соседними страницами
[ ] Проверено отсутствие новых дублей title/H1
```

# Приложение В. Массовая публикация

```
[ ] Baseline снят до старта
[ ] Публикация идёт волнами, а не всем объёмом сразу
[ ] Первая волна — страницы с существующими показами
[ ] Задан критерий продолжения: сдвиг позиций на N за M недель
[ ] Даты обновления разнесены
[ ] Авторство разведено по тематикам
[ ] Near-duplicate кластеры уникализированы до волны
[ ] Диагностика обеих панелей проверяется еженедельно во время волн
[ ] Эффект оценивается сначала по Яндексу (2-8 недель), Google — позже (2-6 месяцев)
```
