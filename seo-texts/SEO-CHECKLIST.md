## 0. Как пользоваться

**Легенда приоритетов**

| Знак | Что значит |
|---|---|
| 🔴 | Блокер. Без этого остальное не имеет смысла или прилетит фильтр |
| 🟠 | Важно. Прямо влияет на позиции/трафик |
| 🟡 | Желательно. Даёт прирост, но не критично |
| ⚪ | Гигиена. Делается один раз и забывается |

**Легенда поисковиков**

| Метка | Что значит |
|---|---|
| **[Я+G]** | Работает одинаково в обоих, делается один раз |
| **[Я]** | Только Яндекс. В Google не работает или работает иначе |
| **[G]** | Только Google. В Яндексе не работает или работает иначе |
| **[⚠️ РАЗНО]** | Поисковики требуют **противоположного** — читать оба подпункта |

**Порядок прохождения:** разделы 1–2 (техничка) → 12 (проверка фильтров) → 4–6 (контент) →
3, 8, 10 (коммерция и поведение) → 13 (волновой запуск) → 14 (замеры).
Разделы 5 и 7 можно делать параллельно с контентом.

## 1.2. robots.txt **[⚠️ РАЗНО — главный источник ошибок]**

- [ ] 🔴 Файл отдаётся по `https://prokompressor.ru/robots.txt` с кодом 200, `Content-Type: text/plain`.
- [ ] 🔴 Закрыт служебный Битрикс: `/bitrix/`, `/local/`, `/upload/` (кроме картинок),
      `/auth/`, `/personal/`, `/cart/`, `/order/`, `*?print=`, `*?action=`, `/search/`.
- [ ] 🔴 **Не закрыты** CSS и JS. Обе ПС рендерят страницу; закрытый `/bitrix/js/` или
      `/bitrix/templates/` ломает рендер и мобильную проверку.
- [ ] 🔴 Указан `Sitemap:` полным абсолютным URL.
- [ ] 🟠 Проверить, что 759 страниц категорий **не попали** под маску Disallow фасетов.

### Отдельно для Яндекса **[Я]**

- [ ] 🟠 `Clean-param:` — **директива только Яндекса**, Google её не понимает и игнорирует.
      Это лучший способ склеить UTM и служебные параметры без потери веса:
      ```
      Clean-param: utm_source&utm_medium&utm_campaign&utm_term&utm_content&yclid&_openstat
      Clean-param: sort&order&display&PAGEN_1 /catalog/
      ```
- [ ] ⚪ `Host:` — **отменена Яндексом в 2018**. Если она ещё в файле — удалить, это мусор.
- [ ] ⚪ `Crawl-delay:` — **Яндекс не учитывает с 2018**. Скорость обхода задаётся в
      Вебмастере → Индексирование → Скорость обхода. Строку из robots.txt удалить.
- [ ] 🟠 Яндекс соблюдает `Disallow` строго: закрытая страница **не индексируется**.
      Это отличие от Google, см. ниже.
- [ ] 🟡 Тег `<noindex>...</noindex>` (нестандартный, только Яндекс) — для скрытия
      кусков текста внутри страницы. Google его просто не видит.
      **Для наших 759 текстов не использовать** — это костыль, а не решение переспама.

### Отдельно для Google **[G]**

- [ ] 🔴 `Disallow` в Google **запрещает обход, но не индексацию**. Google может показать
      URL в выдаче без сниппета («Проиндексировано, несмотря на блокировку в robots.txt»).
      Чтобы страница гарантированно выпала — нужен `<meta name="robots" content="noindex">`,
      и при этом страница **должна быть открыта** для обхода. Закрыть в robots.txt + noindex
      одновременно = Google никогда не увидит noindex.
- [ ] ⚪ `Crawl-delay:` Google **никогда не поддерживал**. Частота обхода — в GSC
      (настройка урезана, регулируется автоматически по отклику сервера).
- [ ] ⚪ `noindex:` внутри robots.txt Google **официально не поддерживает с 01.09.2019**.
      Если строка есть — удалить, она ничего не делает.
- [ ] ⚪ `Clean-param` в файле Google просто пропустит как неизвестную директиву —
      вреда нет, но и пользы тоже. Для Google те же параметры закрываются canonical.

### Общее правило приоритета

Обе ПС при конфликте `Allow` и `Disallow` выбирают **самое длинное (специфичное) правило**.
Проверять каждую спорную маску в: Вебмастер → Инструменты → Анализ robots.txt
и GSC → robots.txt (отчёт).

- [ ] 🟠 `<lastmod>` в формате W3C с таймзоной, **реальная дата правки**, не «сегодня» на всё.
- [ ] 🟡 Карта обновляется автоматически (агент Битрикса), а не руками.
- [ ] 🟡 Отдельный `image-sitemap` для фото оборудования — источник трафика с картинок.

### Отдельно для Google **[G]**

- [ ] 🟠 `<priority>` и `<changefreq>` Google **полностью игнорирует**. Тратить время
      на их простановку бессмысленно.
- [ ] 🟠 `<lastmod>` Google использует **только если доверяет ему**: если во всей карте

      Это ровно наш риск — единая дата «15 июля 2026» на 759 страницах.
- [ ] ⚪ **Ping sitemap (`/ping?sitemap=`) Google отключил в 2023.** Если в Битриксе висит

### Отдельно для Яндекса **[Я]**

- [ ] 🟠 Карта добавляется в Вебмастер → Индексирование → Файлы Sitemap.
      Там же видно, сколько URL Яндекс из неё реально взял.
- [ ] 🟡 Яндекс `changefreq`/`priority` тоже фактически не использует, но `lastmod` учитывает

## 1.4. Управление индексацией **[⚠️ РАЗНО]**

- [ ] 🔴 На всех 759 категориях: **нет** случайного `noindex` (частая беда после
      правок шаблона Aspro). Проверить массово парсером.
- [ ] 🔴 `rel="canonical"` на категории указывает **сам на себя**, абсолютным URL.
- [ ] 🟠 Фасеты со спросом (бренд, давление, мощность) — открыты, self-canonical,
      уникальные title/H1/текст. Фасеты без спроса (сортировки, отображение,
      комбинации 3+ параметров) — закрыты.
- [ ] 🟠 `X-Robots-Tag` для PDF/прайсов, если их не надо в индексе.

### Пагинация **[⚠️ РАЗНО — делать по-разному]**

- **[G]** 🟠 `rel="next"/"prev"` Google **не использует с 2019**. Правильно:
  на каждой странице пагинации **self-canonical** (`/catalog/x/?PAGEN_1=2` канонична сама себе),
  title и H1 с пометкой «— страница 2», и обязательно ссылки на товары должны быть в HTML.
  Canonical со страницы 2 на страницу 1 Google трактует как ошибку и товары со 2-й страницы
  может не найти вовсе.
- **[Я]** 🟠 Яндекс допускает и корректно обрабатывает **canonical со страниц пагинации
  на первую**. Но это уводит в неиндекс товары с глубоких страниц.
  **Рекомендация для нас:** делать self-canonical (вариант Google) — он безопасен
  для обеих ПС, а глубину закрывать нормальной перелинковкой и sitemap товаров.

### Ускорение индексации **[⚠️ РАЗНО]**

- [ ] 🟠 **[Я]** **IndexNow** — поддерживается Яндексом (и Bing). Для Битрикса есть готовые
      модули. Это самый быстрый способ загнать в индекс 277 «пустых» страниц.
      **Google в IndexNow не участвует** — не рассчитывать на него для Google.
- [ ] 🟠 **[Я]** Вебмастер → Индексирование → **Переобход страниц**: лимит зависит от сайта,
      расходовать на приоритетные страницы волны.
- [ ] 🟠 **[G]** GSC → Проверка URL → **Запросить индексирование**: ~10 URL/сутки.
      Для 759 страниц это не инструмент — только для точечной проверки.
      Массовое индексирование в Google решается качеством + внутренними ссылками + sitemap.
- [ ] ⚪ **[G]** Indexing API работает **только для JobPosting и BroadcastEvent**.
      Для каталога компрессоров использовать его нельзя (это нарушение).

## 1.6. Скорость **[⚠️ РАЗНО — разные метрики и разные пороги]**

### Google: Core Web Vitals **[G]**

Официальные пороги (подтверждены web.dev, сентябрь 2026). Оцениваются по **75-му перцентилю**
реальных пользователей (поле CrUX), а не по лабораторному тесту.

| Метрика | Хорошо | Требует улучшения | Плохо |
|---|---|---|---|
| **LCP** (загрузка основного контента) | ≤ 2,5 с | 2,5–4,0 с | > 4,0 с |
| **INP** (отзывчивость; заменил FID в марте 2024) | ≤ 200 мс | 200–500 мс | > 500 мс |
| **CLS** (визуальная стабильность) | ≤ 0,1 | 0,1–0,25 | > 0,25 |

- [ ] 🟠 Смотреть **отчёт CWV в GSC** (полевые данные), а не только PageSpeed Insights.
      Если поля нет (мало трафика на группу URL) — Google берёт данные по группе похожих страниц.
- [ ] 🟠 Типовые убийцы LCP на Битрикс+Aspro: неоптимизированные фото оборудования,
      отсутствие `loading="lazy"` ниже первого экрана (и **обязательно `eager` для LCP-картинки**),
      отсутствие WebP/AVIF, тяжёлый слайдер на первом экране.
- [ ] 🟠 Убийцы INP: тяжёлые обработчики Aspro (фильтр каталога, «быстрый просмотр»),
      подключение всех JS синхронно, счётчики и виджеты чата в `<head>`.
- [ ] 🟠 Убийцы CLS: подгрузка блоков без резервирования высоты, шрифты без `font-display: swap`,
      **наш блок текста, если он вставляется после отрисовки** — проверить отдельно.
- [ ] 🟡 Композитный кеш Битрикса включён, `Vary` настроен корректно.

> ⚠️ В SEO-блогах в 2026 циркулируют утверждения про «Core Web Vitals 2.0», «Visual Stability
> Index (VSI)» и «мартовский апдейт, объединивший три метрики в композитный балл».
> **В официальной документации Google этого нет** (проверено 02.09.2026 на web.dev и
> Search Central). Планировать работы по трём подтверждённым метрикам, блогам не верить.

# РАЗДЕЛ 4. КОНТЕНТ ON-PAGE (по каждой из 759 страниц)

## 4.1. Title **[⚠️ РАЗНО по длине и по правилам переписывания]**

- [ ] 🔴 Title уникален для каждой из 759 страниц. Дублей нет **вообще**.
- [ ] 🔴 Главный ключ — в первых 1–5 словах.
- [ ] 🟠 Формула для категории: `{Тип оборудования} {уточнение/бренд/параметр} — купить в {регион} | {Бренд компании}`.
- [ ] 🟠 Не более одного вхождения ключа. Перечисления через запятую («компрессоры, компрессор,
      компрессоры купить») — прямой путь под Баден-Баден.
- [ ] 🟡 Есть коммерческий модификатор: «купить», «цена», «от … ₽», «с доставкой».

### Различия

- **[G]** 🟠 Google обрезает по **пикселям (~580px, ≈ 55–60 символов)** и **переписывает title
  примерно в 2 из 3 случаев**, беря H1 или текст со страницы. Вывод: писать title
  осмысленно, но не пытаться выжать из него всё — Google всё равно подменит.
  Реальный отображаемый title смотреть в выдаче, а не в коде.
- **[Я]** 🟠 Яндекс показывает длиннее (**≈ 70–80 символов**) и **чаще берёт title как есть**.
  Значит для Яндекса title весит больше и его стоит писать под Яндекс.
- **[Я]** 🟠 В title коммерческой категории имеет смысл **название региона** —
  для геозависимых запросов это работает. Для Google это почти нейтрально.

## 4.2. Description **[⚠️ РАЗНО — приоритет разный]**

- [ ] 🟠 Уникальный на каждой странице, 140–200 символов.
- [ ] 🟠 Содержит ключ, выгоду и **призыв** («Подберём по параметрам за 15 минут»).
- [ ] 🟡 Есть конкретика, которая тянет клик: срок поставки, гарантия, диапазон цен.

### Различия

- **[Я]** 🟠 **Яндекс существенно чаще использует description как сниппет.**
  Для Яндекса это фактически рекламный текст в выдаче → писать всерьёз, под CTR.
- **[G]** 🟡 Google переписывает description **в ~70% случаев**, собирая сниппет из текста
  страницы под конкретный запрос. Description для Google — **не фактор ранжирования**,
  только подсказка. Поэтому: не вылизывать 759 description ради Google;
  вылизывать ради Яндекса, а под Google — обеспечить, чтобы **сам текст**
  содержал готовые к цитированию фрагменты (см. 4.4 и раздел 7).
- **[G]** ⚪ Управление длиной сниппета: `<meta name="robots" content="max-snippet:-1">`
  и `max-image-preview:large` — увеличивают шанс развёрнутого сниппета. Яндекс это игнорирует.

- [ ] 🟠 Основная метрика волны 1: доля страниц зоны 11–30, сдвинувшихся на 2+ позиции.
- [ ] 🟠 Вторичные: показы (рост длинного хвоста), число страниц с ≥1 показом
      (вход «пустых» в индекс), CTR.
- [ ] 🟠 Бизнес-метрика: заявки с категорийных страниц (2,7% квал. / 6% обычных
      по данным за полгода).
- [ ] 🟡 Разделять «упал CTR из-за ИИ-ответа» и «упали позиции» — иначе выводы будут ложными.

# ПРИЛОЖЕНИЕ А. Быстрый чек-лист одной страницы

Проходить по каждой странице волны перед публикацией.

```
[ ] Title уникален, ключ в начале, ≤60 симв. для Google / ≤80 для Яндекса
[ ] Description уникален, с CTA (важнее для Яндекса)
[ ] Один H1, не равен title, не дублирует соседей
[ ] Ключ НЕ идёт цепочкой H1 → H2 → первое предложение
[ ] В первых 500 знаках ≤ 2-3 вхождения ключа
[ ] Нет шаблонных связок из стоп-листа
[ ] Объём отличается от соседних страниц (не все 4500)
[ ] Есть уникальный блок под тип страницы (таблица / кейс / схема выбора)
[ ] Кейс на странице релевантен её теме
    (проверка: не электрическая машина на странице ДИЗЕЛЬНЫХ)
[ ] Числа только из payload, qa_text.py пройден
[ ] Факты бренда прошли гейт достоверности
[ ] Нет длинных тире, нет <ul>, байлайн «ООО «Руспром»»
[ ] Фото-блок — кликабельная карточка-ссылка
[ ] Дата обновления реальная и не совпадает с соседями
[ ] Автор соответствует тематике страницы
[ ] 3-8 внутренних ссылок, анкоры разные, паттерн не копия соседей
[ ] Цена/диапазон и статус наличия видны (критично для Яндекса)
[ ] CTA присутствует
[ ] Текст под листингом товаров, не над ним
[ ] Разметка: BreadcrumbList + Product/Offer (+ FAQPage, если FAQ реально на странице)
[ ] Разметка соответствует видимому контенту
[ ] Мобильная версия содержит тот же текст и он доступен
[ ] canonical сам на себя, нет случайного noindex
[ ] Страница отдаёт 200, в sitemap, lastmod реальный
```
