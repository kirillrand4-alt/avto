# Объект «проект»: схема, сборщик, заслоны и числа

Дыра, которую закрывает эта работа, была не в источниках, а в данных: в `enrich.db`
не было ни одной таблицы про проект или стадию, сшивка шла по ИНН, и один завод с
тремя стройками превращался в кучу из трёх новостей под одним номером.

Уточнение владельца по ходу работы поменяло цель: **перегонка 3 725 старых сигналов —
не цель**. Цель — чтобы новое событие сразу ложилось проектом. Поэтому сделан приёмник
потока, а архив из 3 725 сигналов использован как **проба прибора**: на нём мерится
склейка, на нём же стоят заслоны и контроли.

Хранение — там же и так же, как новости: та же база `C:\sender\enrich.db`, новые
таблицы рядом с `signals`, колонки в стиле `signals` (`inn`, `source`, `source_url`,
`ts`, `sum`, `hotness`). Существующие таблицы не изменены ни одной строкой.

## 2. СХЕМА: ЧЕТЫРЕ НОВЫЕ ТАБЛИЦЫ

### `proekty` — карточка проекта

| колонка | что это |
|---|---|
| `proekt_id` | устойчивый ключ `PR-<sha1(инн + место + объект + работы)>`, при столкновении добавляется номер |
| `inn`, `zakazchik`, `zakazchik_iz` | заказчик: ИНН, название и ИЗ КАКОЙ таблицы название взято |
| `otrasl`, `otrasl_prior`, `otrasl_iz` | отрасль (широко, можно несколько), признак приоритетной, чем опознана |
| `region`, `region_iz`, `mesto`, `adres` | субъект РФ, чем доказан, город/площадка, адрес |
| `obekt`, `tip_rabot` | название объекта (КрАЗ, НкАЗ, Амурский ГХК) и класс работ |
| `stadiya`, `stadiya_kod`, `stadiya_data`, `stadiya_iz`, `stadiya_rannyaya` | стадия воронки 0–8, её код, дата, ссылка-доказательство, самая ранняя виденная стадия |
| `ts`, `data_pervaya`, `data_poslednyaya`, `gody_iz_teksta` | даты события: окно и годы, названные в тексте |
| `sum`, `summa_rub`, `hotness` | сумма как в signals (текст) и разобранная в рублях |
| `ulik`, `istochnikov`, `istochniki` | СКОЛЬКО доказательств, сколько РАЗНЫХ источников и их список |
| `zontik` | 1 = это программа компании («модернизация четырёх заводов»), а не проект одной площадки |
| `yakorya`, `goroda`, `regiony`, `raboty` | признаки для поиска проекта новым событием |
| `sklejka_prichiny` | почему улики слиплись — для контроля глазами |
| `event_types`, `klyuch_sostav`, `created_at`, `updated_at` | тип события, состав ключа, времена |

### `proekt_uliki` — доказательства, которые НАКАПЛИВАЮТСЯ

Строка на доказательство: `ulika_id` (хэш источник+ссылка+цитата), `proekt_id`, `inn`,
`source`, `source_url`, `citata` (полный текст сигнала), `event_type`, `sum`, `hotness`,
`stadiya`, `otrasl`, `ts`, `data_sobytiya`, `data_vzyatiya`, `goroda`, `regiony`,
`yakorya`, `raboty`, `inn_conf`, `suspect`, `signal_rowid`, `prichina`, `added_at`.

Ключ доказательства — хэш, вставка `INSERT OR IGNORE`. Одно и то же доказательство не
удваивается, но **разные доказательства одного события складываются, а не заменяют друг
друга**. Это прямо противоположно `seen_news`, где кто первым взял ключ, тот новость и
забрал.

### `proekt_slovar` и `proekt_gashenie` — служебные

`proekt_slovar` (основа, df, число заглавных и строчных написаний, форма) — замороженный
корпусный словарь. `proekt_gashenie` (ИНН, основа) — якоря без различающей силы внутри
предприятия. Зачем заморожен: признак «имя собственное» считается по доле написаний с
заглавной буквы в корпусе, и если пересчитывать его на каждом событии, вчерашняя склейка
перестанет воспроизводиться. Пересчёт — отдельной командой.

## 3. ТОЧКА ВХОДА ПОТОКА

```python
prinyat_sobytie(con, row, slov) -> (proekt_id, 'новый' | 'дополнен' | 'уже было', причина)
```

`row` — ровно та запись, которую коллектор кладёт в `signals`. Порядок работы:

```
пришло событие
   -> разобрали на признаки (место, регион, объект, работы, стадия, отрасль, дата)
   -> взяли проекты ЭТОГО ИНН
   -> проверили на противоречие с КАЖДОЙ уликой проекта
   -> нашёлся совместимый и связанный  -> ДОБАВИЛИ ДОКАЗАТЕЛЬСТВО
   -> не нашёлся                       -> ЗАВЕЛИ ПРОЕКТ
```

Повторная подача того же события ничего не перезаписывает и ничего не удваивает.

## 4. КАК УСТРОЕНА СКЛЕЙКА

Склейка идёт по СОДЕРЖАНИЮ, а не по одному ИНН: предприятие + объект + место + близкие
даты.

**Якорь** — имя собственное, отличающее один проект от другого. Имя собственное
опознаётся не списком, а замером по корпусу: у основы считается доля написаний с
заглавной буквы. «Тайшет» пишут с заглавной всегда, «строительство» — почти никогда,
поэтому первое слово предложения якорем не становится.

Три фильтра гасят якоря без различающей силы:

1. слишком частые по всему корпусу (df > 150);
2. слишком частые ВНУТРИ ИНН (>= 50 % сигналов предприятия) — так гасится собственное
   имя компании: «РУСАЛ» стоит в большинстве из 46 сигналов и потому не может служить
   доказательством, что два сигнала об одном проекте;
3. стоп-лист месяцев, правовых форм и общепромышленных слов.

**Что разрешает склейку** (в порядке силы): совпадение текстов (Жаккар по 4-граммам
>= 0.45) · два общих якоря · один редкий общий якорь (df <= 15) · общий якорь плюс общий
класс работ · общее место плюс общий класс работ · общее место плюс слабое сходство.

**Что запрещает склейку при любом сходстве (заслоны):**

* у обоих названы ОБЪЕКТЫ (якоря без топонимов) и множества не пересекаются;
* у обоих названы города и множества не пересекаются;
* у обоих названы регионы и не пересекаются;
* у обоих известна дата события и разрыв больше 540 дней;
* один зонтичный, другой площадочный.

Первый заслон добавлен по итогам разбора глазами: самый большой проект пробы (15 улик)
оказался СМЕСЬЮ — пусковые испытания Амурского ГХК на пилотной площадке в Тобольске и
реконструкция компрессорного блока «ЗапСиба» там же. Слепило их правило «общее место
плюс общий класс работ»: город один, работы одного класса. Общий город доказывает
место, но не проект — на площадке предприятия их бывает несколько. После заслона
самый большой проект — 12 улик, и это одна новость «Роснефти» про 14 объектов газовой
инфраструктуры, разобранная двенадцатью источниками. Цена заслона измерена: проектов
стало 3 012 вместо 2 931, подтверждённых двумя источниками 286 вместо 288. То есть
дробление платит двумя подтверждениями за то, что смеси больше нет.

**Полное звено.** Сигнал входит в проект, только если он связан хотя бы с одним
участником И НЕ ПРОТИВОРЕЧИТ НИ ОДНОМУ. Это главный заслон против цепного слипания:
зонтичный сигнал «модернизация четырёх заводов — Братск, Иркутск, Красноярск,
Новокузнецк» иначе сшил бы четыре разных проекта в один.

**Зонтичные сигналы** (три и более разных места в одном тексте) помечаются `zontik=1` и
склеиваются только между собой: программа компании — не проект площадки.

### 6.3. Контроли с заведомо негодным входом — 25 из 25 верно

Ноль доказывается так же тщательно, как находка. Каждый признак проверяется входом,
на котором он ОБЯЗАН промолчать, и входом, на котором обязан сработать:

```
одно предприятие, РАЗНЫЕ города — склейки быть не должно ......... 2 и вышло 2
одно место и объект — склейка обязана быть ....................... 1 и вышло 1
разрыв дат больше окна (540 дней) ................................ 2 и вышло 2
пустые тексты — не слипаются в проект-помойку .................... 5 и вышло 5
одно место, но РАЗНЫЕ названные объекты .......................... 2 и вышло 2
РАЗНЫЕ ИНН с одинаковым текстом .................................. 2 и вышло 2
то же доказательство дважды — не удваивается ..................... 1 и вышло 1
мусорный текст (паспорт компрессора) — мест не должно быть ....... 0 и вышло 0
ловушки места: «два новых корпуса» · «клинкерная линия» ·
  «свободный доступ к октябрьским данным» · «Северо-Комсомольское
  месторождение» · «Черногорское месторождение в Норильском районе» ... все ВЕРНО
ловушки региона: «Приморский район Санкт-Петербурга» · «северная
  площадка» · «ЯНАО» = «Ямало-Ненецкий» · «Комсомольск-на-Амуре» ...... все ВЕРНО
отрасль: офис продаж — приоритета нет; цементный завод — «цементная» . ВЕРНО
```

Пять из этих контролей поймали НАСТОЯЩИЕ ошибки прибора, и каждая была починена:

1. **«Новый» ловился в «двух новых корпусов»** и ставил место «Новый» сорока сигналам.
   Причина: односложные имена городов, совпадающие с обычными словами. Выброшены
   «Новый», «Нижний», «Великий», «Старый», «Свободный», «Октябрьский», «Заречный»,
   «Бор», «Оса», «Шуя», «Приморск»; составные имена заведены по различающему слову.
2. **«Клин» ловился в «клинкерной линии»** и приписывал чеченскому цементному заводу
   подмосковный Клин. Причина: окончание разрешалось «любые четыре буквы». Теперь
   разрешены только настоящие падежные окончания.
3. **Пять пустых сигналов слиплись в один проект** — текст «модернизация» из одного
   слова давал Жаккар 1.00. Теперь сходство текстов не считается короче 12 слов.
4. **«Иркутской области» рождало город Иркутск**, а «Приморский район
   Санкт-Петербурга» — Приморский край. Теперь топоним, за которым стоит
   «область/край/республика», регионом и считается, а составное имя субъекта требует
   обоих слов.
5. **«Северо-Комсомольское месторождение» в ЯНАО давало Комсомольск-на-Амуре**, а
   «Черногорское месторождение» в Норильском районе — город Черногорск в Хакасии.
   Теперь имя, за которым стоит «месторождение/рудник/залежь/участок», местом не
   считается, и дефис перед именем города запрещён.

## 7. ГДЕ АЛГОРИТМ СЛАБ (измерено, не предположено)

**7.1. Место известно у 23 % проектов, регион у 21 %.** Это главный ограничитель.
Тексты сигналов чаще всего не называют город: регион упомянут всего в 440 местах на
3 725 текстов, «г.» — в 177. Где нет ни места, ни объекта, склеивать нечем, и каждый
такой сигнал становится отдельным проектом. Отсюда 2 588 одиночек: это не столько
разные дела, сколько **предел разрешения имеющегося сырья**. Лечится не алгоритмом, а
источником: адрес и кадастр есть в ЕГРЗ и ГИСОГД, а не в новостной ленте.

**7.2. Разбиение зависит от порядка прихода событий.** Замерено прямо: архив прогнан
в прямом, обратном и случайном порядке.

```
                  проектов   подтверждённых   пар «лежат вместе»
прямой порядок      3 012          286              1 290
обратный            3 004          289              1 335
случайный           3 005          291              1 356
совпадение пар прямой/обратный ...... 68 %
совпадение пар прямой/случайный ..... 73 %
```

Итоговое ЧИСЛО проектов устойчиво (расхождение 0,3 %), а вот КОНКРЕТНЫЙ состав примерно
трети склеенных пар зависит от того, кто пришёл первым. Причина — жадное полное звено:
сигнал уходит в первый подходящий проект и больше не пересматривается. Для потока это
приемлемо (проект живёт и дополняется), но если понадобится воспроизводимость до
строки, нужен периодический пересбор всей истории одной командой, а не только приём.

**7.3. Проект привязан к ОДНОМУ ИНН.** Если то же событие придёт с ИНН подрядчика или
проектировщика, получится второй проект. Сшивка между ИНН не сделана намеренно:
склеивать разные предприятия по одному названию объекта опаснее, чем оставить два
проекта рядом. Поле `yakorya` для такой сшивки уже есть.

**7.4. Половина привязок к ИНН не подтверждена в самом сырье.** `inn_conf` пуст у
1 900 сигналов из 3 725. Это унаследовано из `signals` и честно перенесено в улику
(колонка `inn_conf`), но значит: у половины доказательств неизвестно, чьё это дело.

**7.5. Ранние стадии почти отсутствуют: 35 проектов из 3 012 на стадиях 0–4.**
Это свойство сырья, а не разбора. Лента новостей приносит событие, когда стройка уже
идёт. Вход «от события на ранней стадии» закрывается новыми источниками (ЕГРЗ,
разрешения на строительство, ТУ на газ и электросети, ОВОС), и объект «проект» теперь
готов их принять: у него есть стадия, дата стадии и накопление доказательств.

**7.6. Отрасль не определена у 1 250 проектов (41 %).** Там, где текст говорит
«строительство завода» без указания продукта, отраслевой признак взять неоткуда.
Отрасль помечается ШИРОКО (у проекта может быть несколько), приоритетные по списку
владельца помечены `otrasl_prior=1`.

**7.7. Порог зонтичности (три и более места в тексте) груб.** 51 проект помечен как
программа компании. Сигнал, называющий два завода, зонтичным не считается и может
уйти в проект одной из площадок.

**7.8. Словарь заморожен и требует пересчёта.** Признак «имя собственное» считается по
корпусу; когда сигналов станет заметно больше, надо прогнать `--slovar` заново, иначе
новые имена собственные не станут якорями. Пересчёт безопасен: он не меняет уже
заведённые проекты.
