# Расширение базы знаний рассыльщика (КЦ + Meyer)

Основа: аудит неиспользуемых данных + 146 идей от 5 линз fable (`data/kb_ideas_merged.json`).
Принцип владельца: «делай как ценное, так и то, что может пригодиться».

## Фаза 1 — расширение KB из имеющегося (без новых источников)

1. **Проекты: 111 → все 1018** + ретрив под лида (отрасль лида + ГОРОД: «сделали для [клиент]
   в Новосибирске» — идея case_client_city_match). Поля есть: sphere/brand/equipment/client/city.
2. **Цены: 48 → все 303 связки** бренд×категория (азот/кислород/осушители — сейчас рассыльщик их
   цен не знает) + **ценовой коридор по бюджет-баллу ОКВЭД** (наш маппинг 77 кодов: балл 1-2 →
   «решения от 250 тыс», балл 5 → премиум-линейки).
3. **Новостные signals → триггер-блок письма**: свежесть 0-30 дн (тема «В связи с модернизацией…»),
   31-90 (кейс-подход); займ ФРП = «бюджет подтверждён», ОЭЗ-резидент = «инвестплан обязателен».
4. **Директор ФИО** [13] → обращение по имени в письме директору.
5. **Каскад по ролям** (роли уже канонизированы): снабженцу — техдетали/цена, гл.инженеру — ROI/
   надёжность, директору — стратегия/льготы.
6. **Скоринг готовности** (2 линзы сошлись): выручка × бюджет-балл ОКВЭД × свежесть капекс-события
   → топ-сегмент = звонок в день письма (отдел продаж 28 чел).
7. **Гео-агрегаты**: «в [город] у нас N внедрений» (из 1018 проектов), кластеры отрасли по городу.
8. **Deliverability-поля**: verified-флаг (смелость CTA), last_contact_date (гигиена повторов),
   mx_ok-фильтр, A/B тайм-слоты.

## Фаза 2 — Meyer KB (идёт)
- Краул 3 сайтов до 500 стр (в работе) → fable-экстракция: модели/серии, дифференциаторы,
  отрасли, кейсы, клеймы, факты. → `answer-kb-meyer.json` (формат КЦ).
- Данные владельца с дропа (КП/прайсы Meyer) — домерж по прибытии.
- Изоляция контента: базы раздельные, движок общий, выбор по division (ОКВЭД-маппинг).

## Архитектура
- Ядро компактное + **ретрив под лида** (не раздувать промпт): выборка проектов по sphere+city,
  моделей по бренду/серии из письма, цен по категории+бюджет-баллу.
- `build_kb.py` v2 собирает оба файла одним движком.
