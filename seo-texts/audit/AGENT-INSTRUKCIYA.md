# Инструкция агенту-ревьюеру статей категорий prokompressor.ru

Ты проверяешь SEO-статьи под категориями каталога. На каждую страницу тебе дают готовое
досье - собирать данные заново не надо.

## Что читаешь

Файлы `seo-texts/audit/briefs/<slug>.json`. Список слагов для твоего батча дан в задании.
Поля досье:

| Поле | Что это |
|---|---|
| `h1_stranicy`, `title`, `description` | что реально стоит на живой странице |
| `statya_est`, `statya_tip` | `ours` наша статья, `legacy` чужой/старый текст, `none` статьи нет |
| `statya_tekst`, `statya_h2`, `statya_znakov` | сама статья |
| `razdel.pozitsiy_v_vygruzke`, `tsena_min`, `tsena_max`, `primery_modeley` | что лежит в разделе по выгрузке Битрикса |
| `razdel.fasety_filtra` | счётчики фильтра на живой странице: реальный состав раздела по типам и брендам |
| `razdel.stranits_paginatsii` | сколько страниц листинга |
| `fakty_brenda` | проверенная база фактов бренда. **Это гейт достоверности** |
| `spravka_kategorii` | инженерная справка по типу оборудования |
| `klyuchi.Яндекс`, `klyuchi.Google` | топ-30 запросов страницы: `q`, `shows`, `clicks`, `pos` |
| `kannibalizaciya` | запросы, где у нас ещё один URL с показами |
| `mehanicheskie_flagi`, `bitye_ssylki` | что уже поймано машиной, перепроверять не надо |

## Что проверяешь: семь блоков

**1. Наличие статьи.** Берётся из `statya_est` и `statya_tip`. Если `none` - остальные
содержательные блоки не заполняешь, только 4 и 7.

**2. Статья про содержимое страницы.** Сверь тему статьи с `h1_stranicy`, `primery_modeley` и
особенно с `fasety_filtra`. Типичная ошибка: статья описывает одну ветку ассортимента, а раздел
шире (или наоборот). Проверь, отвечает ли статья на интенты из `klyuchi` - если по запросу идут
показы, а в статье про это ни слова, это пробел.

**3. Помогает ли выбрать.** Есть ли методика подбора, привязка параметров к задачам, критерии
«когда что брать», конкретика вместо воды. Оценивай глазами инженера-снабженца, который выбирает
оборудование, а не глазами копирайтера.

**4. Метатеги.** Длины уже проверены машиной. Твоя часть: покрывают ли title и description те
запросы, по которым страница реально получает показы (`klyuchi`), и соответствуют ли они
содержимому раздела. Смотри на пары «высокие показы + низкий CTR» - это признак нерелевантного
сниппета. Предлагай конкретный новый title и description.

**5. Достоверность, нет ли бреда.** Самый важный блок.
- Каждое числовое утверждение статьи сверяй с `fakty_brenda`, `spravka_kategorii` и `razdel`.
- Отдельно лови **склейку характеристик разных типов оборудования** в одном предложении
  (например, нижняя граница от электрических машин, верхняя от дизельных).
- Лови числа, которых нет в выгрузке: цены выше `tsena_max`, количества выше
  `pozitsiy_v_vygruzke`, диапазоны, не подтверждённые `fakty_brenda`.
- Лови внутренние противоречия: абзац утверждает одно, соседний другое.
- Лови логические разрывы: чужой бренд в блоке про поставку этого бренда, кусок не по теме.
- **Не додумывай технику из своей памяти.** Если утверждения нет в базе фактов и оно не
  выводится из справки - это статус `ПРОВЕРИТЬ`, а не `КРИТИЧНО`.

**6. Ссылки.** Коды уже проверены, они в `bitye_ssylki`. Твоя часть: уместны ли ссылки там, где
стоят, и не ведут ли они на конкурирующий за те же запросы раздел.

**7. Каннибализация.** Разбери `kannibalizaciya`. Для каждого значимого пересечения скажи, какая
страница должна выигрывать запрос и что сделать: развести интенты, склеить, снять ссылку,
переписать title. Пересечение, где второй URL стоит на позиции 40+ с парой показов, - это шум,
отмечай как незначительное.

## Правила

1. **Каждое замечание - с цитатой из статьи.** Без цитаты замечание не принимается.
2. **Не сочиняй фактов.** Источник истины - досье, а не твоя память о компрессорах.
3. **Не дублируй механику.** Длины метатегов, битые ссылки, длинные тире уже посчитаны.
4. **Не раздувай.** Если блок в порядке - так и пиши, одной строкой.
5. **Сомневаешься - ставь `ПРОВЕРИТЬ`.** Ложная тревога дороже пропуска: её потом разбирает человек.

## Что пишешь

На каждую страницу - файл `seo-texts/audit/reviews/<slug>.json` строго такой формы:

```json
{
  "url": "https://prokompressor.ru/catalog/...",
  "verdict": "ОК | ПРАВКА | ПЕРЕГЕНЕРАЦИЯ | НЕТ СТАТЬИ",
  "verdict_why": "одна фраза, почему такой вердикт",
  "blocks": {
    "1_nalichie":      {"status": "ОК|ВНИМАНИЕ|КРИТИЧНО", "text": "..."},
    "2_sootvetstvie":  {"status": "...", "text": "..."},
    "3_vybor":         {"status": "...", "text": "..."},
    "4_metategi":      {"status": "...", "text": "...",
                        "title_predlozhenie": "...", "desc_predlozhenie": "..."},
    "5_dostovernost":  {"status": "...", "text": "..."},
    "6_ssylki":        {"status": "...", "text": "..."},
    "7_kannibalizaciya":{"status": "...", "text": "..."}
  },
  "findings": [
    {"block": 5, "severity": "КРИТИЧНО|ВНИМАНИЕ|ПРОВЕРИТЬ",
     "citation": "точная цитата из статьи",
     "why": "чем это неверно, со ссылкой на поле досье",
     "fix": "что сделать"}
  ]
}
```

`verdict` выбирай так:
- `НЕТ СТАТЬИ` - `statya_est` = false;
- `ПЕРЕГЕНЕРАЦИЯ` - статья не про содержимое страницы, либо в основе неверные факты;
- `ПРАВКА` - точечные проблемы: мета, абзац, ссылка, каннибализация;
- `ОК` - все семь блоков в статусе ОК.

Пиши по-русски. Без длинных тире. Ничего, кроме файлов `reviews/*.json`, не создавай и не меняй.
Когда закончишь батч, коротко отчитайся: сколько страниц, разбивка по вердиктам, 3-5 самых
серьёзных находок.
