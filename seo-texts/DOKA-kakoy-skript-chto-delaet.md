# Какой скрипт что делает: две задачи владельца

Коротко и по делу. Всё запускается **на сервере владельца** через раннер, а не в песочнице:

```
python3 seo-texts/zapusk_na_servere.py <скрипт.py> [аргументы]
```

Раннер кладёт файл в `C:\sender\_ops\3s_<имя>` и запускает там. Ограничение одно: задание
умирает по таймауту 1700 с, поэтому длинные проходы режутся бюджетом и гонятся кусками
(для этого и написаны «гонялки» `gnat_*.py`).

**Скрипты лежат в трёх ветках** — сессии работали параллельно. Где что, помечено ниже:
`[3с]` = `claude/procurement-file-delivery-guxgbq`, `[2с]` = `claude/read-intro-section-hrstzj`,
`[1с]` = `claude/nifty-shannon-7nw58j`. Забрать чужой файл: `git show origin/<ветка>:<путь> > <файл>`.

**Важно, где искать: это файлы РЕПОЗИТОРИЯ, а не сервера.** На `C:\sender` и на дропе их
нет — туда попадает только то, что положил раннер под именем `3s_<имя>`. Соседняя сессия
уже искала одиннадцать имён отсюда на сервере, не нашла и записала их в несуществующие;
проверка по git показала, что существуют все одиннадцать. Проверять наличие так:

```
git cat-file -e origin/<ветка>:seo-texts/<файл>.py && echo есть
```

Исключение — модули, которые ЖИВУТ на сервере и в репозитории отсутствуют:
`enrich_contacts.py`, `news_scan.py`, `enrich_db.py`, `lpr_obratnyy.py` (в `C:\sender\server\`),
`people_sources.py` (в `C:\sender\_ops\`), `dept_directory.py` (в `C:\sender\server\ops\`).

## ЗАДАЧА 1. Собрать по словарю карточки всех моделей нужных компрессоров

### Шаг 1. Словарь — с него всё начинается

```
slovar_modeley.py        [2с]  свод словарей МОДЕЛЕЙ компрессоров + слова для обхода площадок
slovar_marok.py          [3с]  марка -> рабочая среда (воздух / азот / кислород / газ)
klassify_marki.py        [3с]  тип машины и среда по марке через провайдера — для марок,
                               которых в словаре нет
```

Почему словарь решает всё: по реестру ЭПБ слово «нагнетатель» дало 3 195 записей против
2 616 у прямого «центробежный компрессор». **Половина парка называется иначе**, и запрос
одним словом теряет её молча.

### Шаг 2. Где искать карточки машин

```
epb_nashi_mashiny.py     [3с]  реестр ЭПБ: наши машины по предприятиям базы (дешёвый запрос)
epb_shirokiy.py          [3с]  широкий проход по ЭПБ ради НОВЫХ предприятий, не по своему списку
epb_sroki.py             [3с]  срок и статус экспертизы по нашим машинам (отдельным проходом:
                               реестр отвечает медленно)
```

Реестр ЭПБ — главный источник **моделей**: в заключении стоит паспорт устройства.

### Шаг 3. Тендерные площадки — там покупают и ремонтируют

```
tender_centro_scan.py    [3с]  РАЗВЕДКА: скан по словарю сразу по всем площадкам, считает,
                               где вообще есть что выгружать. Гонять ПЕРЕД тем, как тратить
                               заходы на карточки
gpb_po_slovam.py         [2с]  ЭТП ГПБ по словам и по всей площадке — канал НОВЫХ предприятий
tp_po_ocheredi.py        [2с]  Tender.pro по каждому предприятию очереди
roseltorg_po_ocheredi.py [2с]  Росэлторг то же самое
tektorg_po_ocheredi.py   [2с]  ТЭК-Торг
rts_po_ocheredi.py       [2с]  РТС-тендер (вход — слаг «ИНН-КПП», КПП обязателен)
sberast_po_ocheredi.py   [2с]  Сбер-А
eis_karta_inn.py         [3с]  ЕИС: карта закупок по ИНН
```

Разница «по словам» и «по очереди»: первое ищет НОВЫЕ предприятия, второе добирает закупки
по УЖЕ известным. Нужны оба, они дают разное.

### Шаг 4. Что с найденным делать

## Порядок, в котором это работает целиком

```
1. slovar_modeley + slovar_marok        <- словарь моделей и сред
2. tender_centro_scan                   <- разведка: где вообще есть что брать
3. epb_* и *_po_ocheredi / *_po_slovam  <- карточки машин и закупок
4. tip_mashiny + harakteristiki_mashin  <- что за машина и что о ней известно
5. enrich_contacts / people_sources /
   dept_directory / kontakty_*          <- контакты предприятия
6. lpr_obratnyy (gnat_back)             <- личный номер конкретного человека
7. email_probe                          <- адрес живой или нет
8. accumulate_contacts + svesti_vseh_lyudej + zalit_v_panel
```

## Три правила, которые дороже любого скрипта

1. **Ноль — это диагноз, а не факт.** Прежде чем писать «источник пуст», проверь ВХОД:
   `col_hh` возвращал ноль два дня, потому что запрос уходил без токена; hh с токеном
   отвечает 200 и отдаёт 214 вакансий по одному запросу.
2. **Крупное число — повод проверить прибор.** «112 не подтверждено» оказалось пустой
   колонкой имени; «51 прямой повод» оказался нашим же ярлыком в заголовке; «12 из 12»
   держалось на подстроке «МЕТР» внутри «параметр».
3. **Смотреть глазами десяток строк.** Ни один счётчик не показал, что письмо про замену
   компрессоров ушло главному бухгалтеру.
