## C. ПОВТОРЯЮЩИЕСЯ ПАТТЕРНЫ (системные проблемы)

### **КАЛЬКИ и переводной синтаксис** (в 6+ текстах):
1. **"закрывают задачи/потребности"** ← "address/meet needs" → *"решают задачи", "обеспечивают", "подходят для"*
2. **"строится на", "основан на"** ← "built on/based on" → *"использует", "с приводом", "работает по принципу"*
3. **"Цена формируется/складывается из"** ← "consists of" → *"Цена зависит от"*
4. **"Линейка включает/охватывает"** ← "line includes" → *"В линейке", "Выпускаем модели"*

### **КАНЦЕЛЯРИТ** (все тексты):
1. **"Поставка ведётся/организуется"** → *"Поставляем"*
2. **"Отгрузка выполняется"** → *"Отгружаем"*
3. **"Производительность составляет"** → *"Производительность 0,7 м³/мин"* (без глагола)
4. **"Машины выпускаются в исполнениях"** → *"Машины доступны в трёх давлениях"*
5. **"определяется", "указывается", "уточняется"** — избыток пассива.

### **НЕЕСТЕСТВЕННЫЕ КОЛЛОКАЦИИ**:
1. **"выполняет пневмоаудит"** (текст 4) — ГРУБАЯ ОШИБКА. Правильно: **"проводит пневмоаудит"**.
2. **"сосуды под давлением"** (текст 9) для ресивера — технически верно, но звучит как испытание на прочность, а не название оборудования.

## C. ПОВТОРЯЮЩИЕСЯ ПАТТЕРНЫ (системные проблемы)

### **1. «Закрывать задачи» (встречается 3+ раза)**
- Тексты 2, 3, 5: «закрывают задачи», «закрывают производительность»
- **Проблема:** Жаргонизм из бизнес-среды, неуместен в техническом каталоге.
- **Решение:** Заменить на «обеспечивают», «подходят для», «решают задачи»

### **2. «Подбор/выбор ведут от...» (встречается 3+ раза)**
- Тексты 1, 8, 10: «подбор ведут от двух параметров», «выбор модели ведут от пяти параметров»
- **Проблема:** Канцелярит, калька с английского «selection is based on».
- **Решение:** «Подбирают по...», «При подборе учитывают...», «Модель выбирают по...»

### **3. «По результатам...» (встречается 3+ раза)**
- Тексты 3, 5, 10: «по результатам пневмоаудита», «по результатам замера»
- **Проблема:** Избыточная канцелярская конструкция.
- **Решение:** «Данные пневмоаудита», «При пневмоаудите», «После замера»

### **4. Номинализации (систематически)**
- «Формирование стоимости», «суммирование расхода», «завышение снижает», «подбор ведут»
- **Проблема:** Отглагольные существительные делают текст искусственным.
- **Решение:** Заменять глаголами: «стоимость складывается», «суммируют расход», «если завысить»

### **5. «В нашем каталоге N моделей/исполнений» (повторяется во всех текстах)**
- **Проблема:** Шаблонная конструкция, выдаёт ИИ-генерацию.
- **Решение:** Варьировать формулировку: «Линейка включает...», «Поставляем...», «Доступны...»

### **6. «Под задачи/под нагрузки» (неправильный предлог)**
- Тексты 3, 5: «под задачи», «под пиковые нагрузки»
- **Проблема:** Калька с английского «for tasks», «for loads».
- **Решение:** «Для задач», «на нагрузки», «при нагрузках»

### **7. Кальки: «референсные условия», «ведёт осушение»**
- Текст 9: грубые кальки, которые носитель не пропустит.
- **Решение:** «Эталонные условия», «осушает воздух»

## D. ВЕРДИКТ: стоит ли постоянный ревьюер-филолог?

### **Да, стоит. Формат: семплер-критик + правила.**

**Причины:**

1. **Системные кальки и канцелярит не ловятся механическими фильтрами.** «Референсные условия», «закрывать задачи», «подбор ведут от» — это проблемы уровня языкового чутья, которое у ИИ отсутствует.

2. **Шаблонность выдаёт ИИ-генерацию.** Повторяющиеся конструкции («В нашем каталоге N моделей», «Подбор ведут от...») создают ощущение роботности.

3. **Ошибки проскакивают.** «Требованями» вместо «требованиями» — опечатка, которую должен был поймать редактор.

4. **Тексты в целом хороши, но не дотягивают до «живого».** Балл 6/10 означает, что с филологом-семплером можно поднять до 8-9/10.

### **Рекомендуемый формат работы:**

- **Семплер-критик:** Филолог проверяет 10-20% текстов и фиксирует системные паттерны (как в этом анализе).
- **Правила:** На основе находок составляется список запрещённых конструкций для промпта ИИ.
- **Per-text гейт:** Для особо важных страниц (главная, ключевые категории) — полная вычитка.

### **Что добавить в правила прямо сейчас:**

1. **Запретить:** «закрывать задачи», «подбор/выбор ведут от», «референсные условия», «под задачи/нагрузки», «формирование стоимости».
2. **Заменить на:** глаголы вместо номинализаций, правильные предлоги, стандартные технические термины.
3. **Варьировать:** вступительные конструкции («В нашем каталоге...»).

## C. ПОВТОРЯЮЩИЕСЯ ПАТТЕРНЫ (системные проблемы)

1. **«Держим в каталоге» / «возим под заказ»** (тексты 1, 3, 6, 8, 10) — разговорная лексика в деловом B2B-контексте. Естественно: «в наличии» / «поставляем под заказ».

2. **«Закрывают задачи»** (тексты 4, 7, 8) — профессиональный жаргон, который может звучать неестественно в письменном тексте. Замена: «используются для» / «применяются в».

3. **Страдательный залог** «поставляется», «привозится», «проводится» (тексты 1, 3, 5, 6) — калька с английского пассива, в русском естественнее активный залог: «мы поставляем», «инженер проводит».

4. **«Складывается из» / «зависит от»** (текст 1) — канцелярит, живой язык: «зависит от».

5. **Точные округлённые числа** «100 исполнений», «230 компрессоров», «2100 вариантов», «3150 моделей» (тексты 2, 3, 4, 5, 10) — выглядят нереалистично, типичный признак ИИ-генерации.

6. **«Ведут от» / «сводится к»** (тексты 1, 4) — канцелярские обороты, естественно: «начинают с» / «нужно выбрать».

7. **«Бренд» вместо «производитель»** (текст 3) — калька с английского brand, в русском профессиональном контексте естественнее «производитель» или «завод».

8. **Регистровые сбои** — переход от безличного («поставляются», «используются») к «мы работаем», «держим», «возим» (тексты 1, 3, 6, 8, 10). Нужен единый регистр: либо безличный официальный, либо «мы».

9. **«Охватывает диапазон»** / **«в диапазоне»** (тексты 1, 5) — калька с covers range, естественно: «от X до Y».

## D. ВЕРДИКТ: нужен ли постоянный ревьюер-филолог?

**Да, нужен**, но в формате **семплер-критик + набор правил**.

### Почему:

Тексты достаточно грамотны, но проходят через **2-3 системных фильтра**, которые делают их узнаваемо машинными для носителя:

1. Смесь разговорного («держим», «возим») и канцелярского («складывается из», «ведут от») регистров.
2. Кальки со страдательным залогом («поставляется», «проводится») вместо естественного активного.
3. Профессиональный жаргон без контекста («закрывают задачи», «на 20 кубов»).

### Что опасно/вредно:

- **Разговорные обороты** («держим», «возим») в деловом тексте снижают доверие.
- **Страдательный залог** и кальки («охватывает диапазон», «бренд») — признак переводного текста.
- **Нереалистичные точные числа** (2100 вариантов, 3150 моделей) — флаг ИИ-генерации.

### Что полезно:

- Структура текстов логична и информативна.
- Технические детали описаны точно.
- FAQ-секции полезны.

### Чего не хватает:

- **Единого регистра**: либо официальный безличный, либо «мы», но не вперемешку.
- **Естественных коллокаций**: «обеспечивают станки воздухом» вместо «поставляют воздух для станков».
- **Живого языка**: меньше канцелярита («ведут от», «сводится к»), больше прямых конструкций («начинают с», «нужно выбрать»).

### Формат работы ревьюера:

1. **Первые 20-30 текстов:** пост-аудит с выявлением всех паттернов и созданием набора правил (бан-лист оборотов, рекомендуемые замены).
2. **Дальше:** выборочный контроль (каждый 5-й текст) + обновление правил при новых находках.
3. **Итог:** правила встраиваются в промпт ИИ → качество текстов растёт → ревьюер переходит в режим spot-check.

- **"Расчёт ведут от суммарного расхода"** — системный повтор.

## C. ПОВТОРЯЮЩИЕСЯ ПАТТЕРНЫ (системные проблемы)

1. **"Ведут" + отглагольное существительное** (расчёт ведут, подбор ведут, поставка ведётся) — **встречается в 8 из 10 текстов**. Типичный канцеляризм. Носитель использует активные глаголы: "рассчитываем", "подбираем", "поставляем".

2. **"Поставляются/привозим/доставим под заказ из линейки производителя"** — **почти дословный повтор в 9 текстах**. Шаблон-заглушка, водянистость.

3. **"Паспортно выдаёт"** — **в 3 текстах**. Неестественное наречие, звучит как калька с "by spec" или "nominally". Нормально: "по паспорту даёт" или "выдаёт (согласно паспорту)".

4. **"Закрывает/закрывают" в значении "обеспечивает"** — **в 4 текстах**. Явная калька с английского "covers" (covers the needs). В русском промышленном контексте говорят "обеспечивает", "покрывает" (расход), но не "закрывает потребность".

5. **"Инженер проводит пневмоаудит"** — **в 4 текстах**. Звучит как переведённый техпроцесс. "Проводим аудит" или "делаем замеры" живее.

6. **Избыточный страдательный залог** — "поставляются", "выполнены", "даются", "ведётся" там, где носитель использовал бы активный. **Системно во всех текстах**.

7. **"Исполнения различаются"** — **в 3 текстах**. Канцелярская конструкция. Живой вариант: "модели отличаются" или "выпускаются в вариантах".

8. **"Объём выбирают исходя из характера потребления"** — **в 2 текстах**. Громоздкая конструкция. Проще: "объём подбирают по характеру потребления" или "выбирают в зависимости от того, как меняется расход".

## D. ВЕРДИКТ: нужен ли постоянный ревьюер-филолог?

**Да, нужен**, но в формате **семплер-критика + правила**.

**Почему:**
- Тексты информативны и технически корректны, но механически созданы по шаблонам. Читается как "хороший перевод инструкции", а не живой редакторский материал.
- Ошибки **системные** и **ловимы правилами**. 80% проблем — это 8-10 повторяющихся паттернов (см. раздел C).
- Носитель чувствует "роботность" не от одной фразы, а от накопительного эффекта канцеляризмов и калек.

**Формат работы:**
1. **Правила-баны** на системные паттерны (список в разделе C — это уже готовый черновик для промпта):
   - Заменить "ведут расчёт/подбор" → "рассчитывают/подбираем"
   - Заменить "закрывает потребность" → "обеспечивает"
   - Заменить "паспортно выдаёт" → "по паспорту даёт"
   - Убрать шаблон "под заказ из линейки производителя", разнообразить формулировки
   - Активный залог вместо страдательного, где возможно
   - Избегать "проводит пневмоаудит" → "проводим аудит" или "замеряем расход"

2. **Семплер-ревьюер (человек)** на 10-15% объёма для контроля качества после применения правил. Задача: ловить то, что не попало в правила, и обновлять список банов.

**Ценность:** Без ревьюера эти тексты сольются с общей массой "SEO-писанины", хотя фактически они на голову выше по содержанию. Редактура вытянет их в категорию "написано профессионалом для профессионалов".

## B. ОШИБКИ

### **КРИТИЧНО**

**1. Тексты ID catalog__vozdushnye-kompressory__kompressory-25000-l-min и vintovye__elektricheskie_1__fiac**

**Цитата 1 (текст 25 м³/мин):**
> "Завышать давление не рекомендуется: каждые 2 бара сверх необходимого снижают производительность на 10-12% при том же энергопотреблении."

**Цитата 2 (текст FIAC):**
> "Завышать тоже невыгодно: рост давления снижает производительность компрессора в пересчёте на кубометры."

**В чём ошибка:**  
Это перевёрнутая зависимость. У винтового компрессора:
- **Производительность FAD (м³/мин на всасывании)** при повышении давления снижается незначительно или остаётся стабильной в пределах рабочего диапазона блока
- **Энергопотребление** растёт на 7-10% на каждый бар избыточного давления
- **Удельное энергопотребление** (кВт·ч на м³) растёт пропорционально давлению

**Как правильно:**  
"Завышать давление невыгодно: каждые 2 бара сверх необходимого **увеличивают энергопотребление на 10-15% при той же производительности**."

**Почему критично:**  
Эта ошибка искажает расчёт экономики и может привести к неправильному выбору давления компрессора. Клиент может подумать, что компрессор 13 бар "слабее" компрессора 8 бар той же мощности, хотя на самом деле они выдают почти одинаковый FAD, но 13-барный жрёт больше энергии.

### **ВАЖНО**

**2. Текст ID vintovye__elektricheskie_1__15-to-15**

**Цитата:**
> "Давление подбирают по паспорту самого требовательного потребителя на участке. Пневмоинструмент работает при 6-7 бар, покрасочные пистолеты требуют 3-4 бар, пескоструйные аппараты и плазморезы - от 10 бар. Компрессор берут с запасом: **если в паспорте краскопульта указано 3 бар, машина должна выдавать минимум 8 бар с учётом потерь в магистрали**."

**В чём ошибка:**  
Потери давления в магистрали при правильном проектировании — 0.5-2 бар. Если краскопульт требует 3 бар на входе, компрессор должен выдавать 3 + 2 = **5 бар**, а не 8 бар. Цифра "8 бар" — это типовое давление компрессора для производственной сети с запасом, но она **НЕ следует из расчёта потерь**.

**Как правильно:**  
"Компрессор берут с запасом на потери в магистрали (обычно 1-2 бар) и запасом на пики разбора. Для краскопульта на 3 бар компрессор на **6-8 бар** обеспечит стабильную работу даже при просадках давления."

**Почему важно:**  
Формулировка создаёт впечатление, что потери в магистрали съедают 5 бар (8 − 3 = 5), что абсурдно для нормально спроектированной пневмосети. Это может напугать клиента избыточными требованиями к компрессору или, наоборот, создать ложное ощущение, что "магистраль жрёт давление".

---

### **МЕЛОЧЬ**

**3. Текст ID osushiteli__refrizheratornye__dali**

**Цитата:**
> "Давление влияет на пропускную способность: осушитель, рассчитанный на 7 бар, при работе на 5 бар пропускает меньший массовый расход."

**В чём неточность:**  
Формулировка путаная. Рефрижераторный осушитель работает с **объёмным расходом** (м³/мин) на входе. При снижении давления с 7 до 5 бар массовый расход действительно падает (меньше плотность), но осушитель пропускает тот же **объёмный** расход. Главное — количество влаги в воздухе (зависит от массового расхода и влажности), а не объёмный расход.

**Как правильно:**  
"Осушитель подбирают по **фактическому расходу воздуха** компрессора при рабочем давлении. Производительность осушителя указывается при номинальном давлении (обычно 7 бар); при другом давлении требуется пересчёт по графикам производителя."

**Почему мелочь:**  
Утверждение не приводит к неправильному подбору (осушитель всё равно подбирают по паспорту компрессора), но формулировка технически небрежна.

## C. СИСТЕМНЫЕ ПАТТЕРНЫ

### **1. Путаница в зависимости ДАВЛЕНИЕ ↔ ПРОИЗВОДИТЕЛЬНОСТЬ ↔ ЭНЕРГИЯ**

**Где повторяется:** тексты 6 (25 м³/мин) и 9 (FIAC).

**Суть паттерна:**  
ИИ смешивает два разных эффекта:
- Рост давления → рост энергопотребления (ВЕРНО)
- Рост давления → падение производительности (НЕВЕРНО для винтовых)

**Правило для исправления:**  
"Для винтового компрессора производительность FAD (м³/мин) в рабочем диапазоне давлений остаётся примерно постоянной. **Энергопотребление** растёт на 7-10% на каждый бар избыточного давления. Поэтому завышать давление сверх необходимого невыгодно."

**Почему опасно:**  
Эта ошибка противоречит опыту любого инженера-эксплуатационника и дискредитирует весь текст.

### **2. Нечёткое различие между ПОТЕРЯМИ В МАГИСТРАЛИ и ЗАПАСОМ ДАВЛЕНИЯ**

**Где встречается:** текст 10 (15 кВт).

**Суть паттерна:**  
ИИ путает:
- Потери давления в магистрали (∆P = 0.5-2 бар)
- Запас давления для стабильности (дополнительные 2-3 бар)

В результате получается абсурдная цифра "8 бар для краскопульта на 3 бар".

**Правило для исправления:**  
Явно разделять:
1. Требуемое давление потребителя (из паспорта)
2. Потери в магистрали (1-2 бар при правильном проектировании)
3. Запас на пики разбора (1-2 бар)
4. Итоговое давление компрессора = сумма всех трёх

**Пример:**  
"Краскопульт требует 3 бар. Потери в магистрали ~1 бар. Запас на пики 2 бар. Компрессор на **6-8 бар** закроет задачу."

- Частотный преобразователь для переменной нагрузки
- Температурные ограничения рефрижераторных осушителей

Всё это говорит о том, что исходная фактура была грамотной.

Google March 2024 update ввёл жёсткие санкции против **scaled content abuse** — массовой генерации страниц по матрице параметров (бренд × мощность × давление × комплектация = тысячи страниц). Ваш случай — **классический пример**: 760 страниц по одному шаблону, где меняются только переменные.

**Что Google видит:**

- Шаблонные FAQ с предсказуемыми вопросами

**Ранг угрозы:** 🔴 **ВЫСОКИЙ** — при запуске 760 страниц одновременно риск алгоритмической или ручной санкции.

## ОБЩИЙ ВЕРДИКТ ПО ПАЧКЕ

### 1. ОПАСНО/ВРЕДНО ⚠️

#### **КРИТИЧНО - Scaled Content Abuse (высокий риск)**
1. **Жесткий шаблон на 100% текстов** - одинаковая структура H2 (Для каких задач → Что поставляется → Как выбрать → Стоимость → FAQ), одинаковые переходы между блоками
2. **Дословное копирование фраз:**
   - "Поставляем по всей России, отгрузка со складов в Москве, Барнауле, Новосибирске" (9 из 10)
   - "Под схожие/те же задачи поставляются электрические компрессоры Enger..." (8 из 10)
   - "Материал подготовил Игорь Волков, технический директор ООО «Руспром», более 5580 реализованных проектов" (10 из 10)
3. **Необоснованные цифры вариантов:** "13 700 вариантов", "890 позиций", "700 вариантов" - создают впечатление автоматической генерации ассортимента
4. **Даты из будущего:** обновления в июне-июле 2026 года выглядят как автоматическая подстановка

#### **ОПАСНО - Keyword Stuffing**
- Плотность "компрессор/компрессоры" достигает 3-4% в некоторых текстах (текст №4: 47 упоминаний)
- Избыточное повторение в H1: "Электрические винтовые компрессоры производительностью 1500 л/мин" - можно короче

#### **ПОДОЗРИТЕЛЬНО - Неестественные внутренние ссылки**
- Почти все тексты заканчиваются ссылкой на бренд Enger - выглядит как проплаченное SEO
- Ссылки не органичны, добавлены шаблонно: "Под те же задачи поставляются..."

#### **ВРЕДНО - Признаки автоматизации**
- Одинаковый эксперт с одинаковым числом проектов (5580) на разных категориях (компрессоры, сепараторы, фильтры)
- FAQ-блоки со схожими вопросами и структурой ответов

---

### 2. ПОЛЕЗНО ✅

#### **E-E-A-T сигналы присутствуют:**
1. **Experience (Опыт):** Упоминание "5580 реализованных проектов", технические расчеты показывают практический опыт
2. **Expertise (Экспертиза):** Технические детали конкретны (расчеты мощности, производительности, давления), формулы подбора оборудования
3. **Authoritativeness (Авторитетность):** Подпись эксперта с должностью (технический директор), но **требует проверки реальности**
4. **Trust (Доверие):** Конкретные бренды (Cross Air, Enger, BERG), конкретные модели (BS-315DF, EN 5), адреса складов

#### **People-first content:**
- FAQ решают реальные вопросы пользователей ("Какая мощность нужна?", "Что будет, если взять впритык?")
- Технические расчеты помогают в выборе (например, расчет объема ресивера: 10-20% от производительности)
- Практические рекомендации (когда нужен осушитель, когда частотный преобразователь)

#### **Уникальность контента:**
- Несмотря на шаблон, **технические параметры различаются** (10 м³/мин vs 1500 л/мин vs 315 кВт)
- Разные категории товаров (компрессоры, сепараторы, фильтры) - не 760 копипастов одного товара

---

### 3. ЧЕГО НЕ ХВАТАЕТ 📋

#### **Критично отсутствует:**
1. **Schema Markup:**
   - Product schema (название, бренд, цена, availability, SKU)
   - FAQPage schema для FAQ-блоков
   - BreadcrumbList для структуры каталога
   - Author schema для экспертной подписи

2. **Доказательства реальности эксперта:**
   - Фото Игоря Волкова
   - Ссылка на профиль LinkedIn или корпоративную страницу
   - **Разные эксперты для разных категорий** (компрессорщик не должен подписывать текст про фильтры)

3. **Уникальная ценность каждой страницы:**
   - Отсутствуют кейсы с конкретными проектами (упомянуто "5580 проектов", но ни одного примера)
   - Нет фото оборудования, схем подключения, видео
   - Нет отзывов клиентов или примеров внедрения

4. **Структурированные данные для сравнения:**
   - Таблицы сравнения моделей (сейчас только перечисления в тексте)
   - Калькулятор подбора компрессора по параметрам

#### **Желательно добавить:**
1. **Региональные различия:** тексты одинаковы для всех городов (Москва, Барнаул, Новосибирск), а могли бы учитывать локальную специфику
2. **Актуальные цены:** везде "уточняйте цену" - можно показать хотя бы диапазон
3. **Сравнительные таблицы:** для брендовых страниц (OZEN vs Enger vs BERG)
4. **Внутренние ссылки на основе семантики:** сейчас все ведут на Enger - нужно разнообразие

### 4. ВЕРДИКТ НА ЗАПУСК 760 СТРАНИЦ 🎯

**Уровень риска: ВЫСОКИЙ** 🔴

#### **3-5 критичных исправлений перед запуском:**

1. **ПРИОРИТЕТ 1 - Разрушить жесткий шаблон:**
   - Переписать 20-30% текстов с другой структурой (не 4 блока, а 3 или 5)
   - Варьировать порядок H2 (в одних текстах начать с FAQ, в других - с брендов)
   - Убрать дословно повторяющиеся фразы про поставку - переформулировать для каждой категории

2. **ПРИОРИТЕТ 2 - Добавить реальные кейсы:**
   - На 100-150 ключевых страницах добавить **реальные примеры проектов** с конкретикой:
     "Цех металлообработки в Челябинске, 2024: установили компрессор Enger BS-37, снизили энергопотребление на 18%"
   - Добавить фото объектов, схемы подключения

3. **ПРИОРИТЕТ 3 - Внедрить Schema Markup:**
   - Product schema на всех страницах товаров
   - FAQPage schema на всех FAQ
   - Author schema с реальным профилем эксперта
   - BreadcrumbList для навигации

4. **ПРИОРИТЕТ 4 - Диверсифицировать экспертов:**
   - Страницы компрессоров подписывает Игорь Волков
   - Страницы фильтров и запчастей - другой эксперт (например, "Алексей Смирнов, главный инженер отдела сервиса")
   - Страницы сепараторов и осушителей - третий эксперт

5. **ПРИОРИТЕТ 5 - Убрать необоснованные цифры:**
   - Вместо "13 700 вариантов" написать "широкий выбор моделей" или указать реальное число товаров на складе
   - Проверить все цифры на правдоподобность (700 вариантов для одной мощности?)

---

### Что спасает от penalty:

1. **Технические параметры реально различаются** (не 760 копий одной страницы)
2. **Категории разные** (компрессоры, сепараторы, фильтры - не одна ниша)
3. **FAQ решают реальные запросы** пользователей
4. **Есть подпись эксперта** (хоть и шаблонная)

### Что губит:

1. **Жесткий шаблон очевиден даже неспециалисту** - это главная метка scaled content abuse
2. **Дословное копирование фраз** в 80%+ текстов
3. **Отсутствие уникальной ценности** - все тексты можно сжать в один "Как выбрать компрессор" без потери информации
