# Сниппет «1 ответ · Лучший ответ: ✅ Цены ✅ В наличии ✅ Доставка»

Разбор сниппета из выдачи (пример drobesfera.ru) и что нужно сделать,
чтобы получить такой же на prokompressor.ru.

## 1. Из чего собран этот сниппет

| Что видно в выдаче | Чем сделано |
|---|---|
| `Дробесфера / drobesfera.ru › … › Berg - Китай › без ресивера` | обычные `title` + хлебные крошки, `BreadcrumbList` |
| синий заголовок | `<title>` страницы |
| строка «Почему стоит купить … в магазине Дробесфера?» | это **не** meta description, а `Question.name` из разметки |
| `5,0 ★★★★★ (6)` | `aggregateRating` на `Product` |
| `1 ответ · Лучший ответ: ✅ Цены: от 194 035 ₽ ✅ В наличии ✅ Доставка по Москве и РФ` | **`QAPage`**: `answerCount: 1` даёт «1 ответ», `acceptedAnswer` - подпись «Лучший ответ», её `text` выводится как есть, вместе с эмодзи |

Ключевое: это `QAPage`, а не `FAQPage`. `FAQPage` с августа 2023 рисуется
в выдаче только у госсайтов и медицинских ресурсов - у коммерции расширенного
результата не даёт вообще (наш блок FAQ в `publish/schema/*` работает на
пользователя и на релевантность, но звёздочек и галочек в выдаче не добавит).
`QAPage` для обычных сайтов Google по-прежнему показывает - на нём и построен
сниппет конкурента.

Галочки - обычные эмодзи U+2705 внутри `Answer.text`. Никакого специального
поля под «Цены/Наличие/Доставку» в разметке нет: Google печатает текст ответа,
поэтому маркеры ставят первыми, до обрезки строки.

## 2. Требования Google к QAPage

Обязательно:
- `QAPage.mainEntity` -> один `Question`;
- у `Question`: `name`, `answerCount`, и `acceptedAnswer` (либо `suggestedAnswer`);
- у `Answer`: `text`.

Рекомендуется (и заметно повышает шанс показа): `author`, `dateCreated`,
`upvoteCount`, `url` с якорем на ответ на этой же странице.

Жёсткое правило: **весь размеченный текст должен быть виден пользователю
на самой странице**. Разметка без видимого блока - скрытый контент и повод
снять расширенные результаты. Поэтому оба скрипта ниже отдают видимый блок
и JSON-LD вместе, одним куском.

## 3. Риски - прочитайте до внедрения

1. **QAPage задуман для страниц, где ответы пишут пользователи** (форумы,
   Q&A-разделы). Карточка товара с одним редакционным вопросом формально
   в это определение не попадает. В рунете так делают массово (пример -
   тот же скриншот), но это серая зона: при ручной проверке возможны санкции
   «Spammy structured markup», и снимают их сразу по всему домену - вместе
   с крошками и товарными сниппетами. Снизить риск можно, сделав блок
   настоящим: форма «задать вопрос» с публикацией ответа менеджера на той же
   странице переводит `QAPage` из натяжки в честное использование.
2. **Рейтинг без отзывов - отдельное нарушение**, и куда более наказуемое.
   `aggregateRating` ставится только на реальные отзывы, видимые на этой же
   странице. В обоих скриптах рейтинг по умолчанию выключен и включается лишь
   при подключении настоящего источника - выдуманные `5,0 (6)` не ставим.
3. **Отзывы о себе (self-serving) на `Organization`/`LocalBusiness` звёзд
   не дают** - Google их не показывает с 2019 года. Сейчас на
   `/company/reviews/` разметка именно такая: `Review` -> `itemReviewed:
   Organization`, 20 отзывов с оценкой 5. Звёзд в выдаче с неё не будет.
   Звёзды даёт `aggregateRating` на **`Product`** в карточке товара, поэтому
   нужны отзывы по конкретным товарам (или интеграция с площадкой отзывов).
4. **Статическая цена в тексте устаревает.** В корпусе 759 страниц цен нет
   намеренно. Строка «от 194 035 ₽», вшитая в описание, через месяц разойдётся
   с ценой на странице: это и плохой UX, и повод снять сниппет. Живая цена -
   только из шаблона.
5. **Яндекс такой сниппет не рисует.** Разметка ему не вредит, но эффект
   ожидается в Google.

## 4. Как внедрять на prokompressor.ru

### Карточка товара (там, где возможны и звёзды, и галочки)
`bitrix-qa-snippet.php` -> в шаблон компонента `bitrix:catalog.element`:

```php
include __DIR__ . '/qa-snippet.php';   // в конце template.php своей копии шаблона
```

Цена, наличие и бренд берутся живыми из `$arResult`; отдаются `QAPage` + `Product`
с `offers`. Рейтинг включается двумя строками (`$ratingValue`, `$reviewCount`),
когда появится реальный источник отзывов по товару.

### Страницы разделов (наши 759 SEO-страниц) - предпочтительный путь
`bitrix-qa-snippet-section.php` -> в шаблон `bitrix:catalog.section`:

```php
include __DIR__ . '/qa-snippet-section.php';
```

Цена «от» и число позиций считаются по живому списку раздела, вопрос строится
из H1 - один файл обслуживает все 759 страниц, и цена никогда не расходится
с каталогом.

### Тот же блок статикой, через наш пайплайн (если правки шаблона недоступны)

```bash
python3 build_qa_schema.py --one <slug>          # посмотреть, что получится
python3 build_qa_schema.py                       # все 759 -> publish/qa/*.html
python3 build_qa_schema.py --inject              # дописать в publish/schema/*.html
python3 make_csv.py                              # CSV для импорта в Битрикс
```

По умолчанию цена в статический блок **не** ставится (пункт 4 выше);
`--price static` включает её осознанно - тогда блоки надо перегенерировать
после каждого обновления выгрузки. `--inject` идемпотентен (старый блок
между маркерами заменяется), но выполнять его нужно после каждого прогона
`build_schema.py`.

В статическом блоке маркер звучит как «В продаже: N позиций», а не
«В наличии»: `count` в payload - это позиции каталога с учётом исполнений,
а не складской остаток. Живое «В наличии» умеет только шаблон - он читает
`CATALOG_AVAILABLE`. Ещё одна причина предпочесть путь через шаблон.

Звёзды подключаются файлом `reviews-index.json` рядом со скриптами:

```json
{"vintovye__elektricheskie_1__enger": {"ratingValue": 4.9, "reviewCount": 12}}
```

Пока файла нет, `aggregateRating` не пишется вообще - и это правильное
поведение по умолчанию.

Тексты маркеров и шаблон вопроса - константы в начале `build_qa_schema.py`
(`DELIVERY_MARKER`, `EXTRA_MARKERS`, `question_text`) и такие же в PHP-файлах.
Каждый маркер - публичное утверждение магазина, добавлять их можно только
если это верно для всех страниц, куда попадёт блок.

## 5. Проверка

1. `https://search.google.com/test/rich-results` - вставить URL или код блока:
   должен определиться тип «Вопросы и ответы» без ошибок.
2. Валидатор schema.org: `https://validator.schema.org/`.
3. Search Console -> Улучшения -> «Вопросы и ответы»: там видно, сколько
   страниц Google принял, и ошибки.
4. Сроки: разметка попадает в выдачу после переобхода, обычно 1-4 недели.
   Ускорить - переотправкой sitemap и запросом индексации по нескольким URL.
5. Если сниппет не появился, а ошибок нет - Google просто решил не показывать
   расширенный результат: это его право, гарантий по разметке не существует.
