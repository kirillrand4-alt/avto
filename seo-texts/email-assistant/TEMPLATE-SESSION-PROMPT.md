## 2. Правила текста письма (жёсткие — нарушение = брак)

1. **БЕЗ длинных тире «—»** нигде (даже в списках/FAQ) — главный маркер ИИ-текста. Только дефис «-» или перестройка фразы. Диапазоны — через дефис без пробелов («7-35 бар») или «от… до…».
2. **Байлайн «ООО «Руспром»» + ИНН** — идентификация рекламодателя обязательна в каждом письме (ФЗ-38 ст.18). Движок добавляет байлайн + футер отписки АВТОМАТИЧЕСКИ при отправке — в черновике их писать НЕ надо (и НЕ считать отсутствие нарушением).
3. **Числа — только реальные** (из payload/факта). Нет числа — не пиши. Точных цен в тексте нет (пересчитываются на сайте по курсу).
4. **Без канцелярита и витрин**: запрещены «таким образом/в заключение/данный/посредством/представлены/в ассортименте». Живой деловой тон инженера-практика.
5. **Объём в 1 экран**, ритм рваный (часть абзацев короткие, часть развёрнутые — анти-детект), один конкретный следующий шаг, подпись менеджера (имя подставляется движком — ФИО в шаблон не вписывай).
6. **Без `<ul>`** (CSS сайта рисует тире-маркеры) — для писем актуально, если шлёшь HTML.
7. Инженерная точность (для КЦ): давление vs производительность — зависимость ОБРАТНАЯ; цепочка подготовки воздуха каноническая; адсорбция — физический процесс. Полные правила — в стайлгайдах.

Стайлгайды и промпты-эталоны: `gen/STYLE-GUIDE.md`, `gen/STYLE-GUIDE-ELEKTRO.md`, `gen/STYLE-GUIDE-PODGOTOVKA.md`, и блоки `SELF_CHECK`/`REFINEMENT`/`DE_TEMPLATE` в `gen_provider.py`.

## 5. Инфраструктура и доступы

**Дроп** (файлообменник на сервере владельца): `bash seo-texts/server/drop_client.sh list | up <file> | down <name> [dst] | del <name>`. Токен и URL — в env (`DROP_TOKEN`, `DROP_URL=https://parsercompressor.online/drop`). Там: выгрузка Битрикса, каталоги брендов, дампы обогащения, финальные CSV, `runner-secrets.env`. На самом сервере локально читается из `C:\seostat\drop\drop-storage\`.

**Провайдер**: `PROVIDER_API_KEY` (+`PROVIDER_BASE_URL`, по умолч. `https://router.cheap`), модель `claude-fable-5`. Клиент `seo-texts/gen_provider.py`. Заголовок `User-Agent: curl/8.5.0` в клиенте — обход WAF шлюза (вход в оплаченный сервис), не сокрытие.

**Чтение писем из тестовых ящиков s1/s2@mail.parsercompressor.online** (для калибровки на реальных входящих):
- Конфиг ящиков (imap_host/port/login/password_env) — в `sender.yaml` на сервере и в таблице `mailbox_overrides` БД панели; пароли — в env службы по `password_env`.
- Из ЭТОЙ сессии (песочница) прямого IMAP-доступа к ящикам НЕТ, пока не даны креды. Два пути: (а) попроси владельца положить IMAP-логин/пароль s1/s2 в env этой сессии, затем читай через `imaplib` (ниже); (б) читай через серверный раннер (джоб `read_stream`/imap на C:\sender, у него креды в env) и забирай результат с дропа.
- Скелет IMAP-чтения (когда есть креды в env `S1_IMAP_LOGIN`/`S1_IMAP_PASS` и т.п.):
  ```python
  import imaplib, email, os
  M = imaplib.IMAP4_SSL('imap.mail.parsercompressor.online', 993)
  M.login(os.environ['S1_IMAP_LOGIN'], os.environ['S1_IMAP_PASS'])
  M.select('INBOX'); typ, ids = M.search(None, 'ALL')
  for i in ids[0].split()[-20:]:
      _, data = M.fetch(i, '(RFC822)')
      msg = email.message_from_bytes(data[0][1])
      print(msg['From'], msg['Subject'])
  ```
  Хост IMAP уточни у владельца (mail.parsercompressor.online — самостоятельный почтовик; возможен `mail.`/`imap.` префикс).
