# План проверок партии писем по канону (по опыту «КЦ газ 11.11»)

Записано 11.11.2026 по просьбе владельца. Порядок — как надо делать в следующий раз сразу, а не догонять.
Скрипты — `seo-texts/server/ops/`, журналы — `C:\sender\_ops\*.jsonl` (fsync, всё резюмируемо),
тяжёлое — через провайдера, фоном (`--zapusk`). Ничего не снимаем без владельца, кроме явных дефектов сборки.

## 0. Канон и образцы — до всего

- Канон пишет владелец (заход «конец года / бюджеты», без болей и цен, «не рекламно»). Модель пишет **одну** фразу
  про производство адресата. Канон — в общем модуле (`gaz_kanon.py`), образцы и боевой генератор берут его оттуда.
- Образцы: 2–3 на отрасль (`gaz_obrazcy.py`), в каждом — продукция с сайта и признаки газа, чтобы владелец видел,
  на чём держится фраза. Правки владельца — сразу в канон, образцы пересобирать, а не перегенерировать.
- Механика текста кодом: без цифр и чисел словами, без длинного тире, без «мы», без вакуума с азотом, без резки/
  заправки для O2 (93 %), 4 абзаца, без повторов одного слова в двух блоках («модульные», «под ключ», «как раз»),
  имя отправителя ≠ имя получателя.

## 1. Отбор компаний (до модели — кодом)

- Резерв ЦА не берём; группировка по «Отрасль основная».
- Стоп компании: ответ/жалоба/отписка (любое направление), реестр «не наш», стоп-лист, активная сделка **КЦ**.
- Конкуренты кодом по продукции и «Газы (паспорт)» (адсорбция, генераторы, компрессорные станции, осушители) +
  отдельный флаг модели. Торговля техгазами — НЕ конкурент.
- Обязательные признаки для шумных отраслей (фрукты, сухое молоко, озонирование, аэрозоли), золото без ЗИФ/
  цианирования, вендинг/кофемашины — отсев кодом.

## 2. Суд модели (ok + фраза)

- Пачками по отрасли, параллельно (6 потоков), журнал `gaz-kc-sud.jsonl`.
- **Двойная страховка:** суд → перепроверка отсеянных (с рассуждением) → строгая проверка возвращённых →
  арбитр по разногласиям. Ничего из этого не режет само: спорное — владельцу списком по категориям.
- Урок: «если сомневаешься — да» делает модель слишком мягкой (выдумывает процесс); «нужно слово на сайте» —
  слишком строгой (режет водоканалы, электронику, сады). Правило арбитра: выгонять только за «нет своего
  производства / торговля / другая сфера», отсутствие слова на сайте — не причина.

## 3. Адреса и проба

- Лесенка: ЛПР тех-роль → руководитель → закупки → прочие с именем → общий → продажи (роли из свежей разметки ЦА).
- Не пишем, если КЦ писал **на этот адрес** < 15 дней (Meyer и другие адреса — не мешают).
- Адрес за другим ИНН в панели: берём по ЦА, кроме домена = сайт другой компании и стопа той компании;
  явные чужие — на дроп сессии ЦА.
- Проба на основном сервере (VPS не работает), сверху вниз до первого не мёртвого; мёртв = «нет ящика»/«нет MX».
  Перед стартом — проверить DNS (MX резолвится) короткой пробой на живой и несуществующий адрес.
- Одно письмо на адрес: проверка дубля адреса в кампании ДО создания сообщения; после прогона —
  `dubli_kartochek.py <кампания> --snyat --prichina=…`.

## 4. Карточки

- В «Подтвердить отправку», не в автоотправку (только по команде владельца).
- Полная панель как в партии 935: `build_panel` (компания, контакты, комплаенс с превью подписи, история,
  стоп-флаги) + данные ЦА (продукция, оборудование, газ, почему подходит, фраза).
  «Контакт с компанией < 30 дней» на другой адрес — подсказка, не удержание (правило владельца).

## 5. Линзы по готовым письмам (после карточек, ничего не снимают сами)

1. **Инженерная** — по фразе: технически верно и про ИХ продукт; даёт исправленную фразу или «газ не нужен»
   (`gaz_inzh_linza.py`). Годные исправления — заменить (с проверкой фразы), остальное — снять.
2. **Адресат** — по всему письму + данным компании: своё ли производство, тот ли продукт, не крошечный ли
   масштаб (`gaz_adresat_linza.py`). Выводы «только по названию (ТД/Трейд/Сервис)» — не снимать.
3. **Продажник / филолог / доверие** — на выборке 60 писем (`gaz_linzy_pisma.py`): ищем повторяющиеся
   огрехи канона. Не брать советы, которые владелец уже отклонил (цифры, цены, «боли», отраслевые референсы
   без данных, убрать «конец года» и просьбу переслать).

**Обязательно:** газ письма определять по хвосту абзаца регуляркой «кислород» (связка «проекты по кислороду»
не содержит «кислородн») — 11.11 из-за этого линзам передали неверный газ. Перед любой линзой — проверка
разнобоя газа (`gaz_raznoboy_gaza.py`: фраза про один газ, станция про другой → 0).

## 6. Финальный контроль перед отдачей владельцу

- `gaz_kartochki_proverka.py` — статусы, ящики, дубли ИНН/адреса, механика текста, 3 примера.
- `prichiny_kampanii_22.py` — сколько снято и почему.
- 10 случайных писем глазами (утренний отчёт).
- Учёт расхода: в следующих скриптах писать usage провайдера в журнал, чтобы цена письма считалась сама.
