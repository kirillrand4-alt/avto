# Газовые письма КЦ (азот/кислород): какие поля файлов использует генерация

Генератор: `seo-texts/server/ops/gaz_obrazcy.py` (сервер: `C:\sender\server\ops\gaz_obrazcy.py`).
Источники на дропе: `CA-ENGER-ZALIVKA.csv` (ЛПР с ФИО) и `CA-ENGER-ZALIVKA-kompanii.csv`
(компании без ЛПР, одна почта). Разделитель `;`, кодировка UTF-8 (с BOM допустимо).

## CA-ENGER-ZALIVKA.csv — письма по имени

| Поле | Для чего |
|---|---|
| `ФИО` | Обращение «Имя Отчество, добрый день!». Строка пропускается, если имя не распознаётся (инициалы, нет имени из словаря) или в ячейке несколько человек через `;`. |
| `Должность` | 1) Выбор ОДНОГО человека на компанию: техслужба/производство (гл. инженер, технолог, энергетик, механик, нач. цеха, тех. директор) → руководитель (не коммерция/финансы) → закупки/снабжение → прочие. 2) Тех-ролям не добавляется «перешлите главному инженеру/технологу», остальным добавляется. |
| `ИНН` | Группировка людей одной компании, чтобы выбрать одного лучшего. |
| `Почта` | Адрес получателя. Годен: формат `x@домен.(ru\|рф\|su\|com\|org\|net\|pro\|biz\|info)`; отсев: .ua/.by/.kz/.uz/.am/.ge/.az/.md, заглушки `@site.ru`, `@example.*`, `@test.*` (обычные @mail.ru, @yandex.ru и т.п. — годны). |

## Оба файла (в ZALIVKA-kompanii.csv ФИО/Должности нет → письмо «Добрый день!»)

| Поле | Для чего |
|---|---|
| `Отрасль` | Группировка: на отрасль 2 письма по имени + 1 без имени. Название отрасли уходит модели. Комбо-отрасли (с `;`) пропускаются. |
| `Газ` | Содержит «Азот» → письмо про азот, иначе про кислород. Определяет абзац про станцию, вопрос в конце и тему. Берётся ОДИН раз на отрасль (по первой строке отрасли) — если в отрасли смешаны газы, это нужно учесть. |
| `Продукция` | Главное поле. Первые 300 знаков → модели. По нему модель решает `ok`: реально ли это производство из этой отрасли и нужен ли ему газ (торговля, логистика, услуги, станки, книги, стройматериалы → отсев). Отсюда же фраза «где у вас нужен газ». В ZALIVKA-kompanii строки с пустой Продукцией пропускаются. |
| `Техпроцесс (где нужен газ)` | Первые 400 знаков → модели как контекст отрасли для той же фразы. Цифры/расходы/модели Enger в письмо НЕ попадают (фраза с любой цифрой бракуется). |
| `Боли` | Первые 500 знаков → модели, чтобы выбрать ОДНУ проблему отрасли (перебои с баллонами, цена покупного газа, брак). В письме — пересказ БЕЗ цифр и цен (фраза с цифрой бракуется). |
| `Компания` | Только в заголовке образца для проверки. В текст письма не вставляется. |

## Не используются

`Телефон`, `Тип почты`, `Роль`, `ЛПР`, `Источник`, `Страница`, `Статус отрасли`, `Оборудование`,
`Признаки газа на сайте`, `Свежая новость`, `Сделки Битрикса`.

Кандидаты на подключение:
- `Признаки газа на сайте` — доп. проверка соответствия;
- `Тип почты` — при прочих равных брать личную;
- `Сделки Битрикса` — исключать компании с активной сделкой.

## Что модель делает, а что — канон в коде

Модель (одна пачка на отрасль) возвращает на компанию: `ok` (подходит ли), `pochemu`, `f` — где в ИХ
производстве нужен газ (12–25 слов), `b` — одна боль отрасли (10–20 слов). Брак фразы: цифры,
«мы/наш», длинное тире, начало «На производстве», слово «вакуум» (азот с вакуумной упаковкой не связан).

Канон в коде (из файла не берётся): приветствие + «Меня зовут <менеджер>, я из Компрессор Центра» +
повод «конец года / бюджеты на следующий год»; абзац «Проектируем и поставляем / Поставляем под ключ
азотные|кислородные станции, в том числе модульные… без баллонов и поставок жидкого газа» + строка про
компрессор и подготовку воздуха + заказчики (3 из РУСАЛ/РЖД/«Северсталь»/«Алроса»); вопрос про планы
на следующий год (+ просьба переслать для не-тех ролей); тема. Ящик-отправитель КЦ выбирается так,
чтобы имя менеджера не совпадало с именем получателя.
