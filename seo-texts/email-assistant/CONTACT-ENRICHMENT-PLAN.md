# План обогащения контактов боевой базы (161 761 компания)

Собрано из 6 линз-моделей. Цель: у высоко-приоритетных компаний получить
доставляемый email (в идеале ролевой — закупки/гл.инженер), не сжигая домен.

## Что в базе (замер)
email 66% (107 681), телефон 72%, сайт 21% (35 119), директор 46%. Дыра: 34%
(~54 тыс.) без email. Сайт только у 21% → краул сайта напрямую закроет ~11k из дыры;
остальным сайт надо СНАЧАЛА найти (2ГИС/Яндекс/поиск).

## Инструменты (готовы, раннер на сервере)
`verify_company` (реквизиты), `enrich_contacts` (сайт→/contacts→ролевые email→MX),
`dadata` (директор+адрес+статус), `browser_probe` (SPA+капча), list-org карточки.

---

## Фаза 0 — валидация существующих 107k email (ПЕРВОЙ, защищает домен)
**Кто:** движок (`validation.py` уже есть) + раннер для MX.
1. Синтаксис → MX-запись → SMTP-ping (existence) без отправки.
2. Детект **catch-all** (accept-all домены дают ложный «valid» и жгут репутацию
   сильнее явных bounce — приоритетный фильтр), disposable, role-мусор
   (no-reply/postmaster удалить; info/sales/zakupki оставить).
3. Итог: колонка `email_status` (valid/risky/dead/catch-all) в recipients; в
   рассылку — только valid. Метрика: сколько из 107k доставляемых.

## Фаза 1 — пилот enrich_contacts на топ-PxR С сайтом (за ночь)
**Кто:** раннер (я драйвлю), провайдер извлекает.
1. Выборка: топ-200 по PxR, у кого нет email, но ЕСТЬ сайт (быстрый путь без капч).
2. `enrich_contacts`: сайт→/contacts→провайдер вытаскивает ВСЕ email с ролями
   (закупки/гл.инженер/директор+ФИО)→MX. Сохраняем ВСЕ адреса (приоритет строим потом).
3. Метрика успеха: доля с валидным РОЛЕВЫМ email, цель ≥40%.

## Фаза 2 — DaData по дыре (статус + директор)
**Кто:** раннер (`dadata`), бесплатно 10k/день.
1. Прогон 54k без email → статус (ACTIVE) + ФИО директора + адрес.
2. **Отсечь банкротов/ликвидированных** сразу (не тратим на них силы).
3. Директор → персонализация письма (НЕ массовое конструирование личных адресов —
   ФЗ-152). Email DaData не даёт — это не источник адресов.

## Фаза 3 — топ-PxR БЕЗ сайта → найти сайт (2ГИС/Яндекс/поиск) → краул
**Кто:** раннер + браузер (капча по типу).
1. Для высоко-PxR без сайта: 2ГИС/Яндекс-карты (там у организации есть сайт+телефон)
   или поиск по ИНН/имени → нашли сайт → `enrich_contacts`.
2. 2ГИС и Яндекс-карты — через БРАУЗЕР (API-заявка 2ГИС долгая, не ждём;
   рендерим карточку организации, берём сайт+телефон+иногда email). Темп низкий (капча/лимиты) → только топ-PxR, не масс.

---

## Приоритизация (консенсус линз)
- Обогащаем **только топ-15–30% по PxR**, не все 54k (ROI на хвосте нулевой).
- Порядок: **сначала валидация 107k** (Фаза 0) → топ-PxR с сайтом (Фаза 1) →
  DaData-дедуп (Фаза 2) → топ-PxR без сайта (Фаза 3).
- Крупным целимся в закупки; мелким хватит info@ + сильная тема.

## Юридически (ФЗ-152/38)
Массово — только **корпоративные ролевые** (info@/zakupki@/sales@). Личный email
директора — риск жалоб; ФИО из DaData брать для персонализации, не для массового
подбора личных адресов. Атрибуцию+отписку движок ставит.

## Главные риски (из линз)
- **catch-all** домены → ложный valid → отдельный детект в Фазе 0.
- Устаревшие адреса уволенных с сайтов → SMTP-ping + тестовая волна на 100 адресов
  перед масштабом.
- 79% без сайта → enrich напрямую даёт ~11k; остальное упирается в Фазу 3 (медленно).

## Что нужно от владельца
- Порог: **топ-30% PxR** (решение владельца).
- 2ГИС/Яндекс — через браузер (без API-заявки, решение владельца).
- Отмашка запускать Фазу 0 + Фазу 1 (пилот) параллельно.
