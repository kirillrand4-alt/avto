# План обучения ассистента для ответов на письма (B2B, Руспром)

Цель: система, которая пишет ответы на (а) ответы клиентов на нашу исходящую
рассылку, (б) входящие запросы с сайта. «Обучение» здесь - не дообучение весов
модели, а сборка корпуса + базы знаний + плейбука + few-shot примеров + петли
оценки. Тяжёлая обработка - через провайдерский API.

## Этап 0. Какие данные нужны (чек-лист выгрузки)

1. **Цепочки писем целиком, не только первые письма.**
   - 800 исходящих: наше письмо -> их ответ -> ответ менеджера -> ... -> финал.
   - 1600 входящих с сайта: письмо клиента -> ответ менеджера -> цепочка.
   - Формат: EML/MBOX или CSV со столбцами: thread_id, направление, дата,
     from, to, тема, тело, вложения (имена), менеджер.
2. **Исход каждой цепочки из CRM** - самое ценное: сделка/отказ/тишина,
   сумма, цикл в днях. Без исходов учимся «звучать как менеджер», с
   исходами - «отвечать как ЛУЧШИЙ менеджер».
3. **Кто из менеджеров сильнейший** (по конверсии ответа в следующий шаг) -
   его ответы станут золотым стандартом тона.
4. **КП-вложения из переписок** - что реально отправляли в ответ (у нас уже
   есть 3800+ КП в базе, но связка «на какой запрос какое КП» - из переписок).
5. **Коммерческие правила**: матрица скидок (что можно обещать без
   согласования), сроки поставки по брендам, условия оплаты/доставки,
   гарантии (частично уже в kb/kp-base-all.json).
6. **Правила эскалации**: какие письма ассистент НЕ отвечает сам
   (рекламации, торг ниже X%, госзакупки, >N млн ₽).

## Этап 1. Разметка корпуса (API, ~2400 писем, копейки)

- Классификация писем по типам: запрос цены/КП, подбор по задаче,
  наличие/сроки, торг, рекламация, «пришлите каталог», нецелевое.
- Из пар «письмо -> ответ лучшего менеджера»: структура ответа, длина, тон,
  что включают сразу (цена? звонок? уточняющие вопросы?), типовые фразы.
- Кросс с исходами: какие паттерны ответов чаще двигают сделку
  (напр. «цена сразу + 1 уточняющий вопрос» vs «давайте созвонимся»).
- Выход: types.json + golden-pairs.json (50-80 лучших пар по типам)
  + стайлгайд ответов STYLE-GUIDE-EMAIL.md (как наши SEO-стайлгайды).

## Этап 2. База знаний для ответов (RAG) - большая часть УЖЕ есть

- kb/kp-base-all.json - 99 брендов, 1588 моделей с характеристиками.
- Прайсы поставщиков + битрикс (цены сайта) - актуальные цены.
- projects-index - 1017 проектов («ставили на заводе вашей отрасли»).
- gap-models - чего нет на сайте, но можем поставить.
- Добавить: наличие склада, сроки поставки, шаблоны КП.

## Этап 3. Плейбук и промпты

На каждый тип письма - скелет ответа + жёсткие правила:
- цены ТОЛЬКО из прайса/битрикса (никогда не выдумывать);
- модели только существующие (сверка с базой);
- тон лучшего менеджера (из золотых пар), подпись, SLA;
- всегда следующий шаг (вопрос/КП/звонок), максимум 1 экран текста;
- стоп-условия -> эскалация человеку.

## Этап 4. Few-shot

В промпт каждого типа - 5-10 золотых пар этого типа. Периметр: 30-50 пар
суммарно, отобранных по исходам, а не по красоте.

## Этап 5. Оценка ДО боя

- Холдаут 150-200 реальных писем (не участвовали в примерах).
- Генерим ответы, менеджер вслепую сравнивает с реальными ответами.
- Скептик-ревьюеры через API (как для текстов): точность цен/моделей,
  тон, галлюцинации. Порог запуска: >=80% черновиков «отправил бы без правок
  или с косметикой».

## Этап 6. Пилот - режим «черновик», НЕ автоотправка

- 2-4 недели ассистент пишет черновики, менеджер правит и отправляет.
- Каждая правка сохраняется -> раз в неделю разбор правок -> итерация
  промптов/плейбука.
- KPI: % черновиков без правок, время первого ответа (цель < 15 мин),
  конверсия ответа в следующий шаг vs ручная база.

## Этап 7. Эксплуатация

- Автообновление цен с дропа; ежемесячный дозабор новых пар в примеры.
- Автоотправку включать только на «безопасные» типы (каталог, наличие)
  после стабильных 4+ недель пилота; цены/торг - всегда через человека.

## Ограничения и риски

- **Персданные**: в письмах ФИО/телефоны/email - перед отправкой корпуса
  в API замаскировать (regex-скраббер: телефоны, email, ФИО из подписей).
- **Обещания**: юридически значимые условия (цена, срок, гарантия) в
  автоответах - риск; поэтому режим copilot до устойчивого качества.
- **Свежесть цен**: ответ с ценой из устаревшего прайса хуже ответа без
  цены - валидация «прайс не старше X дней» обязательна.

## Что нужно от тебя, чтобы начать

1. Выгрузка 800 + 1600 цепочек (EML/MBOX/CSV) на дроп.
2. Исходы из CRM хотя бы в виде «thread_id -> сделка/нет/сумма».
3. Имя лучшего менеджера (или топ-2) и матрица «что можно обещать».
4. 30 минут менеджера на слепую оценку холдаута на этапе 5.

## Этап 5б (идея владельца). Спарринг с менеджерами ДО боевого пилота

Неделя спарринга: ассистент в роли отвечающего (в диалоге на сайте или в
переписке), менеджеры-продажники - в роли дотошных покупателей. Зачем это
лучше синтетики: менеджеры знают реальные боли/каверзы клиентов (торг после
цены, «а у конкурента дешевле», просьба снятой модели, НДС/лизинг), и каждый
раунд сразу оценён экспертом. Механика:
1. Канал: тестовый диалог на сайте владельца ИЛИ просто почтовый тред/чат.
2. Каждый менеджер ведёт 5-10 диалогов по своим реальным сценариям.
3. После каждого диалога менеджер ставит вердикт: «отправил бы / нет / что не так»
   (одна строка). Лог пишется в jsonl.
4. Разбор в конце недели: правки плейбука, пополнение золотых пар лучшими
   ответами, стоп-лист провалов.
5. Выход на Этап 6 (черновики реальным клиентам) - после >=80% «отправил бы»
   именно в спарринге.
Бонус: спарринг генерит размеченный корпус каверз, которого нет в реальной
базе (клиенты редко пишут все edge-case подряд, менеджеры - напишут).
