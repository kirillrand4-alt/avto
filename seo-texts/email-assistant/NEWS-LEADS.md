# Триггерные лиды из новостей (intent-based) — спека пилота

Идея владельца: ловить компании в момент КАПЕКС-события (строят/модернизируют цех,
запускают линию, расширяются, получили займ ФРП, выиграли контракт) — им скоро нужно
компрессорное оборудование → тёплый лид, не холод. Особый упор: **малые города и
сёла**, чьи новости живут в гиперлокале (пример: село Кулунда постит в
Одноклассниках), а не в федеральных СМИ.

## Обязательные требования владельца
- **Ссылка на источник** сохраняется у КАЖДОГО события — человек должен открыть и
  верифицировать новость. Поле `source_url` обязательно.
- **Разные капчи**: у площадок капча разного типа (reCAPTCHA v2/v3, Yandex
  SmartCaptcha, hCaptcha, Cloudflare Turnstile). Браузер детектит тип → берёт
  соответствующую задачу CapMonster. Сейчас проверен reCAPTCHA v2; остальные
  добавляем по мере встречи (тест на реальной площадке, тип задачи CapMonster
  сверять с их докой, не по памяти).

## Карта источников (по ценности, из 6 линз)

### Тир 1 — гиперлокал (высокий сигнал, нулевая конкуренция, покрытие сёл)
| Источник | Как достать | Малые города |
|---|---|---|
| Районные газеты онлайн (`*-vestnik.ru`, `*-gazeta.ru`) | RSS если есть, иначе браузер (простой HTML, редко капча) | высокое |
| Сайты райадминистраций/сельсоветов (разделы Экономика/Инвестиции/Новости) | браузер (статичные CMS), RSS ~30% | высокое |
| Районные паблики ВК («Подслушано [город]», «[Район] онлайн») | VK API (wall.search по группам, нужен токен) / браузер | высокое |
| Одноклассники (группы сёл/райцентров) | браузер+капча + живой аккаунт (прогрев) | очень высокое |
| Региональные/районные Telegram-каналы | Telegram API (сессия) или t.me/[канал] браузером | среднее-высокое |

### Тир 2 — официальные реестры (подтверждённый капекс)
- **ФРП** (frprf.ru) — реестр займов: компания+сумма+цель, займ = гарантированный капекс.
- **Минпромторг СПИК** (gisp.gov.ru), реестры **ОЭЗ/ТОР/индустриальных парков** (резиденты).
- **Инвест-порталы регионов** (~85) и **корпорации развития** — проекты/резиденты.
- Нацпроекты (карта объектов).

### Тир 3 — тендеры/закупки (сигнал перед покупкой)
- **zakupki.gov.ru**: ОКПД2 28.13 (компрессоры/насосы), стройка 41-43 + слова
  «производственный корпус/цех/компрессорная»; заказчик → ОКВЭД-фильтр производства.
  МУП/ГУП малых городов (водоканалы/котельные) — капремонт/расширение.
- **B2B-Center, Росэлторг** — категории «Компрессоры», «Строительство».

### Тир 4 — агрегаторы/СМИ (широкий поток, слабое покрытие сёл)
- Яндекс.Новости (RSS по регионам), Google News (RSS `news.google.com/rss/search?q=`),
  деловые порталы регионов (DK/E1/NGS/74), **отраслевые СМИ** (Агроинвестор, Milknews,
  Мясной эксперт — конкретика вводов мощностей).

### Тир 5 — цифровые следы активности
- **hh.ru API** — всплеск вакансий «оператор ЧПУ/наладчик» у одного работодателя = расширение.
- Страницы компаний ВК/ТГ (анонсы), 2ГИС/Яндекс-карты (новые точки — diff снапшотов).

## Конвейер `news_scan` (задача раннера, ежедневно)
1. **Каталог площадок** (разовая разведка, потом растёт): по региону → список районов
   (ФИАС) → поиск сайта администрации + газеты + пабликов ВК/ОК/ТГ. Хранить в
   `news-sources.json` (можно наращивать; приоритет — регионы плотных производств:
   Поволжье/Урал/Сибирь/Алтай/Кубань + регионы наших кейсов).
2. **Сбор**: обход площадок медленным темпом; RSS где есть, иначе браузер (+капча по типу).
3. **Извлечение** (провайдер): из текста → `{company, inn?, event_type, region, что,
   срок, сумма, source_url, source_name, published}`. `source_url` ОБЯЗАТЕЛЕН.
4. **Матч к ICP**: имя→ИНН через DaData → ОКВЭД-фильтр (производство 10-33 и т.п., кому
   нужны компрессоры). Тёзки — верификация по региону; спорные не берём.
5. **Скоринг горячести**: тип события (новый завод > модернизация > найм) × срок ×
   сумма × отраслевой фит × регион.
6. **Контакт**: `enrich_contacts` (сайт→закупки/инженер email).
7. **Роутинг**: горячий лид → Bitrix (статус выше холодного) со ссылкой на новость;
   дедуп по ИНН. Отдельный шаблон письма со ссылкой на событие.

## Подводные камни (из линз)
- Единого каталога районных площадок НЕТ → каталог собираем полуавтоматически и
  наращиваем; начинать с регионов присутствия/плотных производств.
- Шум: 80% гиперлокал-постов не про производство → жёсткий keyword-гейт («цех/линия/
  оборудование/млн руб/инвестиции») + провайдер-классификатор.
- Имя в новости ≠ юрлицо («завод Ромашка» → ООО Агрохолдинг) → провайдер + DaData +
  гео-верификация.
- Лаг событие→закупка (6-18 мес) → лид не «купит завтра», это воронка «греть».
- ОК/ВК: авторизация + риск бана → живой аккаунт, ротация, медленный темп (раннер это даёт).

## Пилот
`news_scan` на **2 отрасли × 3-4 региона** (металлообработка + пищёвка; Алтай/Новосиб/
Москва — где много кейсов). Собрать события за 30-60 дней → извлечь (со ссылками) →
матч ICP → скоринг. На выходе список горячих с событием/компанией/ИНН/контактом/**ссылкой**.
Владелец смотрит качество → если ок, ставим на ежедневный автопрогон + роутинг в Bitrix.
