# План подготовки доменов и почты для холодной рассылки «Руспром»

Исполнительный ранбук: **что регистрируем, где, на какой хостинг ящиков, какие DNS,
какой прогрев** — под уже собранный движок инженера (`seo-texts/sender/`). Расширяет
`sender/DOMAINS-SETUP.md` до пошаговой подготовки. Дата: 2026-07-21.

---

## 0. Архитектура в одном абзаце (чтобы не сделать лишнего)

**Свой SMTP-сервер НЕ поднимаем.** Письма уходят через SMTP-релеи **Яндекс 360** и
**VK WorkSpace (Mail.ru для бизнеса)** — их IP, их PTR, их репутация магистрали. Наш
сервер `C:\sender` только авторизуется в ящиках (пароль приложения) и отдаёт письма на
`smtp.yandex.ru:465` / `smtp.mail.ru:465`. Значит:

- **Не нужны:** свой MTA, статический «белый» IP под почту, PTR/reverse-DNS, разогрев IP.
- **Нужны:** домены-двойники (не основной), их DNS (SPF/DKIM/DMARC, выровненные под
  Я360/VK), почтовые ящики на этих провайдерах, **прогрев репутации доменов/ящиков**
  (9-дневная рамп-кривая в движке), сопоставление провайдера получателя пулу отправки.

Почему двойники, а не `prokompressor.ru`: холодная рассылка неизбежно ловит часть жалоб;
репутацию основного домена и родного бренда Enger к этому **не привязываем**. Основной
сайт не трогаем вообще (двойники только 301-редиректят на него, чтобы выглядеть живыми).

## 2. Пошагово: регистрация доменов

Для каждого регистратора (RU-CENTER, Beget, Timeweb, Sprinthost, 2domains):

1. Завести аккаунт на владельца (**одна карта, 3-D Secure — только владелец**).
2. Купить назначенные домены (см. таблицу). Период — **на 1 год** (двойники недолгие).
3. **Приватность WHOIS** — включить, если регистратор даёт (для .ru часто персональные
   данные скрыты по умолчанию — проверить).
4. Автопродление — **выключить** (двойники ротируемые, не нужны навсегда).
5. NS оставляем регистраторские (DNS будем править прямо там) ИЛИ, если удобнее единая
   панель, делегируем на Яндекс 360 DNS / Cloudflare — но проще редактировать у
   регистратора, чтобы не плодить сущности.

Смета доменов: 10 × ~250 ₽/год ≈ **2 500 ₽/год**.

## 3. Хостинг ящиков (постмастер) — подключение доменов

### 3.1. Яндекс 360 для бизнеса (домены 1–6)

1. Создать/использовать организацию в **Яндекс 360 для бизнеса** (admin.yandex.ru).
2. Для каждого из 6 доменов: **«Добавить домен»** → Яндекс даёт **verification-запись**
   (TXT или CNAME/HTML). Вставить её в DNS у регистратора → «Проверить».
3. После верификации Яндекс покажет **MX** (`mx.yandex.net`) и **DKIM** (селектор
   `mail._domainkey`, ключ 2048). Их — в DNS (см. §4).
4. Тариф: подключить нужное число ящиков (см. §5). Оплата помесячно.
5. Включить **Яндекс Postmaster** (postmaster.yandex.ru) на каждый домен — мониторинг
   репутации/спам-рейта (нам критично видеть жалобы на раннем прогреве).

### 3.2. VK WorkSpace / Mail.ru для бизнеса (домены 7–10)

1. Организация в **VK WorkSpace** (biz.mail.ru).
2. Для каждого из 4 доменов: **«Добавить домен»** → verification-запись → в DNS → проверить.
3. VK даёт **MX** (`emx.mail.ru`) и **DKIM** (селектор `mailru._domainkey`, 2048). В DNS.
4. Тариф — по числу ящиков.
5. Включить **Mail.ru Postmaster** (postmaster.mail.ru) на каждый домен.

> Google-контур (Gmail-получатели) в конфиге есть (`google: pool_yandex`), но **включаем
> позже** — сперва отладим Яндекс+Mail.ru, потом решим, нужен ли отдельный Google Workspace
> домен. По умолчанию Gmail-получателям шлём с Яндекс-пула (так в `provider_split.routing`).

## 4. DNS-записи (на каждом домене после верификации)

Значения `<...>` берём из панели соответствующего провайдера.

### Домены на Яндекс 360 (1–6)
```
MX     @                 10 mx.yandex.net.
TXT    @                 "v=spf1 redirect=_spf.yandex.net"
TXT    mail._domainkey   "<DKIM 2048 из панели Я360>"
TXT    _dmarc            "v=DMARC1; p=quarantine; rua=mailto:dmarc@<домен>; adkim=s; aspf=s"
TXT    @                 "<verification-запись Я360>"
```

### Домены на VK WorkSpace (7–10)
```
MX     @                 10 emx.mail.ru.
TXT    @                 "v=spf1 redirect=_spf.mail.ru"
TXT    mailru._domainkey "<DKIM 2048 из панели VK>"
TXT    _dmarc            "v=DMARC1; p=quarantine; rua=mailto:dmarc@<домен>; adkim=s; aspf=s"
TXT    @                 "<verification-запись VK>"
```

Правила по всем доменам:
- **SPF** — строго `redirect=` на провайдера (без лишних `include`, без `+all`; хвост `~all`
  внутри провайдерского spf). Один TXT-SPF на домен, не два.
- **DKIM** — 2048 бит, ключ выдаёт панель. Проверить, что подпись проходит (Postmaster).
- **DMARC** — старт `p=quarantine`, `adkim=s aspf=s` (строгое выравнивание — у нас всё с
  одного домена, можно строго). Через **2–3 недели чистой статистики** (bounce<2%,
  жалобы<0.1%) → поднять до `p=reject`. `rua` — на ящик `dmarc@` этого же домена
  (создать или алиас), чтобы читать агрегаты.
- **Выравнивание (alignment)**: From-домен = домен ящика = SPF/DKIM домен → DMARC pass.
  Движок это соблюдает (From ставится по `from_name`+ящик).

## 5. Ящики: сколько, какие имена, настройки

- **~3 ящика на домен → ~30 ящиков** (20 на Я360 + 10 на VK). Точное число подгоняем под
  тариф и объём (см. §7 про пропускную способность).
- **Имена — реальные человеческие**, под «письмо от продажника»: напр. `a.petrov@`,
  `m.ivanova@`, `d.kuznetsov@`. НЕ `sales@`/`info@`/`noreply@` (это триггер спама и не
  вписывается в «пишет живой менеджер»). `from_name` в конфиге — «Имя Фамилия, Руспром».
- На каждый ящик:
  1. Создать в панели Я360/VK.
  2. **Включить IMAP и SMTP** (в Я360 — «Разрешить доступ по протоколам»).
  3. Сгенерировать **пароль приложения** (НЕ обычный пароль! обычный не пройдёт при 2FA).
  4. Пароль — в **env-переменную** на сервере (напр. `BOX1_PASSWORD`), в конфиг пишем
     только ИМЯ переменной (`password_env: BOX1_PASSWORD`). В `sender.yaml` секретов нет.
- Порты (в конфиге уже так): SMTP `465` (SSL), IMAP `993`. Хосты Я360:
  `smtp.yandex.ru`/`imap.yandex.ru`; VK: `smtp.mail.ru`/`imap.mail.ru`.
- **Подпись** каждого ящика (`signature_ref`) — с ФИО, должностью, телефоном, юрлицом
  «ООО «Руспром»» (ФЗ-38 атрибуция дописывается движком автоматически, но человеческая
  подпись всё равно нужна для вида живого письма).

Смета ящиков: ~30 × ~250 ₽/мес ≈ **7 500 ₽/мес**. Вход первого месяца ≈ **10 000 ₽**.

## 6. Трекинг-домен (пиксели открытий + ссылки отписки)

- Отписка (ФЗ-38, обязательна) и трекинг открытий идут через **отдельный поддомен**
  одного из двойников, напр. **`link.kompressor-cc.ru`** — НЕ основной сайт, НЕ From-домен.
- На нём поднимается `unsub_server` движка на **443 (обязательно HTTPS)**; в конфиге
  `legal.unsub_base_url: https://link.kompressor-cc.ru/u`.
- Нужен **TLS-сертификат** (Let's Encrypt/бесплатный у хостинга или Cloudflare-прокси) и
  A-запись поддомена на сервер, где крутится `unsub_server`.
- Секрет подписи ссылок отписки — `UNSUB_SIGNING_SECRET` (32+ случайных байта) в env.
- DNS трекинг-поддомена: `A link → <IP unsub-сервера>` (+ CAA если нужно). MX ему не нужен.

## 7. Пропускная способность и календарь прогрева

Движок жёстко ограничивает объём **рамп-кривой** (`sender/config.example.yaml`):

- Прогрев: `[3, 5, 8, 12, 18, 25, 32, 40, 50]` писем/день/ящик — **9 ступеней до 50/день**.
  Ступень растёт при смене дня; при просадке репутации/росте жалоб движок **паузит** ящик.
- Пейсинг: **90–420 сек** между письмами одного ящика (джиттер), окно **Пн–Пт 09:30–18:00
  МСК**, праздники РФ пропускаются (перенос).
- **Пик:** 30 ящиков × 50/день ≈ **1 500 писем/день** в теории. Реалистично после полного
  прогрева (~2 недели) — **1 000–1 500/день**.

Календарь:
1. **Нед. 0:** регистрация доменов, DNS, верификация, ящики, пароли приложений, конфиг.
2. **Нед. 1–2:** **прогрев** (`is_warmup_node`) — движок гоняет письма МЕЖДУ нашими же
   ящиками (взаимный прогрев, растит reputation), объём по кривой. Реальную холодную базу
   **НЕ трогаем**. Параллельно копим DMARC-статистику.
3. **Конец нед. 2:** если bounce<2% и жалобы<0.1% по всем доменам (Postmaster) → DMARC
   `p=reject`, и **включаем боевую отправку** по прогретой кривой.
4. **Нед. 3+:** выход на пик, ротация, мониторинг репутации ежедневно.

При базе ~20k доставляемых адресов и ~1 200/день это **~3 недели** боевой отправки на
первый проход (без учёта ответов/стопов). Хотим быстрее — больше ящиков/доменов (линейно).

## 8. Провайдер-матчинг (важно для доставляемости)

В конфиге `provider_split.match_recipient_provider: true`:
- Получателю **@mail.ru/@bk.ru/@inbox.ru/@list.ru** → шлём с **VK-ящиков** (пул `pool_mailru`).
- Получателю **@yandex/@ya.ru** и **своим корп-доменам** → с **Яндекс-ящиков** (`pool_yandex`).
- Прочим/Gmail → fallback (пока Яндекс-пул).

Поэтому и держим ящики на обоих провайдерах: «свой-своему» резко улучшает доставку
(внутрисетевая почта Яндекс→Яндекс, Mail→Mail почти не режется). Провайдер получателя
берётся из MX при импорте базы (`mx-summary.json`).

## 9. Соответствие закону (ФЗ-38 / 152-ФЗ) — не пропустить

- **Атрибуция**: движок дописывает КАЖДОМУ письму юрлицо «ООО «Руспром»» + ИНН
  (`legal.entity`, `legal.inn`) — заполнить ИНН Руспрома в конфиге.
- **Отписка**: обязательная ссылка (трекинг-домен, §6), отказ фиксируется и исполняется
  (`refusal_log_max_lag_hours: 24`, авто-suppression). Один раз отписался — больше не пишем.
- **Стоп-на-ответ**: ответил/пожаловался → IMAP-watcher ловит, ящик/лид паузится.
- Юридически санкция одна на юрлицо Руспром — разные домены-двойники этого не меняют.

## 10. Привязка к конфигу движка (`sender.yaml`)

Каждый домен/ящик отражаем в `sender.yaml` (образец — `config/sender.example.yaml`):
- `mailboxes[]` — по ящику: `mailbox_id`, `provider` (yandex|mailru), SMTP/IMAP хост+порт,
  `login`, `password_env`, `from_name`, `signature_ref`, `is_warmup_node` (на прогрев).
- `provider_split.pools` — сгруппировать ящики в `pool_yandex` / `pool_mailru`; `routing` —
  провайдер получателя → пул.
- `ramp_curves` — уже заданы по провайдерам; трогать только при проблемах с репутацией.
- `legal.unsub_base_url` → трекинг-домен; `legal.inn` → ИНН Руспрома.
- Секреты (пароли ящиков, `UNSUB_SIGNING_SECRET`) — в env, НЕ в yaml.
- Стартовать с `service.dry_run: true` (песочница) для смоука, потом `false`.
