# Правки инженеру по провайдерскому ревью панели (на будущее)

Полное ревью: `ENG-REVIEW-PANEL.md`. Все файлы чисты по crit/high — это НЕ блокеры,
а укрепление к бою. Приоритет — MED (перед боевым запуском), LOW — по возможности.

## MED (сделать до боевого запуска)

1. **confirm.py — гонка при идемпотентном submit.** `confirm_submit()` не обёрнут в
   обработку `IntegrityError`. При конкурентной вставке (тот же ИНН|email|campaign) —
   исключение вверх, а не «вернуть существующую запись». Фикс: try/except IntegrityError →
   повторный `confirm_get_by_key` → вернуть существующий id/статус; иначе raise.

2. **confirm.py — контракт `last_contact`.** `_recent_contact()` зовёт
   `self._store.last_contact(email, inn)`; если store метод не реализует — тихий
   `except` маскирует, и заслон «<90 дней» молча не работает. Фикс: явно проверить
   `hasattr(store,'last_contact')` (или внести метод в контракт store) + залогировать,
   если защиты нет.

3. **unsub.py — валидация `unsub_base_url`.** В `__init__` проверяется только
   `unsub_secret_env`, а `unsub_base_url` — нет. Пустая строка проходит молча → в
   `List-Unsubscribe` уйдёт битый URL (`?t=token`), MTA снизят репутацию. Фикс:
   `if not self._base_url: raise ValueError(...)`.

4. **unsub.py — домен `mailto` из названия юрлица.** `mailto:unsub@{entity.lower()...}.ru`
   при кириллическом `entity` («ООО Руспром») даёт нерабочий кириллический домен. Фикс:
   вынести домен отписки в явный конфиг (`unsub_mailto_domain`, напр. `rusprom.ru`), не
   лепить из entity.

5. **unsub_server.py — атомарность one-click.** Убедиться, что `Unsub.handle_one_click()`
   помечает токен использованным АТОМАРНО с записью в suppression (одна транзакция /
   `BEGIN IMMEDIATE`), и повтор того же токена возвращает 200 (идемпотентность RFC 8058).
   Если уже так — ок; если нет — обернуть в транзакцию.

## LOW (по возможности)

6. **infopanel.py** — `load_enrich_lead(email=...)` параметр не используется: убрать или
   применить фильтр по адресу.
7. **infopanel.py** — `_history_block`: при битой дате в send_log ставит recent=True
   (консервативно красный) — стратегия безопасна, но при массово-битом логе даст ложные
   стопы; рассмотреть флаг «проверить вручную» вместо блока.
8. **infopanel.py** — `_kb_block` не отдаёт `available` (в отличие от scoring/enrich):
   добавить для симметрии, чтобы оператор видел «KB недоступна».
