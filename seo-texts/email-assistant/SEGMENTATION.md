# Сегментация холодных писем: максимум групп для персонификации заходов

Собрано из всех источников: кейсы `projects-index.json` (1018 опубликованных из
**5580 всего** — публикуем не всё), база обзвона `obzvon_all` (161 761 компания,
104 861 с выручкой), прайс поставщиков (**66 брендов: 1 свой ENGER + 65 дилерских**),
база знаний `answer-kb.json`. Индексы: `segment-master.json`, `region-index.json`,
`client-revenue-index.json`, `segments-base.json`, `brands-pricelist.json`.

## Принцип: что такое «группа»

«Заход» (смысловой скелет письма) задаётся **отраслью/применением** — от неё
зависят боль, оборудование, кейсы-пруф и крупный клиент для name-drop. Регион и
размер компании — это **переменные**, которые ПОДСТАВЛЯЮТСЯ в заход, а не отдельные
тексты. Итог: небольшое число заходов × параметры = максимум персонализации без
взрыва числа рукописных писем.

Пять осей ниже перемножаются. Практический максимум:
**≈27 заходов × 4 тон-группы по размеру × регион(число+имя) × 3 структуры соц-пруфа.**

## Ось 4 — Регион (переменная: число + имя). 82–90 регионов

В письмо подставляется:
- **Число проектов в регионе получателя — цифрой.** ВАЖНО: опубликованных кейсов
  1018 — это подвыборка 5580. Региональные числа из `region-index.json` — это
  **проверяемый floor** (что показано на сайте). Для письма: либо честный floor
  («более N реализованных проектов в вашем регионе»), либо оценка ×5.5 до реального
  масштаба. Рекомендация: **floor** (защищаемо факт-чекером), а федеральную цифру
  даём полную — «5580+ проектов».
- **Имя крупнейшего клиента региона** (топ по выручке из `region-index.json`).

Топ-регионы по опубликованным кейсам (floor): Москва 94, Алтайский край 86,

## Ось 5 — Структура соц-пруфа (3 варианта первого абзаца)

Выбирается по наличию данных на пересечении отрасль×регион:

1. **Есть кейсы в отрасли И регионе** → «В [регион] сделали [N] проектов, включая
   [крупный клиент]» — самый сильный.
2. **Есть в отрасли, нет в регионе** → отраслевое число + федеральный пруф
   «5580+ проектов, среди клиентов [крупный клиент отрасли]».
3. **Нет ни там, ни там** (холодный сегмент) → без чисел, заход от боли/вопроса.

## Итог: сколько групп

- **Заходов (контент-скелетов): ≈27** (2 направления → отрасли + применения + Meyer).
- **× 4 тон-группы** по размеру = до **108** тон-вариантов (параметр, не 108 текстов).
- **× регион** (число+имя, ~82) и **× 3 структуры соц-пруфа** — подстановка в шаблон.

Операционно: пишем **~27 заходов**, каждый как шаблон с переменными
`{регион}`, `{число_в_регионе}`, `{крупный_клиент}`, `{тон_по_размеру}`,
`{структура_пруфа}`. Это и есть максимум персонификации при разумном объёме
ручной вычитки.

## Ось 6 — приоритет из базы обзвона (готовые баллы, добавлено 2026-07-20)

В базе уже посчитаны 3 колонки приоритета (по стоимости нужного компании
оборудования × ОКВЭД × выручка). Распределения — `priority-analysis.json`.

| Колонка | Что значит | Как использовать |
|---|---|---|
| **Макс. балл по связке (1-5)** | ценность оборудования под ОКВЭД компании | порог качества: 88% базы = 4-5, поэтому отсекаем 2-3 (≈19k) если нужен только сильный фит; 5 = азот/кислород/МКС/дорогие компрессоры |
| **Приоритет × выручка / 10000 (PxR)** | композит «крупная × хорошо подходит» | **порядок отправки (фазовый)**: на ОБКАТКЕ шлём по PxR по ВОЗРАСТАНИЮ (малые/дешёвые первыми — тренируемся, не жжём топ); после зелёных метрик переключаем на убывание (приоритетные первыми, плотная персонализация). 33 546 компаний с PxR≥100k = топ-цели, их бережём на потом |
| **Итоговый балл приоритета** | широта потребности (сумма совпавших оценок) | высокий → в письме уместно упомянуть несколько типов оборудования |

Распределение Макс.балла: 5=87 876, 4=54 959, 3=4 606, 2=14 295 (единиц нет).
PxR-бакеты: 0(без выручки)=56 922, 1k-10k=22 474, 10k-100k=38 810, 100k+=33 546.
По направлению: у Meyer почти всё 4-5, у КЦ разброс шире (есть 2-3).

**Практика разделения:** внутри каждого захода (ось 2) и региона (ось 4) —
сортировка по PxR (фаза обкатки: малые первыми; боевая фаза: приоритетные первыми),
порог по Макс.баллу (кого вообще берём),
name-drop крупных (ось 4) + больше типов оборудования там, где высокий Итоговый
балл. Эти баллы УЖЕ в базе — нужно лишь перенести их в получателей при импорте
и учитывать в порядке отправки (см. промпт инженеру).
