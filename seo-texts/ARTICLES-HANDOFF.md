# SEO-тексты prokompressor.ru: доки для чистой сессии

Проект в подкаталоге `seo-texts/` (в репозитории есть ВТОРОЙ, независимый проект —
антидетект-браузер и рассыльщик в корне и в `seo-texts/sender/`; не путать).

Состояние: **759 страниц каталога сгенерированы, отревьюены и выгружены**
(коммит 16.07.2026, финал после ~289 регенераций). Ниже — что где лежит, как
запускать, и главное про базу знаний брендов.

## 1. Где данные

| Что | Путь | Объём |
|---|---|---|
| Входные данные страниц | `gen/payload-<slug>.json` | 759 |
| Финальные тексты | `gen/result-<slug>.json` | 759 |
| Бэкап первой генерации (для отката) | `gen-orig/` | 759 |
| Готовые страницы к публикации | `publish/plain/`, `publish/schema/` | + `publish/manifest.csv` |
| CSV-деливераблы для Битрикса | `make_csv*.py` → `*.csv` в корне проекта | |
| Стайлгайды | `gen/STYLE-GUIDE.md`, `gen/STYLE-GUIDE-ELEKTRO.md`, `gen/STYLE-GUIDE-PODGOTOVKA.md` | |
| Очереди/состояние регенерации | `regen-*.json`, `regen-monitor.log` | |
| Отчёты | `seo-effect-report.md`, `review-*.md`, `eng-sweep-report*.md`, sweep-и | |

`result-*.json` — это финальный текст страницы; `payload-*.json` — все входные
факты (модели, мощности, цены-диапазоны, фото, категория, бренд). **Числа в
тексте допускаются только из payload** — это правило гейта, а не пожелание.

## 2. База знаний брендов (`kb/`) — сердце достоверности

95 файлов. Структура и назначение:

- `kb/brand-<name>.md` — 41 карточка бренда в человекочитаемом виде.
- `kb/BRENDY-SVODKA.md` — сводка по всем брендам с метками уверенности
  `[high|medium|low]`.
- **`kb/brands-assembled.json`** — сырая сборка фактов из 6 источников
  (сайт производителя, прайс, брендовая страница, веб-поиск и т. д.).
- **`kb/brands-synthesized.json`** (352К) — сведённая запись на бренд: страна,
  позиционирование, серии с диапазонами мощностей, `готовые факты`,
  **`НЕ утверждать`** (запреты) и пометки об источнике/уверенности каждого поля.
- **`kb/brand-facts-clean.json`** (196К) — то, что реально идёт в генерацию:
  прошло adversarial-аудит и верификацию зависимостей.
- `kb/kb-audit.json` — результаты аудита (что помечено небезопасным и почему).
- `kb/deps-verified.json`, `kb/dep-verify-tasks.json` — проверенные
  закономерности из прайса (например, «с такой-то мощности идёт звезда-треугольник»).
- `kb/manuf-facts.json`, `kb/brand-pages-facts.json` — факты по источникам.
- `kb/KACHESTVO-DANNYH.md`, `kb/RASHOZHDENIYA.md`, `kb/ZAVISIMOSTI*.md`,
  `kb/FILTER-PLAN.md` — методички: как оценивалось качество, где источники
  расходятся, какие зависимости подтверждены.

**Как база знаний попадает в текст.** Не напрямую: между KB и генератором стоит
гейт `brand_facts_lib.py` (`from brand_facts_lib import fact_block, tone_for`).
Он берёт ТОЛЬКО `kb/brand-facts-clean.json` и пропускает:
- `positioning` / `country` — если заполнены и не в caveats;
- `series` — только `confidence: high|medium` (low выбрасывается);
- `safe_facts` — выжимка после аудита;
- `confirmed_dependencies` — подтверждённые закономерности из прайса;
- `caveats` — уходят в блок **«НЕ УТВЕРЖДАТЬ»** прямо в промпт, как охранный
  барьер для модели.

Отсюда правило: **новый факт о бренде нельзя дописать в текст руками — его
добавляют в KB и проводят через аудит**, иначе он не переживёт регенерацию.

Скрипты сопровождения KB: `assemble_brands.py` (сборка из источников),
`enrich_kb.py` / `enrich_kb_rest.py` (дообогащение), `audit_kb.py`
(независимый скептик-аудитор помечает небезопасные факты — идёт через
провайдера, параллельно).

## 3. Конвейер генерации

```
build_*_payloads.py  →  gen/payload-*.json
        ↓
gen_provider.py (провайдерский API, стриминг обязателен)
        ↓
qa_text.py — механический гейт на каждом тексте (бесплатно, до 2 раундов доводки)
        ↓
regen_driver.py — регенерация: keep-best + инженер-проверка каждой 6-й страницы
        ↓
publish/ (plain + schema JSON-LD)  →  make_csv*.py  →  CSV для Битрикса
```

- **`gen_provider.py`** — рабочий клиент провайдера с ретраями
  (`make_client`, `call`, `run_one`). Стриминг обязателен. Внутри стоят часы на
  стрим и автоподмена «мёртвых» моделей (`PROVIDER_DEAD_MODELS`,
  `PROVIDER_MODEL`) — лечение случая, когда шлюз принимает запрос и шлёт только
  ping-кадры, а текста не отдаёт.
- **`qa_text.py`** — потекстовые проверки (запрещённая лексика, хеджи
  «около/примерно/порядка», числа не из payload и т. д.). Межстраничные
  проверки (похожесть текстов, повторы FAQ) — в `qa_gate.py`.
- **`regen_driver.py`** — очередь `flagged-facets → flagged-brands → clean-brands`,
  флагнутым страницам инжектируется конкретный дефект из
  `defect-map-resolved.json` как «ОБЯЗАТЕЛЬНО ИСПРАВЬ»; **keep-best** — если
  новая версия механически хуже старой, откат из `gen-orig/`; бюджет-кап по
  токенам со стопом.
- Ревьюеры: `review_all_50.py`, `review_engineer.py`, `review_seo.py`,
  `engineer_sweep.py` (4 персоны + инженерные свипы).

## 4. Правила текстов (нарушение = брак на гейте)

- **Без длинных тире** «—» вообще (главный маркер ИИ-текста); диапазоны — через
  дефис или словами «от… до…».
- **Без `<ul>`**: CSS сайта сам рисует тире-маркеры.
- Байлайн — **ООО «Руспром»**.
- **Числа только из payload**; точных цен в тексте нет нигде (цены на сайте
  пересчитываются по курсу).
- Хедж-слова запрещены: около, примерно, порядка, ориентировочно.
- Витринные конструкции запрещены («в каталоге представлены…») — писать
  действием.
- Фото-блок — кликабельная карточка-ссылка.
- Полные правила — в `gen/STYLE-GUIDE*.md` и в промптах `gen_provider.py`.

## 5. Инфраструктура

- **Провайдерский API**: `PROVIDER_API_KEY` (+ `PROVIDER_BASE_URL`, по умолчанию
  `https://router.cheap`). Правило владельца: всю тяжёлую работу — через него,
  квоту сессии беречь. Контекст про шлюз (оферта не найдена, апстрим не
  подтверждён) — в корневом `CLAUDE.md`, решение о вызовах каждая сессия
  принимает сама.
- **Дроп** (файлообменник владельца): `DROP_URL` + `DROP_TOKEN`, клиент
  `seo-texts/server/drop_client.sh` (`list | up <file> | down <name> | del <name>`).
  Там тяжёлые исходники: выгрузка Битрикса `bitrix-export-full.tar.gz` (4 ГБ, в
  git НЕ включена), каталоги производителей, дампы краулинга, финальные CSV.
  **Скачивать оттуда, а не просить у владельца заново.**
- Проверка «drop и провайдер»: `bash seo-texts/server/drop_client.sh list`
  (должен вернуть список) + короткий тестовый вызов `gen_provider.call()`.

## 6. С чего начать в чистой сессии

1. Прочитать корневой `CLAUDE.md` (два проекта в одном репо, правила текстов).
2. Посмотреть `gen/STYLE-GUIDE.md` и `kb/BRENDY-SVODKA.md`.
3. Для правок фактуры — работать через `kb/` + `audit_kb.py`, а не по тексту.
4. Перед любой массовой генерацией — короткий пробный вызов провайдера
   (модели периодически «молчат» — см. §3) и один прогон `qa_text` на образце.
5. Регенерацию запускать только `regen_driver.py` (keep-best защищает от
   регрессии), не вручную по страницам.
