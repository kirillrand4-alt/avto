# Патч quota-ui: дневная квота AI-генерации в интерфейсе панели (задача 52)

Владелец формулирует темп как расписание: «3 сегодня, 3 завтра, 5 послезавтра».
До этого патча квота жила только в скрипте `sender-patches/ai-letter/ai_gen_quota.py`
(запуск руками, одно число аргументом), а в панели её не было вообще.

Патч переносит логику из скрипта в движок (`sender/ai_quota.py`), вешает на неё
три роута и карточку в UI. Скрипт можно не трогать: он пишет в тот же
`ai_letter_log`, поэтому счётчики в панели видят и его работу тоже.

## Хранение

Новых таблиц НЕТ. Всё в существующих:

- расписание — `panel_settings["ai_daily_quota"]` = `{"<campaign_id>": {"ГГГГ-ММ-ДД": N}}`;
- состояние прогона — `panel_settings["ai_quota_run"]` = `{"<campaign_id>": {...}}`
  (durable: рестарт службы посреди прогона не оставляет UI в вечном «идёт»);
- факт — `ai_letter_log` (создаётся `sender.ai_letter.log_results`; модуль сам
  делает `CREATE TABLE IF NOT EXISTS`, поэтому карточка открывается и на пустой БД);
- письма — `confirm_reviews` через `store.confirm_submit` (очередь подтверждений,
  НЕ отправка; в `panel_json` кладём `{"ai": true, "quota_day": "ГГГГ-ММ-ДД"}`).

## Роуты

| Метод | Путь | Роль | Что делает |
|---|---|---|---|
| GET | `/ai/quota?campaign_id=N&days=7` | любой | дни (план + факт + остаток), `today`, `candidates_left`, состояние прогона |
| POST | `/ai/quota` | owner | патч расписания (`{campaign_id, schedule:{дата:N}}`), аудит `ai_quota.set` |
| POST | `/ai/quota/run` | owner | старт генерации по остатку на сегодня, аудит `ai_quota.run`, ответ сразу (фон) |

## Решения, которые стоит знать

1. **Квоту съедают ВСЕ попытки, ok + брак.** Квота ограничивает расход
   провайдерского API, а не число удачных писем: в плохой день письмо может
   уходить в брак раз за разом. Брак показан в карточке отдельной колонкой,
   чтобы недобор был объясним. Это же поведение было в `ai_gen_quota.py`.
2. **Идемпотентность по факту, а не по нажатиям.** Остаток = `квота - попытки
   за день`, попытки читаются из лога. Повторный запуск догенерирует только
   недостающее; подняли квоту с 3 до 5 — сделает два письма, а не пять.
3. **День считаем по Москве, лог пишется в UTC.** `ai_letter_log.created_at` —
   UTC ISO, поэтому дату берём после перевода в `Europe/Moscow`. Иначе письма
   после 21:00 МСК падали бы в завтрашний счётчик и выбранная квота «сама»
   восстанавливалась. Пояс: `ai.quota_tz` → `timezone` → `Europe/Moscow`.
4. **Прогон в фоне.** Генерация одного письма — несколько LLM-раундов, HTTP-запрос
   столько не живёт. `POST /ai/quota/run` отвечает сразу, UI поллит `GET /ai/quota`
   раз в 5 секунд, пока `run.running`. Двойной клик подхватывает текущий прогон
   (лок в движке), а не запускает второй.
5. **Кандидаты** — получатели сегмента кампании (`config.segment`, иначе имя
   кампании) без письма в `ai_letter_log` И без записи в `confirm_reviews`,
   с отсечкой suppression. Второй источник обязателен: письма мог положить
   старый скрипт до появления модуля.
6. **Тумблер «холд» не трогаем.** Генерация кладёт письма в очередь
   подтверждений; отправку по-прежнему подтверждает оператор вручную.

## Как проверить

```
# бэкенд (24 теста, сети не требуют — генератор подменён фейком)
cd C:\sender && python -m pytest sender\tests\test_ai_quota.py -q

# полный сьют панели
cd C:\sender && python -m pytest -q
```

Руками после деплоя (`Restart-Service SenderPanel -Force`):

1. Экран «Кампании» → карточка «Дневная квота генерации», выбрать кампанию
   «новостные».
2. Проставить `3` на сегодня, `3` на завтра, `5` на послезавтра → «Сохранить
   расписание» → перезагрузить страницу, числа на месте.
3. «Сгенерировать сейчас (3)» → кнопка становится «Генерация идёт…», через
   минуту-другую в строке «Сгенерировано» появляется 3, в очереди подтверждений
   3 новых письма.
4. Нажать «Сгенерировать сейчас» ещё раз в тот же день — кнопка заблокирована
   (остаток 0), в подписи «дневная квота уже выбрана». Дублей нет.
5. Снять квоту на день (поставить 0, сохранить) → запуск отвечает «квота на
   этот день не задана», генератор не вызывается.

## Риски

- `candidates_left` в карточке — **оценка** (два дешёвых запроса без скана базы):
  из числа получателей сегмента вычитается число всех, кому по кампании уже
  делали письмо. Если письма делались получателям вне сегмента, оценка занижена.
  На саму генерацию не влияет — там честный постраничный отбор.
- Фоновый поток живёт в процессе панели: рестарт службы посреди прогона теряет
  недоделанный батч. Уже сделанные письма не теряются (лог пишется после
  каждого батча), отметка `running` через 30 минут гаснет как `stale`.
- `MAX_PER_DAY = 200` — предохранитель от опечатки в поле ввода. Если владельцу
  понадобится больше, править константу в `sender/ai_quota.py`.
- Прогон идёт через `sender.review_lenses.default_caller` (провайдерский API,
  `claude-fable-5`). Ошибка провайдера не роняет прогон: батч пропускается,
  текст ошибки виден в подписи под кнопкой.
