## 1. Что получаем на выходе (три файла + база)

Всё живёт в одной sqlite на сервере `C:\sender\_ops\ak\AK-BAZA.sqlite` (копия на дропе после каждой фазы)
и выгружается в три CSV:

**1) `AK-PREDPRIYATIYA.csv`** - одна строка на юрлицо края, где КО может быть в техпроцессе:

```
inn · ogrn · nazvanie · nazvanie_polnoe · status_egrul · gorod · adres · okved_osn · okved_vse ·
klass:  доказано | косвенно | кандидат          (см. 1.3)

vyruchka_rub · pribyl_rub · nalogi_rub · ssch · fin_god · fin_istochnik · rang (для сортировки)
```

**2) финансы** - те же строки, поля выручка / чистая прибыль / уплаченные налоги / ССЧ / год / источник
(ГИР БО первоисточник, checko вторым, солянка третьим; расхождения записываются, не затираются).
Сортировка важности: `klass` → `vyruchka_rub` вниз → `uverennost`.

**3) `AK-KARTOCHKI-DOKAZATELSTV.csv`** - одна строка на факт, формат как в PARK-VYDACHA-FAKTY-2S и базе
центробежников (`sostoyanie_potverzhdeno_faktom / ssylka_sostoyaniya / data_dokazatelstva`):

```
inn · predpriyatie · vid_fakta (закупка машины | закупка ТО | закупка запчастей | ЭПБ | ОПО | вакансия |
   лот/залог | сайт | СМИ | техпроцесс-вывод) · tip (компрессор/ресивер/воздуходувка/осушитель/ВРУ/…) ·
marka_model · sreda · data · srok_do · status_sroka · sila 1-5 · istochnik (хост) · ssylka (конкретная
страница) · citata (кусок текста, из которого взято) · kto_sobral · ts
```

Правила, унаследованные из базы парка: строк без ссылки ноль; ссылка на конкретную страницу, не на список;
несколько источников = несколько строк; цитата сохраняется в момент записи; агрегаторы не доказывают.

**1.3. Классы:**
- `доказано` - есть хотя бы одна карточка с прямым фактом (ЭПБ/ОПО/закупка/вакансия/лот);
- `косвенно` - прямого факта нет, но техпроцесс требует КО (ОКВЭД × разбор сайта × две линзы провайдера
  согласны) - это и есть «может быть в техпроцессе»;
- `кандидат` - подходит по ОКВЭД/размеру, линзы не согласны или сайта нет. Остаётся в файле с причиной.
Не наше (офисы, торговля без склада, ИП без производства) в файл не идёт, но остаётся в базе с вердиктом.

## 2. Кто что делает

```
ОРКЕСТРАТОР (я, песочница)   ведёт AK-SOSTOYANIE.json на дропе, запускает треки, принимает по контролям,
                             пишет журнал AK-ZHURNAL.md; ничего тяжёлого сам не считает
СУБАГЕНТЫ (Agent, до 4 одновременно)  один трек = один агент; вход: этот план + номер трека + состояние;
                             выход: durable jsonl на сервере + копия на дропе + отчёт числами.
                             Агент не имеет права менять чужой трек и удалять файлы
СЕРВЕР (раннер, 8 потоков, 1700 с на задание)  весь сетевой сбор; скрипт кладётся panel_file_put,
                             гонится panel_py кусками по бюджету, возобновляется по .gotovo/jsonl
ПРОВАЙДЕР (claude-fable-5)   только разбор текста: класс техпроцесса, марка/среда из текста, вердикт
                             «машина или узел», линзы технолог/скептик. Пачки ≤3 длинных текстов
ДРОП                         состояние, копии jsonl раз в час трека, итоговые CSV
```

Правила для каждого агента (вшиваются в промпт):
1. Сначала контроль негодным входом, потом счётчик. Одинаковый ноль по всем целям = сломан прибор.
2. Второе число у каждого фильтра: сколько похожего на цель отброшено.
3. `argv`, `rc`, `stdout_tail` - хвост; результат писать в файл на сервере и забирать кусками (ak_kusok.py).
4. Регион = ИНН на 22 или адрес ЕГРЮЛ «Алтайский край»; Республика Алтай (04) - контроль-чужой.
5. Ни один файл не перезаписывать, только дописывать; удалять ничего.
6. Каждые 60 минут - строка в AK-ZHURNAL.md числами: сделано / отброшено / контроль / что встало.

```
торговая площадка сменила разметку трек помечается «встал», остальные идут; чиним отдельным агентом
```

## 8. Порядок запуска

```
день 0   фаза 0 (я сам, 1 час) → приёмка → фаза 1 треки Т1.1-Т1.3 тремя агентами
день 1   фаза 2 треки Т2.1-Т2.6 (по 4 агента, остальные в очереди), Т4.1 параллельно
день 2-4 фаза 3 (провайдер, 4 потока), Т2.x добираются, Т4.2
день 5   фаза 5, отчёт, файлы на дроп, коммит
```

Команда «пуск» запускает фазу 0. Каждая фаза заканчивается записью в AK-ZHURNAL.md на дропе, чтобы
владелец мог посмотреть в любой момент, не участвуя.
