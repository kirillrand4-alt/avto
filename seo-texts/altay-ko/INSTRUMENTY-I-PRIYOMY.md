# Инструменты: чем работаем, как запускать, где спотыкаются все

Соседний файл `DOKA-kakoy-skript-chto-delaet.md` отвечает на вопрос «какой скрипт что
делает». Этот отвечает на другой: **чем вообще можно работать, как это запустить и где у
каждого инструмента яма**. Всё ниже проверено живым запуском; где инструмент сегодня не
сработал — так и написано, потому что «канал есть» и «канал работает» это разные вещи.

Правило, из которого растёт весь файл: **ноль надо доказывать так же тщательно, как
находку**. Почти все ямы ниже устроены одинаково — прибор молча возвращает пусто, и пустота
неотличима от честного «ничего нет».

## 1. Четыре слоя, между которыми всё ходит

```
ПЕСОЧНИЦА (эта сессия)   репозиторий, git, свои скрипты. Сеть через прокси: часть хостов
                         закрыта (zakupki.gov.ru — рвёт соединение, rusprofile 403,
                         checko 429, trudvsem-карточки 460, torgi.gov.ru 502)
СЕРВЕР ВЛАДЕЛЬЦА         C:\sender — модули (enrich_contacts.py, enrich_db.py и др.),
                         C:\sender\_ops — рабочие файлы и потоки, C:\sender\server — код.
                         Сеть широкая: ЕИС, Портал Москвы, площадки, справочники
ДРОП                     https://parsercompressor.online/drop — обмен между сессиями и
                         хранилище тяжёлых файлов
ПРОВАЙДЕР                Anthropic-совместимый API для тяжёлого разбора текста
```

Что из этого следует практически: **прежде чем объявить хост недоступным, попробуй его с
другого слоя.** У меня 11 ссылок из 27 не открылись из песочницы и 10 из них открылись с
сервера кодом 200. Обратный случай тоже есть: `monitor-pb.ru` с сервера не читается, а из
песочницы читается — на этом однажды 813 фактов чуть не были объявлены недоказуемыми.

## 2. Раннер: запуск своего кода на сервере

### Канонический способ

```bash
python3 seo-texts/zapusk_na_servere.py <скрипт.py> [аргументы...]
```

Кладёт файл в `C:\sender\_ops\3s_<имя>` и запускает. Что важно знать:

```
ключ аргументов          argv, НЕ args. С `args` скрипт видит только своё имя, прогон
                         проходит «успешно» и молча делает не то
код возврата             d['rc'], НЕ returncode
вывод                    d['stdout_tail'] — ХВОСТ, не весь вывод
таймаут задания          1700 с внутри, 1800 снаружи. Длинное режем бюджетом и гоняем кусками
параллельно              два задания одновременно проходят нормально; больше 6-7 с одной
                         сессии ставить нельзя — пул общий на все сессии
```

### Яма №1, самая дорогая: вывод срезается

`zapusk_na_servere.py` печатает `stdout_tail[-6000:]`, да и сам сервер отдаёт только хвост.
У меня прогон из 37 запросов отработал полностью, а увидела я два последних — и это выглядело
как «канал ничего не дал».

**Лечится одним из двух:**

```python
# а) печатать компактно: одна строка на единицу работы, подробности только у находок
# б) писать результат в файл на сервере и забирать его отдельно:
open(r'C:\sender\_ops\3s_moy_vyvod.txt', 'w', encoding='utf-8').write(tekst)
# затем вторым заданием выложить его на дроп или напечатать нужный кусок
```

### Прямой вызов, если нужен свой контроль над ответом

```python
import base64, sys
sys.path.insert(0, '/home/user/avto/seo-texts/server')
import run_on_server as R

R.submit('enrich_contacts', {'op': 'panel_file_put', 'files': [
    {'dest': r'C:\sender\_ops\3s_moy.py',
     'b64': base64.b64encode(open('moy.py', 'rb').read()).decode()}]}, timeout=300)
r = R.submit('enrich_contacts', {'op': 'panel_py',
                                 'script': r'C:\sender\_ops\3s_moy.py',
                                 'argv': ['--limit', '50'], 'timeout': 1500}, timeout=1600)
d = r.get('data') or {}          # ПОЛЕЗНАЯ НАГРУЗКА ЛЕЖИТ ПОД 'data'
print(d.get('rc'), (d.get('stdout_tail') or '')[-60000:])
print(d.get('stderr_tail') or '')
```

### Браузерная проба (когда сайт рисует контент скриптом)

```
запускать с {"proxy": false, "ignore_https_errors": true}   иначе прокси отдаёт 407
результат лежит в eval_js_value, НЕ в eval
script и return выполняются в РАЗНЫХ контекстах — переменная из script в return не видна
возвращать надо ПЛОСКУЮ СТРОКУ, объект не доедет
```

Признак этой ямы: `eval_js_ok=True` и при этом `ReferenceError` внутри. То есть задание
успешно, а данных нет.

## 3. Дроп: обмен между сессиями

```bash
bash seo-texts/server/drop_client.sh list          # что лежит
bash seo-texts/server/drop_client.sh up <файл>     # выложить
bash seo-texts/server/drop_client.sh down <имя>    # забрать
bash seo-texts/server/drop_client.sh del <имя>     # удалить (осторожно, см. ниже)
```

Ответ на `up` печатает `sha256` и размер — это и есть подтверждение, что файл доехал.

**Яма:** файл кладётся целиком, последняя выгрузка выигрывает молча. Если между твоим
чтением и твоей записью кто-то дописал — его правка пропадёт без следа. Для журналов
пользуйся клиентом, он скачивает файл перед дозаписью:

```bash
python3 seo-texts/zhurnal_sessii.py --zapis "текст записи"   # дописать снизу
python3 seo-texts/zhurnal_sessii.py --sled                   # следить за чужими
python3 seo-texts/zhurnal_sessii.py --chitat 1               # прочитать журнал 1-й сессии
```

Следить за чужим журналом по размеру НЕЛЬЗЯ: правка в середине размер не меняет. Признак
изменения — пара `(bytes, mtime)` из листинга.

## 4. Ключи и секреты

```
в песочнице задано       DROP_URL, DROP_TOKEN, PROVIDER_API_KEY, PROVIDER_BASE_URL
на сервере задано        XMLRIVER_USER, XMLRIVER_KEY, DADATA_TOKEN, JOB_SECRET
                         (в окружении службы и в C:\sender\rs.env)
```

Правила: значения **не печатать** — только «есть/нет» и длину; в файлы репозитория не
класть; `.env` не коммитить. Проверка наличия из серверного скрипта:

```python
import os
print('ключи: user=%s key=%s' % ('есть' if os.environ.get('XMLRIVER_USER') else 'НЕТ',
                                 'есть' if os.environ.get('XMLRIVER_KEY') else 'НЕТ'))
```

Если ключа нет в окружении — он может лежать в `C:\sender\rs.env` строками `ИМЯ=значение`
(так я доставала `DADATA_TOKEN`).

## 5. Каналы данных: что готово и как этим пользоваться

### 5.1. ЕГРЮЛ через dadata — ИНН, адрес, руководитель. **Работает, контроль чист**

`seo-texts/pishchevka_dadata.py` — рабочий пример целиком. Суть:

```python
URL = 'https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/party'
telo = json.dumps({'query': 'Хлебокомбинат ПЕКО', 'count': 6}).encode()
req = urllib.request.Request(URL, data=telo, headers={
    'Content-Type': 'application/json', 'Accept': 'application/json',
    'Authorization': 'Token ' + TOKEN})
```

Отдаёт `inn`, `ogrn`, `state.status`, `address.value`, **`management.name` и
`management.post`** — первое лицо из ЕГРЮЛ. Ищет и по названию, и по ИНН.
Контроль: выдуманное предприятие → 0 карточек. Годится как заслон на любую сшивку.

Учти: в `management` может стоять **юрлицо**, а не человек — это управляющая организация
(так у ООО «МАЯК» стоит ООО «ИКС5-Восточная Сибирь»). И данные ЕГРЮЛ расходятся с сайтом:
у ПЕКО сайт называет одного гендиректора, ЕГРЮЛ другого. Обе записи нужны, с источниками.

### 5.2. «Работа России» — вакансии с контактным лицом. **Работает, контроль чист**

Открытые данные, ключ не нужен, читается ИЗ ПЕСОЧНИЦЫ.

```python
# по предприятию
'http://opendata.trudvsem.ru/api/v1/vacancies/company/inn/%s?limit=100' % inn
# по региону + слову (регион = код субъекта + нули до 13 знаков; Алтайский край 2200000000000)
'http://opendata.trudvsem.ru/api/v1/vacancies/region/2200000000000?text=компрессор&limit=100'
```

В каждой вакансии: `contact_person` (ФИО), `contact_list` (телефон, мобильный, почта),
`job-name`, `vac_url`, `creation-date`, `company.inn`. Это **самый дешёвый источник
именованных людей с мобильными**, какой у нас есть, и одновременно косвенное доказательство
машины: вакансия «машинист компрессорных установок» означает, что компрессор стоит.

Яма: сама HTML-карточка `trudvsem.ru/vacancy/card/...` рисует контакт скриптом — в исходнике
имени НЕТ. Ссылкой-доказательством ставь адрес API, карточку — вторым источником.

### 5.3. Реестр ЭПБ monitor-pb — какие машины стоят и когда истекает экспертиза

```bash
python3 seo-texts/mpb_po_inn.py 2124009521 --tolko-mashiny
python3 seo-texts/mpb_po_inn.py --spisok inns.txt --out epb.csv
```

Карточка эксплуатанта `monitor-pb.ru/customer/<ИНН>` отдаёт ВСЕ заключения предприятия —
это дешевле полнотекстового поиска и не требует отбора. Контроль: выдуманный ИНН → 0.
Читается ИЗ ПЕСОЧНИЦЫ, с сервера — нет.

Помни, что реестр доказывает ОПО, а не любую машину: у пищевых предприятий там котлы и
газопроводы, компрессоров может не быть вовсе.

### 5.4. ЕИС zakupki.gov.ru — главный источник доказательств закупки. **Только с сервера**

```
поиск            /epz/order/extendedsearch/results.html?searchString=<слово>&morphology=on
                 &sortBy=UPDATE_DATE&fz44=on&fz223=on
фильтр региона   &customerPlace=<код>&customerPlaceCodes=<номер субъекта>
карточка орг.    /epz/organization/view/info.html?organizationCode=...
```

**Числовой код субъекта возьми из справочника самой ЕИС, а не из головы.** Я гоняла с
`customerPlace=5277&customerPlaceCodes=22`; контроль словом показал, что ПОИСК работает, но
что фильтр указывает именно на Алтайский край — не доказано ничем. Ровно на этом же месте
меня поймал torgi.gov.ru: `dynSubjRF=22` вернул объекты Чувашии, то есть у площадки свой
справочник регионов, не совпадающий с префиксом ИНН. Прежде чем считать «по региону» —
проверь фильтр предприятием, про которое точно знаешь, что оно в этом регионе.

Проверка живости — контрольное слово: у выдуманного «щварцкопфер» страница вдвое короче и
«найдено 0». Полезно помнить и обратную яму: однажды поиск организаций возвращал **168 611
знаков на любой ИНН, включая выдуманный** — страница не читала запрос, а счётчик исправно
писал «карточки нет». Такой сбой неотличим от честного нуля без контроля с негодным входом.

### 5.5. Выдача через xmlriver — веер запросов

Готовый пример: `seo-texts/pishchevka_veer_zaprosov.py`.

**Важно:** серверная `EC._serp_urls()` отдаёт ТОЛЬКО адреса, а имя человека почти всегда
стоит в сниппете. Поэтому разбираем XML сами:

```python
url = ('http://xmlriver.com/search_yandex/xml?user=' + quote(USER) + '&key=' + quote(KEY)
       + '&domain=ru&device=desktop&groupby=10&query=' + quote(q))
# из ответа берём <doc>: <url>, <title>, <passage>
```

Отказ шлюза приходит кодом 200 с текстом «Заняты все доступные вам каналы» — если его не
ловить, отказ неотличим от «ничего не найдено». Ретрай с паузой обязателен.

**Главная яма веера, купленная дважды:** выдача отвечает ВСЕГДА. Контрольный запрос с
выдуманной фамилией при живом предприятии дал 14 документов — столько же, сколько
настоящий. Считать надо не документы, а совпадения: сколько документов содержат И имя
предприятия, И ролевое слово. По этой мерке контрольное предприятие даёт 0, живые — десятки.

### 5.7. Сайт предприятия «глазами»

`seo-texts/sayt_glazami.py` — берёт главную, находит на ней страницы контактов/о компании/
качества/вакансий и печатает **сырые окна текста** вокруг ролевых слов. Решение принимает
человек, а не регулярка.

```bash
python3 seo-texts/sayt_glazami.py https://peko-msk.com/
```

Зачем именно так: первый заход по этим же сайтам вернул «людей с должностью 0», потому что
прибор требовал ФИО в ±260 знаках от должности. Ноль был свойством прибора. Сырые окна сразу
показали «Служба технического директора: 8 (499) 473-97-30».

Две ямы, обе стоили прогона:

```
кодировка   сайт может быть в cp1251 — utf-8 даст «кракозябры» и любой поиск по слову
            вернёт ноль. Пробуй обе и бери ту, где больше кириллицы
punycode    домен на кириллице из песочницы не резолвится; и урл с кириллицей роняет
            urllib с latin-1 ошибкой. Кодируй в IDNA, а провал называй провалом ПРИБОРА
```

### 5.9. Провайдер для тяжёлого разбора текста

```python
from gen_provider import make_client, call
client = make_client()
msg = call(client, [{'role': 'user', 'content': '...'}], model='claude-fable-5', attempts=3)
tekst = ''.join(b.text for b in msg.content if b.type == 'text')
```

```
параметра max_tokens НЕТ — передашь, получишь TypeError, и веер линз молча даст «контактов
   нет» по всем целям (у меня так пропали 27 запросов из 27)
ответ может состоять из ['thinking','text'] с ПУСТЫМ текстовым блоком — проверяй
упавшая линза НЕ ГОЛОСУЕТ: её надо отделять от линзы, ответившей «нет»
```

Приём владельца «веер линз»: один и тот же материал разбирается несколькими РАЗНЫМИ
запросами (найди контакты / докажи, что их нет / перечисли разделы), ответ принимается по
совпадению двух из трёх, а в пачку подмешивается выдуманный текст как контроль.

## 6. Правила прибора: то, что иначе каждая сессия покупает своими ошибками

```
1. У КАЖДОГО ПРИЗНАКА СВОЙ КОНТРОЛЬ — заведомо негодный вход. Нет контроля — числа нет.
2. КОНТРОЛЬ ТОЖЕ БЫВАЕТ НЕГОДНЫМ. Я взяла «префикс ИНН 99» как несуществующий регион и
   получила 3 факта: 99 реально используется межрегиональными инспекциями. Контроль
   ничего не проверил, а выглядел как пробитый фильтр.
3. КОД ОТВЕТА — ЭТО ОТВЕТ. 401, 403, 429, 460, 503 означают, что хост достигнут.
   Недоступен только тот, кто не ответил вовсе.
4. ДЛИНА ОТВЕТА — НЕ ПРИЗНАК. Страница ошибки браузера это ~210 знаков «текста»;
   «текст получен» по длине уже дважды давало ложный успех.
5. ОДИНАКОВЫЙ НОЛЬ ПО ВСЕМ ЦЕЛЯМ, ВКЛЮЧАЯ КОНТРОЛЬ, = сломан прибор, а не пусто в мире.
6. КРУПНОЕ ЧИСЛО — ПОВОД ПРОВЕРИТЬ ПРИБОР, а не радоваться.
7. ЗАМЕР ОБЯЗАН НАЗЫВАТЬ ЖИВОЙ ФАЙЛ и его время. Копия на дропе отставала от файла в _ops
   на 23 человека, и обе назывались одинаково.
8. СНИППЕТ — НАВОДКА, ДОКАЗАТЕЛЬСТВО — ОТКРЫТАЯ СТРАНИЦА.
9. СТРАНИЦА ПОИСКА ≠ КАРТОЧКА. Поиск показывает, что машина закупалась, но не говорит, чья.
   При этом «только поиск» означает «нельзя судить, не открыв», а НЕ «не доказано»:
   выдача ЕИС по номеру закупки называет и машину, и заказчика.
10. АГРЕГАТОРЫ НЕ ДОКАЗЫВАЮТ ПРИНАДЛЕЖНОСТЬ. prodoctorov, list-org, rusprofile, vk, hh,
    avito, 2gis: карточку заводит не предприятие. Полная тёзка — неонатолог из Челябинска —
    стояла доказательством номера начальника цеха водоканала.
11. НОМЕР У НЕСКОЛЬКИХ — НЕ ЛИЧНЫЙ. Самый результативный заслон: 818 -> 613 -> 249.
    Считать по ВСЕМ базам сразу, включая свой поток. Тот же заслон ловит и «номер у двух
    людей» — это линия отдела, а не человек.
12. ЦИТАТА СОХРАНЯЕТСЯ В МОМЕНТ ЗАПИСИ. Доказательство добывается один раз, вместе с
    номером; второй раз его взять негде. У меня 378 личных мобильных без цитаты — они не
    плохие, они НЕДОКАЗУЕМЫЕ.
13. ИСТОЧНИКИ НАКАПЛИВАЮТСЯ, А НЕ ЗАМЕНЯЮТСЯ. Колонки `istochniki` (через « | »),
    `istochnikov` (число), и отдельно — чем именно доказан факт.
14. РАЗДЕЛЯТЬ, А НЕ ОТСЕИВАТЬ. Неподтверждённое кладётся рядом СО СВОЕЙ ПРИЧИНОЙ, а не
    удаляется: выброшенное заново не добывается.
15. CSV ПИСАТЬ csv.writer'ом, не склейкой через «;». Непарная кавычка в названии
    (`ООО "СИБЭЛЕКТРО`) склеивает строки у любого стандартного читателя: 10 542 физических
    строки читались как 10 540 записей.
16. ИМЯ ПОЛЯ ОТВЕТА ПРОВЕРЯТЬ, А НЕ УГАДЫВАТЬ. За сутки: `args` вместо `argv`,
    `returncode` вместо `rc`, `eval` вместо `eval_js_value`, `triggers` вместо `data`.
    Каждый раз ошибка выглядела как пустой, но безобидный результат.
17. УБИРАЯ СЛЕДЫ СВОЕЙ ПРОБЫ, НЕ УДАЛИ ЧУЖОЕ СОСТОЯНИЕ. Файл на дропе кладётся целиком.
```

## 7. Формат базы, чтобы файлы вливались без правки

Колонки те же, что у `p25_baza_edinaya.py` (готовый пример заполнения —
`seo-texts/pishchevka_chetyre_celi.py`):

```
inn · predpriyatie · chelovek · dolzhnost · nomer · dobavochnyy · vid_nomera ·
chem_dokazan · prinadlezhnost · citata · dokazano_iz · pochta · vid_pochty · mashina ·
kanalov · istochnikov · kanaly · istochniki · mashina_ssylka
```

Смысл трёх ключевых колонок:

```
vid_nomera      ЧЕМ ИМЕННО является номер: личный мобильный / приёмная / отдел / 8-800 /
                мобильный предприятия / линия подбора. Владелец: вид номера назван явно
chem_dokazan    как доказан: «номер и фамилия в одной цитате» / «номер в цитате, фамилии
                рядом нет» / «цитата есть, номера в ней нет» / «цитаты нет — доказать нечем»
prinadlezhnost  почему это ТОЧНО наше предприятие: ИНН на странице, свой домен, карточка
                выдана по ИНН
```

Сборка базы и разделение на «точно доказанное» и «остальное с причиной»:

```bash
python3 seo-texts/zapusk_na_servere.py p25_baza_edinaya.py
```
