## 3. Как проверялось по инструментам

Документы: `PARK-2S-INSTRUMENTY-peredacha.md`, `INSTRUMENTY-I-PRIYOMY.md`, и `DOKA-kakoy-skript-chto-delaet.md`.
**Третьего файла из задания, `INSTRUMENTY-KAK-POLZOVATSYA.md`, нет ни на дропе, ни в репозитории, ни в
истории git.** Вместо него взят DOKA: сам INSTRUMENTY-I-PRIYOMY называет его своим парным документом
(«какой скрипт что делает»).

Порядок: 480 идей → свод в приёмы (по металинзе, потом пачками по 3 металинзы, потом общее слияние;
одним вызовом не выходит - ответ режется на ~70 000 знаках) → каждый приём против трёх документов
с обязательной дословной цитатой; цитата проверена подстрокой в документе, без найденной цитаты статус
понижался. Потом все 122 вердикта прочитаны глазами: 27 поправлено (записаны в ruchnye-popravki.json
с причиной). Типичные ошибки классификатора: checko назван «закрытым» (документ говорит: работает с
сервера через пул socks5); реестр ЭПБ «не подтверждён» при описанных park_epb_shirokiy_vse.py и
mpb_po_inn.py; kad.arbitr.ru «частично» с цитатой, которая на самом деле про monitor-pb.

### 6.1. Знаменатель: полный реестр юрлиц края (нет ни одного инструмента)

Без списка всех предприятий региона слово «все» недоказуемо: сколько бы источников мы ни сложили,
ответа «а сколько всего» не будет. Нужно:
- выгрузка всех действующих юрлиц и ИП с ИНН на 22: ИНН, название, ОКВЭД (все коды), численность,
  выручка, адрес, статус. Источники: открытые данные ФНС/ЕГРЮЛ, ГИР БО (bo.nalog.gov.ru),
  реестр МСП (rmsp.nalog.ru), реестр товаропроизводителей края (минпромэнерго). У нас есть только
  точечные запросы по ИНН (dadata, checko); массовой выборки «регион × ОКВЭД» нет (P056, P035);
- отсев ликвидированных (dadata уже показал 346 ликвидированных из 1 911 на другой задаче);
- филиалы и обособленные подразделения федеральных компаний в крае (Алтай-Кокс, Сибэнерго, РЖД,
  Газпром): у них ИНН не на 22, и срез по ИНН их ТЕРЯЕТ. Нужен срез по адресу ЕГРЮЛ/КПП (P055, M10).

### 6.2. Проверенные фильтры региона у каждого источника (частично)

### 6.5. Косвенный слой: отраслевой классификатор (нет)

Прямые доказательства (закупка, ЭПБ, вакансия) покрывают предприятия, которые что-то публикуют.
Молокозавод на 40 человек компрессор покупает у дилера за наличные и нигде не отчитывается.
Нужно: правило «ОКВЭД × размер → вероятность КО» (элеваторы, пищёвка с упаковкой, покраска, литьё,
ПЭТ, деревообработка, водоканалы, котельные, шахты - см. линзы M02) поверх знаменателя из 6.1,
чтобы каждое предприятие края получило класс: доказано / косвенно / кандидат / не наше. Проверка
класса «косвенно» - двумя независимыми линзами провайдера (технолог + скептик, как в LINZY-TEHPROCESS)
и выборкой глазами; иначе среда, придуманная по отрасли, уедет клиенту как факт.

### 6.6. Методика полноты (нет ни одного инструмента)

- одна база: ИНН → класс доказательства → ссылка+цитата → источники (накапливаются, не заменяются);
- оценка полноты по перекрытиям независимых источников (ЭПБ × ЕИС × вакансии; Линкольн-Петерсен, P051)
  и по стратам ОКВЭД × город (P053): где покрытие ниже 30 % - туда следующий прогон;
- обратный замер у каждого фильтра: сколько строк со словом-машиной НЕ дали факта;
- контроли: выдуманное предприятие, чужой регион (04 - Республика Алтай), ликвидированное;
- версии и даты: списки живут, реестр ЭПБ и ЕИС меняются; фиксировать snapshot и время.

### 6.7. Инфраструктура и порядок

- боевой раннер жив (8 потоков), проверочный VPS мёртв с 10.08 - либо поднять, либо не рассчитывать;
- пул прокси для checko достижим только с серверов; из песочницы - только monitor-pb, trudvsem-API,
  провайдер; zakupki - только с сервера. Планировать прогоны по слоям заранее;
- скрипты разложены по трём веткам (DOKA: `[1с]`, `[2с]`, `[3с]`); под региональный прогон собрать их
  в одну ветку с одним списком слов (31 слово ЭПБ + слова ТО/запчастей) и одним срезом региона;
- документ `INSTRUMENTY-KAK-POLZOVATSYA.md` из задания отсутствует; если он существует у владельца -
