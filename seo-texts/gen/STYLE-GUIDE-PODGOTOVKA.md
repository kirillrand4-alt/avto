# Стайлгайд генерации SEO-текстов: подготовка воздуха и газогенерация (осушители, ресиверы, фильтры, генераторы, сепараторы) — prokompressor.ru

- СПИСКИ <ul>/<li> В ТЕКСТЕ ЗАПРЕЩЕНЫ: CSS сайта рисует маркеры длинным тире «—», что читается как ИИ-паттерн. Перечисления оформляй короткими абзацами <p> (каждый пункт - законченное предложение) или строками таблицы.
- Блок фото-карточки ставь ВНЕ <p> (между абзацами), не внутри абзаца.

## Задача
Написать SEO-текст для нижнего блока категории/фасета НЕкомпрессорного оборудования.
Тип категории — в поле `category` payload (`ref_dryer`, `ads_dryer`, `receiver`, `filter`,
`n2_gen`, `o2_gen`, `separator`, `air_prep`, `spare_parts`). Отраслевая фактура — в поле
`category_reference` (выжимка из досье категории). Брендовая фактура (если страница по бренду) —
в `brand_facts`. Результат — JSON (см. «Формат результата»). Title/description НЕ генерируются.

Это оборудование - КОМПОНЕНТЫ пневмосистемы, а не компрессоры. Продаём их «от места в системе
подготовки воздуха», а не как самостоятельную машину. Главный редакционный приём - показать
читателю, ГДЕ звено стоит в цепочке и КАКУЮ задачу закрывает.

## Общие правила — те же, что для компрессоров (действуют полностью)
Все 12 обязательных правил компрессорного стайлгайда переносятся без изменений (кратко ниже). Ключевое, что нарушают чаще:
1. От полноты каталога, БЕЗ «в разделе представлены/собраны», «на этой странице».
2. Без разговорных императивов; нейтральные формы («подойдёт», «подбор ведут от…»).
3. Без интерфейса («фильтр слева») и SEO-жаргона («тег», «фасет», «листинг», «выдача»).
5. Без хеджей («около», «примерно», «порядка», «ориентировочно»). Точная цифра или перестрой фразу.
6. **Длинное тире « — » запрещено полностью.** Только дефис «-» или перестроенная фраза.
   Без штампов ИИ: «незаменим», «идеальное решение», «широкий спектр», «представляет собой», «важно отметить».
7. Точные цены - НЕТ в теле текста (title/description не генерируем, значит цен в результате нет вообще).
8. FAQ в аккордеоне Aspro (точная разметка ниже, раздел «Шаблон аккордеона FAQ»), id уникальные: `accordion-<cat>-<slug>-1…N`.
10. Текст начинается с вводного H2 (не дублирует H1 дословно).
11. Никаких `<script>`/`<style>`.

Переносятся и все «правила ясности» копирайтера:
- «В каталоге»/«на сайте» при первом упоминании - только «в нашем каталоге» (домен НЕ писать), дальше коротко.
- Счётчики позиций - канон-формула: «N позиций в нашем каталоге (с учётом исполнений);
  под заказ поставляется весь модельный ряд». Вторая часть обязательна.
- Пневмоаудит - НЕ субъект действия («инженер проводит пневмоаудит и рассчитывает потребность»).
- Не выдавать за «опцию, влияющую на цену» параметр, детерминированный конструкцией/серией.
- Правило первого упоминания термина: раскрывай ОДНИМ придаточным при первом появлении, если
  расшифровка есть в данных (для этой тематики терминов много - PDP, PSA, коалесценция, ISO 8573).

Таблица (утв. владельцем): если в данных 3+ сопоставимых позиции/серии/класса - ОДНА таблица
сравнения простой разметкой (шаблон ниже, раздел «Таблица сравнения»), только данные из payload, без пустых колонок.

## Тональность (поле tier) — те же тиры
- **rodnoy** (Enger) - для брендовых страниц Enger в этих категориях (у Enger есть осушители,
  генераторы азота/кислорода, фильтры). Продвигаем, факты только из `brand_facts`, БЕЗ мост-блока.
- **druzhestvennyy** (офиц. дилерство «Руспром») - тепло-нейтрально, максимум фактуры из payload.
- **neytralnyy** (остальные бренды и большинство фасетов) - экспертно, без эпитетов и критики.
  Мост к Enger - см. правило моста ниже (оно для этих категорий ДРУГОЕ, чем у компрессоров).

## Правило моста к Enger (решение по SEO, 15.07) — КЛЮЧЕВОЕ ОТЛИЧИЕ
Мост даём коротким (1-2 предложения, БЕЗ отдельного H2 «Альтернатива»), и ТОЛЬКО там, где у
Enger реально есть эта категория:
- **осушители (реф и адс), генераторы азота, генераторы кислорода, фильтры** - короткий мост
  уместен: «В нашем каталоге представлены и осушители Enger…» со ссылкой на соответствующий
  раздел Enger, если он есть в payload (`enger_category_url`). Без сравнения «лучше/хуже».
- **ресиверы, сепараторы, влагомаслоотделители, запчасти** - **МОСТА НЕТ.** У Enger этой
  товарной группы нет; притягивать его - фальшь. Вместо моста - блок перелинковки по системе
  подготовки воздуха (см. ниже), это честнее и полезнее для SEO.
Если `enger_category_url` в payload отсутствует - моста не делаем даже для «мостовых» категорий.

## Перелинковка «по месту в системе» — главный SEO-приём этих страниц
Каждый компонент встроен в цепочку подготовки воздуха. Показывай соседние звенья и ОБЯЗАТЕЛЬНО
оформляй их настоящими ссылками `<a href="URL">якорь</a>` (не просто словом!) минимум на одну,
лучше на две смежные категории ИЗ `related_urls` payload - только оттуда, URL не выдумывать.
Пример: «…поступает в <a href="/catalog/resivery/">ресивер</a>, затем проходит
<a href="/catalog/podgotovka-vozdukha/filtry-magistralnye/">магистральный фильтр</a>…».
Якорь - осмысленное слово-звено (ресивер, магистральный фильтр, осушитель), не «тут»/«подробнее».
Каноническая цепочка (упоминать те звенья, что релевантны странице):
**компрессор → ресивер → циклонный сепаратор → префильтр → рефрижераторный осушитель →
(адсорбционный осушитель для сухого воздуха) → магистральный фильтр → потребитель**;
для газогенерации хвост длиннее: **… → тонкая фильтрация → генератор азота/кислорода →
ресивер газа → потребитель**. Это не «SEO-ссылки ради ссылок», а объяснение, что купить в пару.

## Структура по типу категории (поле skeleton)
Скелеты проще компрессорных - это компоненты. Порядок H2 соблюдай, названия формулируй своими словами.

- **DRY** (осушители реф/адс): Зачем осушать воздух и как работает тип → Как подобрать
  (производительность, давление, T входа/среды, требуемая точка росы) → Место в системе
  подготовки (перелинковка) → [Бренды/серии если есть] → [Мост Enger] → FAQ
- **REC** (ресиверы): Зачем нужен ресивер (3 функции: сглаживание, буфер, конденсат) →
  Как подобрать объём и давление → Сертификация и безопасность (ТР ТС 032/2013 - осторожно,
  без юрсоветов) → Место в системе → FAQ  *(моста нет)*
- **FLT** (фильтры/сепараторы): Что удаляет и три механизма (задержание/коалесценция/адсорбция)
  → Классы ISO 8573-1 и подбор по расходу/давлению → Каскад фильтров и место в системе →
  [Мост Enger для магистральных фильтров] → FAQ
- **GAS** (генераторы азота/кислорода): Азот/кислород на месте вместо баллонов → PSA vs мембрана
  (для N₂) / принцип для O₂ → Подбор по чистоте и производительности + требования к входному
  воздуху → Место в системе (осушитель+фильтры обязательны) → [Мост Enger] → FAQ
- **SPR** (запчасти/расходники): Что входит и как подбирают по модели компрессора →
  Регламент замены → Место в обслуживании → FAQ  *(моста нет; ссылка на ТО уместна)*
Для брендовых страниц Enger в этих категориях используй скелет типа + продвижение (rodnoy).

## Терминологические ловушки по категориям (НАРУШЕНИЕ = фактическая ошибка)
Осушители:
- Осушитель удаляет **воду**, НЕ масло (масло - задача коалесцирующих фильтров). Не писать «удаляет масло».
- **Точка росы под давлением (PDP)** ≠ атмосферная точка росы. Рефрижераторный даёт PDP обычно +3 °C.
- Ниже +3 °C рефрижераторный НЕ работает (обмерзание); для сухого воздуха - адсорбционный.
- Не писать «осушает до 100% сухости» (физически некорректно). Класс по влаге - через ISO 8573-1.
- Рефрижераторный не работает зимой в неотапливаемом помещении (мин. T среды +2…+5 °C).
Ресиверы:
- «Воздухосборник» и «ресивер» - синонимы, не разные товары.
- **Рабочее давление ≠ пробное (испытательное)** давление - это разные строки паспорта.
- Ресивер **осаждает конденсат**, но НЕ очищает воздух и не заменяет фильтр/осушитель.
- Объём (л) ≠ производительность (л/мин): 100 л ресивер ≠ 100 л/мин подачи.
- Сертификация (ТР ТС 032/2013) - юридически чувствительно: отсылать к документации и нормам,
  без конкретных советов «нужна регистрация / не нужна».
Фильтры/сепараторы:
- Класс - только по **ISO 8573-1** (тройка цифр, напр. 1.4.1), а не «степень очистки 99,9%».
- **мкм** (частицы) ≠ **мг/м³** (масло) - разные показатели.
- Коалесцирующий и угольный фильтр - РАЗНЫЕ изделия, не взаимозаменяемы.
- Расход всегда с указанием давления (500 л/мин при 7 бар ≠ при 4 бар).
- Не обещать «стерильный воздух» - это отдельный класс (ISO 8573-7).
Генераторы газов:
- **PSA ≠ адсорбционный осушитель** (принцип похож, назначение другое - не смешивать).
- «Безмасляный азот» - некорректно; правильно про класс масляного загрязнения по ISO 8573.
- Чистота ≠ давление - разные параметры. Чем выше чистота PSA, тем меньше выход при том же воздухе.
- Единицы приводить к одному знаменателю (Нм³/ч, л/мин, SCFM).
- Не обещать конкретный срок окупаемости без данных по ценам на баллонный/жидкий газ.

## FAQ: 3–5 вопросов из пула ПОД КАТЕГОРИЮ (пул - в category_reference досье)
Каждое досье категории несёт свой список реальных вопросов. Выбирай 3-5 под данные страницы,
числа пересчитывай под payload, ответы - без выдуманных цифр. НЕ бери вопросы подряд по списку.
Частые сквозные: «Как подобрать <компонент> под мой компрессор X м³/мин?», «Что ставить до, что
после осушителя?», «Нужен ли автодренаж/слив конденсата?», «Какое ТО требуется?». Для газогенерации
- «Чем генератор выгоднее баллонов?» (только качественно, без цифр окупаемости).

## Использование цифр
- Число позиций: «более N» с округлением вниз до красивого; канон-формула счётчиков.
- Технические диапазоны (давление, производительность, точка росы, классы ISO) - ТОЛЬКО из
  payload/category_reference. Параметры конкретных моделей брать из `sample_models`/`facet_ranges`
  с оговоркой, что диапазоны фильтров - границы раздела, а не именно этой страницы.
- НИЧЕГО не выдумывать сверх данных: ни классов ISO, ни точек росы, ни чистоты азота, ни серий.

## Title / Description
НЕ ГЕНЕРИРУЮТСЯ (решение владельца 15.07). Поля title и description верни пустыми строками.

## Естественность и ритм (анти-детект, методика DrMax v3.6)
Текст должен читаться как написанный инженером. Регистр машинных штампов у нас закрыт (тире,
«представляет собой», хеджи), но следи ещё за тремя вещами:
1. РИТМ АБЗАЦЕВ - не делай все абзацы одинаковой длины (машинный маркер). Чередуй короткие
   (1-2 предложения) и развёрнутые. Длину предложений тоже варьируй.
2. Запрещённый канцелярит: «таким образом», «в заключение», «подводя итог», «важно понимать»,
   «следует обратить внимание», «необходимо отметить», «в свою очередь», «более того»,
   «посредством», «в контексте», «безусловно». Связки «при этом»/«кроме того» - максимум пара на текст.
3. «Данный/данная» в роли «этот» - канцелярит, пиши «этот» (слово «данные»=data не трогаем).
Не «очеловечивай» просторечием («ну», «вот», «типа») - для B2B это новый искусственный паттерн.

## Авторство: НЕ упоминай Игоря Волкова и экспертов в тексте
Блок авторства (Игорь Волков + дата) добавляется АВТОМАТИЧЕСКИ в конец страницы отдельным блоком.
НЕ вставляй в текст фразы «подбор ведут инженеры под руководством Игоря Волкова», «Волков консультировал»
и любые упоминания эксперта - иначе будет дублирование подписи. Просто пиши экспертно по сути.

и FAQ формулируй заново. Приоритет модель генерации - Fable 5.
